# 初期版の検証と読者レビュー

## 対象

日本語を標準に、英語版を`/en`に配置。トップ、概要、最初のプログラム、ローカル開発の手順、関数リファレンスを公開する。読者向けの説明はこのサイト内に置き、GitHubの仕様ファイルへの誘導は使わない。

## 2026-10-12の検証

- Node 24.14.0、Bun 1.3.11。`bun run check`で型エラー・警告なし。`bun run build`で静的ページを生成。
- 初期の注文例はコードの選定と改行が不自然だったため撤去。配送状態の型、`match`、パイプラインを示す`examples/parcel.ssrg`へ置き換えた。Seseragi 0.61.25で`Sent to Kyoto`、`Preparing`、`Sent to Sapporo`を確認。未処理のケース追加では`SES-T0301`、関数リファレンスの呼び出し・部分適用は42を確認。
- Chromeで日本語検索「関数」と英語検索「partial」、検索結果からの遷移、ページごとの言語切り替え、コードコピー、配色の保存を確認。
- 375px、390px、1440pxで、CSSの折り返しを無効にしても掲載コードの各行が収まることを確認。見出しとブランドの負の字間指定を撤去。
- 1440pxと390pxで表示。ページ全体の横あふれ、コード領域の横あふれがないことを確認。短い関数シグネチャは一行に保ち、本体を式の区切りで改行して掲載。
- 10の日英ページと内部リンクがHTTP 200。JavaScriptを無効にしても学習本文を読める。
- パイプラインは初期値と各`|>`を同じ字下げで縦に配置。トップと日英本文で共通の書き方を使う。
- ローカル開発ページの`seseragi new web hello-web`と`seseragi build .`を一時ディレクトリで実行し、生成された`dist/index.html`を確認。
- 日本語本文はyomiyasu v1.1.2で点検。語尾が続く箇所の注意は、自然な機能説明として残した。
- Astroの静的MDXはレイアウト内のReact Contextを引き継がないため、本文のコードコピーはAstroのクリック処理で実装。見出しは通常のアンカーリンクとした。
- Fumadocsの検索ハイライト用`::highlight`に対しCSS最適化ツールが2件の警告を出す。ビルドは成功し、検索の表示・操作をブラウザで確認した。

## 次に確かめること

見た目の方向はユーザーに確認済み。説明の理解しやすさは、実際の初見読者によるレビューが必要。自動検証や文章リンターの結果だけでは読者評価の完了としない。

読者に、`Packing`と`Sent String`の違い、`match`で値を取り出す処理、文字列を返す関数と出力の違いを説明してもらう。続いて状態を変えて実行し、部分適用をリファレンスで探してもらう。つまずいた箇所を記録してから本文を広げる。

Seseragiでこのサイトを再現する場合は、同じ3ページを対象として、見た目、検索・ナビゲーション、日英の本文管理、静的ビルドの4点を比較する。
