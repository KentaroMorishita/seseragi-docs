`.ssrg`ファイル一つが一つのモジュールです。ソース内にモジュール名は書きません。通常のidentityはパッケージ identityとソースルートからの相対モジュール pathで決まり、ファイルの絶対pathでは決まりません。

## 公開範囲

宣言は既定でモジュール内だけで公開です。他のモジュールから使う`fn`、`let`、`type`、`struct`、`newtype`、`alias`、`trait`などへ`pub`を付けます。公開署名から非公開型を漏らすことはできません。

公開ADT/newtypeのコンストラクターと公開structのフィールドは、通常は型と一緒に公開されます。`pub opaque`を使うと、他モジュールには型名と公開operationだけを渡し、コンストラクター・フィールド・分解を定義モジュール内へ隠せます。

inherent メソッドも既定では非公開です。trait instance自体へ`pub`は付けません。instanceのモジュールがtransitive import closureへ含まれると、instance探索の対象になります。

## importと二つのファイル

`labels.ssrg`は、型と表示関数を公開するモジュールです。次は宣言ファイルの内容です。

```seseragi title="src/labels.ssrg"
pub type Stage =
  | Draft
  | Published String

pub fn title stage: Stage -> String =
  match stage {
    Draft -> "Draft"
    Published name -> name
  }
```

同じソースディレクトリの`main.ssrg`から、公開名だけをimportします。この二ファイルのパッケージを実行すると`Seseragi`を出力します。

{/* example: examples/reference/modules-project/src/main.ssrg */}

```seseragi title="main.ssrg"
import { Published, title }
  from "./labels"

pub effect fn main =
  Published "Seseragi"
  |> title
  |> println
```

importはモジュール先頭へ置きます。別名を付ける`import { parse as parseText }`と、`import * as text from "std/text"`のnamespace importも使えます。namespace importは`text.trim`のような修飾参照だけを導入し、全名をunqualifiedにするワイルドカード構文はありません。

## specifierの解決

| 先頭形式 | 解決先 |
| --- | --- |
| `./`、`../` | 現在モジュールと同じルート内の相対ファイル |
| `self/` | 現在パッケージの非公開ソースモジュール |
| `std/` | canonical standard モジュール |
| `gen/` | 現在パッケージのgenerated バインディング |
| bare specifier | 宣言済みの直接依存関係と公開subpath |

`./labels`は正確に`labels.ssrg`へ解決します。ディレクトリ index、別拡張子、working ディレクトリへのfallbackはありません。ソース/test/generated ルートを相対importで横断することもできません。

依存関係ではexport mapにあるsubpathだけ使えます。transitive 依存関係を直接importする場合も、自分のマニフェストへ直接依存関係として宣言します。[プロジェクト設定](/docs/reference/project-configuration)でlayoutとexport mapを確認できます。

## re-exportと名前空間

`pub import { Name } from "./module"`は元のidentityを保ったまま公開APIへ加えます。`pub import * as tools from "./tools"`は公開namespaceを導入します。

型/trait、値/関数/constructor、フィールド/method、モジュールの別名、独自演算子は別namespaceです。newtypeの型とコンストラクターが同じspellingでも、一つのnamed importで両方を導入できます。

unqualified名はlocal バインディング、現在モジュールの宣言、明示import、preludeの順に探します。同じnamespace・同じ段階の重複を勝手に選びません。演算子は`import { operator <+> }`で別にimportし、fixityもinterfaceから取得します。

## 循環と初期化

型だけのimportでもモジュールグラフの循環は禁止です。相互参照する共有型は第三モジュールへ分け、同一モジュールの関数相互再帰は`rec`へまとめます。

モジュールは依存関係順に一度だけ初期化し、top-level `let`はソース順に評価します。後続の`let`を初期化前に読む呼び出しは`SES-N0201`です。同じモジュールを複数箇所からimportしてもtop-level値を二度作りません。

importでSeseragiのEffectは実行しません。foreign モジュールのload modeは別の明示契約です。[TypeScript連携](/docs/reference/typescript-interop)を参照してください。

## 実行モジュール

実行パッケージは`run.entry`から公開`main`を一つ解決します。`main`の成功は`Unit`、要件は閉じたレコードです。ライブラリパッケージに`main`は不要で、importしたモジュールの`main`を暗黙に実行することもありません。

単一ファイルのscratch実行ではパッケージ依存関係や複数ファイルのグラフを推測しません。このページの二ファイル例のようなアプリは、マニフェストとlockを持つパッケージで実行してください。[パッケージを作る](/docs/guides/packages-and-deployment)で手順を説明しています。
