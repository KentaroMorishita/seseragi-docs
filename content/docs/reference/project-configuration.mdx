パッケージのディレクトリには、`seseragi.toml`を一つ置きます。CLIは、対象のファイルから親のディレクトリへたどって最初に見つけた`seseragi.toml`を使います。さらに外側の`seseragi.toml`や`package.json`の設定が混ざることはありません。

## 必須のパッケージと実行設定

```toml title="seseragi.toml"
[package]
name = "docs/hello"
version = "0.0.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"
```

`package.name`・`version`・`language`は必須です。`name`は小文字の単語を`/`でつないだもの、`version`はSemVer、`language`は対応する言語バージョンの範囲です。`language`にはコンパイラーのバージョン番号ではなく、言語のバージョンを書きます。

`run.entry`は、ソースのディレクトリからのモジュールのパス（拡張子なし）です。`run.target`は`process`（CLI）か`web`です。ライブラリでは`[run]`を省略できます。知らないキー、重複したキー、型の違う値はエラーです。ツール独自の設定は`[tool.NAME]`に書きます。

## ソースのルートとモジュールのパス

| ルート | 既定ディレクトリ | 役割 |
| --- | --- | --- |
| ソース | `src` | 通常のモジュール、公開API |
| tests | `tests` | テストランナーだけが読むモジュール |
| benchmarks | `benchmarks` | ベンチマークだけが読むモジュール |
| generated | `.seseragi/generated` | 生成したTypeScriptのbinding |

`[layout]`で変更できます。ルートは互いに重複できず、absolute pathやパッケージ外へエスケープするpathを指定できません。相対importは同じルート内に限ります。

`seseragi.toml`に書くモジュールのパスは、`main`や`http/client`のような形です。`.ssrg`、空の部分、`.`や`..`、バックスラッシュは書けません。大文字小文字やUnicodeの正規化の違いだけで重なる名前もエラーです。生成したモジュールは`gen/`で、自分のパッケージのモジュールは`self/`でimportします。

## exportsと依存関係

`[exports]`は公開subpathからソースモジュールへのmapです。

```toml title="公開API"
[exports]
"." = "lib"
"email" = "email"
```

パッケージ名が`acme/validation`なら、この例では`acme/validation`と`acme/validation/email`の二つをimportできるように公開しています。`[exports]`に書いていないモジュールは、ほかのパッケージからimportできません。テストや生成したファイルを直接公開することもできません。

local 依存関係は次のように設定します。

```toml title="local dependency"
[dependencies.validation]
package = "acme/validation"
path = "../validation"
```

依存関係のキーはimportで使う名前で、依存先の`seseragi.toml`のパッケージ名と一致させます。依存パッケージがさらに依存しているパッケージを使う場合も、自分の依存として書きます。GitのURLやブランチを指定する方法はありません。

言語仕様にはパッケージレジストリからバージョンを指定して取得する方法も定義されていますが、今のCLIが扱えるのはローカルのパスで指定した依存だけです。レジストリからの取得や公開のコマンドはまだありません。

## TypeScriptとWebの設定

foreign TypeScriptを使うパッケージでは`[foreign.typescript]`へresolver、ホストマニフェスト、ホスト lockfileを指定します。生成バインディングはマニフェストとconverter設定から再生成し、手編集しません。

Webアプリでは、必要に応じて`[web]`を設定できます。

```toml title="Web入力"
[web]
index = "web/index.html"
public = "public"
```

custom HTMLのheadに`<!-- seseragi:head -->`、bodyに`<!-- seseragi:entry -->`を各一個置きます。builderがgenerated CSS/scriptへ置換します。publicのregular ファイルは相対pathを保ってcopyします。generated assets、ルート index、build markerなどへの衝突、symlink、パッケージ外の入力はエラーです。

## lockの更新

```bash
seseragi lock update .
```

lockはパッケージのexact identity、ソースダイジェスト、言語/stdlib/Unicode/timezone バージョン、Provider選択とartifact identityを固定します。通常のbuild/testはlockを必須とし、勝手に更新しません。欠落や不一致は`SES-K0102`です。

ソース、`seseragi.toml`、Webの静的ファイル、binding生成の設定などを変えたら、ビルドする前にロックファイルを更新します。`dev`の間だけは、ソースの編集だけなら更新は要りません。設定やProviderの要件を変えた場合は、`dev`中でも更新が必要です。

## プロファイルとrunner設定

`[build].profile`で`development`か`release`を選べます。ターゲットは`[run].target`に書き、`[build]`には書きません。コマンドのオプションで上書きした設定は、その実行の間だけ有効です。

`[test]`には`target`・`jobs`・`timeout_ms`・`cleanup_grace_ms`・`seed`を、`[benchmark]`には`target`・`warmup`・`samples`・`minimum_sample_ms`・`regression_threshold_percent`を書けます。[CLI](/docs/reference/cli)のオプションで上書きできます。

`[providers]`は、アプリがサービスごとにどのProviderを使うかを選ぶ設定です。`[provider].artifacts`は、Providerのパッケージが自分の成果物を公開する設定で、別物です。Providerの選ばれ方は[ランタイムProvider](/docs/reference/runtime-providers)、実際の手順は[パッケージと配布](/docs/guides/packages-and-deployment)にあります。
