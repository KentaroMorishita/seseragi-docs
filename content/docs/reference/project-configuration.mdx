パッケージルートには一つの`seseragi.toml`を置きます。対象ファイルから親へ探索した最初のマニフェストを使い、さらに外側のマニフェストやパッケージ.jsonから設定をmergeしません。

## 必須のパッケージと実行設定

```toml title="seseragi.toml"
[package]
name = "docs/hello"
version = "0.0.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"
```

`package.name`・`version`・`language`は必須です。nameはlowercase segmentを`/`でつなぎ、バージョンはSemVer、languageは言語バージョンの範囲です。配布版コンパイラーのバージョン番号をそのままlanguageへ書くものではありません。

`run.entry`はソースルート内の拡張子なしモジュール pathです。`run.target`はprocessまたはwebです。ライブラリはrunを省略できます。未知のcore key・重複key・型の違う値はエラーです。tool固有設定は`[tool.NAME]`へ置きます。

## ソースのルートとモジュールのパス

| ルート | 既定ディレクトリ | 役割 |
| --- | --- | --- |
| ソース | `src` | 通常のモジュール、公開API |
| tests | `tests` | test runnerだけが読むモジュール |
| benchmarks | `benchmarks` | benchmark runnerだけが読むモジュール |
| generated | `.seseragi/generated` | 再生成するforeign バインディング |

`[layout]`で変更できます。ルートは互いに重複できず、absolute pathやパッケージ外へエスケープするpathを指定できません。相対importは同じルート内に限ります。

マニフェストのモジュール pathは`main`や`http/client`です。`.ssrg`、空segment、`.`/`..`、backslashを含めません。caseとUnicode正規化の衝突も拒否します。generated モジュールは`gen/`、ソース-private モジュールは`self/`から参照します。

## exportsと依存関係

`[exports]`は公開subpathからソースモジュールへのmapです。

```toml title="公開API"
[exports]
"." = "lib"
"email" = "email"
```

パッケージが`acme/validation`ならルート importと`acme/validation/email`を公開します。mapにない内部pathは外部からimportできません。testやgenerated ファイルを直接exportすることもできません。

local 依存関係は次のように設定します。

```toml title="local dependency"
[dependencies.validation]
package = "acme/validation"
path = "../validation"
```

依存関係 keyはimport ルートで、対象マニフェストのパッケージ identityと一致させます。使うtransitive パッケージも直接依存関係として宣言します。core ソースにgit URLや分岐を指定する方式はありません。

仕様はレジストリバージョン範囲も定義していますが、現在の配布版のパッケージローダーはlocal/path プロジェクトを対象とします。ここではレジストリからの自動取得やpublish コマンドを利用できる機能として扱いません。

## ホスト入力とWeb document

foreign TypeScriptを使うパッケージでは`[foreign.typescript]`へresolver、ホストマニフェスト、ホスト lockfileを指定します。生成バインディングはマニフェストとconverter設定から再生成し、手編集しません。

Webではoptionalな`[web]`を設定できます。

```toml title="Web入力"
[web]
index = "web/index.html"
public = "public"
```

custom HTMLのheadに`<!-- seseragi:head -->`、bodyに`<!-- seseragi:entry -->`を各一個置きます。builderがgenerated CSS/scriptへ置換します。publicのregular ファイルは相対pathを保ってcopyします。generated assets、ルート index、build markerなどへの衝突、symlink、パッケージ外の入力はエラーです。

## lockの更新

```bash
seseragi lock update .
```

lockはパッケージのexact identity、ソースダイジェスト、言語/stdlib/Unicode/timezone バージョン、Provider選択とartifact identityを固定します。通常のbuild/testはlockを必須とし、勝手に更新しません。欠落や不一致は`SES-K0102`です。

ソース、マニフェスト、Web input、converter metadataなどの変更後は、通常build前にlockを更新します。devだけはexact グラフとProvider選択を保った通常ソース編集を許容します。設定やProvider要件が変わった場合はdevでも更新が必要です。

## プロファイルとrunner設定

`[build].profile`でdevelopment/releaseを選べます。ターゲットは`[run].target`へ置き、buildに複製しません。CLI overrideはその実行だけに作用します。

`[test]`にはターゲット、jobs、timeout_ms、cleanup_grace_ms、seedを、`[benchmark]`にはターゲット、warmup、samples、minimum_sample_ms、regression_threshold_percentを設定できます。[CLI](/docs/reference/cli)のオプションが対応値を上書きします。

`[providers]`は実行ルートがサービスごとのProviderを選ぶ設定、`[provider].artifacts`はProvider パッケージがartifactを公開する設定です。意味を混ぜないでください。[Runtime Provider](/docs/reference/runtime-providers)で選択条件を説明しています。運用手順は[パッケージとデプロイ](/docs/guides/packages-and-deployment)を参照してください。
