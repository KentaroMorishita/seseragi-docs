Web UIでは、pure関数で不変のHtml ツリーを作り、DOMへの接続をEffectへ置きます。componentは普通の関数です。class、hook、JSX専用構文、関数の呼び出し順から生まれるhidden stateはありません。

## Htmlとchildren

`std/web/html`は全ターゲットで使えるpureなHtmlとSSRを提供します。`Html<Action>`は、イベントからActionを作る可能性のあるツリーです。DOM ノードや購読を内部へ保持しません。

childrenへ渡せるのは`Unit`、`String`、同じAction型の`Html`、そのArray/Listです。Stringはtext ノードへなり、数値は`show`や`html.text`で明示変換します。ArrayにStringとHtmlを混在させるarbitrary unionはありません。

{/* example: examples/reference/web-ui.ssrg */}

```seseragi title="web-ui.ssrg"
import * as html from "std/web/html"

fn view -> html.Html<Unit> =
  html.h1 {
    children: "Seseragi & you",
  }

pub effect fn main =
  view ()
  |> html.renderToString
  |> println
```

出力は`<h1>Seseragi &amp; you</h1>`です。ツリー構築時はStringを保持し、SSRのsinkで一度エスケープしています。

## propsと安全な構築

propsはstructural レコードです。共通の`class`、`id`、`title`、`style`、イベントなどは省略可能なフィールドで、tagが要求するフィールドは必須です。子を持つtagでは`children`が必要です。void elementにはchildrenを指定できません。

`className`ではなく`class`を使います。`style`は型付きpropertyから構築し、URLを必要とするpropsには検査済みの`WebUrl`を渡します。raw HTML Stringをuncheckedに挿入する標準APIはありません。

`renderToString`はfragment、`renderDocument`はdoctypeを含むdocumentを作ります。イベントやkeyはHTML attributeに出さず、SSRはActionを実行しません。HtmlにEq/Ord/Hash/Show instanceはありません。

## Actionと入力スナップショット

イベント propsは操作の意図を表すActionを作ります。`onClick`はAction値、入力イベントは不変スナップショットからActionを返すmapperです。ホストのEventやmutable ターゲットをアプリへ渡しません。

`InputEvent.value`はStringです。`ChangeEvent`は`value`と`checked: Maybe<Bool>`を持ち、checkbox/radioだけcheckedが`Just`になります。文字入力などは`Nothing`です。ファイル inputの`onFileChange`はopaque FileのArrayを渡します。

ActionはADTでも、子featureが返した`Task<Unit>`でも構成できます。fallibleな操作をそのまま無視せず、dispatchのerror型へ写すか、feature内でrecoverしてください。

## DOMへの接続とlifetime

`std/web/dom`はDom サービスを要求するブラウザー専用モジュールです。processでHtmlをSSRできることと、DOMを操作できることは別です。

`query`で対象を取得し、`mount`/`mountContent`でmanaged subtreeへ接続します。取得したDomMountを`awaitMount`で待ち、`unmount`で明示解除できます。`run`などの高水準operationも同じリソース規則を使います。

listener、購読、イベント queue、dispatch Fiberはmountのscopeへ属します。scope終了・failure・キャンセルで受付を止め、解除します。Actionはbounded FIFOで逐次dispatchし、queue overflowを黙ってdropしません。

hydration modeはFreshMount、厳密な一致を要求するHydrateStrict、不一致で作り直すHydrateOrReplaceです。cleanupでDOMを残す設定でも、listenerを残すことはありません。

## Signal バインディングの更新単位

| 更新単位 | 所有する範囲 |
| --- | --- |
| 静的な Html | mount後の値更新を購読しない部分 |
| leaf バインディング | text、attribute、value、checked、styleなど一つのsink |
| structural region | 対象Elementのchildrenと、その内側のリソース |

canonicalな`DomContent`はpureなinitial Htmlとバインディング planを組にします。型付き`BindingTarget<Action, Value>`と`Signal<Value>`を`bind`で接続し、sinkの値型を検査します。`ElementRef`はツリーとplanが共有するlogical identityで、ホスト Nodeやglobal IDではありません。

トランザクションの安定した公開値だけを反映します。leaf更新はElement identity、focus、selection、listenerを置き換えません。region更新はregion外へ影響せず、旧購読を解除して新しいcontentを接続します。keyはregion内のdirect sibling identityで、component stateを作る鍵ではありません。

## 状態の所有

local stateはfeature コンストラクター、shared stateは最も近い共通親、app-wide stateはルート featureが所有します。作成はEffectで一度行い、子へread-only Signalや許可した操作を渡します。モジュール import時のglobal singletonやcomponent呼び出し順へstateを依存させません。
