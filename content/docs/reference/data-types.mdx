データは、作ったあとに書き換えられません。「更新」は、新しい値を作ることです。いくつかの状態のどれかを表すならADT、決まったフィールドに名前を付けてまとめるならstruct、必要なフィールドさえあれば受け取りたいならレコード、同じ中身でも意味の違う値を区別するならnewtypeを使います。

## ADTとコンストラクター

ADTは、決まった数のケースのどれか一つを取る型で、名前で区別されます。データを持たないコンストラクターはそれだけで値、データ（ペイロード）を持つコンストラクターは関数です。ペイロードに複数の値を持たせるときは、一つのタプルにまとめます。

次の例は`Read the docs`を出力します。`TicketId`、`Ticket`、`Status`は、それぞれ異なる役割を持つ型です。

{/* example: examples/reference/data-types.ssrg */}

```seseragi title="data-types.ssrg"
newtype TicketId deriving Eq, Show =
  Int

struct Ticket {
  id: TicketId,
  title: String,
}

type Status =
  | Open Ticket
  | Closed TicketId

fn summary status: Status -> String =
  match status {
    Open ticket -> ticket.title
    Closed id -> `Closed ${id}`
  }

pub effect fn main =
  Open (Ticket {
    id: TicketId 1,
    title: "Read the docs",
  })
  |> summary
  |> println
```

`Closed (TicketId 1)`も`Status`ですが、`Int`や`Ticket`として使うことはできません。型パラメーターを持つADTでは、コンストラクターの型パラメーターは、ペイロード・期待される型・明示した型引数から決まります。ペイロードの取り出し方は[パターン](/docs/reference/patterns)にあります。

### ペイロードなしとタプルペイロード

{/* example: examples/reference/adt-variants.ssrg#variants */}

```seseragi title="宣言: 二つのvariant"
type Shape =
  | Point
  | Rect (Int, Int)
```

`Point`はそれだけで値です。`Rect`はタプルを一つ受け取るコンストラクターなので、二つの数値は`Rect (3, 4)`のようにまとめて渡します。

{/* example: examples/reference/adt-variants.ssrg#payload */}

```seseragi title="宣言: payloadの分解"
fn area shape: Shape -> Int =
  match shape {
    Point -> 0
    Rect (width, height) ->
      width * height
  }
```

{/* example: examples/reference/adt-variants.ssrg#cases */}

```seseragi title="main内: variant別の結果"
println $ show $ area Point
println $ show $ area $ Rect (3, 4)
```

出力は0と12です。`Rect`のペイロードは、パターンの中でタプルとして分解しています。

## structと更新

struct生成時には全フィールドが必要です。同名の変数がある場合はフィールド shorthandを使えます。更新は同じstruct型のspreadを先頭に一個置き、変更するフィールドを後ろに書きます。

```seseragi title="値を作る構文"
Ticket {
  id,
  title: "Read the docs",
}
Ticket {
  ...ticket,
  title: "Write tests",
}
```

spread式を最初に一度評価し、明示フィールドをソース順に一度ずつ評価します。直接書いたフィールドの重複、複数spread、先頭以外のspreadはエラーです。generic structの更新は型引数を変えられません。

`pub`を付けたstructは、フィールドも公開されます。中身を隠す`opaque`については[モジュール](/docs/reference/modules)にあります。

### 更新後も元の値は残る

{/* example: examples/reference/record-shapes.ssrg#person */}

```seseragi title="宣言: nominal struct"
struct Person { name: String }
```

{/* example: examples/reference/record-shapes.ssrg#struct-update */}

```seseragi title="main内: 不変値の更新"
let draft = Person { name: "Aki" }
let edited = Person {
  ...draft,
  name: "Mio",
}
println draft.name
println edited.name
```

`draft`はAki、`edited`はMioです。スプレッドは元の値を書き換えず、新しい`Person`を作ります。

## レコードと省略可能なフィールド

レコードは名前を持たない型で、形で型が決まります。スプレッドは複数書け、書いた順に適用されます。後ろのスプレッドやフィールドが、前の値を上書きします。フィールドの型を変えると、別のレコード型になります。同じフィールド名を二回直接書くとエラーです。

```seseragi title="recordの構文"
{ name: "Aki", age: 30 }
{ ...profile, age: profile.age + 1 }
{ name, }
```

`{ name: name }`の省略形`{ name }`をフィールド一つだけで書くときは、`{ name, }`とカンマを付けます。カンマのない`{ name }`はブロックになります。`{}`は空のレコードです。

`{ id?: String, children: String }`では、`id`を省略できます。省略したフィールドに`Nothing`が自動で入るわけではなく、フィールドそのものがない状態になります。`id`を読むと、あれば`Just 値`、なければ`Nothing`です。スプレッドでコピーしても、フィールドがあるかないかはそのまま引き継がれます。

### フィールドの不在とNothing

{/* example: examples/reference/optional-presence.ssrg#declarations */}

```seseragi title="宣言: optionalとrequired"
alias Optional = { id?: String }
alias Required = {
  id: Maybe<String>,
}
```

省略したフィールドを読むと`Nothing`、あるフィールドを読むと`Just`で返ります。

{/* example: examples/reference/optional-presence.ssrg#optional */}

```seseragi title="main内: presenceを読む"
let absent: Optional = {}
let present: Optional = {
  id: "intro",
}
println $ show absent.id
println $ show present.id
```

出力は`Nothing`、`Just intro`です。一方、`Required`では`id`フィールドを省略できず、値として`Nothing`を明示的に書きます。

{/* example: examples/reference/optional-presence.ssrg#required */}

```seseragi title="main内: requiredなMaybe"
let required: Required = {
  id: Nothing,
}
println $ show required.id
```

最後の出力は`Nothing`です。どちらも読んだ結果は`Maybe`になりますが、値を作るときにフィールドを省略できるかどうかが違います。

## newtypeとalias

`newtype UserId = Int`は、`Int`とは区別される新しい型を作ります。`UserId 42`のように包んで作り、パターンで取り出します。自動で包んだり取り出したりはされず、フィールドの読み取りやスプレッドもできません。

`alias UserId = Int`は名前を付けるだけで、`Int`とまったく同じ型です。`alias`にも型パラメーターを付けられますが、自分自身を（間接的にでも）参照する定義はエラーです。newtypeも同じです。

### aliasとnewtypeを使う

{/* example: examples/reference/alias-newtype.ssrg#declarations */}

```seseragi title="宣言: aliasとnewtype"
alias Count = Int
newtype UserId = Int
```

{/* example: examples/reference/alias-newtype.ssrg#alias-use */}

```seseragi title="main内: aliasは透明"
let count: Count = 41
count + 1
|> show
|> println
```

`Count`は`Int`と同じ型なので、普通に足し算できます。この例は42を出力します。

{/* example: examples/reference/alias-newtype.ssrg#wrap-unwrap */}

```seseragi title="main内: 明示したwrapとunwrap"
let user = UserId 42
let UserId raw = user
raw
|> show
|> println
```

`UserId`はコンストラクターで包み、パターンで取り出します。コンストラクターが一つしかないので、この`let`のパターンは必ず一致します。出力は42です。

### Intをnewtypeとして渡す場合

次のプログラムは、わざとエラーにした例です。`unwrap 42`は、`UserId`が必要な場所に`Int`を渡しているので`SES-T0101`になります。

{/* example: examples/reference/invalid/newtype-coercion.ssrg#invalid */}

```seseragi title="意図的な型エラー"
newtype UserId = Int

fn unwrap user: UserId -> Int =
  match user {
    UserId value -> value
  }

fn invalid -> Int = unwrap 42

pub effect fn main =
  println "ready"
```

## タプル、Array、List、範囲

| 値 | 型・規則 |
| --- | --- |
| `("answer", 42)` | `(String, Int)`、固定長タプル |
| `[1, 2, 3]` | `Array<Int>`、不変の連続列 |
| `` `[1, 2, 3] `` | `List<Int>`、先頭への追加が速い連結リスト |
| `` 1 : `[2, 3] `` | Listの先頭に要素を追加する。右結合 |
| `1..4` | 終端を含まない`Range<Int>` |
| `1..=4` | 終端を含む`Range<Int>` |

要素が一つのタプルはありません。コレクションの要素はすべて同じ型です。空のコレクションの要素の型は、期待される型や型の注釈から決まります。ArrayとListは自動では変換されません。

`array[index]`は`Maybe<A>`を返します。添字は`Int`で、負の数や範囲外なら`Nothing`です。Listには添字の構文はありません。範囲は1ずつ増え、始まりが終わりより大きい場合は空になります。

## 内包表記

書き方は次のとおりです。

```seseragi title="comprehensionの構文"
[n * n | n <- 1..=6, n % 2 == 0]
`[name | Just name <- optionalNames]
```

`|`の右側の、値を取り出す`<-`（ジェネレーター）と`Bool`の条件は、左から順に処理されます。ジェネレーターが複数あるときは、左側が外側のループになります。`<-`の右側には`Iterable`を実装した型なら何でも置け、結果がArrayかListかとは関係ありません。`<-`の左側のパターンに一致しない要素は、取り除かれます（上の例では`Nothing`が除かれます）。内包表記は値を計算するだけなので、Effectを`<-`の右側に置いて実行することはできません。

コレクションの関数と処理のコストは、[標準ライブラリ](/docs/reference/library)と[性能](/docs/reference/performance)にあります。
