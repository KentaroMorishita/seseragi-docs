値がないこと、立て直せる失敗、外の世界とのやり取りは、それぞれ値と型で表します。`null`、`throw`、`try/catch`のような構文はありません。

## Maybe、Either、Effect

| 型 | 意味 | 評価・実行 |
| --- | --- | --- |
| `Maybe<A>` | `Nothing`または`Just A` | 計算済みの値 |
| `Either<E, A>` | `Left E`または`Right A` | 計算済みの結果 |
| `Effect<R, E, A>` | `R`を使って実行し、`E`で失敗するか`A`で成功する | 実行するまで何も起きない |
| `Task<A>` | `Effect<{}, Never, A>` | 何も必要とせず、失敗しないEffect |

値がないこと自体が普通の結果なら`Maybe`、理由のある失敗なら`Either`、実際に何かを実行するなら`Effect`を使います。`Task`はPromiseのような別の型ではなく、Effectの別名です。

`maybe ?? fallback`は、`Just`なら中身を返し、`Nothing`のときだけ右側を計算して返します。右結合で、右側の型は`A`です。`Either`やTypeScriptの`null`になりうる値には使えません。

## 作ることと実行すること

Effectは、作っただけでは実行されません。同じEffectを二回実行すれば、処理も二回行われます。`map`で成功の値を変換し、`flatMap`や`do`で次の処理につなぎます。

{/* example: examples/reference/effects.ssrg */}

```seseragi title="effects.ssrg"
import * as effects from "std/effect"

type InputError deriving Show =
  | BelowZero

fn nonNegative value: Int
  -> Effect<{}, InputError, Int> =
  if value < 0 then
    effects.fail BelowZero
  else
    effects.succeed value

pub effect fn main = do {
  let answer =
    nonNegative (-2)
    |> effects.recover (\_ ->
      effects.succeed 0)
  value <- answer
  value
  |> show
  |> println
}
```

`nonNegative (-2)`は`BelowZero`で失敗するEffectを作ります。`recover`がその失敗を成功の値0に変え、`value <- answer`で実行して結果を受け取ります。出力は0です。

コードの中からEffectを好きなときに実行する関数はありません。Effectを実行するのは、`pub`の`main`、テストランナー、コールバックの変換部分など、決まった場所だけです。`do`は上から順に実行します。並べて実行したいときは`effects.parallel`などで明示し、コンパイラーが勝手に並列化することはありません。

### 同じEffectを二度実行する

{/* example: examples/reference/effect-execution.ssrg#announce */}

```seseragi title="宣言: 出力する計算"
effect fn announce text: String =
  println text
```

`announce`を宣言したら、次のコードを`main`の`do`の中に書きます。

{/* example: examples/reference/effect-execution.ssrg#cold */}

```seseragi title="mainのdo内: 構築と二度の実行"
let job = announce "ran"
println "constructed"
job
job
```

出力は`constructed`、`ran`、`ran`の順です。最初の`let`はEffectを作るだけで、後ろの二つの`job`がそれぞれ実行します。

### 成功の値の変換と受け取り

これも`main`の`do`の中に書くコードです（`effects`は`std/effect`の別名）。`map`で作った`Task<Int>`は、まだ値ではありません。値を使うには`<-`で受け取ります。

{/* example: examples/reference/effect-execution.ssrg#map-task */}

```seseragi title="mainのdo内: Taskを合成する"
let calculation =
  effects.succeed 21
  |> map (\n: Int -> n * 2)
println "mapped"
```

{/* example: examples/reference/effect-execution.ssrg#execution */}

```seseragi title="mainのdo内: 結果を受け取る"
value <- calculation
value
|> show
|> println
```

mappedを出力した後にcalculationを実行し、42を出力します。`let`と`<-`は、ここで異なる役割を持ちます。

## effect fnの二つの形

compact formはパラメーターの後へ直接`=`を書きます。`R`・`E`・`A`をbodyから推論し、公開interfaceには正規Effect型を保存します。

```seseragi title="compact form"
effect fn greet name: String =
  println $ `Hello, ${name}`
```

型を書く形では、成功の型から書き始め、必要なものと失敗の型を固定します。

```seseragi title="contract form"
effect fn greet name: String -> Unit
with Console
fails ConsoleError =
  println $ `Hello, ${name}`
```

型を書く形で`with`を省くと「何も必要としない」（`{}`）、`fails`を省くと「失敗しない」（`Never`）になり、本体から推論はされません。型を省く形に`with`や`fails`だけを書き足すことはできません。どちらの形でも本体はEffectでなければならず、普通の値が自動でEffectに包まれることはありません。

### 推論する宣言と固定する宣言

次の二つは、どちらも「何も必要とせず、失敗せず、`Int`で成功する」Effectを返します。

{/* example: examples/reference/effect-contracts.ssrg#compact */}

```seseragi title="宣言: compact form"
effect fn compact value: Int =
  effects.succeed value
```

{/* example: examples/reference/effect-contracts.ssrg#contract */}

```seseragi title="宣言: contract form"
effect fn contract value: Int
  -> Int =
  effects.succeed value
```

{/* example: examples/reference/effect-contracts.ssrg#run-contracts */}

```seseragi title="mainのdo内: 宣言した計算を使う"
first <- compact 4
second <- contract 5
println `${first}: ${second}`
```

出力は`4: 5`です。

### 普通の値はEffectに自動では包まれない

次は、わざとエラーにした例です。型を省く形でも本体はEffectでなければならないので、`Int`をそのまま返す`answer`は`SES-T0101`になります。

{/* example: examples/reference/invalid/pure-effect.ssrg#invalid */}

```seseragi title="意図的なEffect型エラー"
effect fn answer = 42

pub effect fn main =
  println "ready"
```

## 必要なものと失敗の組み合わせ

`R`は、必要なサービスをフィールドに持つレコードです。Effectを組み合わせると、必要なものはフィールドを合わせたものになります。同じ名前のフィールドは同じ型でなければなりません。「あれば使う」という省略可能な必要物はありません。`with Console`は`{ console: Console }`の省略形です。必要なものは`provide`で明示的に渡せます。

必要なものが少ないEffectは、それを含むより多くを必要とするEffectとして扱えます。型パラメーターを使う宣言では、EffectとStreamの一つ目の型引数に限って、`R & { clock: Clock }`のように必要なものを足し合わせて書けます。これは一般的な交差型ではありません。

failureは自動unionしません。異なるerror型を合わせるには、アプリのADTへ`mapError`で写すか`recover`で処理します。`Never`だけは必要なerror型へwidenできるため、Signalの`Task`をfallibleな`do`へ入れられます。成功型は合成全体で整合する必要があります。

## 失敗、defect、キャンセル

| 終了理由 | 扱い |
| --- | --- |
| 失敗 | `E`として型に書いた、立て直せる失敗。`recover`で扱える |
| defect | 整数の範囲超え、0での割り算、TypeScriptとの境界での約束違反など。コードの中では受け止められない |
| キャンセル | 実行環境や親の処理による中断。失敗としては扱わない |

`recover`は、defectやキャンセルを受け止めません。TypeScript側の例外やrejectは、[TypeScript連携](/docs/reference/typescript-interop)の仕組みで失敗に変換されます。入力ミスのように起こると分かっている問題は、defectにせず、`Either`やEffectの失敗の型として設計してください。

## リソースとmain

`bracket acquire use release`や`acquireRelease`で、使い終わったら必ず解放したいリソースを登録します。成功・失敗・キャンセルのどの場合でも、解放の処理が登録と逆の順に一回ずつ実行されます。リソースを取得してから解放処理を登録するまでの間にキャンセルされて、解放漏れが起きることはありません。解放の処理は、失敗を外に返せません。

`main`は`pub`で公開し、`Unit`の引数を一つ受け取って、`Unit`で成功するEffectを返す関数です。必要なものはフィールドが確定したレコード、失敗の型も具体的な型でなければなりません。失敗の型が`Never`でなければ、`Show`のinstanceが必要です（失敗したときに表示するため）。実行環境が用意できないサービスを必要としている場合は、実行する前にエラーになります。

Effectの組み立て方は[Effect](/docs/learn/effects)、アプリの失敗の設計は[失敗を扱う](/docs/guides/error-handling)にあります。
