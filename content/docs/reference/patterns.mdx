パターンは、値の形を照らし合わせて、中の値に名前を付けます。`match`のほか、`let`、`do`の`<-`、内包表記、Effectの`for`でも、同じ書き方と型の決まりで使えます。場所によって違うのは、一致しなかったときの扱いと、名前が使える範囲です。

## 使えるパターン

| パターン | 意味 |
| --- | --- |
| `value` | 値全体を束縛する |
| `_` | 値を使わない |
| `42`、`"ready"` | リテラルとの一致 |
| `Just value` | コンストラクターとペイロード |
| `(x, y)` | 同じ要素数のタプル |
| `{ name, age: years }` | レコードフィールドを選んで分解 |
| `User { name }` | structのフィールドを分解 |
| `[first, ...rest]` | Arrayの先頭と残り |
| `` `[first, ...rest] `` | Listの先頭と残り（コピーしない） |

パターンは入れ子にできます。一つのパターンの中で、同じ名前を二回使うことはできません。コンストラクターやフィールドの型は照らし合わせる値から決まり、タプルの要素数やペイロードの形が違えば型エラーです。

## matchの評価と網羅性

`match`の対象の式は一度だけ計算されます。分岐を上から順に試し、パターンとガードが最初に一致した分岐の右側だけが計算されます。すべての分岐の結果の型は同じでなければなりません。

{/* example: examples/reference/patterns.ssrg */}

```seseragi title="patterns.ssrg"
fn firstLabel values: Array<String>
  -> String =
  match values {
    [] -> "Empty"
    [first, ..._] -> first
  }

pub effect fn main = do {
  println $ firstLabel []
  println $ firstLabel ["Aki", "Mio"]
}
```

出力は`Empty`、`Aki`の順です。`[]`は長さ0、`[first, ..._]`は長さ1以上のArrayに一致するので、すべての長さを扱えています。`...`のない`[first]`は、長さがちょうど1のときだけ一致します。

扱っていない値がある`match`は、コンパイルエラーになります。前の分岐ですべて受け止められてしまい、決して選ばれない分岐もエラーです。`Int`や`String`はリテラルだけでは全部の値を扱えないので、最後に名前や`_`の分岐を置きます。

## ガード

ガードは`when 条件`の形で書き、条件の中ではパターンで付けた名前を使えます。

```seseragi title="guard付きarm"
Just value when value > 0 ->
  "positive"
Just _ -> "other"
Nothing -> "missing"
```

コンパイラーはガードの中身を見ないので、ガード付きの分岐は「すべての値を扱えているか」の判定に数えられません。`Just value when True`と書いても、ガードのない`Just`の分岐が別に必要です。ガードの条件は、パターンが一致したときだけ計算されます。

### Maybeのガードとfallback

{/* example: examples/reference/pattern-variants.ssrg#maybe-guard */}

```seseragi title="宣言: guard付きmatch"
fn describe value: Maybe<Int>
  -> String =
  match value {
    Just n when n > 0 -> "positive"
    Just _ -> "non-positive"
    Nothing -> "missing"
  }
```

`Just`の中身が正の数なら一つ目、それ以外の`Just`なら二つ目、`Nothing`なら三つ目の分岐に進みます。ガードが`False`なら、次の分岐が試されます。

{/* example: examples/reference/pattern-variants.ssrg#guard-cases */}

```seseragi title="main内: 三つの場合"
println $ describe $ Just 3
println $ describe $ Just 0
println $ describe Nothing
```

出力は`positive`、`non-positive`、`missing`の順です。二つ目の`Just`の分岐を消すと、扱っていない値があるとしてエラーになります。

## 束縛できる場所

パターンには、「どんな値にも必ず一致する」ものと、「一致しない値がある」ものがあります。後者を書ける場所は限られています。

| 場所 | 照らし合わせる値 | 一致しない値があるパターン |
| --- | --- | --- |
| `let pattern = value` | 右辺の値 | 書けない |
| `do`の`let` | 右辺の値 | 書けない |
| `pattern <- computation` | 取り出した値 | 書けない |
| `match`の分岐 | 対象の値 | 書ける |
| 内包表記の`<-` | 各要素 | 書ける（一致しない要素は除かれる） |
| Effectの`for` | 各要素 | 書けない |

必ず一致するのは、名前、`_`、中身もすべて必ず一致するタプル・レコード・structです。ケースが一つしかないADTのコンストラクターとnewtypeも、中身のパターンが必ず一致するなら同じ扱いです。Array・Listでは、要素を一つも決めない`[...rest]`だけが必ず一致します。

そのため`let Just value = maybeValue`とは書けず、`match`で`Nothing`の場合も扱います。一致しなかったら例外を投げる、という動きにはなりません。

### 不要な値と名前の付け替え

{/* example: examples/reference/pattern-variants.ssrg#wildcard */}

```seseragi title="main内: wildcard"
let (label, _) = ("Aki", 42)
println label
```

タプルの二つ目は使わず、`Aki`だけを出力します。`_`は名前を作りません。

{/* example: examples/reference/pattern-variants.ssrg#record-bind */}

```seseragi title="main内: fieldの別名"
let { name, age: years } = {
  name: "Mio",
  age: 7,
}
println `${name}: ${years}`
```

ageの値をyearsとして束縛するため、出力は`Mio: 7`です。フィールド自体をageからyearsへ改名する操作ではありません。

### letでJustだけを分解する場合

次は、わざとエラーにした例です。右辺が`Just`だと見て分かっても、`Maybe`型には`Nothing`もありうるので、`let`では`SES-T0101`になります。`match`で両方を扱ってください。

{/* example: examples/reference/invalid/refutable-binding.ssrg#invalid */}

```seseragi title="意図的なpatternエラー"
pub effect fn main = do {
  let Just value = Just 1
  value
  |> show
  |> println
}
```

## レコードと省略可能なフィールド

レコードのパターンは、書いたフィールド以外を無視します。structのパターンも同じですが、型の名前が合っていて、そのフィールドが見える場所でなければ使えません。パターンの中でスプレッドは使えません。

省略可能なフィールドには`{ id? }`か`{ id?: pattern }`を使います（今のバージョンのコンパイラーはまだ対応しておらず、`SES-T0101`になります。それまではフィールドを読んで得た`Maybe`を`match`してください）。`id?`はフィールドがあるかどうかを`Maybe<A>`として受け取り、`id?: Just value`はフィールドがある場合だけ一致します。必ずあるフィールドに`?`を付けると、いつも`Just`になります。省略可能なフィールドを、普通の`{ id }`で取り出すことはできません。

## 名前が使える範囲とコスト

右辺の式では、そのパターンで作る名前は使えません。`match`で付けた名前はその分岐のガードと右側だけで、`let`や`do`の`<-`で付けた名前はそれより後ろの行だけで使えます。パターン全体が一致してから名前が付くので、一部だけ名前が付いた中途半端な状態はありません。

Listの`...rest`は、元のListの残りをそのまま使います。Arrayの`...rest`は残りのArrayをコピーするので、Arrayを`[head, ...tail]`で最後まで再帰すると、要素数の二乗に比例する時間がかかります。大きなArrayには`reduce`などを使ってください。この違いは[性能](/docs/reference/performance)で確かめられます。
