パターンは値の形を照合し、内部の値へ名前を付けます。`match`だけでなく、`let`、`do`のbind、comprehension、effectful `for`でも同じ型の規則を使います。構文ごとに違うのは、一致しない場合の扱いと名前のscopeです。

## 使えるパターン

| パターン | 意味 |
| --- | --- |
| `value` | 値全体を束縛する |
| `_` | 値を使わない |
| `42`、`"ready"` | literalとの一致 |
| `Just value` | constructorとpayload |
| `(x, y)` | 同じarityのtuple |
| `{ name, age: years }` | record fieldを選んで分解 |
| `User { name }` | nominal structのfieldを分解 |
| `[first, ...rest]` | Arrayの先頭と残り |
| `` `[first, ...rest] `` | Listの先頭と共有tail |

入れ子にできます。同じパターンで同じ名前を二度束縛することはできません。constructorやfieldの型は対象値から決め、tupleのarityやpayloadの形が違う場合は型エラーです。

## matchの評価と網羅性

対象式は一度だけ評価します。armを上から順に試し、patternとguardが最初に一致したarmの式だけを評価します。すべての結果型を揃える必要があります。

{/* example: examples/reference/patterns.ssrg */}

```seseragi title="patterns.ssrg"
fn firstLabel values: Array<String>
  -> String =
  match values {
    [] -> "Empty"
    [first, ..._] -> first
  }

pub effect fn main = do {
  println $ firstLabel []
  println $ firstLabel ["Aki", "Mio"]
}
```

出力は`Empty`、`Aki`の順です。`[]`は長さ0、`[first, ..._]`は一個以上のArrayを扱うため、すべての長さを覆います。restのない`[first]`は長さ1だけに一致します。

網羅しない`match`はコンパイルエラーです。先行armにすべて覆われて到達できないarmもエラーです。`Int`や`String`のliteralだけでは全値を覆えないので、必要なら最後にbindingや`_`を置きます。

## guard

guardは`when Bool式`で書き、patternで導入した名前を参照できます。次はarmの構文です。

```text title="guard付きarm"
Just value when value > 0 ->
  "positive"
Just _ -> "other"
Nothing -> "missing"
```

guard付きarmは網羅性に寄与しません。`Just value when True`だけを置いても、guardのない`Just`を覆うarmが必要です。guardはpatternが一致した後にだけ評価します。

## 束縛できる場所

「必ず一致する」パターンをirrefutable、「一致しない値がある」パターンをrefutableと呼びます。

| 場所 | 入力 | refutable pattern |
| --- | --- | --- |
| `let pattern = value` | RHSの型 | 禁止 |
| `do`の`let` | pure RHSの型 | 禁止 |
| `pattern <- computation` | monadのpayload型 | 禁止 |
| `match` arm | 対象値の型 | 許可 |
| comprehension generator | Iterableの要素型 | 不一致の要素を除外 |
| effectful `for` | Iterableの要素型 | 禁止 |

名前、`_`、内部も必ず一致するtuple/record/structはirrefutableです。一variantだけのconstructorとnewtypeも、内部patternがirrefutableなら使えます。Array/Listでは固定要素を持たない`[...rest]`だけが必ず一致します。

`let Just value = maybeValue`は使えません。`match`で`Nothing`も処理します。失敗しうるbindを暗黙の例外や`MonadFail`へ変換することはありません。

## recordとoptional query

record patternは指定field以外を無視します。struct patternも指定しないfieldを無視しますが、nominal型と公開範囲を守ります。パターン内のspreadはありません。

optional fieldには`{ id? }`または`{ id?: pattern }`を使います。`id?`はpresenceを`Maybe<A>`として束縛し、`id?: Just value`は存在する場合だけ一致します。required fieldへqueryすると常に`Just`です。optional fieldを通常の`{ id }`で取り出すことはできません。

## scopeとコスト

束縛の入力式は、その束縛が作る名前を参照できません。`match`の名前は同じarmのguardとbodyだけ、`let`や`do` bindの名前は後続itemだけで使えます。パターン全体の一致が成功してから名前を導入するため、部分的に束縛された状態は見えません。

Listのrestは既存tailを共有します。Arrayのrestは残りのArrayを作るため、Arrayを`[head, ...tail]`で最後まで再帰すると二乗時間になります。大きなArrayの走査には`reduce`などを使います。[性能](/docs/reference/performance)でこの違いを確認できます。
