Signalは、時間とともに変わる値を表します。どのSignalがどのSignalから計算されるかは、コードで明示します。Signalを持っているだけで、普通の関数の結果が勝手に変わることはありません。今の値を読むことと、値を書き換えることは、どちらもEffectです。

## SignalとMutableSignal

| 型・操作 | 意味 |
| --- | --- |
| `Signal<A>` | 読み取り専用のSignal |
| `MutableSignal<A>` | 書き換えられるSignal。`Signal`としても渡せる |
| `signals.make initial` | `Task<MutableSignal<A>>`を作る |
| `*source` | `signals.read source`、型は`Task<A>` |
| `source := value` | `signals.set value source`、型は`Task<Unit>` |
| `signals.update f source` | 今の値に関数を適用して書き換える。間に別の更新は入らない |

`MutableSignal<A>`は、書き換えできない`Signal<A>`として渡せます。逆はできません。`:=`は、普通の`let`やstructのフィールドへの代入には使えません。

{/* example: examples/reference/signals.ssrg */}

```seseragi title="signals.ssrg"
import * as signals from "std/signal"

fn double value: Int -> Int =
  value * 2

pub effect fn main = do {
  count <- signals.make 1
  let doubled =
    signals.map double count

  count := 3
  value <- *doubled
  value
  |> show
  |> println
}
```

出力は6です。`*doubled`は値そのものではなく、実行した時点の値を読み取るTaskです。`count`を作る・書き換える・読む、を`do`で順に実行しています。

### 現在値へ関数を適用する

{/* example: examples/reference/signal-snapshots.ssrg#increment */}

```seseragi title="宣言: 更新に使うpure関数"
fn increment n: Int -> Int = n + 1
```

読み取りも`update`もTaskなので、`do`の中で実行します（`signals`は`std/signal`の別名）。

{/* example: examples/reference/signal-snapshots.ssrg#read-update */}

```seseragi title="main内: readとupdate"
source <- signals.make 1
before <- *source
source
|> signals.update increment
after <- *source
println `${before}: ${after}`
```

出力は`1: 2`です。`update`は、実行した時点の値に`increment`を一回適用します。

### 読み取った値は変わらない

{/* example: examples/reference/signal-snapshots.ssrg#snapshot */}

```seseragi title="main内: snapshotと次のread"
saved <- *source
source := 10
current <- *source
println `${saved}: ${current}`
```

前の例の`source`を使うと、出力は`2: 10`です。一度読み取った`Int`は、あとでSignalを書き換えても変わりません。

## 派生グラフ

`map`は一つのSignalから、`combine`は二つのSignalから、新しいSignalを計算します。計算に使う関数は値を計算するだけのものにします。関数の中で読んだSignalを自動で追跡する仕組みはありません。

`constant`は変わらない値のSignalです。`distinct`は、`Eq`で比べて直前と同じ値なら通知しません。`distinct`を使わない場合、同じ値をセットしても通知されます。

SignalはFunctorとApplicativeを実装していますが、Monadは実装していません。値によって依存先のSignalを切り替えたいときは、`switchMap`で明示します。切り替えると、古いSignalとのつながりは解除され、新しいSignalの値が使われます。

### 依存関係を明示して更新を読む

doubleは上の完全な例と同じ、Intを二倍するpure関数です。次は同じソースを使うmain内の断片です。

{/* example: examples/reference/signal-snapshots.ssrg#dependence */}

```seseragi title="main内: derived Signal"
let doubled =
  signals.map double source
source := 3
value <- *doubled
value
|> show
|> println
```

`source`を3にしてから`doubled`を読むので、出力は6です。`map`が依存しているのはSignalそのもので、先に読み取った`Int`ではありません。

## トランザクション

`set`と`update`は、それぞれ一回で一つの書き換えです。複数のSignalを同時に書き換えたいときは、`planSet`・`planUpdate`で書き換えの予定を作ってArrayに並べ、`transaction`に渡します。

```seseragi title="複数更新の構文"
signals.transaction [
  signals.planSet 3 width,
  signals.planSet 4 height,
]
```

changeをArray順に適用し、同じソースの後続`planUpdate`はstaging済みの値を受け取ります。commit前のdefectやキャンセルでは一件も公開しません。成功後に一度commitし、影響するderived ノードを依存関係順に高々一度再計算してから購読者へ通知します。途中の不整合な組み合わせは見えません。

`transaction`がまとめて反映するのはSignalの書き換えだけです。ファイルの書き込みなど、ほかのEffectまでまとめるものではありません。

### 二つのSignalをまとめて書き換える

{/* example: examples/reference/signal-transaction.ssrg#area */}

```seseragi title="宣言: 二つの値を合成する"
fn area width: Int
  -> height: Int -> Int =
  width * height
```

{/* example: examples/reference/signal-transaction.ssrg#combine */}

```seseragi title="main内: combineとread"
width <- signals.make 2
height <- signals.make 4
let combined =
  signals.combine area width height
before <- *combined
println $ show before
```

最初の出力は8です。続けて、二つの書き換えを`transaction`に渡します。

{/* example: examples/reference/signal-transaction.ssrg#transaction */}

```seseragi title="main内: transaction後のread"
signals.transaction [
  signals.planSet 3 width,
  signals.planSet 5 height,
]
after <- *combined
println $ show after
```

次の出力は15です。書き換えたあとの幅3と高さ5から計算した値が読み取られます。

## 複数のSignalを同じ瞬間の値で読む

readはその実行時点で公開済みの値を返します。複数の`*source`を同じdoに置いても、途中で別トランザクションがcommitすると後のreadは新しい値を読みます。

複数のSignalを、同じ瞬間の値の組として読みたいときは、`combine`でタプルやレコードを返すSignalを作り、それを一回だけ読みます。読み取った値はあとで変わりませんが、そのあとの処理の間にほかの書き換えが入ることまでは防げません。

## 購読と解除

`subscribe observer source`で購読を始めると、まず今の値で`observer`が一回呼ばれます。そのあとも、通知は順番に一つずつ処理され、同じ`observer`が同時に二回動くことはありません。`observer`の中でSignalを書き換えた場合、その書き換えは今の更新が終わってから行われます。

observerのEffectはfailure型が`Never`でなければなりません。回復可能な失敗を内部で処理するか、failure channelを持つStream consumerへ変換します。

購読に成功すると`Subscription`が返ります。`unsubscribe`は何回呼んでも問題ありません。購読は、スコープの終了・失敗・キャンセルのときにも解除されます。計算したSignalを作ったり、一回読んだりするだけでは、購読は始まりません。

Webでの状態の持ち方と画面の更新は[Web UI](/docs/reference/web-ui)、Signalを小さな例で順に学ぶなら[Signal](/docs/learn/signals)を見てください。
