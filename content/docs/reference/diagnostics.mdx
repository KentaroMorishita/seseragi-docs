エラーメッセージは、問題のある場所と理由を教えてくれます。コンパイルエラーがあると、プログラムは生成されません。実行中にEffectが失敗するのとは、起きるタイミングが違います。

## 位置と理由を読む

CLIのエラーには、ファイル名、行と列、`SES-T0101`のようなコード、問題の箇所、理由が表示されます。エラーがたくさん出たときは、まず最初のエラーを見てください。一つの定義の間違いが、それを使っているいくつもの場所のエラーになっていることがあります。

JSONで受け取りたいときは、`run`や`lint`の`--diagnostic-format json`を使います。今の`build`には、このオプションはありません。

```sh
seseragi lint parcel.ssrg \
  --diagnostic-format json
```

lintはコンパイラの診断に加え、未使用のローカル定義を調べます。`--deny-warnings`を付けると、警告がある場合もlintの失敗になります。コマンドごとのオプションは[CLIリファレンス](/docs/reference/cli)で確認できます。

## 引数の型を合わせる

次のコードは`SES-T0101`エラーになります。importした`console.println`は`String`を受け取りますが、`42`は`Int`だからです。

{/* example: examples/diagnostics/type-mismatch.ssrg */}

```seseragi
import * as console
  from "std/console"

pub effect fn main =
  console.println 42
```

`show`で文字列にしてから`console.println`に渡すか、`Show`を持つ値をそのまま表示できる`console.printValue`を使います。関数の型は[ConsoleのAPI](/docs/reference/library/console)で確かめられます。

## すべてのケースを処理する

次の定義には`Sent`の場合の処理がありません。`main`が今は`Packing`しか使っていなくても、`SES-T0301`エラーになります。

{/* example: examples/diagnostics/non-exhaustive.ssrg */}

```seseragi
type Parcel =
  | Packing
  | Sent String

fn label parcel: Parcel -> String =
  match parcel {
    Packing -> "Preparing"
  }

pub effect fn main =
  Packing
  |> label
  |> println
```

`Sent city`の分岐を足してください。コンパイラーは、今実際に使われている値ではなく、その型が取りうるすべての値について確かめます。[パターンマッチ](/docs/learn/pattern-matching)で、ケースごとの書き方を学べます。

## Intの範囲を確認する

`Int`の範囲は`-9007199254740991..9007199254740991`です。次のリテラルは`SES-P0203`エラーになります。

{/* example: examples/diagnostics/integer-range.ssrg */}

```seseragi
pub effect fn main =
  9007199254740992
  |> show
  |> println
```

もっと大きな整数には[BigInt](/docs/reference/library/big-int)を使います。範囲外の`Int`を書いてから変換する、という書き方はできません。

## 古いロックファイルを更新する

`SES-K0102`は、ロックファイルがないか、依存パッケージ・設定・Providerの選択・ソースの内容と食い違っていることを表します。何が変わったかを確かめてから、`seseragi lock update`で更新してください。

```sh
seseragi lock update
```

ソースを編集してからテストを実行するときも、更新が必要です。開発サーバーの起動中は自分のパッケージのソースの変更だけなら更新は要りませんが、依存パッケージや設定を変えたときは、ロックファイルを更新してサーバーを起動し直してください。詳しくは[プロジェクト設定](/docs/reference/project-configuration)にあります。

## コンパイルエラーと実行時の失敗を分ける

コンパイルエラーでは、プログラムは実行されません。実行中のEffectの失敗は型で表された値で、`recover`などで立て直せます。バグによる異常（defect）やキャンセルは、それとは別に扱われます。詳しくは[失敗を扱う](/docs/guides/error-handling)と[Effectリファレンス](/docs/reference/effects)を見てください。
