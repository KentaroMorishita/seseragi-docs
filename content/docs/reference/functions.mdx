関数は値です。引数を一つずつ受け取り、別の関数へ渡したり、本体の結果として返したりできます。通常の`fn`はpureな値を計算し、外部操作を実行する計算は[Effect](/docs/reference/effects)として返します。

## 宣言と型

parameter名と型を`->`でつなぎ、最後に戻り型を書きます。通常の`fn`ではparameter型と戻り型が必須です。

```text title="宣言の構文"
fn add x: Int -> y: Int -> Int =
  x + y
```

`add`の型は`Int -> Int -> Int`、つまり`Int -> (Int -> Int)`です。引数を持たないように見える`fn ready -> Bool`も、名前のないUnit parameterを一つ受け取り、`ready ()`で呼びます。

公開する関数には`pub`を付けます。型parameterは`fn identity<A> value: A -> A`のように名前の直後へ置きます。推論とconstraintの規則は[型](/docs/reference/types)と[型クラス](/docs/reference/type-classes)を参照してください。

## 適用と部分適用

`add 20 22`は、空白で区切った二つの引数`20`と`22`を渡す式です。一部の引数だけを渡すと、残りを受け取る関数になります。

適用は左から順に進むので、`add 20 22`は`(add 20) 22`と同じです。ここで括弧は`add 20`という式をまとめています。`add (20 + 1) 22`なら、括弧でまとめた計算結果の21を最初の引数として渡します。

{/* example: examples/reference/functions.ssrg */}

```seseragi title="functions.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

pub effect fn main = do {
  let increment = add 1
  41
  |> increment
  |> show
  |> println
}
```

`increment`の型は`Int -> Int`です。`show`でIntをStringへ変換し、`println`へ渡すので出力は42です。入力を先に書く`value |> function`は`function value`と同じです。標準collection APIなどはdata argumentが最後なので、関数を部分適用してpipelineへ置けます。

### 括弧でまとめる範囲

以下は`add`を使う`main`の`do`ブロック内へ置く断片です。最初の二つは同じ適用を別の括弧で書き、最後は引数の計算を括弧でまとめます。

{/* example: examples/reference/function-values.ssrg#grouping */}

```seseragi title="mainのdo内: 適用と括弧"
add 10 2
|> show
|> println
(add 10) 2
|> show
|> println
add (10 + 1) 2
|> show
|> println
```

出力は順に12、12、13です。関数へ渡す引数の区切りと、計算をまとめる括弧を区別してください。

### 残りの引数を受け取る関数

{/* example: examples/reference/function-values.ssrg#partial */}

```seseragi title="mainのdo内: 部分適用"
let increment = add 1
[1, 2, 3]
|> map increment
|> show
|> println
```

`add 1`の型は`Int -> Int`です。Arrayへ適用した出力は`[2, 3, 4]`になります。

## 評価順とlambda

Seseragiはstrict evaluationです。引数を左から右へ一度ずつ評価し、適用された本体を評価します。部分適用は残りのparameterを受け取る関数を作り、まだ与えていない引数を評価しません。Effectを返す関数の呼び出しは、返した計算の実行とは別です。

lambdaは`\x -> x + 1`、複数parameterなら`\x y -> x + y`と書きます。parameter型は文脈から決まる場合に省略できます。決まらない場合は`\x: Int -> x + 1`のように注釈します。

```text title="高階関数の構文"
map (\value: Int -> value + 1) [1, 2]
```

lambdaは必要なlexical bindingをcaptureします。型parameterは実行時の値ではないので、generic関数の中で型名を調べて分岐することはできません。

### 匿名関数とoperator value

lambdaを直接渡す場合も、名前付き関数を渡す場合も、必要な型は同じです。次はmain内の断片で、`[2, 4, 6]`を出力します。

{/* example: examples/reference/function-values.ssrg#lambda */}

```seseragi title="mainのdo内: lambda"
[1, 2, 3]
|> map (\n: Int -> n * 2)
|> show
|> println
```

operator valueは、型を指定したbindingへ保存してから使えます。この断片も`[2, 4, 6]`を出力します。

{/* example: examples/reference/function-values.ssrg#operator */}

```seseragi title="mainのdo内: operator value"
let times: Int -> Int -> Int = (*)
let twice = times 2
[1, 2, 3]
|> map twice
|> show
|> println
```

<LanguageVersion />には、`(+) 20 22`のような直接適用を`SES-T0101`で拒否するcompiler制約があります。operatorを関数値にすること自体の禁止ではありません。上のbindingを介する形を使ってください。

{/* example: examples/reference/invalid/direct-operator.ssrg#invalid */}

```seseragi title="対象版で拒否される形"
fn answer -> Int = (+) 20 22

pub effect fn main =
  println "ready"
```

## ブロックとlocal関数

ブロックは最後の式を返します。`let`は再代入できず、その後からブロック末尾まで見えます。localな`fn`は、自身のbodyと宣言後のitemから参照できます。宣言前のbindingをcaptureできますが、後続bindingはcaptureできません。

```text title="local関数の構文"
fn twice value: Int -> Int = {
  fn double x: Int -> Int = x + x
  double value
}
```

関数を宣言するだけでは、本体のuser codeやEffectを実行しません。localな相互再帰は`rec { ... }`へまとめます。local functionへ`pub`は付けられません。

### local関数がcaptureする値

{/* example: examples/reference/local-functions.ssrg#closure */}

```seseragi title="宣言: lexical capture"
fn shifted amount: Int -> value: Int
  -> Int = {
  fn shift n: Int -> Int =
    n + amount
  shift value
}
```

`shift`は外側のparameter `amount`をcaptureします。`shifted 3 7`は10です。後から宣言するlocal bindingをcaptureする規則ではありません。

## 再帰

名前付き関数は自分自身を呼べます。相互再帰する関数は同じ`rec` groupに置きます。通常の`let`は、自分自身を右辺から参照できません。

完全に引数を渡した、pureな名前付き関数への直接self tail callは、入力件数に比例してhost stackを増やしません。相互再帰、再帰結果へ演算する呼び出し、lambdaの内側からの呼び出しは同じ保証を持ちません。[性能](/docs/reference/performance)に確認した実行例があります。

## methodとEffect関数

`value.method arg`は静的に`Type.method value arg`へ解決します。methodはnominal型を定義したmoduleの`impl Type`へ置き、第一parameterは`self: Type`です。動的dispatchや継承はありません。

`effect fn`はEffectを返す関数の宣言構文です。引数のcurry規則は通常の関数と同じです。本体が普通の値なら、`succeed`などで明示的にEffectへ包みます。詳しいcontract form・compact formは[Effectと失敗](/docs/reference/effects)で説明しています。

部分適用とpipelineを順に読むなら、[関数とパイプライン](/docs/learn/functions-and-pipelines)へ進んでください。
