すべての式は、実行する前に型が決まります。型チェックに通らないプログラムは実行されません。型が決まらないところを`any`のような何でもありの型で済ませることはなく、型を書くよう求めます。

## 基本型

| 型 | 値と制約 |
| --- | --- |
| `Int` | -9007199254740991〜9007199254740991の正確な整数 |
| `Float` | IEEE 754 binary64。`Int`とは別の型 |
| `Bool` | `True`または`False`。ほかの値を真偽値として扱うことはない |
| `Char` | Unicodeスカラー値一個 |
| `String` | Unicodeスカラー値の不変列 |
| `Unit` | 値は`()`だけ |
| `Never` | 値を一つも持たない型 |

`Int`の計算が範囲を超えたときや、0で割ったときは、桁あふれせずにその場でプログラムが止まります（defect）。`-0`はありません。`Float`のNaNや無限大は、数値リテラルではなく、標準ライブラリにある名前の付いた値です。もっと大きな整数を扱うには、[標準ライブラリ](/docs/reference/library)の`std/big-int`を使います。

`Never`は、どんな型が必要な場所にも置けます。「値が存在しない」型で、`()`という値をちゃんと返す`Unit`とは違います。

## 型の書き方

| 型式 | 意味 |
| --- | --- |
| `Array<A>`、`List<A>` | 別々の不変コレクション |
| `Maybe<A>` | 値がない場合がある |
| `Either<E, A>` | 計算済みの失敗または成功 |
| `Effect<R, E, A>` | 必要なもの・失敗・成功の型を持つ、まだ実行されていない処理 |
| `Task<A>` | `Effect<{}, Never, A>`の別名 |
| `(A, B)` | タプル |
| `{ name: String }` | レコード（形で型が決まる） |
| `A -> B -> C` | `A -> (B -> C)`、右結合の関数型 |

型引数は`,`で区切り、入れ子にもできます。値の型として書くときは、型引数をすべて指定します。`Maybe`や`Either<String>`だけでは値の型になりません。ただし、`F<_>`のように「型引数を一つ受け取る型」が必要な場所には、`Maybe`や`Either<String, _>`を渡せます。

## 型の注釈とジェネリクス

`fn`には、引数の型と結果の型を書きます。公開しない`let`は型を省略できますが、`pub`を付けた`let`には型をすべて書きます。例外として、[Effect関数](/docs/reference/effects)を型を省いた形で書いた場合は、本体からEffectの型が推論されます。

型パラメーターは宣言の名前のすぐ後ろに書き、その宣言の中でだけ使えます。次の`identity`は、呼び出すたびに型パラメーターが決まり直します。

{/* example: examples/reference/generics.ssrg */}

```seseragi title="generics.ssrg"
fn identity<A> value: A -> A =
  value

pub effect fn main = do {
  let number = identity 42
  let text = identity "ready"
  println `${number}: ${text}`
}
```

出力は`42: ready`です。`identity<String> "ready"`のように型引数を明示することもできます。明示するときは、宣言した順にすべての型引数を書き、それが引数や期待される型と合っている必要があります。

`let identity = \value -> value`のような（再帰しない）`let`も、いろいろな型で使えるように一般化されます。ただし、関数の引数やレコードのフィールドに「呼ぶたびに型が変わる関数」を入れること（higher-rank型）はできません。

### letの一般化と期待型

次の例では、`let`で作った`identity`を、`Int`と`String`の両方に使っています。

{/* example: examples/reference/inference-context.ssrg#generalized */}

```seseragi title="main内: letの多相性"
let identity = \value -> value
let number = identity 42
let text = identity "ready"
println `${number}: ${text}`
```

出力は`42: ready`です。空のArrayや`Nothing`は中身から型が分からないので、次のように型を書いて決めます。

{/* example: examples/reference/inference-context.ssrg#context */}

```seseragi title="main内: 型を指定する値"
let empty: Array<Int> = []
let missing: Maybe<String> = Nothing
println $ show empty
println $ show missing
```

出力は`[]`と`Nothing`です。

## 同じ型として扱える範囲

ADT・struct・newtypeは、名前で区別される型です。形やフィールドがまったく同じでも、別々に宣言すれば別の型になります。`alias`は新しい型を作らず、元の型とまったく同じ型です。

レコードは、余分なフィールドがあっても受け取れます。`{ name: String }`が必要な関数に、`{ id: Int, name: String }`を渡せます。ただしフィールドの型は同じでなければならず、フィールドの中身についてまで余分を許すことはありません。

`{ id?: String }`の`id`を読むと`Maybe<String>`になります。`?`はフィールドそのものがないかもしれないことを表し、`{ id: Maybe<String> }`（フィールドは必ずあり、値が`Maybe`）とは別の型です。`?`付きのフィールドを、必ずあるフィールドとして扱うことはできません。

### 必要なレコードフィールドだけを受け取る

{/* example: examples/reference/record-shapes.ssrg#record-param */}

```seseragi title="宣言: record parameter"
fn name value: { name: String }
  -> String =
  value.name
```

{/* example: examples/reference/record-shapes.ssrg#record-width */}

```seseragi title="main内: width subtyping"
name { name: "Aki", age: 30 }
|> println
```

`age`という余分なフィールドがあっても、必要な`name`が`String`なので`Aki`を返します。ただし、structの`Person`がこのレコード型として受け取られるわけではありません。

## 暗黙変換とエラー

| 変換 | 扱い |
| --- | --- |
| `Int`から`Float` | 明示的に変換する |
| `A`から`Maybe<A>` | `Just`で包む |
| 内部値からnewtype | コンストラクターで包む |
| structから同じフィールドのレコード | 新しいレコードを明示的に作る |
| `Array<A>`から`List<A>` | 変換関数を呼ぶ |
| `Js.Nullable<A>`から`Maybe<A>` | 変換関数を書く |

user-defined型とコレクションはinvariantです。レコードの互換性があっても、`Array<広いrecord>`と`Array<狭いrecord>`が自動で互換になるわけではありません。必要なら`map`で変換します。

自動で変換されるのは、`Never`、レコードの余分なフィールド、Effectの必要なものと失敗の型の拡大、`MutableSignal<A>`から`Signal<A>`（読み取り専用）への変換だけです。それぞれの条件は[Effect](/docs/reference/effects)と[Signal](/docs/reference/signals)にあります。型引数が足りない、`alias`が循環している、結果の型パラメーターが決まらない、型引数の数が合わない、といった場合は実行前にエラーになります。
