このページでは、配布されているCLIの`seseragi --help`に載っているコマンドを説明します。手元のCLIのバージョンは、`seseragi --version`か`seseragi --version-json`で確かめられます。インストールの仕方は[ローカルで使う](/docs/learn/local-development)にあります。

## コマンド一覧

| コマンド | 用途 |
| --- | --- |
| `new web PATH` | Webアプリのひな形とロックファイルを作る |
| `run FILE_OR_PACKAGE` | CLIアプリを実行する |
| `build FILE_OR_PACKAGE` | CLIアプリやWebアプリの配布物を作る |
| `dev [PACKAGE]` | Webアプリの開発サーバーを起動する（保存すると自動でビルドし直す） |
| `lock update [PACKAGE]` | ロックファイルを更新する |
| `lint FILE_OR_PACKAGE` | コードの問題点を指摘する |
| `format [--check] FILE` | ソースを整形する、または整形済みか調べる |
| `test [PACKAGE]` | `tests/`のテストを実行する |
| `benchmark [PACKAGE]` | `benchmarks/`のベンチマークを計測する |
| `doc [PACKAGE] --test` | ドキュメントコメントの中のコード例を実行して確かめる |
| `dts convert [PACKAGE]` | `.d.ts`からTypeScriptのbindingを生成する |

`new`で作れるひな形は、今は`web`だけです。すでにあるディレクトリには作りません。`doc`は今のところ`--test`だけで、APIドキュメントのサイトを作る機能はありません。

## runとターゲット

ファイルを一つだけ渡して、そのまま実行できます。複数のモジュールや依存パッケージを使うときは、`seseragi.toml`と`seseragi.lock`を持つパッケージのディレクトリを渡します。

```bash
seseragi run main.ssrg
seseragi run . --profile release
```

logical ターゲットは`process`と`web`です。現在`run`はprocess、`dev`はwebを実行し、`build`は両方に対応します。オプションの値として受理しても、コマンドが未対応の組み合わせを別ターゲットへfallbackしません。

ターゲット（CLIで動かすか、ブラウザーで動かすか）は、コマンドのオプション、`run.target`、コマンドの種類の順に決まります。プログラムが必要とするサービスをターゲットが用意できない場合は、実行する前にエラーになります。HTTPサーバーはCLIアプリとして扱われ、Webアプリにはなりません。

## buildと開発サーバー

```bash
seseragi build . --profile release
seseragi dev \
  --host 127.0.0.1 \
  --port 3000
```

`build`では`--out-dir PATH`と`--source-map emit|omit`を指定できます。プロファイル（developmentかreleaseか）は、コマンドのオプション、`[build].profile`の順に決まり、どちらもなければdevelopmentです。ソースマップは、developmentでは出力し、releaseでは出力しません。CLIアプリの入口のファイルは、developmentでは`entry.ts`、releaseでは`entry.js`です。出力に含まれる`artifact-manifest.json`で、実際の入口を確かめられます。

`dev`は保存したソースを見張り、`build`と同じ仕組みでビルドし直します。`dev`の間は、ソースを編集してもロックファイルを更新する必要はありません（`build`や`test`では、ソースを変えるとロックファイルの更新が必要です）。ただし、`seseragi.toml`・依存パッケージ・Providerの要件を変えたときは、`dev`中でも更新が必要です。`--open`を付けるとブラウザーが開きます。

## 診断と整形

`run`と`lint`では`--diagnostic-format text|json`を指定できます。JSON形式では色の制御文字を含みません。ツールでエラーを見分けるときは、メッセージの文言ではなく、変わらない`SES-*`のコードを使ってください。`lint --deny-warnings`は、警告も失敗として扱います。

```bash
seseragi lint . --deny-warnings
seseragi format --check main.ssrg
```

フォーマッターは、プログラムの意味を変えずに整形します。整形のスタイルは一つに決まっていて、インデントや引用符の好みを指定するオプションはありません。

## test、benchmark、document test

```bash
seseragi test . --target node
seseragi benchmark . --target node
seseragi doc . --test --target node
```

`test`では、`--filter TEXT`か`--exact NAME`で実行するテストを選べ、`--jobs`・`--timeout`・`--seed`も指定できます。テストは`pub let tests: test.Test`として公開します。

`benchmark`では、ベンチマークを`pub let benchmarks: benchmark.Benchmark`として公開し、`--warmup`・`--samples`・`--minimum-sample-ms`・`--json`・`--baseline`・`--save-baseline`・`--regression-threshold-percent`などを指定できます。上の例では、どの環境で動かすかがはっきりするよう、`node`を明示しています。詳しくは[テスト](/docs/guides/testing)と[性能](/docs/reference/performance)にあります。

## CLIアプリの実行オプションと終了コード

`run`では、`--signal-mode cancel|forward`・`--shutdown-grace-ms`・`--hash-seed entropy|INT`・`--random-seed entropy|INT`も指定できます。どれも`seseragi.toml`の設定をその実行の間だけ上書きするもので、ファイルは書き換えません。乱数のシードを固定するのは結果を再現するためで、暗号用の乱数まで固定するものではありません。

| status | 意味 |
| --- | --- |
| 0 | 正常終了 |
| 1 | 処理されなかった失敗、またはテスト・lintの不合格 |
| 2 | コマンド・コンパイル・設定・ターゲットなど、実行前のエラー |
| 70 | 実行中のdefect（バグによる異常終了） |

signalによる終了はホストのsignal status規則へ従います。cancel modeではルート Effectへキャンセルを要求し、grace期間内にfinalizerを実行します。forward modeやgraceの設定はターゲットのcapabilityに従い、未対応の設定は事前エラーになります。
