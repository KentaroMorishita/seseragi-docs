## import

```seseragi
import * as effect from "std/effect"
```

## 選び方と注意

- Effectはcoldです。作成やprovideだけで実行せず、同じ計算を実行するたびに処理を繰り返します。実行ごとの構築が必要ならdeferを使います。
- recoverとattemptは型付き失敗だけを扱い、defectやキャンセルを捕捉しません。異なるエラー型はmapErrorなどでアプリのADTへ明示的に揃えます。
- do/flatMapは逐次実行です。並列化は明示し、外部操作の順序やリソースの所有をそのAPIの契約に合わせます。
- bracketやacquireReleaseでリソースをスコープへ登録します。終了処理は逆順に一度ずつ実行し、型付き失敗を外へ残せません。
- timeoutは元の処理をキャンセルして後始末を待ちます。retry/repeatは元の操作を再実行するため、外部への書き込みを重複させてもよいかを確認してください。

### `repeat`

<small className="api-kind">Effectを返す関数</small>

ScheduleとClockに従い、成功した計算を繰り返します。

```seseragi
repeat<R, E, A>
  Schedule<A>
  -> Effect<R, E, A>
  -> Effect<
       R & { clock: Clock },
       E,
       A
     >
```

この版のAPI catalogは、結果の環境型から元のRを省略しています。ここでは仕様とruntimeに従ってRを補っています。実行には元の環境RとClockが必要です。要求するserviceがあれば、そのproviderも引き続き必要です。
