## 選び方と注意

- Pathのparse/normalizeはlexicalな操作です。symlinkを解決せず、sandboxの認可境界にもならないため、filesystemへの権限判断と分けます。
- existsはNotFoundなどをFalseにしますが、権限やI/O障害を不在へ変換しません。型付き失敗を別に扱います。
- readBytes/readTextUtf8は全内容をメモリへ保持するsmall-file APIです。大きなfileにはreadChunksを使い、textのstrict UTF-8検査も意識します。
- readChunksやdirectory streamはterminal スコープでリソースを所有します。途中終了・failure・キャンセルでもhandleを閉じ、iteratorを外へ保持してlifetimeを延ばさない構成にします。

## 型と型クラス

### `DirectoryEntry`

<small className="api-kind">struct</small>

```text
struct DirectoryEntry {
  name: String,
  path: Path,
  fileType: Maybe<FileType>
}
```

- `name`: directory内のentry名。
- `path`: entryのpath。
- `fileType`: entryの種類。提供されなければNothing。

### `FileMetadata`

<small className="api-kind">struct</small>

```text
struct FileMetadata {
  fileType: FileType,
  sizeBytes: Int,
  modified: Maybe<Instant>,
  created: Maybe<Instant>
}
```

- `fileType`: 対象fileの種類。
- `sizeBytes`: 取得したバイト数。
- `modified`: 更新時刻。取得できなければNothing。
- `created`: 作成時刻。取得できなければNothing。

### `FileSystemError`

<small className="api-kind">struct</small>

```text
struct FileSystemError {
  operation: FileSystemOperation,
  path: Path,
  otherPath: Maybe<Path>,
  kind: FileSystemErrorKind
}
```

- `operation`: 失敗したfilesystem操作の種類。
- `path`: 失敗した操作の対象path。
- `otherPath`: 二つのpathを使う操作の追加path。ない場合はNothing。
- `kind`: 失敗の種類。
