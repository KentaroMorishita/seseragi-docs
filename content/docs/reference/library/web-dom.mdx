## import

```seseragi
import * as web_dom
  from "std/web/dom"
```

## 選び方と注意

- DOM操作はbrowserのDom capabilityを要求します。processでHtmlをSSRできることと、実DOMを操作できることは別です。
- DomContentのinitial Htmlとbinding planで、更新するsinkを明示します。leaf更新はElement identityやfocusを保ち、regionはそのchildrenを所有します。
- Actionはbounded FIFOで逐次dispatchします。queue overflowはfailureで、Actionを黙ってdropしたり並列handlerへ変えたりしません。
- mountのlistener、subscription、dispatchは同じスコープへ登録します。failure・キャンセル・unmountで解除し、DOMを残す後始末設定でもlistenerは残しません。
- キーはregion内のdirect sibling identityです。global IDやcomponent stateの暗黙identityとして使いません。

### `DomOptions`

<small className="api-kind">struct</small>

```seseragi
struct DomOptions {
  eventCapacity: Int,
  hydration: HydrationMode,
  cleanup: CleanupMode
}
```

- `eventCapacity`: DOMから送られるActionのqueue容量。
- `hydration`: 初回mountで既存DOMを扱う方針。
- `cleanup`: unmount時に描画したDOMを扱う方針。
