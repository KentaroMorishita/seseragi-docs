---
title: "MaybeとEither"
description: "値がない場合と、失敗した理由を残す場合を型で区別する。"
---

検索した値がないことと、入力が不正なことは別の結果です。値の欠如が正常なら`Maybe`、失敗理由を残したいなら`Either`を使います。まず欠如と失敗を別々に扱い、その後で候補のポート番号を取得して検査する例へ進みます。

## Maybeで存在と欠如を表す

`Maybe<A>`には、値を持つ`Just A`と、持たない`Nothing`があります。`Just 21`は整数が存在する値です。欠如だけでは中身の型が分からない場合は、`let absent: Maybe<Int> = Nothing`のように注釈します。

`maybeValue ?? fallback`は、Justなら中の値を、Nothingなら右側の既定値を返します。既定値はNothingのときだけ評価されます。`??`はMaybe専用で、Eitherから成功値を取り出す演算子ではありません。

### 存在する値だけを変える

次は`main`内の束縛です。Arrayに使った`map`を、Maybeの中の値にも使えます。

{/* example: examples/learn/focused/maybe-map.ssrg#present */}
```seseragi title="main内の束縛"
let present =
  Just 21
  |> map (\n -> n * 2)
```

`present`は`Just 42`です。値がない場合も同じ操作を適用してみます。

{/* example: examples/learn/focused/maybe-map.ssrg#absent */}
```seseragi title="main内の束縛"
let absent: Maybe<Int> =
  Nothing
  |> map (\n: Int -> n * 2)
```

`absent`はNothingのままです。Nothingにラムダを適用して、架空の整数を作ることはありません。

## Eitherで失敗理由を残す

`Either<E, A>`は、失敗を表す`Left E`か、成功を表す`Right A`です。文字列の失敗理由と整数の成功値を扱う型へ、次の別名を付けます。これはモジュールに置く宣言で、新しいnominal型を作りません。

{/* example: examples/learn/focused/either-do.ssrg#result-type */}
```seseragi title="型の別名"
alias Result = Either<String, Int>
```

次は`main`内の束縛です。

{/* example: examples/learn/focused/either-map.ssrg#success */}
```seseragi title="main内の束縛"
let success: Result =
  Right 21
  |> map (\n -> n * 2)
```

`success`は`Right 42`です。失敗についてもmapを試します。

{/* example: examples/learn/focused/either-map.ssrg#failure */}
```seseragi title="main内の束縛"
let input: Result = Left "invalid"
let failure =
  input
  |> map (\n -> n * 2)
```

`failure`は`Left "invalid"`のままです。Leftは成功値を持たないので、ここでは先にResultの注釈で中身の型を決めています。MaybeのNothingと同じように、mapは失敗側へ変換関数を適用しません。失敗理由の文字列も保持します。

## 中身を変換し、次の計算へ進む

変換する関数もMaybeを返す場合を考えます。次の関数は、正の整数なら残し、それ以外なら欠如を返します。モジュールに置く宣言です。

{/* example: examples/learn/focused/maybe-flatmap.ssrg#declaration */}
```seseragi title="関数の宣言"
fn positive n: Int -> Maybe<Int> =
  if n > 0 then Just n else Nothing
```

この関数をmapへ渡すと、Maybeの中へもう一つMaybeを入れます。次は`main`内の束縛です。

{/* example: examples/learn/focused/maybe-flatmap.ssrg#nested */}
```seseragi title="main内の束縛"
let nested =
  Just 2
  |> map positive
```

`nested`の型は`Maybe<Maybe<Int>>`です。showの結果は`Just Just 2`で、二つのJustに包まれています。次の計算もMaybeを返すなら、flatMapでつなげられます。

{/* example: examples/learn/focused/maybe-flatmap.ssrg#chained */}
```seseragi title="main内の束縛"
let chained =
  Just 2
  |> flatMap positive
```

`chained`は`Just 2`で、型は`Maybe<Int>`です。次の計算が欠如を返す場合も試します。

{/* example: examples/learn/focused/maybe-flatmap.ssrg#rejected */}
```seseragi title="main内の束縛"
let rejected =
  Just (-1)
  |> flatMap positive
```

`rejected`はNothingです。最初の値がNothingなら、次の関数は呼びません。`>>=`も、成功値から次の計算へ進む同じ合成を表せます。

### doで依存を順に書く

Eitherを返す検査を二つ組み合わせます。先ほどのResultを使い、モジュールに次の関数を宣言します。

{/* example: examples/learn/focused/either-do.ssrg#validation */}
```seseragi title="関数の宣言"
fn requirePositive n: Int -> Result =
  if n > 0 then
    Right n
  else
    Left "must be positive"
```

両方の成功値が必要な足し算は、次のように書けます。これも通常の純粋な関数です。

{/* example: examples/learn/focused/either-do.ssrg#combination */}
```seseragi title="関数の宣言"
fn addChecked x: Int -> y: Int
  -> Result = do {
    left <- requirePositive x
    right <- requirePositive y
    Right (left + right)
  }
```

| 呼び出しの式 | 結果 |
| --- | --- |
| `addChecked 2 3` | `Right 5` |
| `addChecked (-1) 3` | `Left "must be positive"` |

`left <- ...`と`right <- ...`は、Rightの成功値を取り出します。最初がLeftなら、その理由を保って次の検査へ進みません。最後の`Right (left + right)`が全体の成功結果です。`do`はEffect専用ではなく、ここでは同期のEitherを合成しています。

## 候補の取得と検査を組み合わせる

`Either<E, A>`は、失敗を表す`Left E`か、成功を表す`Right A`です。この例では`PortError`が失敗の型、`Int`が成功の型になります。`PortResult`は、この`Either<PortError, Int>`に付けた型の別名です。

{/* example: examples/learn/maybe-and-either.ssrg */}
```seseragi title="maybe-and-either.ssrg"
type PortError =
  | OutOfRange Int

alias PortResult =
  Either<PortError, Int>

fn validPort n: Int -> PortResult =
  if n >= 1 && n <= 65535 then
    Right n
  else
    Left (OutOfRange n)

fn explain result: PortResult
  -> String =
  match result {
    Right port -> `Port: ${port}`
    Left (OutOfRange n) ->
      `Invalid port: ${n}`
  }

pub effect fn main = do {
  let ports = [8080]
  let candidate = ports[0] ?? 3000
  candidate
  |> validPort
  |> explain
  |> println
}
```

```text title="実行結果"
Port: 8080
```

候補がなければ3000を使い、その値を`validPort`へ渡します。1から65535なら`Right n`、それ以外なら`Left (OutOfRange n)`を返します。失敗した入力もpayloadへ残しているので、表示に使えます。



## パターンで結果を扱う

`explain`は`Right port`から成功値を取り出し、`Left (OutOfRange n)`から失敗した整数を取り出します。両方の分岐で表示用の`String`を返します。

`Left`を作った時点では例外を投げません。Eitherはすでに計算された通常の値で、`match`や関数へ渡せます。画面への出力は、この例でも最後の`println`が返すEffectで行います。

## 同期の結果と外部処理を区別する

このポート検査は、入力から結果を返す純粋な同期計算です。ネットワークへ接続する処理そのものはEitherに隠さず、Effectとして表します。

`Maybe`は欠如の理由を持ちません。入力を拒否した理由や複数の失敗ケースを表示する必要があるなら、ADTを失敗型に持つEitherが適しています。失敗の理由を捨てて`Nothing`へ変換するかどうかは、利用する側の方針として決めます。

## 欠如と失敗をそれぞれ試す

`ports`を型注釈付きの空配列`let ports: Array<Int> = []`へ変えると、出力は`Port: 3000`です。`[-1]`へ変えると、候補は存在しますが検査に失敗して`Invalid port: -1`です。値がないことと、ある値が不正なことの違いを確認してください。

次は[ジェネリクス](/docs/learn/generics)で、`Maybe<A>`のように型引数を持つデータ型と関数を自分で定義します。外部処理の失敗は[Effect](/docs/learn/effects)と[エラー処理](/docs/guides/error-handling)で扱います。
