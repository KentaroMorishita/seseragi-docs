title: "MaybeとEither"
description: "値がない場合と、失敗した理由を残す場合を型で区別する。"
---

TypeScriptでは、値がないことを`undefined`や`null`で、失敗を例外で表すことがよくあります。どちらも型には現れにくく、チェックを忘れても気づけません。

Seseragiでは、この二つを型で表します。「探したけど見つからなかった」のように値がないこと自体が普通の結果なら`Maybe`、「入力が正しくなかった」のように失敗の理由を伝えたいなら`Either`を使います。この章では二つを順に試してから、ポート番号を検査する例で組み合わせます。

この章のコードでは、[関数](/docs/learn/functions)のラムダ、[パイプライン](/docs/learn/pipelines)の`|>`、[代数的データ型](/docs/learn/algebraic-data-types)、[パターンマッチ](/docs/learn/pattern-matching)の`match`、[ArrayとList](/docs/learn/arrays-and-lists)を使います。

## Maybeで存在と欠如を表す

`Maybe<A>`は、値がある`Just 値`か、値がない`Nothing`のどちらかです。`Just 21`は整数がある状態を表します。`Nothing`だけでは中身の型が分からないので、必要なら`let absent: Maybe<Int> = Nothing`のように型を書きます。

`maybeValue ?? fallback`は、`Just`なら中の値を、`Nothing`なら右側の代わりの値を返します。右側が計算されるのは`Nothing`のときだけです。`??`は`Maybe`専用で、`Either`には使えません。

### 値があるときだけ変換する

Arrayで使った`map`は、`Maybe`にも使えます。

{/* example: examples/learn/focused/maybe-map.ssrg#present */}
```seseragi title="main内の束縛"
let present =
  Just 21
  |> map (\n -> n * 2)
```

`present`は`Just 42`です。値がない場合も試してみます。

{/* example: examples/learn/focused/maybe-map.ssrg#absent */}
```seseragi title="main内の束縛"
let absent: Maybe<Int> =
  Nothing
  |> map (\n: Int -> n * 2)
```

`absent`は`Nothing`のままです。`Nothing`には中身がないので、ラムダは呼ばれません。「値があるかどうか」を毎回確かめなくても、ある場合の処理だけを書けます。

## Eitherで失敗理由を残す

`Either<E, A>`は、失敗を表す`Left エラー`か、成功を表す`Right 値`のどちらかです。ここでは、失敗の理由が文字列、成功の値が整数の`Either`に、`Result`という別名を付けます。`alias`は名前を付けるだけで、新しい型は作りません。

{/* example: examples/learn/focused/either-do.ssrg#result-type */}
```seseragi title="型の別名"
alias Result = Either<String, Int>
```

{/* example: examples/learn/focused/either-map.ssrg#success */}
```seseragi title="main内の束縛"
let success: Result =
  Right 21
  |> map (\n -> n * 2)
```

`success`は`Right 42`です。失敗の場合も試します。

{/* example: examples/learn/focused/either-map.ssrg#failure */}
```seseragi title="main内の束縛"
let input: Result = Left "invalid"
let failure =
  input
  |> map (\n -> n * 2)
```

`failure`は`Left "invalid"`のままです。`Maybe`の`Nothing`と同じく、`Left`のときはラムダが呼ばれず、失敗の理由もそのまま残ります。（`Left`だけでは成功の型が分からないので、`input`には`Result`と型を書いています。）

## 失敗するかもしれない処理をつなぐ

変換する関数そのものも`Maybe`を返す場合を考えます。次の関数は、正の整数ならそのまま返し、それ以外なら`Nothing`を返します。

{/* example: examples/learn/focused/maybe-flatmap.ssrg#declaration */}
```seseragi title="関数の宣言"
fn positive n: Int -> Maybe<Int> =
  if n > 0 then Just n else Nothing
```

この関数を`map`に渡すと、`Maybe`の中にもう一つ`Maybe`が入ってしまいます。

{/* example: examples/learn/focused/maybe-flatmap.ssrg#nested */}
```seseragi title="main内の束縛"
let nested =
  Just 2
  |> map positive
```

`nested`の型は`Maybe<Maybe<Int>>`で、表示すると`Just Just 2`です。次の処理も`Maybe`を返すときは、`map`の代わりに`flatMap`を使います。

{/* example: examples/learn/focused/maybe-flatmap.ssrg#chained */}
```seseragi title="main内の束縛"
let chained =
  Just 2
  |> flatMap positive
```

`chained`は`Just 2`で、型は`Maybe<Int>`です。`positive`が`Nothing`を返す場合も試します。

{/* example: examples/learn/focused/maybe-flatmap.ssrg#rejected */}
```seseragi title="main内の束縛"
let rejected =
  Just (-1)
  |> flatMap positive
```

`rejected`は`Nothing`です。また、最初の値が`Nothing`なら、`positive`は呼ばれません。`flatMap`の代わりに`>>=`演算子でも同じことを書けます。

### doで順番に書く

`flatMap`を何段も重ねると読みにくくなります。そこで使うのが`do`記法です。`Either`を返す検査を二つ組み合わせてみます。

{/* example: examples/learn/focused/either-do.ssrg#validation */}
```seseragi title="関数の宣言"
fn requirePositive n: Int -> Result =
  if n > 0 then
    Right n
  else
    Left "must be positive"
```

二つの値がどちらも正のときだけ足し算をする関数は、`do`を使って次のように書けます。

{/* example: examples/learn/focused/either-do.ssrg#combination */}
```seseragi title="関数の宣言"
fn addChecked x: Int -> y: Int
  -> Result = do {
    left <- requirePositive x
    right <- requirePositive y
    Right (left + right)
  }
```

| 呼び出しの式 | 結果 |
| --- | --- |
| `addChecked 2 3` | `Right 5` |
| `addChecked (-1) 3` | `Left "must be positive"` |

`left <- requirePositive x`は、結果が`Right`なら中の値を`left`として取り出し、次の行に進みます。`Left`なら、そこで止まり、その`Left`が関数全体の結果になります。TypeScriptで、失敗したら早めに`return`する書き方に近いものです。最後の`Right (left + right)`が、すべて成功したときの結果です。

`do`は、あとで学ぶEffect専用の書き方ではありません。ここでは、`Maybe`や`Either`のような普通の値をつなぐのに使っています。

## MaybeとEitherを組み合わせる

設定からポート番号を取り出して、正しい範囲か検査する例です。設定に値がないことは`Maybe`で、範囲外の値は`Either`で扱います。失敗の型には、文字列ではなく自分で定義した`PortError`を使っています。

{/* example: examples/learn/maybe-and-either.ssrg */}
```seseragi title="maybe-and-either.ssrg"
type PortError =
  | OutOfRange Int

alias PortResult =
  Either<PortError, Int>

fn validPort n: Int -> PortResult =
  if n >= 1 && n <= 65535 then
    Right n
  else
    Left (OutOfRange n)

fn explain result: PortResult
  -> String =
  match result {
    Right port -> `Port: ${port}`
    Left (OutOfRange n) ->
      `Invalid port: ${n}`
  }

pub effect fn main = do {
  let ports = [8080]
  let candidate = ports[0] ?? 3000
  candidate
  |> validPort
  |> explain
  |> println
}
```

```text title="実行結果"
Port: 8080
```

`ports[0] ?? 3000`で、値がなければ3000を使います。その値を`validPort`に渡し、1から65535の範囲なら`Right n`、範囲外なら`Left (OutOfRange n)`を返します。失敗した値を`OutOfRange`に持たせているので、エラーメッセージに使えます。

`explain`は`match`で二つの場合を分け、`Right port`なら成功の値を、`Left (OutOfRange n)`なら失敗した値を取り出して、表示用の文字列を返します。

`Left`を返しても、例外のように処理が飛ぶことはありません。`Either`はただの値なので、`match`で調べたり、別の関数に渡したりできます。

## MaybeとEitherの使い分け

`Maybe`は、値がない理由を持ちません。なぜ失敗したのかを伝えたいときや、失敗の種類が複数あるときは、ADTを失敗の型にした`Either`を使います。

この章のポートの検査は、値を受け取って結果を返すだけの計算です。実際にネットワークへ接続するような処理は、`Either`ではなく[Effect](/docs/learn/effects)で表します。

## 欠如と失敗をそれぞれ試す

`ports`を空のArray`let ports: Array<Int> = []`にすると、`Port: 3000`と表示されます。`[-1]`にすると、値はあるものの検査に失敗し、`Invalid port: -1`と表示されます。「値がない」と「値が正しくない」が、別々に扱われていることを確かめてください。

次の[ジェネリクス](/docs/learn/generics)では、`Maybe<A>`のように型を引数に取るデータ型や関数を、自分で定義します。外部とのやり取りでの失敗は、[Effect](/docs/learn/effects)と[エラー処理](/docs/guides/error-handling)で扱います。
