文字列を組み立てることと、その文字列を画面に出力することは、別のことです。前者は何度やっても同じ結果になりますが、後者は外の世界に影響を与えます。

Seseragiでは、出力・状態の読み書き・非同期処理のような外の世界とのやり取りを、`Effect`という値で表します。Effectは「実行すると何かをする処理」を表す値で、作っただけではまだ何も起こりません。この章では、Effectの作り方、実行の仕方、失敗の扱い方を学びます。

## 成功する計算から値を受け取る

まずは、外の世界を使わずに、ただ値を返すだけのEffectを作ってみます。`std/effect`をimportします。

{/* example: examples/learn/focused/effect-bind.ssrg#import */}
```seseragi title="importの宣言"
import * as effects from "std/effect"
```

`succeed`は、普通の値から「その値で成功するEffect」を作ります。

{/* example: examples/learn/focused/effect-bind.ssrg#declaration */}
```seseragi title="関数の宣言"
effect fn answer -> Int =
  effects.succeed 42
```

`answer ()`を呼んで返ってくるのは、整数そのものではなく「42で成功するEffect」です。中の値を使うには、`main`の`do`の中で`<-`を使って取り出します。

{/* example: examples/learn/focused/effect-bind.ssrg#bind */}
```seseragi title="mainのdo内の式"
value <- answer ()
value
|> show
|> println
```

42と表示されます。`value <- answer ()`でEffectを実行して成功の値を受け取り、そのあとは普通の整数として使っています。TypeScriptの`const value = await answer()`に近い書き方です。

## Effectは作っただけでは実行されない

{/* example: examples/learn/effects.ssrg */}
```seseragi title="effects.ssrg"
effect fn greet name: String -> Unit
with Console
fails ConsoleError =
  println `Hello, ${name}`

pub effect fn main = do {
  let greeting = greet "Aki"
  println "Before greeting"
  greeting
  greeting
}
```

```text title="実行結果"
Before greeting
Hello, Aki
Hello, Aki
```

`let greeting = greet "Aki"`は、「挨拶を出力するEffect」を作って名前を付けるだけで、この時点では何も出力しません。そのため最初に表示されるのは`Before greeting`です。そのあと`greeting`を二回実行すると、挨拶も二回表示されます。

ここがTypeScriptのPromiseとの大きな違いです。Promiseは作った瞬間に処理が始まり、結果は一度しか得られません。Effectは作っただけでは始まらず、実行するたびに処理が行われます。そのため、Effectは変数に入れたり、関数に渡したり、あとで何度でも実行したりできる、ただの値として扱えます。

## Effectの型が教えてくれること

Effectの型`Effect<R, E, A>`には、三つの情報が入っています。`R`は処理に必要なもの、`E`は起こりうる失敗、`A`は成功したときの結果です。例の`greet`の型は次のとおりで、「コンソールを使い、`ConsoleError`で失敗することがあり、成功すると`Unit`を返す」と読めます。

```seseragi
Effect<
  { console: Console },
  ConsoleError,
  Unit
>
```

`effect fn`の宣言では、`-> Unit`が成功の型、`with Console`が必要なもの、`fails ConsoleError`が失敗の型にあたります。関数のシグネチャを見るだけで、その関数が何を使い、どう失敗しうるのかが分かります。TypeScriptの関数では、中で`fetch`や`console.log`を呼んでいても型からは分かりませんし、何を`throw`するかも分かりません。

## doで順番に実行する

`do`の中に書いたEffectは、上から順に実行されます。成功の値を使いたいときは`value <- effect`と書きます。`do`の中の`let`は、普通の値に名前を付けるだけで、Effectを実行しません。

`do`の最後はEffectにします。普通の値を結果にしたいときは、`succeed value`か`pure value`でEffectに包みます。なお、`do`ではない普通のブロック`{ ... }`にEffectを並べても、順に実行されるわけではありません。

[MaybeとEither](/docs/learn/maybe-and-either)の章でも`do`を使いました。`do`は同じ書き方で、Maybeなら「値がなければ止まる」、Eitherなら「失敗したら止まる」、Effectなら「処理を順に実行し、失敗したら止まる」という動きになります。

## 型を書くか、推論に任せるか

例の`greet`は、成功・必要なもの・失敗の型をすべて書いています。`main`のように`->`・`with`・`fails`を全部省くと、本体からすべて推論されます。

注意したいのは、`-> Unit`のように成功の型を書いたときです。この場合、省いた`with`は「何も必要としない」、省いた`fails`は「失敗しない（`Never`）」という意味になり、本体から推論はされません。コンソールに出力するなら、例のように`with Console`と`fails ConsoleError`も書きます。

推論に任せた場合も、必要なものと失敗の型は関数の型に残ります。必要なものは自動でまとめられますが、種類の違う失敗の型が自動で一つにまとめられることはありません。失敗をどう分類するかは、ADTと`mapError`を使って自分で決めます。

## 失敗を扱う

一つの`do`の中で組み合わせるEffectは、失敗の型を揃える必要があります（失敗しない`Never`は、どの失敗の型にも合わせられます）。起こりうる失敗は`fail`で表し、`recover`で立て直せます。

### 失敗から立て直す

まず失敗の型を定義します。この例でも`std/effect`を`effects`としてimportしています。

{/* example: examples/learn/focused/effect-recovery.ssrg#failure-type */}
```seseragi title="型の宣言"
type CheckError =
  | Rejected
```

次は、`allowed`が`True`なら42で成功し、`False`なら`Rejected`で失敗するEffectです。

{/* example: examples/learn/focused/effect-recovery.ssrg#declaration */}
```seseragi title="関数の宣言"
effect fn accepted allowed: Bool
  -> Int fails CheckError =
  if allowed then
    effects.succeed 42
  else
    effects.fail Rejected
```

失敗したときに代わりに実行する関数を用意します。成功したときと同じ`Int`を返すEffectにします。

{/* example: examples/learn/focused/effect-recovery.ssrg#fallback */}
```seseragi title="関数の宣言"
effect fn fallback error: CheckError
  -> Int =
  effects.succeed 0
```

`recover`でつなぎます。

{/* example: examples/learn/focused/effect-recovery.ssrg#recover */}
```seseragi title="mainのdo内の式"
value <-
  accepted False
  |> effects.recover fallback
```

`value`は0です。`False`を`True`に変えると42になり、`fallback`は呼ばれません。失敗したときだけ、`recover`に渡した関数が実行されます。TypeScriptの`try ... catch`に近いですが、どんな失敗が来るかは型で決まっています。

### 失敗の型を変換する

文字列の失敗を、アプリで使うADTの失敗に変えたいときは`mapError`を使います。まず、変換先の型を定義します。

{/* example: examples/learn/focused/effect-map-error.ssrg#failure-type */}
```seseragi title="型の宣言"
type InputError =
  | Invalid String
```

変換元は、文字列で失敗するEffectです。

{/* example: examples/learn/focused/effect-map-error.ssrg#source */}
```seseragi title="関数の宣言"
effect fn load -> String
fails String =
  effects.fail "empty"
```

`mapError Invalid`で、失敗の文字列を`Invalid`に包んで`InputError`にします。

{/* example: examples/learn/focused/effect-map-error.ssrg#mapping */}
```seseragi title="関数の宣言"
effect fn checked -> String
fails InputError =
  load ()
  |> effects.mapError Invalid
```

`mapError`は失敗の型を変えるだけで、失敗から立て直すわけではありません。立て直すには、さらに`recover`を使います。

{/* example: examples/learn/focused/effect-map-error.ssrg#recovery */}
```seseragi title="回復する関数の宣言"
effect fn describe error: InputError
  -> String =
  match error {
    Invalid reason -> {
      let message =
        `invalid: ${reason}`
      effects.succeed message
    }
  }
```

`main`では次のように使います。

{/* example: examples/learn/focused/effect-map-error.ssrg#use */}
```seseragi title="mainのdo内の式"
value <-
  checked ()
  |> effects.recover describe
println value
```

`invalid: empty`と表示されます。`mapError`は失敗を分類し直し、`recover`は失敗から成功の結果を作ります。

なお、プログラムのバグによる異常終了や処理のキャンセルは、`fails`で表す失敗とは別のものです。`recover`は、どんな異常でも捕まえる`catch`ではありません。失敗の設計の仕方は[エラー処理](/docs/guides/error-handling)のガイドで扱います。

プログラムを実行すると、CLIが`pub`の`main`が返すEffectを実行します。`effect fn`は「Effectを返す関数」を読みやすく書くための構文で、普通の`fn`でも型を書けばEffectを返せます。

## 実行回数を変える

`greeting`を実行する行を一つ消すと、挨拶も一回になります。`let greeting = ...`だけを残して実行する行を両方消すと、挨拶は表示されません。Effectは作っただけでは実行されないことを確かめてください。

次の[Signal](/docs/learn/signals)では、変化する状態をEffectで読み書きします。Effectの細かい決まりは[Effectリファレンス](/docs/reference/effects)にあります。
