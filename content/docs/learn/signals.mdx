Seseragiの値は、一度作ったら変わりません。でも、ボタンを押した回数のように、時間とともに変わる状態も必要です。そのために使うのがSignalです。

`MutableSignal<A>`は書き換えられる状態の入れ物で、Effectを使って読み書きします。状態から計算した値は、読み取り専用の`Signal<A>`として作れます。元の状態が変わると、計算した値も自動で追従します。

この章のコードでは、[関数](/docs/learn/functions)のラムダ、[パイプライン](/docs/learn/pipelines)の`|>`と`show`、[ArrayとList](/docs/learn/arrays-and-lists)、[Effect](/docs/learn/effects)の`do`と`<-`を使います。

## 値を指定して更新する

まずは、状態を書き換えて読み取るだけの例です。`std/signal`を`signals`としてimportしておきます（importの書き方は[モジュール](/docs/learn/modules)で扱います）。

{/* example: examples/learn/focused/signal-set.ssrg#set */}
```seseragi title="mainのdo内の式"
count <- signals.make 1
before <- *count
count := 5
after <- *count
```

`signals.make 1`で、1が入ったSignalを作ります。`*count`で今の値を読み取り、`count := 5`で値を書き換えます。`before`は1、`after`は5です。先に読み取った`before`は、書き換えたあとも1のままです。

## 状態から計算した値を作る

{/* example: examples/learn/signals.ssrg */}
```seseragi title="signals.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  count <- signals.make 1
  let doubled =
    count
    |> signals.map (\n -> n * 2)
  first <- *doubled
  println `before: ${first}`
  signals.update (\n -> n + 1) count
  second <- *doubled
  println `after: ${second}`
}
```

```text title="実行結果"
before: 2
after: 4
```

`signals.map (\n -> n * 2) count`は、「`count`の2倍」を表すSignalを作ります。`count`を1から2に増やすと、`doubled`も2から4に変わります。表計算ソフトで、あるセルを参照する式を書いておくと、元のセルを変えたときに結果も変わるのと似ています。

`signals.map`に渡す関数は、値を計算するだけの関数にします。出力などのEffectは入れません。

## 読み取りもEffect

`*doubled`は、今の値を読み取るEffect（`Task<Int>`）です。読むタイミングによって結果が変わるので、整数そのものではなくEffectになっています。そのため`first <- *doubled`のように`<-`で受け取ります。受け取った`first`は普通の整数です。

あとでSignalが変わっても、すでに受け取った`first`は変わりません。新しい値が欲しければ、もう一度読み取ります。

## 今の値をもとに更新する

`signals.update (\n -> n + 1) count`は、今の値に1を足した値で更新します。読み取りと書き込みが一度に行われるので、間に別の更新が割り込むことはありません。

値を直接指定するときは`count := 2`と書きます。`:=`は`MutableSignal`にだけ使え、`doubled`のような計算したSignalには使えません。今の値をもとに更新したいときは、読み取ってから`:=`するより、`update`を使いましょう。

## 複数の更新をまとめる

幅と高さを同時に変えて、面積を計算する例です。

{/* example: examples/learn/signal-transaction.ssrg */}
```seseragi title="signal-transaction.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  width <- signals.make 3
  height <- signals.make 4
  let area =
    signals.combine (*) width height
  signals.transaction [
    signals.planSet 5 width,
    signals.planSet 6 height,
  ]
  current <- *area
  current
  |> show
  |> println
}
```

```text title="実行結果"
30
```

`signals.combine (*) width height`は、二つのSignalの値を掛け算した値のSignalを作ります。`(*)`は、掛け算を二つの引数を取る関数として使う書き方です。どのSignalに依存するかは引数で明示します。関数の中で読んだSignalを自動で追跡する仕組みではありません。

`planSet`は「この値に変える」という予定を作り、`transaction`がそれらを一度に反映します。幅だけ変わって高さはまだ、という途中の状態が、`area`などから見えることはありません。ただし`transaction`がまとめるのはSignalの更新だけで、ファイルへの書き込みなど他の処理までまとめるものではありません。

## 一度読むか、変化を受け取り続けるか

`*`での読み取りは、その瞬間の値を一回だけ取り出します。二つのSignalを別々に読むと、その間に更新が入るかもしれません。同じ瞬間の二つの値を使いたいときは、`combine`などで一つにまとめたSignalを一回だけ読みます。

変化を受け取り続けたいときは、`subscribe`で購読します。購読を始めると、まず今の値が一度通知され、そのあと更新のたびに通知されます。要らなくなったら、`subscribe`が返した`Subscription`を`unsubscribe`に渡して解除します。計算したSignalを作ったり、一度読んだりするだけでは、購読は始まりません。

同じ値で更新した場合も、通知は届きます。値が変わったときだけ通知してほしい場合は`distinct`を使います。購読の細かい決まりは[Signalリファレンス](/docs/reference/signals)、画面とのつなぎ方は[状態とアクション](/docs/guides/state-and-actions)のガイドにあります。

### 購読と解除を試す

通知された値を、別のSignalに入れたListに記録してみます。`History`は、長い型に付けた別名です。

{/* example: examples/learn/focused/signal-subscription.ssrg#callback */}
```seseragi title="通知を記録する関数"
alias History =
  signals.MutableSignal<List<Int>>

effect fn remember history: History
  -> n: Int -> Unit = {
  let prepend = \seen -> n : seen
  signals.update prepend history
}
```

この関数は、通知された値をListの先頭に足すだけです。`main`は次のように始め、以下のコードをこの`do`の中に書きます。

{/* example: examples/learn/focused/signal-subscription.ssrg#entry */}
```seseragi title="mainの宣言の先頭"
pub effect fn main -> Unit
with Console
fails ConsoleError = do {
```

まず、見張る状態と、記録用の空のListを用意します。

{/* example: examples/learn/focused/signal-subscription.ssrg#setup */}
```seseragi title="mainのdo内の式"
count <- signals.make 0
let empty: List<Int> = `[]
history <- signals.make empty
```

購読を始めてから、状態を一度変えます。

{/* example: examples/learn/focused/signal-subscription.ssrg#subscription */}
```seseragi title="mainのdo内の式"
let observer = remember history
subscription <-
  count
  |> signals.subscribe observer
count := 1
```

購読を始めたときの0と、更新後の1が通知されます。記録はListの先頭に足していくので、新しいものが前に来ます。

{/* example: examples/learn/focused/signal-subscription.ssrg#cleanup */}
```seseragi title="mainのdo内の式"
signals.unsubscribe subscription
count := 2
events <- *history
```

`events`を表示すると、次のようになります。

```text title="記録された値"
`[1, 0]
```

解除したあとの2は記録されません。

### 同じ値の通知を省く

上の`remember`を使って、普通の購読と`distinct`を通した購読を比べます。`count`を0で作り、記録用に空のListを入れた`all`と`unique`を用意してから、次のように書きます。

{/* example: examples/learn/focused/signal-distinct.ssrg#views */}
```seseragi title="mainのdo内の式"
let distinct = signals.distinct count
let allObserver = remember all
let uniqueObserver = remember unique
normalSub <-
  count
  |> signals.subscribe allObserver
uniqueSub <-
  distinct
  |> signals.subscribe uniqueObserver
```

同じ値で二回更新します。

{/* example: examples/learn/focused/signal-distinct.ssrg#updates */}
```seseragi title="mainのdo内の式"
count := 1
count := 1
```

| 購読するSignal | 記録された値 |
| --- | --- |
| count | `` `[1, 1, 0] `` |
| distinct | `` `[1, 0] `` |

普通の購読には、同じ1での更新も二回とも届きます。`distinct`を通すと、直前と同じ値の通知は省かれます。`distinct`は元の`count`を変えるのではなく、通知の仕方だけを変えます。（この例でも、最後に二つの購読を`unsubscribe`で解除しています。）

## 更新と計算を変える

2つ目の例で、更新を`\n -> n + 3`に変えると、最後の表示は`after: 8`になります。`doubled`の計算を3倍に変えると、`before: 3`、`after: 6`です。

最後に`first`をもう一度表示すると、更新したあとでも2のままです。一度読み取った値と、状態に追従するSignalの違いを確かめてください。

次の[型クラス](/docs/learn/type-classes)では、`map`のような関数がArrayにもMaybeにも使える仕組みを学びます。
