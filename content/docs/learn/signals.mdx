通常の値は不変です。時間とともに変わる状態が必要な場合は、`MutableSignal<A>`を作り、Effectから読み書きします。状態から計算した値は、読み取り専用の`Signal<A>`としてつなげられます。

## 値を指定して更新する

まず派生値を作らず、更新と読み取りだけを試します。モジュールでは`std/signal`をsignalsとしてimportしてください。次は`main`のdo内に置く式です。

{/* example: examples/learn/focused/signal-set.ssrg#set */}
```seseragi title="mainのdo内の式"
count <- signals.make 1
before <- *count
count := 5
after <- *count
```

`before`は1、`after`は5です。`count := 5`は保存した状態を変えます。すでに読み取った`before`は、更新後も1のままです。次の例で、状態から計算した値へ進みます。

## 更新元と派生値を作る

{/* example: examples/learn/signals.ssrg */}
```seseragi title="signals.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  count <- signals.make 1
  let doubled =
    count
    |> signals.map (\n -> n * 2)
  first <- *doubled
  println `before: ${first}`
  signals.update (\n -> n + 1) count
  second <- *doubled
  println `after: ${second}`
}
```

```text title="実行結果"
before: 2
after: 4
```

`signals.make 1`は、整数を保持する更新可能なSignalを作る計算です。`count <- ...`で成功値を取り出します。

`signals.map (\n -> n * 2) count`は、`count`から2倍の値を得る派生Signalを作ります。`map`の関数は純粋な計算です。派生値を作るときに、出力や非同期処理をその関数へ入れません。

## 読み取りもEffect

`*doubled`は、現在値を読み取る`Task<Int>`です。整数そのものを返す純粋な参照ではないので、`first <- *doubled`と書きます。読み取った`first`は普通の不変の整数です。

後からSignalが変わっても、すでに取得した`first`の値は変わりません。更新後の値が必要なら、再び読み取ります。Signalを通常の`let`の再代入や、常に変わり続ける整数そのものと混同しないでください。

## 現在値に基づく更新

`signals.update (\n -> n + 1) count`は、その時点の値を受け取り、新しい値を保存します。この更新はatomicです。

値をそのまま指定する場合は`count := 2`と書けます。この演算子はMutableSignalだけに使えます。派生した`doubled`や普通の変数へは代入できません。現在値に依存する更新は、先に読んでから`:=`する二段階ではなく、`update`で表せます。

## 複数の更新をtransactionにする

幅と高さを同時に更新して、面積を計算する例です。

{/* example: examples/learn/signal-transaction.ssrg */}
```seseragi title="signal-transaction.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  width <- signals.make 3
  height <- signals.make 4
  let area =
    signals.combine (*) width height
  signals.transaction [
    signals.planSet 5 width,
    signals.planSet 6 height,
  ]
  current <- *area
  current
  |> show
  |> println
}
```

```text title="実行結果"
30
```

`combine`は二つのSignalの値を`(*)`へ渡します。`(*)`は乗算を二引数の関数として参照した値です。依存するSignalを引数で明示しており、関数内の読み取りを自動追跡する方式ではありません。

`planSet`は更新計画を作り、`transaction`がすべてを一度に公開します。派生値や購読先に、幅だけ変わった途中の組み合わせを見せません。transactionはSignalの更新をまとめる操作で、任意のI/Oをatomicにする仕組みではありません。

## snapshotと購読を使い分ける

一度の読み取りは、その時点のsnapshotです。二つのSignalを別々に読むと、読み取りの間に更新が入る可能性があります。同じ時点の組を使いたい場合は、`combine`などでまとめた派生Signalを一度だけ読みます。取得後の排他制御まで保証するものではありません。

更新を継続的に受け取るには`subscribe`を明示します。成功時には現在値も一度通知されます。返されたSubscriptionは、不要になったら`unsubscribe`で解除します。派生値を作ったり一度読んだりするだけでは、購読は始まりません。

同じ値の更新も既定では通知されます。重複を避けたい場合は`distinct`を使います。購読の寿命や失敗の扱いは[Signalリファレンス](/docs/reference/signals)、画面との接続は[状態とアクション](/docs/guides/state-and-actions)で扱います。

### 購読開始と解除を確かめる

通知された整数を、別のSignalにListで記録してみます。次の宣言をモジュールに置きます。Historyは、長い型に付けた別名です。

{/* example: examples/learn/focused/signal-subscription.ssrg#callback */}
```seseragi title="通知を記録する関数"
alias History =
  signals.MutableSignal<List<Int>>

effect fn remember history: History
  -> n: Int -> Unit = {
  let prepend = \seen -> n : seen
  signals.update prepend history
}
```

このobserverはSignalを更新するだけで、失敗型はNeverです。Consoleへの出力はmainで行います。確認用プログラムのmainは、Consoleの環境と失敗を明示しています。次はその宣言の先頭の断片で、後のコードをこのdoブロック内に置きます。

{/* example: examples/learn/focused/signal-subscription.ssrg#entry */}
```seseragi title="mainの宣言の先頭"
pub effect fn main -> Unit
with Console
fails ConsoleError = do {
```

まず、観測する状態と、記録用の空Listを用意します。

{/* example: examples/learn/focused/signal-subscription.ssrg#setup */}
```seseragi title="mainのdo内の式"
count <- signals.make 0
let empty: List<Int> = `[]
history <- signals.make empty
```

次に購読を開始し、状態を一度変えます。

{/* example: examples/learn/focused/signal-subscription.ssrg#subscription */}
```seseragi title="mainのdo内の式"
let observer = remember history
subscription <-
  count
  |> signals.subscribe observer
count := 1
```

購読開始時の0と、更新後の1が通知されます。記録は先頭に追加するので、新しい通知が先頭になります。

{/* example: examples/learn/focused/signal-subscription.ssrg#cleanup */}
```seseragi title="mainのdo内の式"
signals.unsubscribe subscription
count := 2
events <- *history
```

`events`をshowで表示すると、次のListです。

```text title="記録された値"
`[1, 0]
```

解除後の2は記録されません。読み取りと、通知を受け続ける購読の寿命を分けて確認できます。

### 同じ値の通知を減らす

上のrememberを使い、普通の購読とdistinctを通した購読を比べます。mainのdo内でcountを0から作り、記録用のMutableSignalをallとuniqueとして空Listから作った後の式です。

{/* example: examples/learn/focused/signal-distinct.ssrg#views */}
```seseragi title="mainのdo内の式"
let distinct = signals.distinct count
let allObserver = remember all
let uniqueObserver = remember unique
normalSub <-
  count
  |> signals.subscribe allObserver
uniqueSub <-
  distinct
  |> signals.subscribe uniqueObserver
```

二つの購読へ、同じ更新を渡します。

{/* example: examples/learn/focused/signal-distinct.ssrg#updates */}
```seseragi title="mainのdo内の式"
count := 1
count := 1
```

| 購読するSignal | 記録された値 |
| --- | --- |
| count | `` `[1, 1, 0] `` |
| distinct | `` `[1, 0] `` |

普通の購読は同じ1への更新も通知し、distinct側は直前と等しい値を抑えます。この例も、最後に両方のSubscriptionをunsubscribeしています。distinctは更新元を書き換える操作ではなく、通知する側の振る舞いを変えます。

## 更新と計算を変える

最初の例の更新を`\n -> n + 3`へ変えると、最後の出力は`after: 8`です。派生関数を3倍へ変えると、元の1を足す更新では3から6へ変わります。

`first`を最後にもう一度出力すると、更新後も2のままです。snapshotと派生Signalの違いを確かめてください。次は[型クラス](/docs/learn/type-classes)で、`map`のような操作が異なる型にも使える仕組みを学びます。
