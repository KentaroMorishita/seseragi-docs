[レコードとstruct](/docs/learn/records-and-structs)では、複数の値を一緒に持つデータを作りました。ここでは、赤か青のどちらかになる信号を例に、取りうる状態を一つの型として定義します。型宣言と値の構文を順に見ていきます。

## ケースを並べて型を定義する

`type`の宣言では、`|`でケースを並べます。このように複数のケースから一つを選ぶ型を、代数的データ型、またはADTと呼びます。次の構文例は二つのケースを持つ型の宣言です。

```seseragi title="型宣言の構文例"
type Light =
  | Red
  | Green
```

`Red`も`Green`も`Light`の値です。一つの値が同時に両方のケースになることはありません。この宣言にはない`Yellow`を`Light`の値として使うこともできません。

前の章のstructが複数のフィールドを一緒に持つのに対して、この型は複数のケースから一つを選びます。

## データを持たないケースを使う

`Red`と`Green`には追加のデータがないので、ケース名だけで値になります。上の宣言を使うと、次の束縛を書けます。これは`main`などのブロック内へ置く構文例です。

```seseragi title="値の束縛の構文例"
let red: Light = Red
let green: Light = Green
```

二つの値は異なるケースですが、どちらの型も`Light`です。これらの断片は型と値の作り方を示しており、出力するプログラムではありません。ケースごとに文字列を返す関数は、次の章で作ります。

## ケースにデータを持たせる

次に、測定結果の型を作ります。測定していない状態には追加のデータがなく、測定済みの状態は整数を一つ持ちます。

```seseragi title="payloadを持つ型の構文例"
type Reading =
  | NoReading
  | Measured Int
```

`NoReading`はそれだけで`Reading`の値です。`Measured`は整数を一つ受け取るコンストラクターで、データを渡すと`Reading`の値が完成します。ケースが持つデータをpayloadと呼びます。

```seseragi title="値の束縛の構文例"
let absent: Reading = NoReading
let measured: Reading = Measured 23
```

`Measured "warm"`は、整数が必要な場所へ文字列を渡しているためエラーです。`Measured`だけなら、まだ整数を受け取る関数であり、完成した`Reading`の値ではありません。

## 複数の値を持つケース

一つのケースで複数の値を持つには、tupleを一つのpayloadとして使えます。次の断片では、長方形が幅と高さを持ちます。

{/* example: examples/learn/focused/adt-tuple-payload.ssrg#declaration */}
```seseragi title="型の宣言"
type Shape =
  | Circle Int
  | Rectangle (Int, Int)
```

値は`Rectangle (3, 4)`です。`(3, 4)`は二つの整数を一つにまとめたtupleであり、コンストラクターの引数はそのtuple一つです。`Rectangle 3 4`という二引数の呼び出しにはなりません。

次は上のShape宣言を使い、`main`内へ置く束縛です。tupleを渡した結果がShapeであることを、注釈でも確認できます。

{/* example: examples/learn/focused/adt-tuple-payload.ssrg#value */}
```seseragi title="main内の束縛"
let rectangle: Shape =
  Rectangle (3, 4)
```

フィールド名で区別したいデータは、前の章で学んだstructにまとめ、そのstructをケースに持たせられます。ADTで状態を選び、structで一緒に持つデータを定義します。

### structをpayloadにする

ログイン済みの場合だけ、アカウント情報を持つ型を考えます。先に、モジュールで情報の形を定義します。

{/* example: examples/learn/focused/adt-struct-payload.ssrg#data */}
```seseragi title="structの宣言"
struct Account {
  name: String,
}
```

次に、その情報が必要なケースを定義します。

{/* example: examples/learn/focused/adt-struct-payload.ssrg#declaration */}
```seseragi title="型の宣言"
type Session =
  | Guest
  | SignedIn Account
```

`Guest`は情報なしで作れます。`SignedIn`ではAccountが必須です。次の束縛は`main`内に置きます。

{/* example: examples/learn/focused/adt-struct-payload.ssrg#value */}
```seseragi title="main内の束縛"
let session: Session =
  SignedIn (Account { name: "Aki" })
```

内側のAccountの生成を括弧で一つの引数にまとめ、SignedInへ渡しています。これらも宣言と値の断片です。ケースを区別して情報を読む方法は、次のパターンマッチで学びます。

## 型の名前と入力の条件

ADTは宣言した名前によって区別される型です。同じケース名と構成を持つ別の型へ、暗黙に変換されません。必要な変換は関数で表します。

型はpayloadの型を決めますが、その値についてのあらゆる条件を検査するわけではありません。この`Reading`では、23も−1も`Measured`のpayloadにできます。測定値の範囲などの条件は、値を作る関数で検査します。

## ケースごとの処理へ進む

ここまでは、どのような値を作れるかを決めました。値を受け取った関数でケースを区別し、payloadを取り出すには`match`を使います。その書き方は次の[パターンマッチ](/docs/learn/pattern-matching)で学びます。

まず`Light`の宣言へ`Yellow`を追加すると、`Yellow`も`Light`の値になります。`Reading`では、`Measured 23`を`NoReading`へ変えても結果の型は同じです。ケースの選択とpayloadの型を分けて確かめてください。

型の宣言を確認するときは[データ型リファレンス](/docs/reference/data-types)を参照してください。次の[パターンマッチ](/docs/learn/pattern-matching)では、まずBoolの二つの値を分岐し、その後で`Reading`のpayloadを取り出します。
