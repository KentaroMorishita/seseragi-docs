[レコードとstruct](/docs/learn/records-and-structs)では、複数の値をまとめて持つデータを作りました。この章では、「赤か青のどちらか」のように、いくつかの状態のうち一つを取るデータを型で表します。

## ケースを並べて型を定義する

`type`で型を宣言し、取りうるケースを`|`で並べます。このように「いくつかのケースのどれか一つ」を表す型を、代数的データ型（ADT）と呼びます。TypeScriptの`"red" | "green"`のようなユニオン型に近いものです。

```seseragi title="型宣言の構文例"
type Light =
  | Red
  | Green
```

`Red`も`Green`も`Light`型の値です。一つの値が両方のケースを同時に取ることはなく、宣言にない`Yellow`を`Light`として使うこともできません。

structが「全部のフィールドを同時に持つ」型だとすれば、ADTは「ケースのうち一つだけを取る」型です。

## データを持たないケースを使う

`Red`と`Green`は、データを持たないケースです。ケース名を書くだけで値になります。

```seseragi title="値の束縛の構文例"
let red: Light = Red
let green: Light = Green
```

ケースは違っても、どちらも型は`Light`です。ケースによって処理を変える方法は、次の章で学びます。

## ケースにデータを持たせる

ケースにはデータを持たせられます。次の`Reading`は測定結果を表す型で、「まだ測っていない」ケースはデータを持たず、「測定済み」のケースは測った値を整数で持ちます。

```seseragi title="payloadを持つ型の構文例"
type Reading =
  | NoReading
  | Measured Int
```

`NoReading`は、それだけで`Reading`の値です。`Measured`は整数を一つ受け取って`Reading`の値を作る関数で、コンストラクターと呼びます。ケースが持つデータは、ペイロードと呼びます。

```seseragi title="値の束縛の構文例"
let absent: Reading = NoReading
let measured: Reading = Measured 23
```

`Measured "warm"`のように整数以外を渡すと、型エラーになります。また`Measured`とだけ書いたものは、まだ整数を待っている関数で、`Reading`の値ではありません。

## 複数の値を持つケース

一つのケースに複数の値を持たせたいときは、タプルを使います。次の`Rectangle`は、幅と高さの二つの整数を持ちます。

{/* example: examples/learn/focused/adt-tuple-payload.ssrg#declaration */}
```seseragi title="型の宣言"
type Shape =
  | Circle Int
  | Rectangle (Int, Int)
```

値を作るときは`Rectangle (3, 4)`と書きます。`(3, 4)`は二つの整数をまとめた一つのタプルで、`Rectangle`はそのタプルを一つ受け取ります。`Rectangle 3 4`とは書けません。

{/* example: examples/learn/focused/adt-tuple-payload.ssrg#value */}
```seseragi title="main内の束縛"
let rectangle: Shape =
  Rectangle (3, 4)
```

フィールドに名前を付けたいときは、前の章のstructをペイロードにします。ADTで「どの状態か」を表し、structで「その状態が持つデータ」を表す、という組み合わせです。

### structをペイロードにする

ログインしているときだけアカウント情報を持つ型を考えます。まず、アカウント情報をstructで定義します。

{/* example: examples/learn/focused/adt-struct-payload.ssrg#data */}
```seseragi title="structの宣言"
struct Account {
  name: String,
}
```

次に、ログイン状態を表す型を定義します。

{/* example: examples/learn/focused/adt-struct-payload.ssrg#declaration */}
```seseragi title="型の宣言"
type Session =
  | Guest
  | SignedIn Account
```

`Guest`はアカウント情報なしで作れますが、`SignedIn`を作るには`Account`が必ず要ります。「ログインしているのにアカウント情報がない」状態は、そもそも作れません。

{/* example: examples/learn/focused/adt-struct-payload.ssrg#value */}
```seseragi title="main内の束縛"
let session: Session =
  SignedIn (Account { name: "Aki" })
```

`Account { ... }`を括弧で囲んで一つの引数にし、`SignedIn`に渡しています。ケースを見分けてアカウント情報を取り出す方法は、次の章で学びます。

## 型の名前と入力の条件

ADTもstructと同じく、名前で区別される型です。ケースの名前や形がまったく同じ別の型があっても、自動では変換されません。変換が必要なら、関数を書きます。

また、型が決めるのはペイロードの型までです。この`Reading`では、23も−1も`Measured`に渡せます。「測定値は0以上」のような条件は、値を作る関数の中で確かめます。

## ケースごとの処理へ進む

この章では、どんな値を作れるかを型で決めました。値を受け取った側でケースを見分け、ペイロードを取り出すには`match`を使います。

試しに、`Light`の宣言に`Yellow`を足してみてください。`Yellow`も`Light`の値として使えるようになります。`Reading`では、`Measured 23`を`NoReading`に変えても、型はどちらも`Reading`のままです。

型の宣言の書き方は[データ型リファレンス](/docs/reference/data-types)にまとめています。次の[パターンマッチ](/docs/learn/pattern-matching)では、ケースごとに処理を分け、`Reading`のペイロードを取り出します。
