プログラムが大きくなったら、ファイルを分けます。Seseragiでは、一つの`.ssrg`ファイルが一つのモジュールです。この章では、荷物の配送状況を表す型と関数を`parcel.ssrg`に置き、`main.ssrg`から使います。複数のファイルは、パッケージとしてまとめて実行します。

この章のコードでは、[パイプライン](/docs/learn/pipelines)の`|>`、[代数的データ型](/docs/learn/algebraic-data-types)、[パターンマッチ](/docs/learn/pattern-matching)の`match`を使います。

## ファイルの役割を分ける

新しいディレクトリに、次のようにファイルを作ります。

```text
parcel-app/
  seseragi.toml
  src/
    main.ssrg
    parcel.ssrg
```

`parcel.ssrg`には配送の型と関数を、`main.ssrg`にはプログラムの入口を書きます。`src`の下のファイルの位置が、そのままモジュールの場所になります。ファイルの中でモジュール名を宣言する必要はありません。

## 型と関数を公開する

`src/parcel.ssrg`に、次の内容を保存します。

{/* example: examples/learn/modules/src/parcel.ssrg */}
```seseragi title="parcel.ssrg"
pub type Parcel =
  | Packing
  | Sent String

pub fn label parcel: Parcel -> String =
  match parcel {
    Packing -> "Preparing"
    Sent city -> `Sent to ${city}`
  }
```

何も付けない宣言は、そのファイルの中だけで使えます。ほかのファイルから使わせたい型や関数には`pub`を付けます。`pub type`で公開した`Parcel`は、`Packing`と`Sent`というケースも一緒に公開されます。

なお、ファイルをimportしただけで何かが実行されることはありません。

## 名前をimportする

`src/main.ssrg`に、次の内容を保存します。

{/* example: examples/learn/modules/src/main.ssrg */}
```seseragi title="main.ssrg"
import { label, Sent } from "./parcel"

pub effect fn main =
  Sent "Kyoto"
  |> label
  |> println
```

`import { label, Sent } from "./parcel"`は、`parcel.ssrg`が公開している名前のうち、`label`と`Sent`を使えるようにします。書き方はTypeScriptとほぼ同じです。`"./parcel"`は、このファイルと同じディレクトリの`parcel.ssrg`を指します。TypeScriptと違い、`index`ファイルや別の拡張子を探すことはありません。

名前がぶつかるときは、`import { label as parcelLabel } from "./parcel"`のように別名を付けられます。`import * as parcels from "./parcel"`と書くと、`parcels.label`や`parcels.Sent`のように使えます。importはファイルの先頭に書きます。

## seseragi.tomlで入口を指定する

最後に、パッケージの設定ファイル`seseragi.toml`を作ります。`[run]`の`entry`で、どのモジュールから実行するかを指定します。

```toml title="seseragi.toml"
[package]
name = "docs/learn-modules"
version = "0.0.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"
```

`parcel-app`に移動して、ロックファイルを作ってから実行します。

```sh
seseragi lock update .
seseragi run .
```

```text title="実行結果"
Sent to Kyoto
```

一つ目のコマンドで`seseragi.lock`ができます。`seseragi run .`のようにディレクトリを渡すと、`seseragi.toml`とロックファイルを読んで、パッケージとして実行します。設定ファイルの書き方は[プロジェクト設定](/docs/reference/project-configuration)にあります。

## 公開範囲と依存関係

型の中身を外から見せたくないときは、`pub opaque struct`や`pub opaque type`を使います。型の名前だけが公開され、中身には公開した関数を通してしかアクセスできなくなります。

importのパスは、`self/`で始まれば自分のパッケージ、`std/`で始まれば標準ライブラリ、それ以外は`seseragi.toml`に書いた依存パッケージを指します。相対パスでパッケージの外に出たり、依存パッケージの公開されていないファイルを直接importしたりはできません。

モジュールどうしが互いにimportし合うことはできません。そうなりそうなときは、共通の型を三つ目のモジュールに分けて、依存の向きを一方向にします。

## 公開APIを変えてみる

ファイルを変えたら、`seseragi lock update .`でロックファイルを更新してから`seseragi run .`で実行します。

まず、`label`の`pub`を外してみてください。`main.ssrg`のimportがエラーになります。`pub`を戻したら、`main`の`Sent "Kyoto"`を`Packing`に変え、importにも`Packing`を足します。`Preparing`と表示されれば成功です。

「学ぶ」はここまでです。お疲れさまでした。次は[CLIアプリ](/docs/guides/cli-app)や[Webアプリ](/docs/guides/web-app)のガイドで、入力や画面のあるアプリを作ってみてください。モジュールの細かい決まりは[モジュールリファレンス](/docs/reference/modules)、パッケージの依存関係と公開の仕方は[パッケージとデプロイ](/docs/guides/packages-and-deployment)にあります。
