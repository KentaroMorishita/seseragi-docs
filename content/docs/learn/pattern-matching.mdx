`match`は、値の形に応じて結果を選ぶ式です。TypeScriptの`switch`に似ていますが、値を返す式であることと、ケースの中のデータを取り出せることが違います。まずBoolで分岐し、そのあと前の章の[代数的データ型](/docs/learn/algebraic-data-types)からデータを取り出します。

この章のコードでは、[パイプライン](/docs/learn/pipelines)の`|>`、[レコードとstruct](/docs/learn/records-and-structs)を使います。

## 二つの値で分岐する

次の関数は、`True`なら`"enabled"`、`False`なら`"disabled"`を返します。

{/* example: examples/learn/pattern-matching.ssrg */}
```seseragi title="pattern-matching.ssrg"
fn label enabled: Bool -> String =
  match enabled {
    True -> "enabled"
    False -> "disabled"
  }

pub effect fn main =
  True
  |> label
  |> println
```

```text title="実行結果"
enabled
```

`match`は、矢印`->`の左に書いたパターンを上から順に試し、最初に一致した分岐の右側を結果にします。

どの分岐も同じ型の値を返す必要があり、ここではどちらも`String`です。`True`と`False`の両方を扱っているので、どんなBoolを渡しても結果が返ります。

## ケースのデータに名前を付ける

前の章の`Reading`を使います。`NoReading`はデータを持たず、`Measured`は整数を一つ持つのでした。`match`では、ケースを見分けるのと同時に、その整数に名前を付けて取り出せます。

{/* example: examples/learn/pattern-payloads.ssrg */}
```seseragi title="pattern-payloads.ssrg"
type Reading =
  | NoReading
  | Measured Int

fn label reading: Reading -> String =
  match reading {
    NoReading -> "No reading"
    Measured n -> `Reading: ${n}`
  }

pub effect fn main =
  Measured 23
  |> label
  |> println
```

```text title="実行結果"
Reading: 23
```

`Measured n`は、値が`Measured`のときに一致し、中の整数を`n`という名前で取り出します。`n`はその分岐の中だけで使えます。`main`の`Measured 23`は値を「作る」書き方、分岐の`Measured n`は値を「分解する」書き方で、同じ形でも役割は逆です。

TypeScriptでは、`reading.kind === "measured"`を確かめてから`reading.value`を読む、という手順を自分で書きます。`match`では、ケースの確認とデータの取り出しが一つになっているので、確認を忘れてデータを読んでしまうことがありません。

## 残りの値を_で扱う

整数のように値が無数にある型では、全部を列挙できません。特定の値を書いたあとに、「それ以外」を受ける分岐を置きます。

```seseragi
match number {
  0 -> "zero"
  _ -> "nonzero"
}
```

`_`はどんな値にも一致するパターンです。`_`の代わりに`n`のような名前を書くと、どんな値にも一致したうえで、その値に名前が付きます。

注意したいのは、名前を書いても外側にある同じ名前の変数との比較にはならないことです。特定の値と比べたいときは、`0`のようなリテラルを書くか、次のガードを使います。

## ガードで条件を足す

パターンの後ろに`when`で条件を付けられます。これをガードと呼びます。パターンが一致し、さらに条件も`True`のときだけ、その分岐が選ばれます。

```seseragi
match number {
  n when n > 0 -> "positive"
  _ -> "zero or negative"
}
```

条件が`False`なら、次の分岐に進みます。コンパイラはガードの条件の中身までは見ないので、条件に当てはまらなかった値を受ける分岐も必ず書きます。

正・ゼロ・負を見分ける関数にしてみます。

{/* example: examples/learn/focused/pattern-guard.ssrg#declaration */}
```seseragi title="関数の宣言"
fn sign number: Int -> String =
  match number {
    n when n > 0 -> "positive"
    0 -> "zero"
    _ -> "negative"
  }
```


{/* example: examples/learn/focused/pattern-guard.ssrg#inputs */}
```seseragi title="main内の束縛"
let negative = sign (-1)
let zero = sign 0
let positive = sign 1
```

結果は順に`negative`、`zero`、`positive`です。−1は最初の条件にも`0`にも当てはまらないので、最後の分岐に進みます。

### レコードのフィールドを調べる

レコードもパターンに使えます。次の関数は、`online`と`name`を持つレコードを受け取ります。

{/* example: examples/learn/focused/pattern-record.ssrg#declaration */}
```seseragi title="関数の宣言"
fn caption value: {
  online: Bool,
  name: String,
} -> String =
  match value {
    { online: True, name } -> name
    _ -> "offline"
  }
```

`online`が`True`のときだけ名前を取り出し、それ以外は`offline`を返します。`main`で`let user = { online: True, name: "Aki" }`を用意して、次のように呼び出します。

{/* example: examples/learn/focused/pattern-record.ssrg#use */}
```seseragi title="main内の式"
user
|> caption
|> println
```

`Aki`と表示されます。`online`を`False`にすると`offline`になります。フィールドの値を確かめることと、別のフィールドを取り出すことを、一つのパターンでまとめて書けます。

## タプルとガードを組み合わせる

ここまでのパターンとガードを組み合わせて、座標がどこにあるかを判定します。タプルは、複数の値を順番付きでまとめた値です。`(3, 0)`は二つの整数のタプルで、`describe`はこのタプルを一つの引数として受け取ります。

{/* example: examples/learn/pattern-tuples.ssrg */}
```seseragi title="pattern-tuples.ssrg"
fn describe point: (Int, Int)
  -> String =
  match point {
    (0, 0) -> "origin"
    (x, 0) when x > 0 -> "east"
    (_, 0) -> "horizontal axis"
    (0, _) -> "vertical axis"
    _ -> "off the axes"
  }

pub effect fn main =
  (3, 0)
  |> describe
  |> println
```

```text title="実行結果"
east
```

`(0, 0)`は、二つとも0のときに一致します。`(x, 0)`は、二つ目が0のときに一致し、一つ目に`x`という名前を付けます。ガードで`x > 0`に絞っているので、その次の`(_, 0)`が受けるのは、横軸上で0より左にある点です。

`(3, 0)`の括弧はタプルを作るためのもので、関数呼び出しの括弧ではありません。

## 網羅性と失敗しない分解

`match`は、どんな値が来ても必ずどれかの分岐に当てはまるように書く必要があります。Boolなら`True`と`False`、ADTならすべてのケースです。扱っていないケースがあると、実行する前にコンパイラが教えてくれます。ADTにあとからケースを足したときも、対応を忘れた`match`をすべて見つけてくれます。

逆に、絶対に選ばれない分岐もエラーになります。座標の例で最後の`_`を先頭に移すと、それより下の分岐は選ばれなくなるので、エラーになります。

`let`でもパターンを使えますが、必ず一致するパターンに限られます。`let (x, y) = point`は、タプルなら必ず分解できるので書けます。`let (0, y) = point`は、一つ目が0でないと一致しないので書けません。`Reading`から`Measured n`だけを取り出したいときも、`NoReading`の場合を含めて`match`で書きます。

## 分岐を変えて確かめる

Boolの例で`main`の`True`を`False`に変えると、`disabled`が表示されます。そのあと`False`の分岐を消すと、扱っていないケースがあるというエラーが出ます。`Reading`の例では、`main`の値を`NoReading`にして、`No reading`が表示されることを確かめてください。

座標の例では、入力を変えて結果を比べてみましょう。

| 入力 | 出力 |
| --- | --- |
| `(0, 0)` | `origin` |
| `(-3, 0)` | `horizontal axis` |
| `(0, 4)` | `vertical axis` |
| `(2, 3)` | `off the axes` |
