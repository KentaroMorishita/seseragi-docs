---
title: ローカルで使う
description: CLIを導入してコードを実行し、Webアプリの開発とビルドを始める。
---

手元でSeseragiを使うには、CLIとBunの二つが必要です。インストールせずに試すだけなら、ブラウザで[Playground](https://seseragi.vercel.app/)を使えます。

## CLIとBunを導入する

[CLIのダウンロード](https://github.com/KentaroMorishita/seseragi/releases)ページから、使っているOSとCPUに合うアーカイブをダウンロードします。展開して出てくる`seseragi`を、PATHの通ったディレクトリに置いてください。エディター用のLSPも同じアーカイブに入っています。

Bunは[公式のインストール手順](https://bun.sh/docs/installation)に従って入れてください。配布されているCLIを使うなら、Rustは要りません。

ターミナルで次の二つを実行し、どちらもバージョンが表示されれば準備完了です。

```sh
seseragi --version
bun --version
```

## ソースファイルを実行する

[最初のプログラム](/docs/learn/first-program#一行を表示する)のコードを`hello.ssrg`に保存し、そのディレクトリで実行します。

```sh
seseragi run hello.ssrg
```

次の一行が表示されます。

```text
Hello, Seseragi!
```

## VS Codeで編集する

CLIと同じダウンロードページに、VS Code拡張のVSIXファイルもあります。OSとCPUに合うものをダウンロードし、VS Codeのコマンドパレットで「Extensions: Install from VSIX...」を実行して、そのファイルを選んでください。

VSIXにはLSPも入っているので、ほかに何かをインストールする必要はありません。

## Webアプリを作る

次のコマンドで、新しいWebアプリのプロジェクトを作ります。`hello-web`というディレクトリがまだない場所で実行してください。

```sh
seseragi new web hello-web
cd hello-web
```

`seseragi.toml`、`seseragi.lock`、`src/app.ssrg`、`src/main.ssrg`が作られます。アプリの状態と画面は`app.ssrg`に、それをブラウザのページに表示する処理は`main.ssrg`に書かれています。

## ブラウザで開発する

プロジェクトのディレクトリで開発サーバーを起動します。

```sh
seseragi dev --open
```

ブラウザで`http://127.0.0.1:3000/`が開きます。ソースを保存するたびに自動でビルドし直され、ブラウザも再読み込みされます。

## 公開用にビルドする

開発サーバーを`Ctrl-C`で止めてから、同じディレクトリでビルドします。

```sh
seseragi build .
```

`dist/`に、HTML・JavaScript・CSSなどの静的ファイルができます。公開するときは、このディレクトリの中身を静的サイトとして置くだけです。

## 依存関係を変更したとき

`seseragi.lock`は、プロジェクトが使うパッケージや設定を固定するファイルです。依存関係や`seseragi.toml`の設定を変えたとき、また依存しているパッケージが公開するコードを変えたときは、次のコマンドで更新してください。

```sh
seseragi lock update
```

ロックファイルがなかったり、設定と食い違っていたりすると、`run`・`dev`・`build`は`SES-K0102`というエラーで止まります。意図しない変更が紛れ込まないように、ロックファイルは自動では更新されません。エラーが出たら、何が変わったかを確かめてから更新してください。
