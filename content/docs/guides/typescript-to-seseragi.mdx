TypeScriptでいつも書いているコードと並べながら、Seseragiの関数・データ・副作用・Web UIの書き方を見ていきます。同じ結果になる例がほとんどですが、数値の扱いや副作用が実行されるタイミングのように、振る舞いが違うところもあります。そうした違いも一緒に確かめます。

`main`を含む例は、見出しのファイル名で保存して`seseragi run ファイル名.ssrg`で実行できます。CLIの準備は[ローカルで使う](/docs/learn/local-development)を見てください。

TypeScriptの例は、すべて`strict`で型チェックし、Node.jsで実行して出力を確かめています。

## 数値を関数へ渡す

関数の呼び出し方だけを、整数を二倍にする例で比べます。

{/* example: examples/guides/migration-typescript/call.ts#example */}

```typescript title="call.ts"
function double(value: number) {
  return value * 2;
}
console.log(double(21));
```

Seseragiでは`fn`で関数を定義します。`n: Int`が引数、最後の`Int`が結果の型です。呼び出すときは括弧を使わず、`double 21`のように関数名の後ろに空白を空けて引数を書きます。

`printValue`は値をそのまま表示する関数です。`main`はプログラムの入口で、出力を行うので`pub effect fn`で定義します。

{/* example: examples/guides/migration.ssrg */}

```seseragi title="migration.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = {
  let answer = double 21
  printValue answer
}
```

出力

```text
42
```

どちらも42です。Seseragiの`let`はTypeScriptの`const`にあたり、あとから別の値を代入することはできません。

`printValue`は末尾に改行を付けません。後の例で複数の結果を一行ずつ表示するときは、文字列を受け取る`println`を使います。数値などは`show`で文字列に変換できます。

## numberをIntとFloatに分けて考える

TypeScriptでは、次の二つの計算はどちらも`number`です。[TypeScript Handbookの基本型](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)には、整数用と小数用で別の型を持たないことが説明されています。

{/* example: examples/guides/migration-typescript/numeric.ts#example */}

```typescript title="numeric.ts"
const whole: number = 5 / 2;
const fraction: number = 5.0 / 2.0;
console.log(`${whole}, ${fraction}`);
```

出力

```text
2.5, 2.5
```

Seseragiでは、整数は`Int`、小数は`Float`という別の型です。整数どうしの割り算は、結果の小数部分を切り捨てます（0に近いほうへ丸めるので、`-5 / 2`は`-2`です）。

{/* example: examples/guides/migration-numeric.ssrg */}

```seseragi title="migration-numeric.ssrg"
pub effect fn main = {
  let whole: Int = 5 / 2
  let fraction: Float = 5.0 / 2.0
  println `${whole}, ${fraction}`
}
```

出力

```text
2, 2.5
```

`5`は`Int`、`5.0`は`Float`と推論されるので、この例の型は書かなくても構いません。`Int`と`Float`が自動で変換されることはなく、変換するときは関数を使います。

また、`Float`は`==`や`>`で直接比べられません。比べるときは、`ieeeEq`や`totalCompare`など、[Floatの関数](/docs/reference/library/float)から目的に合うものを選びます。

TypeScriptの`number`を、何でも`Int`に置き換えればいいわけではありません。`.d.ts`から型を取り込むとき、`number`はまず`Float`になります。`Int`にするのは、整数で、しかも安全な範囲に収まると分かっている場合だけです。詳しくは[TypeScriptと連携する](/docs/guides/typescript-bindings)と[型](/docs/reference/types)にあります。

## 括弧で引数の式をまとめる

括弧の役割を、二つの結果を並べて確認します。

{/* example: examples/guides/migration-typescript/grouping.ts#example */}

```typescript title="grouping.ts"
function double(value: number) {
  return value * 2;
}
const outside = double(20) + 1;
const grouped = double(20 + 1);
console.log(
  `${outside}, ${grouped}`,
);
```

Seseragiでも、関数を適用する部分と足し算をする部分で結果が変わります。

{/* example: examples/guides/migration-grouping.ssrg */}

```seseragi title="migration-grouping.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = {
  let outside = double 20 + 1
  let grouped = double (20 + 1)
  println `${outside}, ${grouped}`
}
```

出力

```text
41, 42
```

`double 20 + 1`は、20を二倍にした結果へ1を足します。`double (20 + 1)`は、先に足した21を二倍にします。

Seseragiの括弧は、引数に渡す式をひとまとめにするためのもので、関数呼び出しの記号ではありません。関数は空白で呼び出し、式をまとめたいところにだけ括弧を書く、と考えてください。

## 引数を一つずつ受け取る

TypeScriptで二つの引数を取る関数は、よく次の形になります。

{/* example: examples/guides/migration-typescript/arguments.ts#example */}

```typescript title="arguments.ts"
function add(x: number, y: number) {
  return x + y;
}
console.log(add(20, 22));
```

Seseragiでは、各引数を`->`で区切ります。呼び出すときは`add 20 22`です。

{/* example: examples/guides/migration-arguments.ssrg */}

```seseragi title="migration-arguments.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

pub effect fn main =
  printValue (add 20 22)
```

出力

```text
42
```

`Int -> Int -> Int`は、「`Int`を受け取って、『`Int`を受け取って`Int`を返す関数』を返す」という型です。そのため、`add 20`のように引数を一つだけ渡すと、残りの引数を待つ関数になります。

TypeScriptで同じ形にするなら、関数を返す関数として書きます。

{/* example: examples/guides/migration-typescript/partial.ts#example */}

```typescript title="partial.ts"
const add = (x: number) =>
  (y: number) => x + y;

const addTwenty = add(20);
console.log(addTwenty(22));
```

Seseragiでは、何も工夫しなくても、引数を一部だけ渡せます（部分適用）。

{/* example: examples/guides/migration-partial.ssrg */}

```seseragi title="migration-partial.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

pub effect fn main = {
  let addTwenty = add 20
  let answer = addTwenty 22
  printValue answer
}
```

出力

```text
42
```

`addTwenty`の型は`Int -> Int`です。なお、TypeScriptの癖で`add (20, 22)`と書くと、二つの引数ではなく`(20, 22)`という一つのタプルを渡すことになり、型エラーになります。

[関数](/docs/learn/functions)と[パイプライン](/docs/learn/pipelines)で、適用する順番と関数の型を練習できます。

## 名前のない関数を渡す

TypeScriptのアロー関数に対応する、Seseragiのラムダ式を見ます。

{/* example: examples/guides/migration-typescript/lambda.ts#example */}

```typescript title="lambda.ts"
console.log(
  [1, 2, 3].map((n) => n * 2),
);
```

Seseragiでは`\n: Int -> n * 2`が、その場で作る関数です。先頭の`\`の後ろに引数を書きます。

{/* example: examples/guides/migration-lambda.ssrg */}

```seseragi title="migration-lambda.ssrg"
pub effect fn main =
  [1, 2, 3]
  |> map (\n: Int -> n * 2)
  |> show
  |> println
```

どちらも各要素を二倍にします。Node.jsの配列表示には要素の周囲に空白が入りますが、得られる要素は同じです。Seseragiの出力は次のとおりです。

出力

```text
[2, 4, 6]
```

短い処理を一度だけ使うならラムダ式が便利です。複数の場所で使う処理や、名前で意味を伝えたい処理は、次の例の`double`のように関数として定義します。

## メソッドの連続をパイプラインにする

まず、一段の変換を比べます。

{/* example: examples/guides/migration-typescript/pipeline.ts#example */}

```typescript title="pipeline.ts"
function double(value: number) {
  return value * 2;
}
console.log([1, 2, 3].map(double));
```

Seseragiの`|>`は、左の値を右の関数へ渡します。`map double`は配列を待つ関数で、前の節と同じ部分適用です。

{/* example: examples/guides/migration-pipeline.ssrg */}

```seseragi title="migration-pipeline.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main =
  [1, 2, 3]
  |> map double
  |> printValue
```

出力

```text
[2, 4, 6]
```

次は、1より大きい数を残してから二倍にします。

{/* example: examples/guides/migration-typescript/steps.ts#example */}

```typescript title="steps.ts"
function double(value: number) {
  return value * 2;
}
console.log(
  [1, 2, 3]
    .filter((n) => n > 1)
    .map(double),
);
```

Seseragiでは入力と各段階を縦に並べます。`map`はpreludeから使えますが、この`filter`は`std/array`から読み込みます。

{/* example: examples/guides/migration-steps.ssrg */}

```seseragi title="migration-steps.ssrg"
import * as arrays from "std/array"

fn double n: Int -> Int = n * 2
fn keep n: Int -> Bool = n > 1

pub effect fn main =
  [1, 2, 3]
  |> arrays.filter keep
  |> map double
  |> show
  |> println
```

出力

```text
[4, 6]
```

最初の段階は要素を選び、次の段階は残った要素を変換します。どちらも元の配列を変更しません。操作ごとの使い分けは[配列とList](/docs/learn/arrays-and-lists)で扱います。

## 条件分岐の結果を値として使う

TypeScriptで、条件に応じて文字列を返す例です。

{/* example: examples/guides/migration-typescript/condition.ts#example */}

```typescript title="condition.ts"
function result(score: number) {
  return score >= 70
    ? "pass"
    : "retry";
}
console.log(result(82));
console.log(result(65));
```

Seseragiの`if`は式です。`then`と`else`のどちらかの値が、そのまま関数の結果になります。

{/* example: examples/guides/migration-condition.ssrg */}

```seseragi title="migration-condition.ssrg"
fn result score: Int -> String =
  if score >= 70 then
    "pass"
  else
    "retry"

pub effect fn main = do {
  println (result 82)
  println (result 65)
}
```

出力

```text
pass
retry
```

二つの分岐は同じ型でなければなりません。この例ではどちらも`String`です。TypeScriptの三項演算子`? :`に近く、`let`で変数を用意して分岐ごとに代入する、という書き方は要りません。

この例の`main`は、複数の出力を順に実行するために`do { ... }`を使っています。`do`のない普通の`{ ... }`は最後の式を返すブロックで、中のEffectを順に実行するわけではありません。この違いは[値と式](/docs/learn/values-and-expressions)と[Effect](/docs/learn/effects)で詳しく扱います。

## レコードのフィールドを読む

名前の付いた値をまとめ、ドットで取り出す点は似ています。

{/* example: examples/guides/migration-typescript/record.ts#example */}

```typescript title="record.ts"
const point = { x: 3, y: 4 };
console.log(point.x);
```

{/* example: examples/guides/migration-record.ssrg */}

```seseragi title="migration-record.ssrg"
pub effect fn main = {
  let point = { x: 3, y: 4 }
  printValue point.x
}
```

出力

```text
3
```

Seseragiでは`{ x: 3, y: 4 }`がレコードです。レコードの型は、フィールドの名前と型で決まります。TypeScriptのオブジェクト型と同じく、形で判断されます。

## 更新後のレコードを新しく作る

TypeScriptの`const`は変数への再代入を防ぐだけで、オブジェクトの中身は書き換えられます。元の値を残すには、スプレッド構文でコピーを作ります。

{/* example: examples/guides/migration-typescript/immutable.ts#example */}

```typescript title="immutable.ts"
const base = { count: 1 };
const next = {
  ...base,
  count: base.count + 1,
};
console.log(
  `${base.count}, ${next.count}`,
);
```

Seseragiのレコードは、そもそも中身を書き換えられません。同じスプレッド構文で、一部のフィールドだけが違う新しいレコードを作ります。

{/* example: examples/guides/migration-immutable.ssrg */}

```seseragi title="migration-immutable.ssrg"
pub effect fn main = {
  let base = { count: 1 }
  let next = {
    ...base,
    count: base.count + 1
  }
  let report =
    `${base.count}, ${next.count}`
  println report
}
```

出力

```text
1, 2
```

`next`の`count`は2で、`base`は1のままです。[Reactでオブジェクトの状態を更新する](https://react.dev/learn/updating-objects-in-state)ときにコピーを作るのと同じ考え方で、Seseragiではそれが唯一の方法になっています。

## 型の別名とstructを区別する

TypeScriptでオブジェクトの形に名前を付ける例です。

{/* example: examples/guides/migration-typescript/alias.ts#example */}

```typescript title="alias.ts"
type Point = {
  x: number;
  y: number;
};

function horizontal(point: Point) {
  return point.x;
}
const point: Point = { x: 3, y: 4 };
console.log(horizontal(point));
```

Seseragiでレコード型に名前を付けるなら`alias`を使います。

{/* example: examples/guides/migration-alias.ssrg#declaration */}

```seseragi title="型と関数の宣言"
alias Point = { x: Int, y: Int }

fn horizontal point: Point -> Int =
  point.x
```

同じファイルの`main`内で、この形を持つレコードを渡します。

{/* example: examples/guides/migration-alias.ssrg#use */}

```seseragi title="main内の抜粋"
let point: Point = { x: 3, y: 4 }
printValue (horizontal point)
```

出力

```text
3
```

`alias`は名前を付けるだけなので、`alias Point`は同じフィールドを持つどんなレコードでも受け取ります。TypeScriptの`type`と同じ振る舞いです。

一方、Seseragiの`struct Point { ... }`は、名前で区別される型を作ります。フィールドがまったく同じでも、名前の違うstructとは別の型です。TypeScriptのオブジェクト型を移すときは、形で扱いたいならレコード、意味の違いで区別したいならstruct、と選んでください。具体例は[レコードとstruct](/docs/learn/records-and-structs)にあります。

## ユニオンをケースとmatchで扱う

ここからは、荷物の発送状態を表すデータで比べます。TypeScriptでは、`kind`のような目印のプロパティを持つユニオン型でケースを表せます。

{/* example: examples/guides/migration-typescript/data.ts#declaration */}

```typescript title="data.ts"
type Delivery =
  | { kind: "preparing" }
  | { kind: "sent"; city: string };
```

値を作ります。

{/* example: examples/guides/migration-typescript/data.ts#construct */}

```typescript title="data.ts"
const delivery: Delivery = {
  kind: "sent",
  city: "Kyoto",
};
```

`switch`でケースを確認すると、そのケースのデータを取り出せます。

{/* example: examples/guides/migration-typescript/data.ts#label */}

```typescript title="data.ts"
function label(value: Delivery) {
  switch (value.kind) {
    case "preparing":
      return "Preparing";
    case "sent":
      return value.city;
  }
}
```

Seseragiでは`Preparing`と`Sent String`がケースです。`Sent "Kyoto"`で、都市名を持つ`Sent`の値を作ります。目印のプロパティを自分で用意する必要はありません。

`match`でケースを分け、`Sent city`で都市名を取り出します。

{/* example: examples/guides/migration-data.ssrg */}

```seseragi title="migration-data.ssrg"
type Delivery =
  | Preparing
  | Sent String

fn label d: Delivery -> String =
  match d {
    Preparing -> "Preparing"
    Sent city -> city
  }

pub effect fn main = {
  let delivery = Sent "Kyoto"
  println (label delivery)
}
```

出力

```text
Kyoto
```

TypeScript側も`label(delivery)`で`Kyoto`を返します。違うのは、ケースの扱い漏れです。Seseragiの`match`は、扱っていないケースがあるとコンパイルエラーになります。

ケースの定義は[代数的データ型](/docs/learn/algebraic-data-types)、値の取り出し方は[パターンマッチ](/docs/learn/pattern-matching)で詳しく扱います。

## 値の不在をMaybeで表す

TypeScriptでは、ないかもしれない値を`string | undefined`などで表します。次は、名前がないときだけ`Guest`を返す関数です。

{/* example: examples/guides/migration-typescript/maybe.ts#name */}

```typescript title="maybe.ts"
function name(
  value: string | undefined,
): string {
  return value ?? "Guest";
}
```

Seseragiでは`Maybe<String>`を使います。値がある`Just`か、値がない`Nothing`のどちらかです。

{/* example: examples/guides/migration-maybe.ssrg#name */}

```seseragi title="Maybeを受け取る関数"
fn name value: Maybe<String>
  -> String =
  value ?? "Guest"
```

どちらの`??`も、値がないときだけ右側を使います。空文字列は「値がある」ので、そのまま返ります。

三つの入力で比べてみます。空文字列も見えるように、表示するときだけ角括弧で囲んでいます。

{/* example: examples/guides/migration-typescript/maybe.ts#inputs */}

```typescript title="maybe.ts"
console.log(`[${name("Ada")}]`);
console.log(`[${name(undefined)}]`);
console.log(`[${name("")}]`);
```

Seseragiでは、次のように書きます。

{/* example: examples/guides/migration-maybe.ssrg#inputs */}

```seseragi title="main内の抜粋"
let present = name (Just "Ada")
let absent = name Nothing
let empty = name (Just "")
println ("[" + present + "]")
println ("[" + absent + "]")
println ("[" + empty + "]")
```

出力

```text
[Ada]
[Guest]
[]
```

`Just ""`と`Nothing`は別物です。空文字列も受け付けたくない場合は、値がないときの処理とは別に検証します。

## Maybeの中身だけを変換する

値があるときだけ二倍にする関数で比べます。

{/* example: examples/guides/migration-typescript/maybe-map.ts#example */}

```typescript title="maybe-map.ts"
const double = (n: number) => n * 2;
function doublePresent(
  value: number | undefined,
) {
  return value === undefined
    ? undefined
    : double(value);
}
console.log(doublePresent(21));
console.log(
  doublePresent(undefined),
);
```

出力は21に対して42、不在に対して`undefined`です。Seseragiでは`map`が同じ役割を持ちます。

{/* example: examples/guides/migration-maybe-map.ssrg */}

```seseragi title="migration-maybe-map.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = do {
  Just 21
  |> map double
  |> show
  |> println
  let absent: Maybe<Int> =
    Nothing
    |> map double
  absent
  |> show
  |> println
}
```

出力

```text
Just 42
Nothing
```

`map double`は`Just`の中身だけを変換し、`Nothing`はそのまま返します。TypeScriptのように`if`で値の有無を確かめる必要はありません。（`Nothing`だけでは中身の型が分からないので、`Maybe<Int>`と型を書いています。）

この`map`は、配列の`map`と同じ関数です。どちらも「入れ物の中身を変換する」操作だからです。この仕組みは[型クラス](/docs/learn/type-classes)、値がない場合の扱いは[MaybeとEither](/docs/learn/maybe-and-either)で詳しく学べます。

## 理由のある失敗をEitherで表す

名前が空なら失敗の理由を、そうでなければ成功の値を返す例です。TypeScriptでは、成功と失敗をユニオン型で表せます。

{/* example: examples/guides/migration-typescript/either.ts#validate */}

```typescript title="either.ts"
type NameResult =
  | { ok: true; value: string }
  | { ok: false; error: string };

function validate(
  text: string,
): NameResult {
  if (text === "") {
    return {
      ok: false,
      error: "Enter a name",
    };
  }
  return { ok: true, value: text };
}
```

Seseragiでは`Either<String, String>`を使います。一つ目の型が失敗の理由、二つ目の型が成功の値で、ここではどちらも文字列です。

{/* example: examples/guides/migration-either.ssrg#validate */}

```seseragi title="検証する関数"
fn validate text: String
  -> Either<String, String> =
  if text == "" then
    Left "Enter a name"
  else
    Right text
```

結果を表示用の文字列にする関数も作ります。

{/* example: examples/guides/migration-typescript/either.ts#report */}

```typescript title="either.ts"
function report(value: NameResult) {
  return value.ok
    ? `Hello, ${value.value}`
    : value.error;
}
```

{/* example: examples/guides/migration-either.ssrg#report */}

```seseragi title="結果を表示する関数"
fn report r: Either<String, String>
  -> String =
  match r {
    Right name -> `Hello, ${name}`
    Left error -> error
  }
```

`"Ada"`の検証は成功、`""`は失敗です。失敗も例外ではなく普通の値なので、`match`でケースごとに処理できます。

{/* example: examples/guides/migration-either.ssrg#cases */}

```seseragi title="main内の抜粋"
validate "Ada"
|> report
|> println
validate ""
|> report
|> println
```

出力

```text
Hello, Ada
Enter a name
```

TypeScriptでも`report(validate("Ada"))`と`report(validate(""))`で同じ二つの文字列を得られます。

`Either`は、すでに計算し終わった結果を表す値です。非同期の処理を始めたり、例外を投げたりはしません。そうした処理は、次に見るEffectで表します。[失敗を扱う](/docs/guides/error-handling)では、`Either`による検証とEffectの失敗の扱いを組み合わせます。

## PromiseとEffectの実行時点を比べる

TypeScriptの`async`関数も、Seseragiの`effect fn`も、副作用のある処理に名前を付けたものです。ただし、処理がいつ実行されるかが違います。

次のTypeScriptの関数は、呼ばれるとすぐにメッセージを出力します。

{/* example: examples/guides/migration-typescript/effect.ts#announce */}

```typescript title="effect.ts"
async function announce(s: string) {
  console.log(s);
}
```

関数を呼んで、同じPromiseを二回`await`します。（単独のファイルで試すときは、上の宣言と合わせ、最後に`export {};`を足してください。）

{/* example: examples/guides/migration-typescript/effect.ts#execute */}

```typescript title="effect.ts"
const job = announce("ran");
console.log("constructed");
await job;
await job;
```

出力

```text
ran
constructed
```

`announce("ran")`を呼んだ瞬間に本体が動くので、`ran`が`constructed`より先に出力されます。同じPromiseを二回待っても、本体はもう実行されません。

Seseragiでは、`effect fn`を呼んでも「実行すると出力する処理」ができるだけで、まだ何も起こりません。

{/* example: examples/guides/migration-effect.ssrg#announce */}

```seseragi title="Effectを作る関数"
effect fn announce text: String =
  println text
```

`main`の`do`の中で、`let job`で処理を作り、そのあと`job`の行で実行します。

{/* example: examples/guides/migration-effect.ssrg#execute */}

```seseragi title="main内の抜粋"
let job = announce "ran"
println "constructed"
job
job
```

出力

```text
constructed
ran
ran
```

今度は`constructed`が先に出力されます。そして同じEffectを二回実行すると、出力も二回起きます。

実行した結果を何度も使いたいときは、`<-`で一度だけ実行して結果を受け取ります。次は、出力してから42を返す例です。

{/* example: examples/guides/migration-effect-result.ssrg */}

```seseragi title="migration-effect-result.ssrg"
import * as effects from "std/effect"

effect fn produce n: Int = do {
  println "ran"
  effects.succeed n
}

pub effect fn main = do {
  let job = produce 42
  answer <- job
  println `${answer}, ${answer}`
}
```

出力

```text
ran
42, 42
```

`answer <- job`で処理を一回実行し、結果の整数を`answer`で受け取ります。そのあとの二つの`answer`は整数を使い回しているだけなので、`ran`は一回しか出力されません。`<-`の代わりに`let answer = job`と書くと、処理そのものに名前が付くだけで、実行はされません。

Effectの型`Effect<R, E, A>`には、必要なもの`R`、失敗の型`E`、成功の型`A`の三つが入っています。成功の型しか分からない`Promise<A>`と違い、何を使い、どう失敗しうるかまで型で分かります。

| 扱いたいこと | Seseragiで使うもの |
| --- | --- |
| 引数から値を計算する | 通常の`fn` |
| 値が存在しないかもしれない | `Maybe<A>` |
| 得られた結果が成功か失敗か | `Either<E, A>` |
| 副作用のある処理を作り、あとで実行する | `Effect<R, E, A>` |

Effectの組み立て方と`do`は[Effect](/docs/learn/effects)、型の細かい決まりは[Effectリファレンス](/docs/reference/effects)にあります。

## Reactのpropsと表示する関数を比べる

まずは、状態もイベントも持たない部品で比べます。Reactでは、[props](https://react.dev/learn/passing-props-to-a-component)で親からコンポーネントに値を渡します。

{/* example: examples/guides/migration-typescript/react.tsx#badge */}

```tsx title="Reactのコンポーネント"
type BadgeProps = { label: string };

function Badge(props: BadgeProps) {
  return <span>{props.label}</span>;
}
```

Seseragiでは、propsを受け取ってHTMLを返す、普通の関数として書きます。JSXの代わりに`html`モジュールの関数を使います。

{/* example: examples/guides/migration-props.ssrg#badge */}

```seseragi title="HTMLを返す関数"
import * as html from "std/web/html"

alias BadgeProps = { label: String }

fn badge props: BadgeProps
  -> html.Html<Never> =
  html.span { children: props.label }
```

`Html<A>`の`A`は、その画面が発生させるイベント（Action）の型です。この部品はイベントを発生させないので`Html<Never>`です。`badge { label: "Ready" }`をHTMLの文字列にすると、次のようになります。

出力

```text
<span>Ready</span>
```

propsを読む点は似ていますが、Seseragiの`badge`自体はHTMLの値を作る純粋な関数です。DOMへ取り付ける処理は別に行います。[コンポーネント](/docs/guides/components)では、複数のpropsとエスケープを扱います。

なお、今のバージョンでは`Html<Never>`の部品を`Html<Action>`の画面にそのまま入れることはできません。画面に組み込む部品は、画面と同じAction型にそろえます。いろいろな画面で使い回したい部品は、Action型を[ジェネリクス](/docs/learn/generics)の型引数にして、`Html<A>`を返すようにします。

## 状態の更新を純粋な関数として比べる

Reactの[reducer](https://react.dev/learn/extracting-state-logic-into-a-reducer)は、今の状態とActionから次の状態を返す関数です。画面を作る前に、この関数だけを比べてみます。

{/* example: examples/guides/migration-typescript/update.ts#update */}

```typescript title="update.ts"
type Action =
  | { type: "increment" }
  | { type: "reset" };

function reducer(
  count: number,
  action: Action,
): number {
  switch (action.type) {
    case "increment":
      return count + 1;
    case "reset":
      return 0;
  }
}
```

Seseragiでも、次の状態を計算する`update`を作ります。ActionはADTで表すので、`match`で扱い漏れがあればコンパイラーが教えてくれます。引数の順番はAction、今の状態の順で、Reactのreducerとは逆なので注意してください。

{/* example: examples/guides/migration-update.ssrg#update */}

```seseragi title="状態を更新する宣言"
type Action =
  | Increment
  | Reset

fn update action: Action
  -> count: Int -> Int =
  match action {
    Increment -> count + 1
    Reset -> 0
  }
```

TypeScriptでは、次のように確かめられます。

{/* example: examples/guides/migration-typescript/update.ts#cases */}

```typescript title="update.ts"
console.log(reducer(
  0, { type: "increment" },
));
console.log(reducer(
  9, { type: "reset" },
));
```

Seseragiでは次のとおりです。

{/* example: examples/guides/migration-update.ssrg#cases */}

```seseragi title="main内の抜粋"
update Increment 0
|> show
|> println
update Reset 9
|> show
|> println
```

出力

```text
1
0
```

`Increment`は今の値に1を足し、`Reset`は今の値に関係なく0を返します。画面とつなぐ前に、更新の決まりだけを実行したりテストしたりできます。

## イベントと状態を画面へ接続する

Reactでは、`useReducer`でreducerを画面につなぎます。

{/* example: examples/guides/migration-typescript/react.tsx#events */}

```tsx title="Reactのイベントと状態"
function Counter() {
  const [count, dispatch] =
    useReducer(reducer, 0);
  const increment = () => {
    dispatch({ type: "increment" });
  };
  return (
    <button onClick={increment}>
      {count}
    </button>
  );
}
```

Reactでは、クリックされたときの関数の中で`dispatch`を呼びます。Seseragiでは、`onClick`にActionの値そのものを渡します。

{/* example: examples/guides/migration-web/src/main.ssrg#view */}

```seseragi title="Web用packageの表示関数"
fn view count: Int
  -> html.Html<Action> =
  html.button {
    buttonType: "button",
    onClick: Increment,
    children: `Count: ${count}`
  }
```

`view`は、カウントから`Html<Action>`を作るだけの関数です。`onClick: Increment`は「クリックされたら`Increment`を送る」という意味です。状態を書き換える処理は`view`には書かず、すべて`update`に任せます。

最後に、`main`で画面に取り付けます。`dom`は`std/web/dom`からimportします。

{/* example: examples/guides/migration-web/src/main.ssrg#mount */}

```seseragi title="Web用packageの入口"
pub effect fn main =
  dom.app {
    target: "#app",
    initial: 0,
    update,
    view
  }
```

`dom.app`は、`#app`の要素に画面を取り付け、状態0から始めます。クリックで送られたActionを`update`に渡して次の状態を作り、それを`view`に渡して画面を更新します。ボタンは最初`Count: 0`で、一回クリックすると`Count: 1`になります。

この例はブラウザで動かすWebアプリなので、`seseragi run`ではなくWeb用のパッケージとしてビルドします。手順は[Webアプリを作る](/docs/guides/web-app)を見てください。

`dom.app`は、状態の管理と画面の更新をまとめて引き受けます。部品ごとに状態を持たせる方法は[状態を持つ機能](/docs/guides/stateful-features)、入力をActionに変える例は[フォーム](/docs/guides/forms)で扱います。
