TypeScriptで使っている書き方と比べながら、Seseragiの関数、データ、副作用、Web UIを学びます。まず同じ入力で同じ結果になる例を読み、数値や副作用のように動作が異なるところも確認します。

本文のSeseragi例は<LanguageVersion />を対象にしています。`main`を含む例は、そのコードを掲載ファイル名で保存して`seseragi run ファイル名.ssrg`で実行できます。宣言や`main`内の抜粋、Web用packageは、その都度区別します。CLIの準備は[ローカルで使う](/docs/learn/local-development)を参照してください。

TypeScriptのプログラムは`strict`で型を確認し、Node.jsで出力も確認しています。ReactのTSXはコンポーネントの抜粋で、型チェックを行っています。SeseragiのWeb例はブラウザ向けにビルドします。

## 数値を関数へ渡す

関数の呼び出し方だけを、整数を二倍にする例で比べます。

{/* example: examples/guides/migration-typescript/call.ts#example */}

```typescript title="call.ts"
function double(value: number) {
  return value * 2;
}
console.log(double(21));
```

Seseragiの`fn`は関数を定義します。`n: Int`が引数、最後の`Int`が結果の型です。`double 21`は、空白の後ろに置いた21を引数として渡します。

整数の表示には`printValue`を使います。`main`はプログラムの入口で、出力を伴うため`pub effect fn`として定義します。

{/* example: examples/guides/migration.ssrg */}

```seseragi title="migration.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = {
  let answer = double 21
  printValue answer
}
```

出力

```text
42
```

どちらも42です。`let answer`は計算した値に名前を付ける束縛です。Seseragiの`let`は不変で、TypeScriptの`let`のような再代入はできません。

`printValue`は末尾に改行を付けません。後の例で複数の結果を一行ずつ表示するときは、文字列を受け取る`println`を使います。数値などは`show`で文字列に変換できます。

## numberをIntとFloatに分けて考える

TypeScriptでは、次の二つの計算はどちらも`number`です。[TypeScript Handbookの基本型](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)には、整数用と小数用で別の型を持たないことが説明されています。

{/* example: examples/guides/migration-typescript/numeric.ts#example */}

```typescript title="numeric.ts"
const whole: number = 5 / 2;
const fraction: number = 5.0 / 2.0;
console.log(`${whole}, ${fraction}`);
```

出力

```text
2.5, 2.5
```

Seseragiでは整数が`Int`、浮動小数点数が`Float`です。整数同士の除算では、結果を0方向へ丸めます。たとえば`-5 / 2`は`-2`です。

{/* example: examples/guides/migration-numeric.ssrg */}

```seseragi title="migration-numeric.ssrg"
pub effect fn main = {
  let whole: Int = 5 / 2
  let fraction: Float = 5.0 / 2.0
  println `${whole}, ${fraction}`
}
```

出力

```text
2, 2.5
```

`5`は`Int`、`5.0`は`Float`と推論されるので、この例の型注釈は省略できます。`Int`と`Float`の暗黙の変換はありません。必要な変換は明示します。

標準の定義では、`Float`の比較に`==`や`>`を直接使えません。浮動小数点数の比較には`ieeeEq`や`totalCompare`など、[Floatの関数](/docs/reference/library/float)から用途に合うものを選びます。

TypeScriptの`number`を一律に`Int`へ置き換えないでください。`.d.ts`との連携では`number`は既定で`Float`として取り込み、`Int`へ指定する場合は整数かどうかと安全な範囲を確認します。詳しくは[TypeScriptと連携する](/docs/guides/typescript-bindings)と[型](/docs/reference/types)を参照してください。

## 括弧で引数の式をまとめる

括弧の役割を、二つの結果を並べて確認します。

{/* example: examples/guides/migration-typescript/grouping.ts#example */}

```typescript title="grouping.ts"
function double(value: number) {
  return value * 2;
}
const outside = double(20) + 1;
const grouped = double(20 + 1);
console.log(
  `${outside}, ${grouped}`,
);
```

Seseragiでも、関数を適用する部分と足し算をする部分で結果が変わります。

{/* example: examples/guides/migration-grouping.ssrg */}

```seseragi title="migration-grouping.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = {
  let outside = double 20 + 1
  let grouped = double (20 + 1)
  println `${outside}, ${grouped}`
}
```

出力

```text
41, 42
```

`double 20 + 1`は、20を二倍にした結果へ1を足します。`double (20 + 1)`は、先に足した21を二倍にします。

Seseragiの括弧は、ここでは引数に渡す式をまとめています。関数呼び出しを示す記号ではありません。以降の例でも、まず空白による適用を読み、式をまとめる必要があるところに括弧が現れると考えてください。

## 引数を一つずつ受け取る

TypeScriptで二つの引数を取る関数は、よく次の形になります。

{/* example: examples/guides/migration-typescript/arguments.ts#example */}

```typescript title="arguments.ts"
function add(x: number, y: number) {
  return x + y;
}
console.log(add(20, 22));
```

Seseragiでは、各引数を`->`で区切ります。呼び出すときは`add 20 22`です。

{/* example: examples/guides/migration-arguments.ssrg */}

```seseragi title="migration-arguments.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

pub effect fn main =
  printValue (add 20 22)
```

出力

```text
42
```

`Int -> Int -> Int`は、`Int`を受け取り、次の`Int`を受け取る関数を返す型です。したがって`add 20`まで適用して、残りの引数を待つ関数を作れます。

TypeScriptで同じ形にするなら、関数を返す関数として書きます。

{/* example: examples/guides/migration-typescript/partial.ts#example */}

```typescript title="partial.ts"
const add = (x: number) =>
  (y: number) => x + y;

const addTwenty = add(20);
console.log(addTwenty(22));
```

Seseragiでは特別なラッパーを用意せずに部分適用できます。

{/* example: examples/guides/migration-partial.ssrg */}

```seseragi title="migration-partial.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

pub effect fn main = {
  let addTwenty = add 20
  let answer = addTwenty 22
  printValue answer
}
```

出力

```text
42
```

`addTwenty`の型は`Int -> Int`です。`add (20, 22)`と書くと、二つの引数を渡すことにはなりません。`(20, 22)`という一つのタプルを渡すため、上の`add`の型とは合いません。

[関数とパイプライン](/docs/learn/functions-and-pipelines)で、適用する順番と関数の型を練習できます。

## 名前のない関数を渡す

TypeScriptのアロー関数に対応する、Seseragiのラムダ式を見ます。

{/* example: examples/guides/migration-typescript/lambda.ts#example */}

```typescript title="lambda.ts"
console.log(
  [1, 2, 3].map((n) => n * 2),
);
```

Seseragiでは`\n: Int -> n * 2`が、その場で作る関数です。先頭の`\`の後ろに引数を書きます。

{/* example: examples/guides/migration-lambda.ssrg */}

```seseragi title="migration-lambda.ssrg"
pub effect fn main =
  [1, 2, 3]
  |> map (\n: Int -> n * 2)
  |> show
  |> println
```

どちらも各要素を二倍にします。Node.jsの配列表示には要素の周囲に空白が入りますが、得られる要素は同じです。Seseragiの出力は次のとおりです。

出力

```text
[2, 4, 6]
```

短い処理を一度だけ使うならラムダ式が便利です。複数の場所で使う処理や、名前で意味を伝えたい処理は、次の例の`double`のように関数として定義します。

## メソッドの連続をパイプラインにする

まず、一段の変換を比べます。

{/* example: examples/guides/migration-typescript/pipeline.ts#example */}

```typescript title="pipeline.ts"
function double(value: number) {
  return value * 2;
}
console.log([1, 2, 3].map(double));
```

Seseragiの`|>`は、左の値を右の関数へ渡します。`map double`は配列を待つ関数で、前の節と同じ部分適用です。

{/* example: examples/guides/migration-pipeline.ssrg */}

```seseragi title="migration-pipeline.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main =
  [1, 2, 3]
  |> map double
  |> printValue
```

出力

```text
[2, 4, 6]
```

次は、1より大きい数を残してから二倍にします。

{/* example: examples/guides/migration-typescript/steps.ts#example */}

```typescript title="steps.ts"
function double(value: number) {
  return value * 2;
}
console.log(
  [1, 2, 3]
    .filter((n) => n > 1)
    .map(double),
);
```

Seseragiでは入力と各段階を縦に並べます。`map`はpreludeから使えますが、この`filter`は`std/array`から読み込みます。

{/* example: examples/guides/migration-steps.ssrg */}

```seseragi title="migration-steps.ssrg"
import * as arrays from "std/array"

fn double n: Int -> Int = n * 2
fn keep n: Int -> Bool = n > 1

pub effect fn main =
  [1, 2, 3]
  |> arrays.filter keep
  |> map double
  |> show
  |> println
```

出力

```text
[4, 6]
```

最初の段階は要素を選び、次の段階は残った要素を変換します。どちらも元の配列を変更しません。操作ごとの使い分けは[配列とList](/docs/learn/arrays-and-lists)で扱います。

## 条件分岐の結果を値として使う

TypeScriptで、条件に応じて文字列を返す例です。

{/* example: examples/guides/migration-typescript/condition.ts#example */}

```typescript title="condition.ts"
function result(score: number) {
  return score >= 70
    ? "pass"
    : "retry";
}
console.log(result(82));
console.log(result(65));
```

Seseragiの`if`は式です。`then`と`else`のどちらかの値が、そのまま関数の結果になります。

{/* example: examples/guides/migration-condition.ssrg */}

```seseragi title="migration-condition.ssrg"
fn result score: Int -> String =
  if score >= 70 then
    "pass"
  else
    "retry"

pub effect fn main = do {
  println (result 82)
  println (result 65)
}
```

出力

```text
pass
retry
```

両方の分岐は同じ型になります。この例ではどちらも`String`です。Seseragiでは、条件ごとに変数へ代入するよりも、条件式の値を返す形で書けます。

複数の出力を順に実行するため、ここでは`main = do { ... }`を使っています。通常の`{ ... }`は最後の式を返すブロックで、並べたEffectを自動で順に実行するものではありません。[値と式](/docs/learn/values-and-expressions)と[Effect](/docs/learn/effects)で、この二つの役割を確認できます。

## レコードのfieldを読む

名前の付いた値をまとめ、ドットで取り出す点は似ています。

{/* example: examples/guides/migration-typescript/record.ts#example */}

```typescript title="record.ts"
const point = { x: 3, y: 4 };
console.log(point.x);
```

{/* example: examples/guides/migration-record.ssrg */}

```seseragi title="migration-record.ssrg"
pub effect fn main = {
  let point = { x: 3, y: 4 }
  printValue point.x
}
```

出力

```text
3
```

Seseragiでは`{ x: 3, y: 4 }`がレコードです。レコードの型は、fieldの名前とそれぞれの型から決まります。

## 更新後のレコードを新しく作る

TypeScriptの`const`は変数への再代入を防ぎますが、それだけでオブジェクトのfieldを不変にはしません。ここでは元の値を保つため、スプレッド構文でコピーを作ります。

{/* example: examples/guides/migration-typescript/immutable.ts#example */}

```typescript title="immutable.ts"
const base = { count: 1 };
const next = {
  ...base,
  count: base.count + 1,
};
console.log(
  `${base.count}, ${next.count}`,
);
```

Seseragiのレコード自体は不変です。既存のfieldを引き継いで、一部が異なる新しいレコードを作ります。

{/* example: examples/guides/migration-immutable.ssrg */}

```seseragi title="migration-immutable.ssrg"
pub effect fn main = {
  let base = { count: 1 }
  let next = {
    ...base,
    count: base.count + 1
  }
  let report =
    `${base.count}, ${next.count}`
  println report
}
```

出力

```text
1, 2
```

`next`の`count`は2、`base`は1のままです。`{ ...base, count: ... }`は元の値の書き換えではありません。この考え方は、[Reactでオブジェクトの状態を更新する](https://react.dev/learn/updating-objects-in-state)ときにコピーを作る形にも近いものです。

## 型の別名とstructを区別する

TypeScriptでオブジェクトの形に名前を付ける例です。

{/* example: examples/guides/migration-typescript/alias.ts#example */}

```typescript title="alias.ts"
type Point = {
  x: number;
  y: number;
};

function horizontal(point: Point) {
  return point.x;
}
const point: Point = { x: 3, y: 4 };
console.log(horizontal(point));
```

Seseragiでレコード型に別名を付けるなら`alias`を使います。次は宣言部分です。

{/* example: examples/guides/migration-alias.ssrg#declaration */}

```seseragi title="型と関数の宣言"
alias Point = { x: Int, y: Int }

fn horizontal point: Point -> Int =
  point.x
```

同じファイルの`main`内で、この形を持つレコードを渡します。

{/* example: examples/guides/migration-alias.ssrg#use */}

```seseragi title="main内の抜粋"
let point: Point = { x: 3, y: 4 }
printValue (horizontal point)
```

出力

```text
3
```

この`alias Point`は新しい名義型を作りません。同じfieldと型を持つレコードを受け取ります。

一方、Seseragiの`struct Point { ... }`は名前で区別される型を作ります。fieldが同じでも別のstructとは異なる型です。TypeScriptのobject型をすべて機械的にstructへ置き換えるのではなく、構造で扱うレコードか、名前で区別する型かを選びます。[レコードとstruct](/docs/learn/records-and-structs)に具体例があります。

## ユニオンをケースとmatchで扱う

ここからは数値の関数を離れ、発送状態を表すデータで比べます。TypeScriptでは判別可能なユニオンでケースを分けられます。次は型の宣言です。

{/* example: examples/guides/migration-typescript/data.ts#declaration */}

```typescript title="data.ts"
type Delivery =
  | { kind: "preparing" }
  | { kind: "sent"; city: string };
```

値を作る部分です。

{/* example: examples/guides/migration-typescript/data.ts#construct */}

```typescript title="data.ts"
const delivery: Delivery = {
  kind: "sent",
  city: "Kyoto",
};
```

`switch`でケースを確認すると、そのケースのデータを取り出せます。

{/* example: examples/guides/migration-typescript/data.ts#label */}

```typescript title="data.ts"
function label(value: Delivery) {
  switch (value.kind) {
    case "preparing":
      return "Preparing";
    case "sent":
      return value.city;
  }
}
```

Seseragiでは`Preparing`と`Sent String`がケースです。大文字で始まる`Sent`はconstructorで、`Sent "Kyoto"`が都市名を持つ値を作ります。関数の引数を渡す構文とは、ここで役割を分けて読んでください。

`match`はケースを分け、`Sent city`から都市名を取り出します。次は独立したプログラムです。

{/* example: examples/guides/migration-data.ssrg */}

```seseragi title="migration-data.ssrg"
type Delivery =
  | Preparing
  | Sent String

fn label d: Delivery -> String =
  match d {
    Preparing -> "Preparing"
    Sent city -> city
  }

pub effect fn main = {
  let delivery = Sent "Kyoto"
  println (label delivery)
}
```

出力

```text
Kyoto
```

TypeScript側も`label(delivery)`で`Kyoto`を返します。Seseragiでは、定義したケースをすべて扱わない`match`はコンパイル時に診断されます。

ケースの定義は[代数的データ型](/docs/learn/algebraic-data-types)、値の取り出し方は[パターンマッチ](/docs/learn/pattern-matching)で詳しく扱います。

## 値の不在をMaybeで表す

TypeScriptでは`string | undefined`などで、存在しないかもしれない値を表せます。次は不在のときだけ`Guest`を返す関数です。

{/* example: examples/guides/migration-typescript/maybe.ts#name */}

```typescript title="maybe.ts"
function name(
  value: string | undefined,
): string {
  return value ?? "Guest";
}
```

Seseragiの`Maybe<String>`は、値を持つ`Just`か、値を持たない`Nothing`です。次は関数の宣言部分です。

{/* example: examples/guides/migration-maybe.ssrg#name */}

```seseragi title="Maybeを受け取る関数"
fn name value: Maybe<String>
  -> String =
  value ?? "Guest"
```

両言語の`??`は、不在のときに右辺を評価して使います。空文字列は存在する値なので、そのまま返ります。

TypeScriptで三つの入力を比べます。結果の文字列が空でも見えるよう、表示時だけ角括弧で囲みます。

{/* example: examples/guides/migration-typescript/maybe.ts#inputs */}

```typescript title="maybe.ts"
console.log(`[${name("Ada")}]`);
console.log(`[${name(undefined)}]`);
console.log(`[${name("")}]`);
```

Seseragiでは、次を同じファイルの`main = do { ... }`内に置きます。

{/* example: examples/guides/migration-maybe.ssrg#inputs */}

```seseragi title="main内の抜粋"
let present = name (Just "Ada")
let absent = name Nothing
let empty = name (Just "")
println ("[" + present + "]")
println ("[" + absent + "]")
println ("[" + empty + "]")
```

出力

```text
[Ada]
[Guest]
[]
```

`Just ""`と`Nothing`は異なります。空文字列も拒否したい場合は、不在の処理とは別に入力を検証します。

## Maybeの中身だけを変換する

TypeScriptで、値があるときだけ二倍にする関数です。

{/* example: examples/guides/migration-typescript/maybe-map.ts#example */}

```typescript title="maybe-map.ts"
const double = (n: number) => n * 2;
function doublePresent(
  value: number | undefined,
) {
  return value === undefined
    ? undefined
    : double(value);
}
console.log(doublePresent(21));
console.log(
  doublePresent(undefined),
);
```

出力は21に対して42、不在に対して`undefined`です。Seseragiでは`map`が同じ役割を持ちます。

{/* example: examples/guides/migration-maybe-map.ssrg */}

```seseragi title="migration-maybe-map.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = do {
  Just 21
  |> map double
  |> show
  |> println
  let absent: Maybe<Int> =
    Nothing
    |> map double
  absent
  |> show
  |> println
}
```

出力

```text
Just 42
Nothing
```

`map double`は`Just`の中身を変換します。`Nothing`はそのままです。型注釈`Maybe<Int>`は、値を持たないケースでも中身の型を決めるために使っています。

この`map`と配列の`map`は、どちらも容器の中身を変換する操作です。型クラスの仕組みは[型クラス](/docs/learn/type-classes)、不在の扱いは[MaybeとEither](/docs/learn/maybe-and-either)で学べます。

## 理由のある失敗をEitherで表す

名前が空なら理由を返し、それ以外なら成功の値を返す例です。TypeScriptでは、成功と失敗をユニオンにできます。

{/* example: examples/guides/migration-typescript/either.ts#validate */}

```typescript title="either.ts"
type NameResult =
  | { ok: true; value: string }
  | { ok: false; error: string };

function validate(
  text: string,
): NameResult {
  if (text === "") {
    return {
      ok: false,
      error: "Enter a name",
    };
  }
  return { ok: true, value: text };
}
```

Seseragiでは`Either<String, String>`を使います。最初の型は失敗の理由、次の型は成功の値です。ここでは両方を文字列にしています。

{/* example: examples/guides/migration-either.ssrg#validate */}

```seseragi title="検証する関数"
fn validate text: String
  -> Either<String, String> =
  if text == "" then
    Left "Enter a name"
  else
    Right text
```

結果を表示用の文字列に変える部分も、別の関数にします。

{/* example: examples/guides/migration-typescript/either.ts#report */}

```typescript title="either.ts"
function report(value: NameResult) {
  return value.ok
    ? `Hello, ${value.value}`
    : value.error;
}
```

{/* example: examples/guides/migration-either.ssrg#report */}

```seseragi title="結果を表示する関数"
fn report r: Either<String, String>
  -> String =
  match r {
    Right name -> `Hello, ${name}`
    Left error -> error
  }
```

`"Ada"`を検証した結果は成功、`""`は失敗です。どちらも結果を持つ値なので、ケースごとに処理できます。

次はSeseragiの`main = do { ... }`内の抜粋です。

{/* example: examples/guides/migration-either.ssrg#cases */}

```seseragi title="main内の抜粋"
validate "Ada"
|> report
|> println
validate ""
|> report
|> println
```

出力

```text
Hello, Ada
Enter a name
```

TypeScriptでも`report(validate("Ada"))`と`report(validate(""))`で同じ二つの文字列を得られます。

`Either`は、検証してすでに得られた結果です。非同期の処理を始めることや、例外を投げることは、この型自体の役割ではありません。次のEffectと区別してください。[失敗を扱う](/docs/guides/error-handling)では、入力の検証とEffectの失敗からの回復を分けて実装します。

## PromiseとEffectの実行時点を比べる

TypeScriptの`async`関数とSeseragiの`effect fn`は、名前を付けた副作用の処理を表せます。ただし、いつ処理が実行されるかは同じではありません。

このTypeScript関数には`await`より前の出力だけがあります。

{/* example: examples/guides/migration-typescript/effect.ts#announce */}

```typescript title="effect.ts"
async function announce(s: string) {
  console.log(s);
}
```

関数を呼び、同じPromiseを二回待ちます。次はES moduleのトップレベルの抜粋です。単独のTypeScriptファイルで試す場合は、上の宣言と組み合わせ、末尾へ`export {};`を加えてmoduleにします。

{/* example: examples/guides/migration-typescript/effect.ts#execute */}

```typescript title="effect.ts"
const job = announce("ran");
console.log("constructed");
await job;
await job;
```

出力

```text
ran
constructed
```

`announce("ran")`を呼ぶと関数の本体が進むため、`constructed`より先に出力します。同じPromiseを二回待っても、その本体をもう一度呼ぶことにはなりません。

Seseragiでは、`effect fn`を呼ぶと実行する計算を作ります。次は宣言部分です。

{/* example: examples/guides/migration-effect.ssrg#announce */}

```seseragi title="Effectを作る関数"
effect fn announce text: String =
  println text
```

次を`main = do { ... }`内に置きます。`let job`は計算を作り、その後の`job`でその計算を実行します。

{/* example: examples/guides/migration-effect.ssrg#execute */}

```seseragi title="main内の抜粋"
let job = announce "ran"
println "constructed"
job
job
```

出力

```text
constructed
ran
ran
```

先に`constructed`が出力されます。同じEffectを二回実行すると、出力も二回起きます。

実行して得た値を再利用するには、`do`内で`<-`を使います。次は、出力してから42を返す別のプログラムです。

{/* example: examples/guides/migration-effect-result.ssrg */}

```seseragi title="migration-effect-result.ssrg"
import * as effects from "std/effect"

effect fn produce n: Int = do {
  println "ran"
  effects.succeed n
}

pub effect fn main = do {
  let job = produce 42
  answer <- job
  println `${answer}, ${answer}`
}
```

出力

```text
ran
42, 42
```

`let job`は計算を作り、`answer <- job`がその計算を一回実行して結果を束縛します。後ろの二つの`answer`は結果の整数を再利用するため、`ran`は一回だけです。`let answer = job`なら計算そのものを束縛し、実行しません。

`Effect<R, E, A>`は、必要な環境R、失敗の型E、成功の型Aを表します。TypeScriptの`Promise<A>`のように成功値だけを読む型とは異なり、環境と失敗も型で扱います。

| 扱いたいこと | Seseragiで使うもの |
| --- | --- |
| 引数から値を計算する | 通常の`fn` |
| 値が存在しないかもしれない | `Maybe<A>` |
| 得られた結果が成功か失敗か | `Either<E, A>` |
| 副作用を伴う計算を作り、後で実行する | `Effect<R, E, A>` |

Effectの合成と`do`の規則は[Effect](/docs/learn/effects)、明示する環境や失敗の型は[Effectリファレンス](/docs/reference/effects)を参照してください。

## Reactのpropsと表示する関数を比べる

まず、状態もイベントも持たない部品で比べます。[Reactのprops](https://react.dev/learn/passing-props-to-a-component)は、親からコンポーネントへ値を渡します。次はReactコンポーネントの抜粋です。

{/* example: examples/guides/migration-typescript/react.tsx#badge */}

```tsx title="Reactのコンポーネント"
type BadgeProps = { label: string };

function Badge(props: BadgeProps) {
  return <span>{props.label}</span>;
}
```

Seseragiでは、propsを受け取りHTMLを返す通常の関数にします。次はimport、型、関数の宣言です。

{/* example: examples/guides/migration-props.ssrg#badge */}

```seseragi title="HTMLを返す関数"
import * as html from "std/web/html"

alias BadgeProps = { label: String }

fn badge props: BadgeProps
  -> html.Html<Never> =
  html.span { children: props.label }
```

この部品はActionを発生させないので、結果の型は`Html<Never>`です。`badge { label: "Ready" }`をHTMLの文字列にすると、次の結果になります。

出力

```text
<span>Ready</span>
```

propsを読む点は似ていますが、Seseragiの`badge`自体はHTMLの値を作る純粋な関数です。DOMへ取り付ける処理は別に行います。[コンポーネント](/docs/guides/components)では、複数のpropsとエスケープを扱います。

この例は`Html<Never>`を単独のHTML出力に使っています。対象版では、`Html<Never>`を`Html<Action>`へそのまま渡せません。画面に組み込む部品では、画面とActionの型を揃えます。複数のAction型で使う部品は、Actionの型を[ジェネリクス](/docs/learn/generics)の引数Aにし、関数の結果を`Html<A>`にします。

## 状態の更新を純粋な関数として比べる

Reactの[reducer](https://react.dev/learn/extracting-state-logic-into-a-reducer)は、現在の状態とActionから次の状態を返します。UIを付ける前に、この関数だけを比較できます。

{/* example: examples/guides/migration-typescript/update.ts#update */}

```typescript title="update.ts"
type Action =
  | { type: "increment" }
  | { type: "reset" };

function reducer(
  count: number,
  action: Action,
): number {
  switch (action.type) {
    case "increment":
      return count + 1;
    case "reset":
      return 0;
  }
}
```

Seseragiでも次の状態を計算する`update`を作ります。`dom.app`へ渡す関数の引数は、Action、現在の状態の順です。Reactのreducerとは順序が逆なので注意してください。

{/* example: examples/guides/migration-update.ssrg#update */}

```seseragi title="状態を更新する宣言"
type Action =
  | Increment
  | Reset

fn update action: Action
  -> count: Int -> Int =
  match action {
    Increment -> count + 1
    Reset -> 0
  }
```

TypeScriptでは、次の二つの呼び出しで確認できます。

{/* example: examples/guides/migration-typescript/update.ts#cases */}

```typescript title="update.ts"
console.log(reducer(
  0, { type: "increment" },
));
console.log(reducer(
  9, { type: "reset" },
));
```

Seseragiでは、次を`main = do { ... }`内に置きます。

{/* example: examples/guides/migration-update.ssrg#cases */}

```seseragi title="main内の抜粋"
update Increment 0
|> show
|> println
update Reset 9
|> show
|> println
```

出力

```text
1
0
```

`Increment`は現在の値を一つ増やし、`Reset`は現在の値にかかわらず0を返します。状態を画面へ取り付ける前に、更新の規則だけを実行・テストできます。

## イベントと状態を画面へ接続する

ここでReactの`useReducer`へつなぎます。次は、前の`reducer`と`useReducer`のimportを使うコンポーネントの抜粋です。

{/* example: examples/guides/migration-typescript/react.tsx#events */}

```tsx title="Reactのイベントと状態"
function Counter() {
  const [count, dispatch] =
    useReducer(reducer, 0);
  const increment = () => {
    dispatch({ type: "increment" });
  };
  return (
    <button onClick={increment}>
      {count}
    </button>
  );
}
```

Reactでは、クリックする関数から`dispatch`を呼びます。Seseragiでは`onClick`にActionの値を渡します。次は、前の`Action`を使う`view`の宣言です。

{/* example: examples/guides/migration-web/src/main.ssrg#view */}

```seseragi title="Web用packageの表示関数"
fn view count: Int
  -> html.Html<Action> =
  html.button {
    buttonType: "button",
    onClick: Increment,
    children: `Count: ${count}`
  }
```

この`view`はカウントから`Html<Action>`を作ります。`onClick: Increment`は、クリックのときに送るActionです。状態を書き換える処理を`view`に埋め込まず、`update`へ渡します。

同じWeb用packageの`main`で接続します。`dom`は`std/web/dom`からimportします。

{/* example: examples/guides/migration-web/src/main.ssrg#mount */}

```seseragi title="Web用packageの入口"
pub effect fn main =
  dom.app {
    target: "#app",
    initial: 0,
    update,
    view
  }
```

`dom.app`は`#app`へ取り付け、初期状態0から始めます。クリックのActionを`update`へ渡し、次の状態を`view`へ渡して表示を更新します。ボタンは最初が`Count: 0`、一回クリックすると`Count: 1`です。

この例はWeb用packageとしてビルドするコードです。単独のCLIファイルとして実行する例とは異なります。package、HTMLの入口、ビルドからブラウザで動かすまでの手順は[Webアプリを作る](/docs/guides/web-app)を参照してください。

`dom.app`が状態のSignalとDOMへの接続を管理します。Reactのhookをそのまま書き換えるものではありません。独立した状態や共有する状態は[状態を持つ機能](/docs/guides/stateful-features)、入力値をActionへ変換する例は[フォーム](/docs/guides/forms)で扱います。
