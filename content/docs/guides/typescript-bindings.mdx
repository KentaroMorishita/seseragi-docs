title: TypeScriptとの接続
description: pureとtaskを選び、TypeScriptの関数と例外を型付き境界で扱う。
---

自分で書いたTypeScriptの関数を、Seseragiから呼び出します。文字列を加工するだけの関数と、Promiseを返して失敗することもある関数の二つを、それぞれに合った方法でつなぎます。外部のライブラリは使わないので、ネットワークなしで試せます。

[モジュール](/docs/learn/modules)のimportと、[Effect](/docs/learn/effects)の実行・失敗を使います。TypeScriptとの境界を宣言する`foreign`の構文は、このガイドで説明します。

## ファイルを用意する

次のファイルを作ってください。TypeScript側の`package.json`とロックファイルは、Seseragiの`seseragi.toml`・`seseragi.lock`とは別に用意します。

```text
bindings/
  seseragi.toml
  host/
    package.json
    bun.lock
    format.ts
  src/
    format.ssrg
    main.ssrg
```

```toml title="seseragi.toml"
[package]
name = "docs/typescript-bindings"
version = "0.1.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"

[foreign.typescript]
resolver = "node"
manifest = "host/package.json"
lockfile = "host/bun.lock"
```

```json title="host/package.json"
{
  "name": "docs-host",
  "version": "0.1.0",
  "type": "module"
}
```

host側には依存がないため、`host/bun.lock`は次の内容で保存できます。Bunが依存なしのinstallで空ロックを削除した場合も、宣言した入力が存在する必要があります。

```json title="host/bun.lock"
{
  "lockfileVersion": 1,
  "workspaces": {
    "": {
      "name": "docs-host",
      "version": "0.1.0"
    }
  },
  "packages": {}
}
```

## ホスト側の関数を書く

{/* example: examples/guides/typescript-bindings/host/format.ts */}

```typescript title="host/format.ts"
export function bracket(
  value: string,
) {
  return `[${value}]`;
}

export async function loadLabel() {
  throw new Error(
    "Temporarily unavailable",
  );
}
```

`bracket`は、文字列をその場で加工して返すだけの関数です。`loadLabel`は、失敗の扱いを試すため、わざとPromiseをrejectします。

## foreignで呼び出し方を宣言する

{/* example: examples/guides/typescript-bindings/src/format.ssrg */}
```seseragi title="src/format.ssrg"
pub foreign "typescript"
from "../host/format.ts" {
  pure fn bracket value: String
    -> String
  task fn loadLabel -> String
}
```

`pure`は、「その場で結果を返し、同じ入力には必ず同じ結果を返し、例外を投げず、外の世界を読みも書きもしない」ことを、bindingを書く人が約束する宣言です。コンパイラーはこの約束を確かめられないので、「軽い処理だから」という理由で付けてはいけません。

`task`を付けた関数は、Seseragiからは成功の型が`String`、失敗の型が`Js.Error`のEffect（`Effect<{}, Js.Error, String>`）に見えます。関数が例外を投げたり、Promiseがrejectされたりすると、`Js.Error`の失敗になります。

なお、同じTypeScriptモジュールに`pure`の関数が一つでもあると、そのモジュールは読み込むだけなら副作用がない、という扱いになります。読み込んだだけで何かが起きたり失敗したりするライブラリでは、`pure`の関数を宣言しないでください。

## Seseragi側から使う

{/* example: examples/guides/typescript-bindings/src/main.ssrg */}
```seseragi title="src/main.ssrg"
import * as effects from "std/effect"
import { bracket, loadLabel }
  from "./format"

pub effect fn main = do {
  "ready"
  |> bracket
  |> println
  result <-
    loadLabel ()
    |> effects.attempt
  let message = match result {
    Right value -> value
    Left _ -> "Please try again"
  }
  println message
}
```

`bracket`は普通の関数としてパイプラインに置けます。`loadLabel`はEffectを返すので、`attempt`で失敗を値として受け取り、場合分けしています。TypeScript側の例外も、`try/catch`ではなく型の付いた失敗として扱えます。

## 実行して境界を確かめる

`bindings/`で実行します。

```sh
seseragi lock update
seseragi run .
```

```text
[ready]
Please try again
```

`loadLabel`を呼んだだけでは、TypeScriptの関数はまだ実行されません。`main`の`do`の中で実行され、わざと起こしたrejectを`attempt`が受け止めています。

## bindingをアプリの型へ包む

TypeScriptの関数が`null`や`undefined`を返す場合、bindingでは`Js.NullOr`や`Js.UndefinedOr`のような型で受け取ります。そのうえで、アプリから使う関数の中で`Maybe`に変換します。中身が書き換わるかもしれないオブジェクトを、そのまま不変のレコードとして扱うことはしません。

大きなライブラリなら、`seseragi dts convert`で`.d.ts`からbindingのたたき台を作れます。ただし`.d.ts`からは、関数が純粋か、例外を投げるかまでは分かりません。変換できなかった項目の一覧を確かめ、生成したファイルをそのまま使うのではなく、それをimportする手書きのラッパーを用意してください。

変換の決まり、`null`の扱い、opaque型、エラーの種類は[TypeScript連携リファレンス](/docs/reference/typescript-interop)にあります。ラッパーをパッケージとして公開する方法は[パッケージと配布](/docs/guides/packages-and-deployment)で扱います。
