---

数量の入力を検証して、正しければ数量を、間違っていれば直し方を表示するプログラムを作ります。数字として読めない入力と、範囲外の入力は、別の失敗として扱います。

「学ぶ」の[代数的データ型](/docs/learn/algebraic-data-types)・[パターンマッチ](/docs/learn/pattern-matching)・[MaybeとEither](/docs/learn/maybe-and-either)・[Effect](/docs/learn/effects)の内容を組み合わせて使います。`deriving Show`は[型クラス](/docs/learn/type-classes)、`$`は[関数適用演算子](/docs/learn/application-operator)で扱います。

## 失敗を型で表す

失敗の種類を`QuantityError`という型にします。ケースは`NotANumber`（数字ではない）と`OutsideRange`（範囲外）の二つです。`quantity`関数は`Either<QuantityError, Int>`を返し、成功なら数量、失敗ならその理由が入ります。

値がないこと自体が普通の結果なら`Maybe`でも構いません。ここでは利用者が入力を直せるように理由を伝えたいので、`Either`を使います。

## 完成したプログラム

次の内容を`errors.ssrg`に保存してください。

{/* example: examples/guides/errors.ssrg */}
```seseragi title="errors.ssrg"
import * as ints from "std/int"
import * as effects from "std/effect"

type QuantityError deriving Show =
  | NotANumber
  | OutsideRange

alias Result =
  Either<QuantityError, Int>

fn quantity text: String -> Result =
  match ints.parse text {
    Left _ -> Left NotANumber
    Right n ->
      if n >= 1 && n <= 1000 then
        Right n
      else
        Left OutsideRange
  }

effect fn report text: String = do {
  result <-
    quantity text
    |> fromEither
    |> effects.attempt
  let message = match result {
    Right n -> `Quantity: ${n}`
    Left NotANumber ->
      "Enter a number"
    Left OutsideRange ->
      "Use 1 to 1000"
  }
  println message
}

pub effect fn main = do {
  report "3"
  report "many"
  report "0"
}
```

`ints.parse`が返す細かい失敗は、ここではまとめて`NotANumber`にしています。範囲の決まりは`quantity`に、表示する文言は`report`の`match`にまとまっていて、どこを見れば何が分かるかがはっきりしています。

## EitherをEffectへ移す

`fromEither`は、`Right`なら成功、`Left`なら失敗するEffectを作ります。`effects.attempt`はその逆向きの変換で、Effectの失敗を受け止めて、成功なら`Right`、失敗なら`Left`の値として返します。

`attempt`のおかげで、`report`の中では成功も失敗も普通の値として`match`で場合分けでき、どちらの場合も表示する文を作れます。

## 結果を確かめる

```sh
seseragi run errors.ssrg
```

```text
Quantity: 3
Enter a number
Use 1 to 1000
```

「many」と0の失敗はメッセージの表示に変えているので、プログラム全体は成功で終わります。ただし、`println`そのものが出力に失敗した場合は処理していません。そういう失敗まで成功扱いにしてしまうわけではありません。

## 失敗したときだけ既定値を返す

次は、テーマの設定がなければ`light`を使い、あればその値を使う、という別の例です。次の二つのコードを順に`error-recovery.ssrg`に書いてください。ファイルなどは読まず、設定があるかどうかを`Maybe<String>`で渡します。

{/* example: examples/guides/error-recovery.ssrg#fallback */}
```seseragi title="error-recovery.ssrg"
import * as effects from "std/effect"

type ThemeError =
  | MissingSetting

effect fn theme saved: Maybe<String>
  -> String fails ThemeError =
  effects.fromMaybe MissingSetting $
    saved

effect fn fallback error: ThemeError
  -> String =
  match error {
    MissingSetting -> succeed "light"
  }
```

`effects.fromMaybe`は、`Nothing`のときに`MissingSetting`で失敗するEffectを作ります。`fallback`は、失敗したときに代わりに`light`を返すEffectです。何も必要とせず失敗もしないので、型は`Task<String>`です。

{/* example: examples/guides/error-recovery.ssrg#paths */}
```seseragi title="error-recovery.ssrg"
pub effect fn main = do {
  missing <-
    theme Nothing
    |> effects.recover fallback
  println missing
  present <-
    theme (Just "dark")
    |> effects.recover fallback
  println present
}
```

```sh
seseragi run error-recovery.ssrg
```

```text
light
dark
```

`Nothing`を渡したときは失敗するので、`recover`が`fallback`を呼んで`light`になります。`Just "dark"`のときは成功するので、そのまま`dark`です。

前の例の`attempt`は「成功も失敗も値として受け取って場合分けする」方法、この例の`recover`は「失敗したときに代わりのEffectを実行する」方法です。

## アプリの失敗型へ揃える

入力・ファイル・通信など、失敗の型が違うEffectを組み合わせるときは、`mapError`でアプリ全体の失敗の型に揃えます。[CLIアプリを作る](/docs/guides/cli-app)では、`InputFailure StdinError`と`OutputFailure ConsoleError`を一つの`AppError`にまとめています。

成功の値を変換するのが`map`、失敗の理由を変換するのが`mapError`です。失敗から立て直して続けるか、呼び出し元に失敗を返すかは、アプリごとに決めます。

## バグやキャンセルは別扱い

`attempt`や`recover`が扱うのは、`fails`で型に書いた失敗だけです。プログラムのバグによる異常（defect）や、処理のキャンセルは、普通の失敗として受け止めることはできません。

Seseragiには`try/catch`構文はありません。TypeScript側の関数が投げる例外を扱うときは、[TypeScriptとの接続](/docs/guides/typescript-bindings)で紹介する`task` bindingを使います。失敗・defect・キャンセルの細かい決まりは[Effectリファレンス](/docs/reference/effects)にあります。
