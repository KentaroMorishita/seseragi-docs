配送状況のカードを、タイトルと説明を受け取ってHTMLを返す関数に切り出します。Seseragiのコンポーネントは、特別な仕組みのない普通の`fn`です。HTMLを作ることと、それをブラウザーに表示することが分かれているので、同じ関数をブラウザーでも、HTMLの文字列を作るのにも使えます。

propsには[レコード](/docs/learn/records-and-structs)を、Actionの型には[ジェネリクス](/docs/learn/generics)を使います。画面を表示する`main`では、[Effect](/docs/learn/effects)と[モジュール](/docs/learn/modules)のimportも使います。

## propsの形を決める

カードに必要なのは、`title`と`detail`の二つの文字列です。これを`CardProps`というレコード型にします。

propsには、画面を作るのに必要な値だけを渡します。部品の中で状態を読み書きすることはせず、状態が必要なら、状態を持っている親から今の値を渡してもらいます。

## 完成したカードを書く

次の内容を`components.ssrg`に保存してください。

{/* example: examples/guides/components.ssrg */}
```seseragi title="components.ssrg"
import * as html from "std/web/html"

alias CardProps = {
  title: String,
  detail: String
}

fn card<Action> props: CardProps
  -> html.Html<Action> =
  html.section {
    class: "card",
    children: [
      html.h2<Action, String> {
        children: props.title
      },
      html.p<Action, String> {
        children: props.detail
      }
    ]
  }

pub effect fn main =
  card {
    title: "Delivery",
    detail: "Sent to Kyoto"
  }
  |> html.renderToString
  |> println
```

`card<Action>`の`Action`は、このHTMLが送るイベントの型です。カード自体はイベントを送らないので、型引数にしておくと、どんなActionの画面にも組み込めます。`html.h2<Action, String>`では、Actionの型と子要素の型を明示しています。

子要素には文字列をそのまま置けます。数値は`show`で文字列にします。子要素の配列で文字列とHTMLを混ぜるときは、文字列を`html.text`で包みます。

## HTMLへ描画する

```sh
seseragi run components.ssrg
```

`section`の中に`h2`と`p`が入った、一行のHTMLが表示されます。改行して読みやすくすると、次のようになります。

```html
<section class="card">
  <h2>Delivery</h2>
  <p>Sent to Kyoto</p>
</section>
```

`renderToString`はHTMLの文字列を作るだけの関数です。表示しているのは`println`です。

## propsを変えて比べる

もっと小さな、文字を一つ表示するだけのバッジで試してみます。次の二つのコードを順に`component-props.ssrg`に書いてください。

{/* example: examples/guides/component-props.ssrg#badge */}
```seseragi title="component-props.ssrg"
import * as html from "std/web/html"

alias BadgeProps = { label: String }

fn badge props: BadgeProps
  -> html.Html<Never> =
  html.span {
    class: "badge",
    children: props.label
  }
```

このバッジはイベントを送らないので、Actionの型を`Never`にしています。同じ`label`を渡せば、いつでも同じHTMLが返ります。

{/* example: examples/guides/component-props.ssrg#labels */}
```seseragi title="component-props.ssrg"
pub effect fn main = do {
  badge { label: "Ready" }
  |> html.renderToString
  |> println
  badge { label: "Waiting" }
  |> html.renderToString
  |> println
  badge { label: "<script>" }
  |> html.renderToString
  |> println
}
```

```sh
seseragi run component-props.ssrg
```

一行目と二行目は、`span`に`Ready`と`Waiting`を表示するHTMLです。三行目では`"<script>"`を渡していますが、タグではなくただの文字として表示されます。改行して読みやすくすると、次のようになります。

```html
<span class="badge">
  &lt;script&gt;
</span>
```

propsの文字列がHTMLとして解釈されないことも、この例で確かめられます。

## Webの画面から呼ぶ

[Webアプリを作る](/docs/guides/web-app)の`view`の中に、`card { title: "Delivery", detail: "Sent to Kyoto" }`を子要素として置けます。

ボタンのようにイベントを送る部品では、クリックで送るActionもpropsで受け取ります。部品が親の状態を直接変えるのではなく、親から渡されたActionを送るだけにします。Reactでコールバックをpropsで渡すのと似た考え方です。

## 安全な値の描画を保つ

`title`や`detail`の文字列は、自動でエスケープされます。`"<script>"`を渡しても、その文字が表示されるだけで、スクリプトとして実行されることはありません。

リンクや画像のURLには、検証済みの`WebUrl`型を渡します。文字列を`parseWebUrl`で検証し、失敗した場合も型で扱います。propsと表示の細かい決まりは[Web UIリファレンス](/docs/reference/web-ui)にあります。

## 状態を持つ部分を分ける

部品に今の値を渡して表示する作り方は、同じ状態をいくつかの部品で見せるときに向いています。部品ごとに別々の状態を持たせたいときは、[状態を持つ機能](/docs/guides/stateful-features)の作り方を使います。二つのカウンターを並べて、それぞれ独立して動かす例があります。
