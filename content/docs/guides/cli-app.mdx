title: CLIアプリを作る
description: 標準入力を読み、数量を検証し、金額を出力するCLIを作る。
---

標準入力から数量を一行読み、単価480円の合計金額を表示するCLIを作ります。受け付ける数量は1から1000までの整数です。文字列の変換と検証は普通の関数に書き、標準入力と出力は`main`だけで行います。

「学ぶ」の[代数的データ型](/docs/learn/algebraic-data-types)・[パターンマッチ](/docs/learn/pattern-matching)・[MaybeとEither](/docs/learn/maybe-and-either)・[Effect](/docs/learn/effects)の内容を使います。型に付ける`deriving Show`は[型クラス](/docs/learn/type-classes)で扱います。

## 準備する

[ローカルで使う](/docs/learn/local-development)の手順で、Seseragi CLIとBunを入れておいてください。プログラムは一つのファイルだけで動き、追加のパッケージは要りません。

標準入力とコンソールを使うので、ブラウザーではなくCLI（`process`ターゲット）で実行します。

## 受け付ける入力を決める

`quantity`関数は、文字列を整数に変換して範囲を確かめ、`Either<AppError, Int>`を返します。整数でない文字列、0、1001などは、すべて`InvalidQuantity`という失敗にします。

`readLine`は、入力が終わっていれば`Nothing`、空の行を読んだら`Just ""`を返し、この二つは区別されます。このアプリでは、どちらも正しい数量ではないので失敗として扱います。

## 完成したプログラム

次の内容を`quantity.ssrg`に保存してください。

{/* example: examples/guides/cli-app.ssrg */}
```seseragi title="quantity.ssrg"
import * as ints from "std/int"

type AppError deriving Show =
  | InputFailure StdinError
  | InvalidQuantity
  | OutputFailure ConsoleError

alias Quantity = Either<AppError, Int>

fn quantity text: String -> Quantity =
  match ints.parse text {
    Right n ->
      if n >= 1 && n <= 1000 then
        Right n
      else
        Left InvalidQuantity
    Left _ -> Left InvalidQuantity
  }

pub effect fn main = do {
  line <-
    readLine ()
    |> mapError InputFailure
  let parsed: Quantity = match line {
      Just text -> quantity text
      Nothing -> Left InvalidQuantity
  }
  count <- fromEither parsed
  let total = 480 * count
  `Total: ${total}`
  |> println
  |> mapError OutputFailure
}
```

`fromEither`は、検証した結果の`Either`をEffectに変えます。`Left`ならそこでEffectが失敗します。

標準入力の失敗`StdinError`と、出力の失敗`ConsoleError`は、`mapError`でアプリの`AppError`に揃えています。種類の違う失敗が自動で一つの型にまとめられることはないので、このように自分でまとめます。

## 入力を渡して実行する

macOSやLinuxでは、次のようにして数量を標準入力に渡せます。

```sh
printf '3\n' |
  seseragi run quantity.ssrg
```

```text
Total: 1440
```

`seseragi run quantity.ssrg`だけを実行した場合は、数量を打ち込んでEnterを押してください。`readLine`は一行だけ読むので、二行目以降は使われません。

## 不正な入力を確かめる

```sh
printf '0\n' |
  seseragi run quantity.ssrg
printf 'many\n' |
  seseragi run quantity.ssrg
```

どちらも`InvalidQuantity`で失敗し、その失敗を誰も処理していないので、CLIは終了コード1で終わります。金額は表示されません。（コンパイルエラーや設定の問題で実行できなかった場合は、終了コード2になります。）

失敗したときに利用者向けのメッセージを出したい場合は、[失敗を扱う](/docs/guides/error-handling)で紹介する`attempt`と`match`を使います。

## 空入力と変換失敗を分ける

ここからは、入力の整え方だけを試す別のプログラムです。次の三つのコードを順に`cli-normalization.ssrg`に書いてください。標準入力は使わず、決まった文字列で試します。

### 前後の空白を除いてから読む

`std/text`の`trim`で前後の空白を取り除きます。空になったら`EmptyLine`、整数として読めなければ`NotANumber`と、失敗の理由を分けておきます。

{/* example: examples/guides/cli-normalization.ssrg#parser */}
```seseragi title="cli-normalization.ssrg"
import * as ints from "std/int"
import * as text from "std/text"

type InputError =
  | EmptyLine
  | NotANumber

alias Parsed =
  Either<InputError, Int>

fn parse input: String -> Parsed = {
  let cleaned = text.trim input
  if cleaned == "" then
    Left EmptyLine
  else
    match ints.parse cleaned {
      Right n -> Right n
      Left _ -> Left NotANumber
    }
}
```

### 理由ごとに案内を変える

`message`は、結果を表示する文に変えるだけの関数です。入力を読んだり出力したりはしません。

{/* example: examples/guides/cli-normalization.ssrg#message */}
```seseragi title="cli-normalization.ssrg"
fn message result: Parsed -> String =
  match result {
    Right n -> `Quantity: ${n}`
    Left EmptyLine ->
      "Enter quantity"
    Left NotANumber ->
      "Enter a whole number"
  }
```

### 四つの入力を比べる

{/* example: examples/guides/cli-normalization.ssrg#inputs */}
```seseragi title="cli-normalization.ssrg"
pub effect fn main = do {
  parse " 3 "
  |> message
  |> println
  parse ""
  |> message
  |> println
  parse "many"
  |> message
  |> println
  parse "0"
  |> message
  |> println
}
```

```sh
seseragi run cli-normalization.ssrg
```

```text
Quantity: 3
Enter quantity
Enter a whole number
Quantity: 0
```

`" 3 "`は3に変換され、空文字列と`"many"`にはそれぞれ違う案内が出ます。0は整数として読めるので、この`parse`では成功します。1から1000の範囲に絞るには、前の`quantity`のような確認を足します。

## パッケージへ進める

関数を別のファイルに分けたり、テストを書いたりしたくなったら、`seseragi.toml`を置いてパッケージにします。CLIアプリなら、`[run]`に`target = "process"`と書きます。

[テスト](/docs/guides/testing)では境界の値の確認を自動化し、[パッケージと配布](/docs/guides/packages-and-deployment)ではアプリの入口と公開する関数を分けます。コマンドのオプションは[CLIリファレンス](/docs/reference/cli)にあります。
