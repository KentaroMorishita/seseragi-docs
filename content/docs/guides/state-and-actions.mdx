[Webアプリを作る](/docs/guides/web-app)のカウンターの「増やす」「戻す」を、画面なしで確かめます。「どの操作で状態がどう変わるか」を`update`という一つの関数にまとめておくと、画面を作る前に動きを確かめられます。

操作の種類には[代数的データ型](/docs/learn/algebraic-data-types)、`update`の分岐には[パターンマッチ](/docs/learn/pattern-matching)、状態をまとめるのには[struct](/docs/learn/records-and-structs)を使います。

## 現在値と操作を分ける

状態は今の数を表す`Int`、操作は`Increment`と`Reset`の二つのケースを持つ`Action`です。`update action state`は、操作と今の状態から新しい状態を返します。

操作と状態は別の型にします。`Reset`という操作を受けた結果の状態は、`Reset`ではなく`0`です。

## 完成した更新例

次の内容を`state.ssrg`に保存してください。

{/* example: examples/guides/state.ssrg */}
```seseragi title="state.ssrg"
type Action =
  | Increment
  | Reset

fn update action: Action -> n: Int
  -> Int =
  match action {
    Increment -> n + 1
    Reset -> 0
  }

pub effect fn main = do {
  0
  |> update Increment
  |> update Increment
  |> show
  |> println
  5
  |> update Reset
  |> show
  |> println
}
```

`update Increment`は、状態を待っている関数です（部分適用）。そのため`0 |> update Increment`は`update Increment 0`と同じ意味になり、パイプラインで操作を続けて書けます。

## 操作の列を実行する

```sh
seseragi run state.ssrg
```

```text
2
0
```

一つ目のパイプラインは、0に`Increment`を二回適用して2に、二つ目は5に`Reset`を適用して0にしています。`println`以外は値を計算しているだけなので、何度実行しても同じ結果になります。

## 複数の値をまとめて状態にする

フォームなどでは、数だけでなく入力中の文字列やメッセージも状態に持ちたくなります。そのときは、状態をstructにまとめます。更新するときは、`Model { ...model, draft: value }`のように新しい値を作ります。フィールドに代入して書き換えることはできません。より大きな例は[フォーム](/docs/guides/forms)にあります。

### 一つのフィールドだけを変える

カウントと入力中の文字列を持つ例です。次の三つのコードを順に`state-fields.ssrg`に書いてください。

{/* example: examples/guides/state-fields.ssrg#model */}
```seseragi title="state-fields.ssrg"
struct Model {
  count: Int,
  draft: String
}

type Action =
  | Edited String
  | ResetCount
```

`Edited`は入力された文字列を持ち、`ResetCount`は数だけを0にします。変えないフィールドは`...model`でそのまま引き継ぎます。

{/* example: examples/guides/state-fields.ssrg#update */}
```seseragi title="state-fields.ssrg"
fn update action: Action
  -> model: Model -> Model =
  match action {
    Edited draft -> Model {
      ...model,
      draft
    }
    ResetCount -> Model {
      ...model,
      count: 0
    }
  }
```

### 元の値と更新後の値を比べる

{/* example: examples/guides/state-fields.ssrg#cases */}
```seseragi title="state-fields.ssrg"
pub effect fn main = do {
  let initial = Model {
    count: 2,
    draft: ""
  }
  let edited =
    update (Edited "Ada") initial
  println edited.draft
  println `Count: ${edited.count}`
  `Original: "${initial.draft}"`
  |> println
  let reset =
    update ResetCount edited
  println `Count: ${reset.count}`
  println reset.draft
}
```

```sh
seseragi run state-fields.ssrg
```

```text
Ada
Count: 2
Original: ""
Count: 0
Ada
```

編集後の`draft`は`Ada`ですが、元の`initial.draft`は空のままです。`Edited`では`count`の2がそのまま残り、`ResetCount`では入力の`Ada`がそのまま残ります。

## 副作用の位置を決める

`update`は値を計算するだけの関数なので、中で通信などはできません。

通信などが必要になったら、Effectを実行する部分と、状態を更新する部分を分けます。Signalを直接更新する例は[状態を持つ機能](/docs/guides/stateful-features)にあります。通信の結果をActionとして`update`に戻す場合は、成功と失敗の両方をActionのケースにしておきます。

## 更新規則をテストする

ボタンを毎回押して確かめる代わりに、「`update Increment 0`は1」「`update Reset 5`は0」をテストに書いておけます。書き方は[テスト](/docs/guides/testing)で扱います。

Actionに新しいケースを足したときは、`update`の`match`で扱い忘れがないかもコンパイラーが確かめてくれます。パターンの細かい決まりは[パターンリファレンス](/docs/reference/patterns)にあります。
