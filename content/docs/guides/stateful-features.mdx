---
title: 状態を持つ機能を組み合わせる
description: privateなSignalを作り、読み取り専用の画面を親へ返す。
---

「Today」と「Tomorrow」の二つのカウンターを並べ、片方を押してももう片方は変わらないようにします。カウンターのモジュールが自分の状態を持ち、親には画面（`Signal<Html<Task<Unit>>>`）だけを返します。親は子の状態に触れません。

「学ぶ」の[Effect](/docs/learn/effects)、[Signal](/docs/learn/signals)、[モジュール](/docs/learn/modules)の内容を使います。状態には[struct](/docs/learn/records-and-structs)、ボタンの処理には[関数](/docs/learn/functions)のラムダ、括弧を減らすのに[関数適用演算子](/docs/learn/application-operator)の`$`を使います。`Task<Unit>`は`Effect<{}, Never, Unit>`の別名で、何も必要とせず失敗もしないEffectです。ボタンは、このTaskをクリック時のActionとして持ちます。

## プロジェクトを準備する

```sh
seseragi new web two-counters
cd two-counters
```

`seseragi new web`で作ったプロジェクトに`src/counter.ssrg`を追加し、`src/main.ssrg`を置き換えます。最初からある`app.ssrg`は使いません。

## 子が状態を作る

{/* example: examples/guides/stateful-features/src/counter.ssrg */}
```seseragi title="src/counter.ssrg"
import * as html from "std/web/html"
import * as signals from "std/signal"
import { MutableSignal, Signal }
  from "std/signal"

struct Count { count: Int }

alias View = html.Html<Task<Unit>>

fn view title: String
  -> state: MutableSignal<Count>
  -> current: Count
  -> View =
  html.section {
    children: [
      html.h2<Task<Unit>, String> {
        children: title
      },
      html.p<Task<Unit>, String> {
        children: show current.count
      },
      html.button {
        buttonType: "button",
        children: "Add one",
        onClick: signals.update
          (\n: Count -> Count {
            count: n.count + 1
          }) state
      }
    ]
  }

pub effect fn create title: String
  -> Signal<View> = do {
  state <-
    signals.make $ Count { count: 0 }
  state
  |> signals.map (view title state)
  |> succeed
}
```

`create`はEffectで、実行すると`signals.make`で状態を一つ作り、その状態から作った画面のSignalを返します。

書き換えられる`MutableSignal`はモジュールの中に閉じ込め、親には読み取り専用の`Signal`だけを返します。ボタンには「状態を更新するTask」をActionとして渡しているので、子がどんなActionを持つかを親が知る必要はありません。

## 親が画面を組み合わせる

{/* example: examples/guides/stateful-features/src/main.ssrg */}
```seseragi title="src/main.ssrg"
import * as dom from "std/web/dom"
import * as html from "std/web/html"
import * as signals from "std/signal"
import { create } from "./counter"

alias View = html.Html<Task<Unit>>

fn layout first: View -> second: View
  -> View =
  html.main {
    style: html.style {
      margin: "32px auto",
      maxWidth: "32rem",
      padding: "24px"
    },
    children: [first, second]
  }

fn perform action: Task<Unit>
  -> Task<Unit> = action

fn queryError error: dom.DomError
  -> String = show error

alias DomFailure =
  dom.DomRuntimeError<Never>

fn runtimeError error: DomFailure
  -> String = show error

pub effect fn main = do {
  first <- create "Today"
  second <- create "Tomorrow"
  let content =
    signals.combine layout first $
      second
  target <-
    dom.query "#app"
    |> mapError queryError
  let options = dom.defaultOptions ()
  (
    dom.run options target perform $
      content
  )
  |> mapError runtimeError
}
```

`create "Today"`と`create "Tomorrow"`はそれぞれ実行され、別々の状態を作ります。`signals.combine`で二つの画面を`layout`に渡し、一つの画面にまとめます。

`perform`は、子が用意したTaskをそのまま返すだけの関数です。クリックされると、`dom.run`がそのTaskを実行します。

## ブラウザーで独立性を確かめる

```sh
seseragi lock update
seseragi dev --open
```

最初はどちらも0です。「Today」の「Add one」を二回押すとTodayだけが2になり、「Tomorrow」を一回押すとTomorrowが1になります。Todayは2のままです。

状態がいくつできるかは、`create`を何回実行したかで決まります。画面を描き直すたびに状態が作り直されることはなく、HTMLの`key`で状態が決まるわけでもありません。

## Signalの作り方だけを確かめる

画面を使わずに、状態が独立していることだけを確かめる二つのプログラムです。それぞれ別のファイルに保存してください。

### 別々にmakeを実行する

`signal-independence.ssrg`では`signals.make`を二回実行します。片方を更新しても、もう片方は変わりません。

{/* example: examples/guides/signal-independence.ssrg#independent */}
```seseragi title="signal-independence.ssrg"
import * as signals from "std/signal"

fn increment n: Int -> Int = n + 1

pub effect fn main = do {
  first <- signals.make 0
  second <- signals.make 0
  signals.update increment first
  signals.update increment first
  signals.update increment second
  today <- signals.read first
  tomorrow <- signals.read second
  println `Today: ${today}`
  println `Tomorrow: ${tomorrow}`
}
```

```sh
seseragi run signal-independence.ssrg
```

```text
Today: 2
Tomorrow: 1
```

`signals.read`で、その時点の値を読み取っています。

### 同じSignalに別の名前を付ける

`signal-shared.ssrg`では`make`は一回だけです。`same`は`source`と同じSignalを指しています。

{/* example: examples/guides/signal-shared.ssrg#shared */}
```seseragi title="signal-shared.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  source <- signals.make 0
  let same = source
  signals.set 2 same
  first <- signals.read source
  second <- signals.read same
  println `Source: ${first}`
  println `Same: ${second}`
}
```

```sh
seseragi run signal-shared.ssrg
```

```text
Source: 2
Same: 2
```

`let same = source`は名前を増やすだけで、状態をコピーするわけではありません。別々の状態が欲しければ`make`をそれぞれ実行し、同じ状態を共有したければ同じSignalを渡します。

## 共有状態の所有者を選ぶ

二つのカウンターで同じ値を操作したいなら、共通の親が状態を作り、子には今の値と、許可する更新のTaskだけを渡します。子にアプリ全体の`MutableSignal`を渡すと、子がどこまでも書き換えられるようになってしまいます。

アプリ全体で使う状態は一番上の親で作ります。モジュールのトップレベルにグローバルな状態を置くことはしません。

## 終了とリソースの扱いを分ける

`dom.run`は、画面の更新に使う購読とイベントリスナーを自分で管理し、終了するときに解除します。`dom.run`自身の失敗は、`mapError`で`String`に変換しています。

子が自分で購読やタイマー、通信などを持つ場合は、その後始末をEffectのスコープや`DomMount`に結び付けます。画面から消えただけで自動的に片付くわけではありません。細かい決まりは[Signalリファレンス](/docs/reference/signals)と[Web UIリファレンス](/docs/reference/web-ui)にあります。
