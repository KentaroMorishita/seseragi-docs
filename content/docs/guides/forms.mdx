---
title: フォームを作る
description: 入力値、Action、検証結果をつないで、名前を受け取るフォームを作る。
---

名前を入力して「Greet」を押すと挨拶が表示されるフォームを作ります。空のまま送ると「Enter your name」と表示します。入力中の文字列と検証の結果を一つの`Model`にまとめ、`update`で更新します。

状態・Action・`view`の役割分担は、[Webアプリを作る](/docs/guides/web-app)と同じです。

## プロジェクトを準備する

```sh
seseragi new web greeting-form
cd greeting-form
```

`seseragi new web`で作ったプロジェクトの`src/main.ssrg`を、次のコードに置き換えます。最初からある`app.ssrg`は使いません。

## フォーム全体を書く

{/* example: examples/guides/forms/src/main.ssrg */}
```seseragi title="src/main.ssrg"
import * as dom from "std/web/dom"
import * as html from "std/web/html"

struct Model {
  draft: String,
  message: String
}

type Action =
  | Edited String
  | Submitted

alias View = html.Html<Action>

fn update action: Action
  -> model: Model -> Model =
  match action {
    Edited draft -> Model {
      ...model,
      draft,
      message: ""
    }
    Submitted ->
      if model.draft == "" then
        Model {
          ...model,
          message: "Enter your name"
        }
      else
        Model {
          ...model,
          message:
            `Hello, ${model.draft}`
        }
  }

fn edited event: html.InputEvent
  -> Action =
  Edited event.value

fn view model: Model -> View =
  html.main {
    style: html.style {
      margin: "32px auto",
      maxWidth: "32rem",
      padding: "24px"
    },
    children: [
      html.h1 {
        children: "Greeting"
      },
      html.form {
        onSubmit: Submitted,
        children: [
          html.label {
            htmlFor: "name",
            children: "Your name"
          },
          html.input {
            id: "name",
            name: "name",
            value: model.draft,
            onInput: edited
          },
          html.button {
            buttonType: "submit",
            children: "Greet"
          }
        ]
      },
      html.p {
        role: "status",
        children: model.message
      }
    ]
  }

pub effect fn main =
  dom.app {
    target: "#app",
    initial: Model {
      draft: "",
      message: ""
    },
    update,
    view
  }
```

`draft`は入力中の文字列、`message`は送信したあとに表示する結果です。`Edited`で入力が変わると前回のメッセージを消し、`Submitted`で今の入力を検証します。

## 入力イベントをActionへ変える

`html.InputEvent`の`value`には、入力された文字列が入っています。`edited`は、その文字列から`Edited`のActionを作ります。ブラウザーの`Event`オブジェクトそのものを状態に入れることはありません。

`value: model.draft`で入力欄に今の値を表示し、`onInput: edited`で入力のたびにActionを送ります。Reactの「制御されたコンポーネント」と同じ形です。ラベルの`htmlFor: "name"`と入力欄の`id: "name"`を揃えて、ラベルをクリックすると入力欄が選ばれるようにしています。

## 送信して検証する

```sh
seseragi lock update
seseragi dev --open
```

`Ada`と入力して「Greet」を押すと、「Hello, Ada」と表示されます。空のまま送ると「Enter your name」です。`onSubmit`を指定したフォームは、ページの再読み込みを自動で止めてActionを送ります（`preventDefault`は要りません）。入力欄でEnterを押しても送信されます。

この例では、空白だけの入力も名前として受け付けます。空白を取り除きたい場合は、次の節のように検証の前に整えます。

## 名前の検証を小さく試す

ここでは「前後の空白を取り除き、空になったら受け付けない」という検証を、画面なしで試します。次の三つのコードを順に`form-validation.ssrg`に書いてください。前のWebフォームとは別のプログラムです。

### 成功した名前と失敗を返す

[Either](/docs/learn/maybe-and-either)を使い、受け付けた名前は`Right`に、直し方の案内は`Left`に入れます。

{/* example: examples/guides/form-validation.ssrg#validation */}
```seseragi title="form-validation.ssrg"
import * as text from "std/text"

alias Name = Either<String, String>

fn name input: String -> Name = {
  let cleaned = text.trim input
  if cleaned == "" then
    Left "Enter your name"
  else
    Right cleaned
}
```

### 結果を挨拶へ変える

{/* example: examples/guides/form-validation.ssrg#greeting */}
```seseragi title="form-validation.ssrg"
fn greeting result: Name -> String =
  match result {
    Right value -> `Hello, ${value}`
    Left message -> message
  }
```

`greeting`は、成功なら名前を使った挨拶を、失敗なら案内をそのまま返します。

### 正常・空・空白だけを比べる

{/* example: examples/guides/form-validation.ssrg#inputs */}
```seseragi title="form-validation.ssrg"
pub effect fn main = do {
  name " Ada "
  |> greeting
  |> println
  name ""
  |> greeting
  |> println
  name "   "
  |> greeting
  |> println
}
```

```sh
seseragi run form-validation.ssrg
```

```text
Hello, Ada
Enter your name
Enter your name
```

`" Ada "`は空白が取り除かれて`Ada`になり、`""`と`"   "`はどちらも受け付けられません。この検証をWebフォームで使うなら、`Submitted`で`name model.draft`を呼び、その結果から`message`を作ります。

## 検証結果を画面へ戻す

検証に失敗しても、アプリが止まるわけではありません。`Submitted`は、入力の問題を`message`に入れて次の状態として返します。`role: "status"`を付けた段落に、その結果が表示されます。

サーバーへの保存などを足す場合は、入力の検証の失敗と、保存の失敗を分けておきます。入力の失敗なら入力し直し、通信の失敗ならやり直し、と利用者への案内が違うからです。失敗の扱い方は[失敗を扱う](/docs/guides/error-handling)で学べます。

## 画面を部品へ分ける

ラベルと入力欄の組のように繰り返す部分は、propsを受け取ってHTMLを返す関数に分けられます（[コンポーネント](/docs/guides/components)）。別々の状態を持つフォームを二つ並べたい場合は、[状態を持つ機能](/docs/guides/stateful-features)の作り方を使います。入力やキーボードのイベントの細かい決まりは[Web UIリファレンス](/docs/reference/web-ui)にあります。
