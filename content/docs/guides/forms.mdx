---
title: フォームを作る
description: 入力と結果をSignalに保存し、名前を受け取るフォームを作る。
---

名前を入力して「Greet」を押すと挨拶が表示されるフォームを作ります。空のまま送ると「Enter your name」と表示します。入力中の文字列と送信後の結果を、それぞれ[Signal](/docs/learn/signals)に保存します。

画面への接続は[Webアプリを作る](/docs/guides/web-app)と同じです。イベントで実行する`Task<Unit>`と`do`は[Effect](/docs/learn/effects)、HTMLのpropsに使うレコードは[レコードとstruct](/docs/learn/records-and-structs)で説明しています。

## プロジェクトを準備する

```sh
seseragi new web greeting-form
cd greeting-form
```

`seseragi new web`で作ったプロジェクトの`src/main.ssrg`を、次のコードに置き換えます。最初からある`app.ssrg`は使いません。

## フォーム全体を書く

{/* example: examples/guides/forms/src/main.ssrg */}
```seseragi title="src/main.ssrg"
import * as dom from "std/web/dom"
import * as html from "std/web/html"
import * as signals from "std/signal"
import { MutableSignal }
  from "std/signal"

alias Field = MutableSignal<String>

alias View = html.Html<Task<Unit>>

fn greeting name: String -> String =
  if name == "" then
    "Enter your name"
  else
    `Hello, ${name}`

fn edited draft: Field
  -> reply: Field
  -> event: html.InputEvent
  -> Task<Unit> =
  signals.transaction [
    signals.planSet event.value draft,
    signals.planSet "" reply
  ]

fn submitted draft: Field
  -> reply: Field
  -> Task<Unit> = do {
  name <- signals.read draft
  signals.set (greeting name) reply
}

fn view draft: Field
  -> reply: Field
  -> current: String
  -> result: String -> View =
  html.main {
    style: html.style {
      margin: "32px auto",
      maxWidth: "32rem",
      padding: "24px"
    },
    children: [
      html.h1 {
        children: "Greeting"
      },
      html.form {
        onSubmit:
          submitted draft reply,
        children: [
          html.label {
            htmlFor: "name",
            children: "Your name"
          },
          html.input {
            id: "name",
            name: "name",
            value: current,
            onInput:
              edited draft reply
          },
          html.button {
            buttonType: "submit",
            children: "Greet"
          }
        ]
      },
      html.p {
        role: "status",
        children: result
      }
    ]
  }

fn perform action: Task<Unit>
  -> Task<Unit> = action

fn queryError error: dom.DomError
  -> String = show error

alias DomFailure =
  dom.DomRuntimeError<Never>

fn runtimeError error: DomFailure
  -> String = show error

pub effect fn main = do {
  draft <- signals.make ""
  reply <- signals.make ""
  let render = view draft reply
  let content =
    signals.combine render draft reply
  target <-
    dom.query "#app"
    |> mapError queryError
  let opts = dom.defaultOptions ()
  dom.run opts target perform content
  |> mapError runtimeError
}
```

`Field`は`MutableSignal<String>`の別名です。`draft`は入力中の文字列、`reply`は送信後の結果を保存します。`signals.combine`で二つのSignalの値を`view`に渡し、入力欄と結果の段落が両方の変化に追従するようにします。

## 入力でSignalを更新する

`html.InputEvent`の`value`には、入力された文字列が入っています。`edited draft reply`は、イベントの情報を受け取って更新のTaskを作る関数です。`onInput`がその関数を呼び、`dom.run`がTaskを実行します。

`signals.planSet`で入力の保存と前回の結果の消去を予定し、`signals.transaction`でまとめて反映します。二つのSignalを一度に変える決まりは[Signalの更新](/docs/learn/signals#複数の更新をまとめる)で説明しています。

`value: current`で入力欄に現在の文字列を表示します。ラベルの`htmlFor: "name"`と入力欄の`id: "name"`を揃えているので、ラベルをクリックすると入力欄が選ばれます。

## 送信して検証する

```sh
seseragi lock update
seseragi dev --open
```

`Ada`と入力して「Greet」を押すと、「Hello, Ada」と表示されます。空のまま送ると「Enter your name」です。`onSubmit`を指定したフォームは、ページの再読み込みを自動で止め、`submitted draft reply`のTaskを送ります（`preventDefault`は要りません）。入力欄でEnterを押しても送信されます。

この例では、空白だけの入力も名前として受け付けます。空白を取り除きたい場合は、次の節のように検証の前に整えます。

## 名前の検証を小さく試す

ここでは「前後の空白を取り除き、空になったら受け付けない」という検証を、画面なしで試します。次の三つのコードを順に`form-validation.ssrg`に書いてください。前のWebフォームとは別のプログラムです。

### 成功した名前と失敗を返す

[Either](/docs/learn/maybe-and-either)を使い、受け付けた名前は`Right`に、直し方の案内は`Left`に入れます。

{/* example: examples/guides/form-validation.ssrg#validation */}
```seseragi title="form-validation.ssrg"
import * as text from "std/text"

alias Name = Either<String, String>

fn name input: String -> Name = {
  let cleaned = text.trim input
  if cleaned == "" then
    Left "Enter your name"
  else
    Right cleaned
}
```

### 結果を挨拶へ変える

{/* example: examples/guides/form-validation.ssrg#greeting */}
```seseragi title="form-validation.ssrg"
fn greeting result: Name -> String =
  match result {
    Right value -> `Hello, ${value}`
    Left message -> message
  }
```

`greeting`は、[パターンマッチ](/docs/learn/pattern-matching)で成功と失敗を分け、成功なら名前を使った挨拶を、失敗なら案内をそのまま返します。

### 正常・空・空白だけを比べる

{/* example: examples/guides/form-validation.ssrg#inputs */}
```seseragi title="form-validation.ssrg"
pub effect fn main = do {
  name " Ada "
  |> greeting
  |> println
  name ""
  |> greeting
  |> println
  name "   "
  |> greeting
  |> println
}
```

```sh
seseragi run form-validation.ssrg
```

```text
Hello, Ada
Enter your name
Enter your name
```

`" Ada "`は空白が取り除かれて`Ada`になり、`""`と`"   "`はどちらも受け付けられません。Webフォームへ組み込むときは、この`Name`と二つの関数で元の`greeting`を置き換えます。`submitted`で読み取った文字列を`name`と`greeting`へ順に渡してから、`reply`に保存します。

## 検証結果を画面へ戻す

`submitted`は、送信時点の入力を`signals.read`で読み、`greeting`で文字列にして`signals.set`で`reply`へ保存します。空の入力でも処理は失敗せず、案内の文字列を保存します。`role: "status"`を付けた段落に、その結果が表示されます。

サーバーへの保存などを足す場合は、入力の検証の失敗と、保存の失敗を分けておきます。入力の失敗なら入力し直し、通信の失敗ならやり直し、と利用者への案内が違うからです。失敗の扱い方は[失敗を扱う](/docs/guides/error-handling)で学べます。

## 画面を部品へ分ける

ラベルと入力欄の組のように繰り返す部分は、propsを受け取ってHTMLを返す関数に分けられます（[コンポーネント](/docs/guides/components)）。別々の状態を持つフォームを二つ並べたい場合は、[状態を持つ機能](/docs/guides/stateful-features)の作り方を使います。入力やキーボードのイベントの細かい決まりは[Web UIリファレンス](/docs/reference/web-ui)にあります。
