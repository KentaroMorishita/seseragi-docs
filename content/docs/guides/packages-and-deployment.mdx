---
title: パッケージと配布
description: 公開APIと実行入口を分け、processとwebの成果物を配布する。
---

送料の計算を小さなライブラリとして切り出し、別のアプリから使います。どのモジュールを公開し、どのパッケージに依存するかは、`seseragi.toml`で決めます。後半では、CLIアプリとWebアプリの配布の仕方を扱います。

「学ぶ」の[モジュール](/docs/learn/modules)と[ローカルで使う](/docs/learn/local-development)の内容を使います。

## 二つのパッケージを作る

次のファイルを作ってください。`shipping/`がライブラリ、`app/`がそれを使うアプリです。

```text
shop/
  shipping/
    seseragi.toml
    src/
      shipping.ssrg
  app/
    seseragi.toml
    src/
      main.ssrg
```

親のディレクトリに共通の設定ファイルは要りません。`seseragi.toml`があるディレクトリが、それぞれ一つのパッケージになります。

## ライブラリの公開入口を決める

```toml title="shipping/seseragi.toml"
[package]
name = "docs/shipping"
version = "0.1.0"
language = ">=0.1.0 <0.2.0"

[exports]
"." = "shipping"
```

{/* example: examples/guides/packages/shipping/src/shipping.ssrg */}
```seseragi title="shipping/src/shipping.ssrg"
pub fn fee subtotal: Int -> Int =
  if subtotal >= 3000 then 0 else 400
```

`pub`で関数を公開し、`[exports]`でほかのパッケージから使えるモジュールを決めます。`[exports]`に書いていないモジュールは、パスを指定してもほかのパッケージからはimportできません。npmの`package.json`の`exports`と同じ考え方です。

## アプリからpath依存を使う

```toml title="app/seseragi.toml"
[package]
name = "docs/shop"
version = "0.1.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"

[dependencies.shipping]
package = "docs/shipping"
path = "../shipping"
```

{/* example: examples/guides/packages/app/src/main.ssrg */}
```seseragi title="app/src/main.ssrg"
import { fee } from "shipping"

pub effect fn main =
  fee 2999
  |> show
  |> println
```

`shipping`は、ソースのimportで使う名前です。実際のパッケージ名`docs/shipping`と、そこへの相対パス`../shipping`を書いています。importで別のパッケージの`src/`を直接指定することはしません。

## ロックして実行する

`shop/`で実行します。

```sh
seseragi lock update app
seseragi run app
```

```text
400
```

`app/seseragi.lock`には、依存パッケージの中身や、使うツールの情報が記録されます。`seseragi.toml`や依存パッケージのソースを変えたら、変更を確かめてからロックファイルを更新します。

`run`や`build`がロックファイルを自動で更新することはなく、古いままだと`SES-K0102`で止まります。`seseragi.toml`と`seseragi.lock`は、どちらもGitなどで管理してください。

## processの成果物を動かす

```sh
cd app
seseragi build . --profile release
bun dist/entry.js
```

ビルドしたものを実行しても400が表示されます。ビルドすると、生成されたJavaScriptとランタイムが`entry.js`一つにまとめられ、それをBunで実行します。OS向けの実行ファイルが一つできるわけではありません。

HTTPサーバーのようなアプリも、静的サイトではなく、このCLIアプリと同じ形で配布します。アプリが使える機能は[ランタイムProvider](/docs/reference/runtime-providers)で確かめられます。

## Webの成果物を配信する

[Webアプリを作る](/docs/guides/web-app)の`counter/`では、次のビルドを使います。

```sh
seseragi lock update
seseragi build . --profile release
```

`dist/`に`index.html`と、ブラウザー向けのJavaScript・CSSができます。このディレクトリを静的ホスティングに置くだけで公開できます。公開したページを表示するのに、Seseragiは要りません。

たとえばVercel CLIを入れてログインしていれば、ビルドしたディレクトリを指定して公開できます。

```sh
vercel deploy dist --prod
```

Vercel側では追加のビルドを行わない設定にします。`--prod`を付けると本番のドメインに公開されます。詳しくは[Vercel CLIの公式ドキュメント](https://vercel.com/docs/cli/deploy)を見てください。

## HTMLと公開ファイルを加える

ページのタイトルやfaviconを自分で決めたいときは、`[web]`の`index`と`public`で、自分のHTMLと静的ファイルのディレクトリを指定します。HTMLの`head`に`<!-- seseragi:head -->`を、`body`に`<!-- seseragi:entry -->`を一つずつ書き、画面を表示する`<div id="app"></div>`も用意します。

静的ファイルを足したり変えたりしたときも、ビルドの前にロックファイルを更新します。できあがった`dist/`を手で書き換えることはしません。設定の細かい決まりは[プロジェクト設定](/docs/reference/project-configuration)にあります。

## 公開する範囲を確認する

path依存はローカル開発用です。レジストリーへ公開するmanifestへpath依存を残すことはできません。現在のCLIにはパッケージの`publish`コマンドがないため、このガイドはローカルのパッケージ分割とアプリ成果物の配布を扱っています。

公開するモジュールを変えたら、[テスト](/docs/guides/testing)で、外からのimportがちゃんと通るか確かめられます。TypeScriptのbindingを公開したい場合は、[TypeScriptとの接続](/docs/guides/typescript-bindings)で紹介した手書きのラッパーを公開します。
