[Records and structs](/en/docs/learn/records-and-structs) grouped several values together. This chapter describes data that takes one of several states, such as "red or green", as a type.

## Define a type by listing cases

Declare a type with `type` and list its possible cases separated by `|`. A type that is "one of several cases" is called an algebraic data type (ADT). It is close to a TypeScript union such as `"red" | "green"`.

```seseragi title="Type declaration syntax"
type Light =
  | Red
  | Green
```

Both `Red` and `Green` are values of type `Light`. A value is never both cases at once, and `Yellow`, which is not declared, cannot be used as a `Light`.

If a struct is a type that holds all its fields at once, an ADT is a type that takes exactly one of its cases.

## Use a case without data

`Red` and `Green` are cases without data. Writing the case name is enough to make a value.

```seseragi title="Value binding syntax"
let red: Light = Red
let green: Light = Green
```

The cases differ, but both values have type `Light`. The next chapter shows how to do something different for each case.

## Attach data to a case

A case can carry data. `Reading` below represents a measurement: the "not measured yet" case carries nothing, and the "measured" case carries the measured value as an integer.

```seseragi title="Type declaration with payloads"
type Reading =
  | NoReading
  | Measured Int
```

`NoReading` is a value of `Reading` on its own. `Measured` is a function that takes one integer and creates a value of `Reading`; it is called a constructor. The data a case carries is called its payload.

```seseragi title="Value binding syntax"
let absent: Reading = NoReading
let measured: Reading = Measured 23
```

Passing anything other than an integer, as in `Measured "warm"`, is a type error. And `Measured` alone is still a function waiting for an integer, not a value of `Reading`.

## Cases that hold several values

To give a case several values, use a tuple. `Rectangle` below carries two integers, a width and a height:

{/* example: examples/learn/focused/adt-tuple-payload.ssrg#declaration */}
```seseragi title="Type declaration"
type Shape =
  | Circle Int
  | Rectangle (Int, Int)
```

Create a value with `Rectangle (3, 4)`. `(3, 4)` is one tuple holding two integers, and `Rectangle` takes that single tuple. You cannot write `Rectangle 3 4`.

{/* example: examples/learn/focused/adt-tuple-payload.ssrg#value */}
```seseragi title="Binding in main"
let rectangle: Shape =
  Rectangle (3, 4)
```

When you want named fields, use a struct from the previous chapter as the payload. The ADT says which state you are in, and the struct says what data that state carries.

### Use a struct as a payload

Consider a type that holds account information only while signed in. First, define the account information as a struct:

{/* example: examples/learn/focused/adt-struct-payload.ssrg#data */}
```seseragi title="Struct declaration"
struct Account {
  name: String,
}
```

Then define the type for the sign-in state:

{/* example: examples/learn/focused/adt-struct-payload.ssrg#declaration */}
```seseragi title="Type declaration"
type Session =
  | Guest
  | SignedIn Account
```

`Guest` needs no account information, but `SignedIn` cannot be created without an `Account`. The state "signed in but no account information" simply cannot exist.

{/* example: examples/learn/focused/adt-struct-payload.ssrg#value */}
```seseragi title="Binding in main"
let session: Session =
  SignedIn (Account { name: "Aki" })
```

Parentheses turn `Account { ... }` into one argument for `SignedIn`. The next chapter shows how to tell the cases apart and take the account information out.

## Type names and input conditions

Like structs, ADTs are identified by their names. Another type with exactly the same case names and shapes is not converted automatically; write a function when you need a conversion.

A type also only fixes the payload's type. This `Reading` accepts both 23 and −1 in `Measured`. Check conditions such as "a measurement is never negative" in the function that creates the value.

## Continue to case-specific behavior

In this chapter, types decided which values can exist. To tell the cases apart and take out the payload on the receiving side, use `match`.

Try adding `Yellow` to the `Light` declaration: `Yellow` becomes a valid `Light`. In `Reading`, changing `Measured 23` to `NoReading` keeps the type `Reading`.

The [data types reference](/en/docs/reference/data-types) covers how to write declarations. Next, [Pattern matching](/en/docs/learn/pattern-matching) handles each case separately and extracts the payload of `Reading`.
