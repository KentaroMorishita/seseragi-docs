---
title: "Modules"
description: "Split types and functions into files and define public APIs and package boundaries."
---

Each `.ssrg` file is one module. Put the parcel type and its display function in `parcel.ssrg`, then use them from `main.ssrg`. A package groups the files and declares the execution entry point.

## Assign a role to each file

Save files in a new directory with this layout:

```text
parcel-app/
  seseragi.toml
  src/
    main.ssrg
    parcel.ssrg
```

`parcel.ssrg` contains the type and calculation; `main.ssrg` performs output at the entry point. The path below `src` identifies a module's location within this package. There is no module-name declaration at the top of a source file.

## Export a type and function

Save this as `src/parcel.ssrg`:

{/* example: examples/learn/modules/src/parcel.ssrg */}
```seseragi title="parcel.ssrg"
pub type Parcel =
  | Packing
  | Sent String

pub fn label parcel: Parcel -> String =
  match parcel {
    Packing -> "Preparing"
    Sent city -> `Sent to ${city}`
  }
```

Declarations are module-private by default. Add `pub` to types and functions needed by another file. This `Parcel` is not opaque, so its `Packing` and `Sent` constructors are exported with the type.

`label` only returns a display string. Importing this file does not start output or other I/O.

## Import the required names

Save this as `src/main.ssrg`:

{/* example: examples/learn/modules/src/main.ssrg */}
```seseragi title="main.ssrg"
import { label, Sent } from "./parcel"

pub effect fn main =
  Sent "Kyoto"
  |> label
  |> println
```

`import { label, Sent }` introduces only the requested public names into the local scope. `"./parcel"` means `parcel.ssrg` beside the current file. Resolution does not search the working directory, try alternative extensions, or look for a directory index.

To avoid a name collision, use `import { label as parcelLabel } from "./parcel"`. A namespace import, `import * as parcels from "./parcel"`, exposes names such as `parcels.label` and `parcels.Sent`. Imports appear at the beginning of the file.

## Declare the package entry point

Save the following as `seseragi.toml`:

```toml title="seseragi.toml"
[package]
name = "docs/learn-modules"
version = "0.0.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"
```

Change into `parcel-app`, create its lockfile, and run the package:

```sh
seseragi lock update .
seseragi run .
```

```text title="Output"
Sent to Kyoto
```

The first command generates `seseragi.lock`. Package execution uses the manifest and lockfile. Distinguish single-file execution from package execution, which resolves multiple modules. See [Project configuration](/en/docs/reference/project-configuration) for the configuration contract.

## Preserve visibility and dependency boundaries

Public contracts must use types their consumers can understand. Hide a type's representation with `pub opaque struct` or `pub opaque type` when needed, and expose functions for working with it.

`self/` identifies the current package, `std/` identifies a standard library module, and other package names refer to direct dependencies declared in the manifest. Relative imports cannot cross package boundaries, and a dependency's private source files are not importable API.

Module import cycles are prohibited. If two files need each other's types, separate shared types into a third module and make dependencies one-directional. Use `rec` for mutually recursive functions within one module.

## Change the public API

After changing a file, update the lock with `seseragi lock update .` before executing `seseragi run .`.

Remove `pub` from `label` and inspect the import diagnostic. Restore it, then change the input in `main` to `Packing`. Add `Packing` to the named import to print `Preparing`.
