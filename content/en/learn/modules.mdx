title: "Modules"
description: "Split types and functions into files and define public APIs and package boundaries."
---

As a program grows, you split it into files. In Seseragi, each `.ssrg` file is one module. This chapter puts a type and a function for parcel delivery status in `parcel.ssrg` and uses them from `main.ssrg`. Several files are run together as a package.

The code in this chapter uses [Pipelines](/en/docs/learn/pipelines) for `|>`, [Algebraic data types](/en/docs/learn/algebraic-data-types), and [Pattern matching](/en/docs/learn/pattern-matching) for `match`.

## Assign a role to each file

Create files in a new directory like this:

```text
parcel-app/
  seseragi.toml
  src/
    main.ssrg
    parcel.ssrg
```

`parcel.ssrg` holds the delivery type and function, and `main.ssrg` holds the program's entry point. A file's location under `src` is its module's location. You do not declare a module name inside the file.

## Export a type and function

Save the following as `src/parcel.ssrg`:

{/* example: examples/learn/modules/src/parcel.ssrg */}
```seseragi title="parcel.ssrg"
pub type Parcel =
  | Packing
  | Sent String

pub fn label parcel: Parcel -> String =
  match parcel {
    Packing -> "Preparing"
    Sent city -> `Sent to ${city}`
  }
```

A declaration without anything in front is usable only inside its file. Add `pub` to types and functions other files should use. A `Parcel` exported with `pub type` also exports its cases, `Packing` and `Sent`.

Importing a file never runs anything by itself.

## Import the required names

Save the following as `src/main.ssrg`:

{/* example: examples/learn/modules/src/main.ssrg */}
```seseragi title="main.ssrg"
import { label, Sent } from "./parcel"

pub effect fn main =
  Sent "Kyoto"
  |> label
  |> println
```

`import { label, Sent } from "./parcel"` makes `label` and `Sent`, two of the names `parcel.ssrg` exports, available here. The syntax is almost the same as TypeScript. `"./parcel"` refers to `parcel.ssrg` in the same directory as this file. Unlike TypeScript, there is no lookup of `index` files or other extensions.

When names collide, rename one: `import { label as parcelLabel } from "./parcel"`. With `import * as parcels from "./parcel"`, use `parcels.label` and `parcels.Sent`. Imports go at the top of the file.

## Set the entry point in seseragi.toml

Finally, create the package configuration file `seseragi.toml`. `entry` under `[run]` says which module to run:

```toml title="seseragi.toml"
[package]
name = "docs/learn-modules"
version = "0.0.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"
```

Move into `parcel-app`, create the lockfile, and run it:

```sh
seseragi lock update .
seseragi run .
```

```text title="Output"
Sent to Kyoto
```

The first command creates `seseragi.lock`. Passing a directory, as in `seseragi run .`, reads `seseragi.toml` and the lockfile and runs it as a package. [Project configuration](/en/docs/reference/project-configuration) explains how to write the configuration file.

## Visibility and dependencies

To hide what is inside a type, use `pub opaque struct` or `pub opaque type`. Only the type's name is exported, and its contents can be reached only through the functions you export.

An import path starting with `self/` refers to your own package, `std/` to the standard library, and anything else to a dependency listed in `seseragi.toml`. A relative path cannot leave the package, and you cannot import a dependency's unexported files directly.

Modules cannot import each other in a cycle. When that seems necessary, move the shared types into a third module so dependencies point one way.

## Change the public API

After changing a file, update the lockfile with `seseragi lock update .`, then run `seseragi run .`.

First, remove `pub` from `label`: the import in `main.ssrg` becomes an error. Restore `pub`, change `Sent "Kyoto"` in `main` to `Packing`, and add `Packing` to the import. If it prints `Preparing`, you are done.
