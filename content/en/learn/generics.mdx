Instead of making one box for integers and another for strings, you can make a single `Box<A>` whose content type is a parameter. These are generics, the same idea as TypeScript's `Box<T>`. `A` is not a value; it stands in for a type name.

The code in this chapter uses [Functions](/en/docs/learn/functions), [Pipelines](/en/docs/learn/pipelines) for `|>` and `show`, [Records and structs](/en/docs/learn/records-and-structs), [Algebraic data types](/en/docs/learn/algebraic-data-types), and [Pattern matching](/en/docs/learn/pattern-matching) for `match`. The `do { ... }` in `main` runs the steps inside it from top to bottom; [Effects](/en/docs/learn/effects) covers it in detail.

## Keep the argument and result types related

Start with a small function that uses one type parameter. The `<A>` after the function name is the type parameter:

{/* example: examples/learn/focused/generic-identity.ssrg#declaration */}
```seseragi title="Function declaration"
fn identity<A> value: A -> A = value
```

Each call replaces `A` with a concrete type. You can also pass the type explicitly, as in `<Int>`:

{/* example: examples/learn/focused/generic-identity.ssrg#explicit */}
```seseragi title="Bindings in main"
let number = identity<Int> 42
let text = identity<String> "hello"
```

`number` is the `Int` 42 and `text` is the `String` `"hello"`. The same function keeps the relationship "returns the same type it receives".

## Parameterize a type

{/* example: examples/learn/generics.ssrg */}
```seseragi title="generics.ssrg"
struct Box<A> {
  value: A,
}

fn unbox<A> box: Box<A> -> A =
  box.value

fn identity<A> value: A -> A =
  value

pub effect fn main = do {
  let number = Box { value: 42 }
  let text = Box { value: "hello" }
  number
  |> unbox
  |> identity
  |> show
  |> println
  text
  |> unbox
  |> identity
  |> show
  |> println
}
```

```text title="Output"
42
hello
```

`Box { value: 42 }` is a `Box<Int>`, and `Box { value: "hello" }` is a `Box<String>`. The type follows from the value inside, so you do not need to write it.

`unbox<A>` takes the `A` out of a `Box<A>`: an integer from a `Box<Int>`, a string from a `Box<String>`.

## A type parameter accepts anything

`identity<A> value: A -> A` accepts any type, but in exchange it knows nothing about `A`. If you change the body to `value + 1`, it fails, because `A` is not necessarily a number. To require something such as "only types that support addition", use a [type class](/en/docs/learn/type-classes) constraint.

## Supply a type when inference needs it

Type arguments are usually worked out from the arguments or the expected result. When you write one, as in `identity<String> "hello"`, put no space between the function name and `<`.

Sometimes the value does not reveal the type, as with an empty Array. Then write the type: `let empty: Array<Int> = []`. When a type cannot be determined, the compiler asks you to write it instead of falling back to a catch-all type.

### Transform to a different type

A function that transforms the content of a Box uses two type parameters: `A` before the transformation and `B` after it.

{/* example: examples/learn/focused/generic-map-box.ssrg#declaration */}
```seseragi title="Function declaration"
fn mapBox<A, B> f: (A -> B)
  -> box: Box<A> -> Box<B> =
  Box { value: f box.value }
```

{/* example: examples/learn/focused/generic-map-box.ssrg#transform */}
```seseragi title="Bindings in main"
let number: Box<Int> =
  Box { value: 42 }
let labeled: Box<String> =
  number
  |> mapBox (\n -> `score: ${n}`)
```

`number` is `Box<Int>`, `labeled` is `Box<String>`, and `labeled.value` is `score: 42`. Because the function turns an `Int` into a `String`, the Box type changes from `Box<Int>` to `Box<String>` too.

## Reuse a data shape

ADTs can have type parameters too. `Result<A>` below uses `A` for the type of a successful value:

{/* example: examples/learn/focused/generic-result.ssrg#data */}
```seseragi title="Type declaration"
type Result<A> =
  | Failed String
  | Succeeded A
```

`Result<Int>` and `Result<String>` have the same cases and differ only in the success type. `Maybe<A>` and `Either<E, A>` from the previous chapter are built the same way.

To give a type another name, write `alias Pair<A> = (A, A)`. An `alias` only adds a name; it does not create a new type.

A function that takes a value out of a `Result` can use a type parameter as well:

{/* example: examples/learn/focused/generic-result.ssrg#declaration */}
```seseragi title="Function declaration"
fn valueOr<A> fallback: A
  -> result: Result<A> -> A =
  match result {
    Failed _ -> fallback
    Succeeded value -> value
  }
```

{/* example: examples/learn/focused/generic-result.ssrg#inputs */}
```seseragi title="Bindings in main"
let number =
  Succeeded 42
  |> valueOr 0
let text =
  Failed "unavailable"
  |> valueOr "untitled"
```

`number` is 42 and `text` is `untitled`. The success value and the fallback are both `A`, so the result is `A` too.

## Functions bound with let work at many types

A function bound with `let` can also be used at a different type each time:

{/* example: examples/learn/focused/generic-local-function.ssrg#polymorphic */}
```seseragi title="Bindings in main"
let same = \value -> value
let number = same 42
let text = same "hello"
```

`number` is 42 and `text` is `hello`. Calling `same` with an integer first does not make it integer-only.

Generics do not mean you can mix element types in one Array, though. `Array<Int>` and `Array<String>` are different types, and a `Box<Int>` never converts to a `Box<Float>` automatically.

## Extract another type

Change `Box { value: "hello" }` in the example to `Box { value: True }`. Without touching `unbox`, the result becomes a `Bool`. Then make `unbox` add 1 to the value: it fails, because `A` is not necessarily a number.
