Start by declaring and calling a function that adds two integers. Then learn to supply some of its arguments and combine functions in a pipeline.

## Declare and apply a function

A function declaration has the form `fn name parameter: Type -> ResultType = body`. Join multiple parameters with `->`. This fragment shows the declaration shape:

```seseragi
fn add x: Int -> y: Int -> Int =
  x + y
```

Supply 20 and 22 to `add` as follows:

```seseragi title="Application expression"
add 20 22
```

The two arguments follow the function name, separated by spaces. This expression returns 42.

Put the declaration and call together in a complete program:

{/* example: examples/learn/function-application.ssrg */}
```seseragi title="function-application.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

pub effect fn main = {
  let answer = add 20 22
  println `answer: ${answer}`
}
```

```text title="Output"
answer: 42
```

`add` is an ordinary function that returns the calculation result. `main` binds that result to `answer` and displays it using the string template introduced in the previous chapter.

### Call a declaration without named parameters

A function that omits named parameters still receives the `Unit` value `()` when called. Place this declaration at module scope:

{/* example: examples/learn/focused/function-unit.ssrg#declaration */}
```seseragi title="Function declaration"
fn ready -> String = "ready"
```

Use this expression inside `main` to call `ready` and display its string:

{/* example: examples/learn/focused/function-unit.ssrg#use */}
```seseragi title="Expression in main"
ready ()
|> println
```

The output is `ready`. In `ready ()`, `()` is one argument containing the Unit value; it is not an argument-list call syntax. `ready` alone refers to the function before application.

## Supply some arguments

`add` has type `Int -> Int -> Int`. Function types associate to the right, so read this as `Int -> (Int -> Int)`. `add 1` is a function waiting for one more integer.

`let increment = add 1` binds a function that adds 1 to its input. No remaining argument is evaluated at this point. Calling `increment 20` gives 21, just like `add 1 20`. Partial application constructs a function value with some arguments already supplied.

## Put the calculation in reading order

{/* example: examples/learn/functions-and-pipelines.ssrg */}
```seseragi title="functions-and-pipelines.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

fn double x: Int -> Int =
  x * 2

pub effect fn main = {
  let increment = add 1
  20
  |> increment
  |> double
  |> show
  |> println
}
```

```text title="Output"
42
```

The value `20` goes through `increment` to produce 21, then through `double` to produce 42. `show` converts the integer to a `String`; `println` constructs an Effect that prints that string. `println` accepts a string.

`value |> f` is the same application as `f value`. The pipeline operator does not add asynchronous execution or laziness. `20 |> add 1` supplies 20 to the function `add 1`; it does not automatically fill an arbitrary parameter position.

## Group an expression used as an argument

When an argument is a calculation, parentheses mark its extent. This binding belongs inside `main` and uses `add` from above:

{/* example: examples/learn/focused/function-grouping.ssrg#arithmetic */}
```seseragi title="Binding in main"
let grouped = add (20 + 1) 22
```

`20 + 1` becomes the first argument: `add` receives 21 and 22, so `grouped` is 43. Parentheses group one expression; they do not introduce an argument-list call such as `add(20, 22)`.

Group another function's result in the same way. This binding also uses `double` from the previous example:

{/* example: examples/learn/focused/function-grouping.ssrg#nested */}
```seseragi title="Binding in main"
let nested = double (add 20 1)
```

The result of `add 20 1`, 21, is the single argument to `double`, so `nested` is 42. This nests expressions in the same order as the pipeline.

## Create a function without a declaration

A lambda is an expression that creates a function without a named `fn` declaration. Bind a doubling function inside `main`:

{/* example: examples/learn/focused/function-lambda.ssrg#lambda */}
```seseragi title="Binding in main"
let double = \n: Int -> n * 2
```

After that binding, call it just like an ordinary function:

{/* example: examples/learn/focused/function-lambda.ssrg#call */}
```seseragi title="Expression in main"
double 21
|> show
|> println
```

The output is 42. When the surrounding type determines the parameter type, omit the annotation with `\n -> n * 2`. A two-parameter lambda is `\x y -> x + y`. [Arrays and lists](/en/docs/learn/arrays-and-lists) passes lambdas to `map` and `filter`.

### Return a function that uses an outer value

A function can return another function. This declaration receives a prefix and returns a greeting function that uses that prefix:

{/* example: examples/learn/focused/function-closure.ssrg#declaration */}
```seseragi title="Function declaration"
fn prefixWith prefix: String
  -> (String -> String) =
  \name -> `${prefix}${name}`
```

Use it inside `main`:

{/* example: examples/learn/focused/function-closure.ssrg#use */}
```seseragi title="Expression in main"
let welcome = prefixWith "Hi, "
welcome "Aki"
|> println
```

The output is `Hi, Aki`. The returned lambda can still refer to `prefix` when called. A function retaining outer values in this way is a closure. It does not update the captured value. Supplying `"Hello, "` creates another function with that prefix.

## Understand what application evaluates

Ordinary function arguments are evaluated once, from left to right. Applying a function to another value does not modify an outer `let` binding.

`add` and `double` return ordinary values. `println` returns a computation that performs output, so `main` is an `effect fn`. Piping a value into a function does not itself execute an Effect. [Effects](/en/docs/learn/effects) explains the execution boundary.

## Change the composition

Change `let increment = add 1` to `let increment = add 2`; the result becomes 44. Then swap `double` and `increment`. With the original increment of 1, the result becomes 41. Check how ordering the functions changes the calculation.
