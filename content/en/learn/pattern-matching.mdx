title: "Pattern matching"
description: "Branch on values and extract the parts you need."

`match` is an expression that chooses a result based on the shape of a value. It resembles TypeScript's `switch`, but it returns a value and it can take data out of a case. Start with `Bool`, then extract data from the [algebraic data types](/en/docs/learn/algebraic-data-types) of the previous chapter.

## Branch on two values

This function returns `"enabled"` for `True` and `"disabled"` for `False`:

{/* example: examples/learn/pattern-matching.ssrg */}
```seseragi title="pattern-matching.ssrg"
fn label enabled: Bool -> String =
  match enabled {
    True -> "enabled"
    False -> "disabled"
  }

pub effect fn main =
  True
  |> label
  |> println
```

```text title="Output"
enabled
```

`match` tries the patterns to the left of each `->` from top to bottom, and the right side of the first matching branch becomes the result.

Every branch must return the same type; here both return a `String`. Because both `True` and `False` are handled, any `Bool` gives a result.

## Name data inside a case

This uses `Reading` from the previous chapter: `NoReading` carries no data, and `Measured` carries one integer. A `match` can tell the cases apart and, at the same time, take that integer out under a name.

{/* example: examples/learn/pattern-payloads.ssrg */}
```seseragi title="pattern-payloads.ssrg"
type Reading =
  | NoReading
  | Measured Int

fn label reading: Reading -> String =
  match reading {
    NoReading -> "No reading"
    Measured n -> `Reading: ${n}`
  }

pub effect fn main =
  Measured 23
  |> label
  |> println
```

```text title="Output"
Reading: 23
```

`Measured n` matches when the value is `Measured` and takes the integer out as `n`. `n` is available only inside that branch. `Measured 23` in `main` builds a value, while `Measured n` in a branch takes one apart: the same shape, opposite roles.

In TypeScript, you check `reading.kind === "measured"` yourself and then read `reading.value`. With `match`, checking the case and taking out the data are one step, so you cannot read the data and forget the check.

## Handle remaining values with _

A type like `Int` has too many values to list. Write the specific values you care about, then a branch for "everything else":

```seseragi
match number {
  0 -> "zero"
  _ -> "nonzero"
}
```

`_` matches any value. Writing a name such as `n` instead also matches any value, and gives it that name.

Note that a name never compares against an outer variable with the same name. To compare with a specific value, write a literal such as `0`, or use a guard, introduced next.

## Add a condition with a guard

You can add a condition after a pattern with `when`. This is called a guard. The branch is chosen only when the pattern matches and the condition is also `True`.

```seseragi
match number {
  n when n > 0 -> "positive"
  _ -> "zero or negative"
}
```

If the condition is `False`, the next branch is tried. The compiler does not look inside guard conditions, so always write a branch for the values the condition rejects.

Here is a function that tells positive, zero, and negative apart:

{/* example: examples/learn/focused/pattern-guard.ssrg#declaration */}
```seseragi title="Function declaration"
fn sign number: Int -> String =
  match number {
    n when n > 0 -> "positive"
    0 -> "zero"
    _ -> "negative"
  }
```


{/* example: examples/learn/focused/pattern-guard.ssrg#inputs */}
```seseragi title="Bindings in main"
let negative = sign (-1)
let zero = sign 0
let positive = sign 1
```

The results are `negative`, `zero`, and `positive`. −1 matches neither the first condition nor `0`, so it reaches the last branch.

### Match fields of a record

Records can be patterns too. This function takes a record with `online` and `name`:

{/* example: examples/learn/focused/pattern-record.ssrg#declaration */}
```seseragi title="Function declaration"
fn caption value: {
  online: Bool,
  name: String,
} -> String =
  match value {
    { online: True, name } -> name
    _ -> "offline"
  }
```

It takes out the name only when `online` is `True`, and returns `offline` otherwise. Define `let user = { online: True, name: "Aki" }` in `main`, then call it:

{/* example: examples/learn/focused/pattern-record.ssrg#use */}
```seseragi title="Expression in main"
user
|> caption
|> println
```

This prints `Aki`. With `online` set to `False`, it prints `offline`. One pattern can both check a field's value and take another field out.

## Combine tuples and guards

Now combine patterns and guards to find where a point lies. A tuple groups values in order into one value. `(3, 0)` is a tuple of two integers, and `describe` takes it as one argument.

{/* example: examples/learn/pattern-tuples.ssrg */}
```seseragi title="pattern-tuples.ssrg"
fn describe point: (Int, Int)
  -> String =
  match point {
    (0, 0) -> "origin"
    (x, 0) when x > 0 -> "east"
    (_, 0) -> "horizontal axis"
    (0, _) -> "vertical axis"
    _ -> "off the axes"
  }

pub effect fn main =
  (3, 0)
  |> describe
  |> println
```

```text title="Output"
east
```

`(0, 0)` matches when both are zero. `(x, 0)` matches when the second is zero and names the first `x`. The guard narrows it to `x > 0`, so the next branch, `(_, 0)`, receives points on the horizontal axis left of zero.

The parentheses in `(3, 0)` create a tuple; they are not call parentheses.

## Exhaustiveness and decomposition that cannot fail

A `match` must be written so that every possible value lands in some branch: both `True` and `False` for `Bool`, every case for an ADT. If a case is missing, the compiler tells you before the program runs. When you later add a case to an ADT, it finds every `match` that forgot to handle it.

A branch that can never be chosen is also an error. Moving the final `_` to the top of the coordinate example makes every branch below it unreachable, so it fails.

`let` also accepts patterns, but only ones that always match. `let (x, y) = point` always works on a tuple. `let (0, y) = point` fails when the first value is not zero, so it is not allowed. To take only `Measured n` out of a `Reading`, use a `match` that also handles `NoReading`.

## Change the branches

In the `Bool` example, change `True` in `main` to `False`: it prints `disabled`. Then delete the `False` branch to see the error about an unhandled case. In the `Reading` example, change the value in `main` to `NoReading` and check that it prints `No reading`.
