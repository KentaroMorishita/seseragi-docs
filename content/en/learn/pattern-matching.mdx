title: "Pattern matching"
description: "Branch on values and extract the parts you need."

`match` is an expression that selects a result based on an input value. Start with the two values of `Bool`, then extract data from the cases introduced in [Algebraic data types](/en/docs/learn/algebraic-data-types).

## Branch on two values

This function returns `"enabled"` for `True` and `"disabled"` for `False`:

{/* example: examples/learn/pattern-matching.ssrg */}
```seseragi title="pattern-matching.ssrg"
fn label enabled: Bool -> String =
  match enabled {
    True -> "enabled"
    False -> "disabled"
  }

pub effect fn main =
  True
  |> label
  |> println
```

```text title="Output"
enabled
```

`match enabled` evaluates `enabled` once and tries branch patterns from top to bottom. The first matching branch supplies the result of the whole `match` expression. Here, the patterns are `True` and `False`.

Every branch must return the same type. Both return a `String` here. Handling both values means the function returns a result for any `Bool` input.

## Name data inside a case

The next example uses `Reading` from the previous chapter. `NoReading` holds no data, and `Measured` holds one integer. While distinguishing a case, a `match` pattern can give that integer a name.

{/* example: examples/learn/pattern-payloads.ssrg */}
```seseragi title="pattern-payloads.ssrg"
type Reading =
  | NoReading
  | Measured Int

fn label reading: Reading -> String =
  match reading {
    NoReading -> "No reading"
    Measured n -> `Reading: ${n}`
  }

pub effect fn main =
  Measured 23
  |> label
  |> println
```

```text title="Output"
Reading: 23
```

`Measured n` matches a value of the `Measured` case and binds its payload to `n`. That name is available only within its branch. Constructing a value with `Measured 23` in `main` and decomposing one with `Measured n` in a pattern serve different purposes.

## Handle remaining values with _

Integers have many possible values. After listing a specific value, handle the rest with another branch. This fragment distinguishes zero from other integers:

```text
match number {
  0 -> "zero"
  _ -> "nonzero"
}
```

`_` matches any value without naming it. A pattern containing only an ordinary name also matches anything, binding the value to that name. A lowercase name does not test equality with an outer variable. Use a literal pattern or a guard, introduced next, to compare specific values.

## Add a condition with a guard

Attach a `Bool` condition with `when` to check it after the pattern matches. This fragment handles positive integers in the first branch:

```text
match number {
  n when n > 0 -> "positive"
  _ -> "zero or negative"
}
```

`n` binds the input integer. A `True` condition selects the first branch; a `False` condition proceeds to the next branch. Guards do not establish exhaustiveness, so another branch must handle inputs for which the condition fails.

## Combine tuple decomposition and a condition

Combine these patterns and guards to classify coordinates. A tuple groups values into one ordered value. `(3, 0)` is a tuple of two integers, and `describe` receives that tuple as one argument.

{/* example: examples/learn/pattern-tuples.ssrg */}
```seseragi title="pattern-tuples.ssrg"
fn describe point: (Int, Int)
  -> String =
  match point {
    (0, 0) -> "origin"
    (x, 0) when x > 0 -> "east"
    (_, 0) -> "horizontal axis"
    (0, _) -> "vertical axis"
    _ -> "off the axes"
  }

pub effect fn main =
  (3, 0)
  |> describe
  |> println
```

```text title="Output"
east
```

`(0, 0)` matches when both values are zero. `(x, 0)` binds the first integer to `x` and checks that the second is zero. After the guarded branch, `(_, 0)` handles nonpositive points on the horizontal axis.

The parentheses in `(3, 0)` construct a tuple. Distinguish them from the spaces that supply arguments to a function.

## Exhaustiveness and decomposition that cannot fail

A `match` needs branches for every possible input. Handle both `True` and `False` for `Bool`, or every case for an ADT. A pattern for remaining inputs can follow branches that handle specific conditions.

Unreachable branches are also errors. Moving the final `_` to the beginning of the coordinate example makes every following branch unreachable.

`let (x, y) = point` always extracts both parts of this tuple type. In contrast, `let (0, y) = point` fails to match when the first integer is not zero. Ordinary `let` does not accept patterns that can fail. To extract only `Measured n` from `Reading`, use a `match` that also handles `NoReading`.

## Change the branches

Change `True` in the first program's `main` to `False`: it prints `disabled`. Then remove the `False` branch to see the exhaustiveness diagnostic. In the `Reading` example, change `main` to `NoReading` and check that it prints `No reading`.

In the coordinate example, change only the input to compare results:

| Input | Output |
| --- | --- |
| `(0, 0)` | `origin` |
| `(-3, 0)` | `horizontal axis` |
| `(0, 4)` | `vertical axis` |
| `(2, 3)` | `off the axes` |
