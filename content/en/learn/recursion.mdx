Recursion calls the same function on a smaller problem. Start with a small factorial to see the base case, then move to summation, mutual recursion, and trees.

## Check termination with a small example

The factorial of 5 is `5 * 4 * 3 * 2 * 1`. Place this declaration at module scope:

{/* example: examples/learn/focused/recursion-factorial.ssrg#declaration */}
```seseragi title="Function declaration"
fn factorial n: Int -> Int =
  if n <= 1 then
    1
  else
    n * factorial (n - 1)
```

These bindings belong inside `main`:

{/* example: examples/learn/focused/recursion-factorial.ssrg#inputs */}
```seseragi title="Bindings in main"
let zero = factorial 0
let five = factorial 5
```

`zero` is 1; `five` is 120. The function ends when `n <= 1`, and otherwise calls itself with the smaller `n - 1`. This implementation also returns 1 for negative inputs. Choose a policy such as validating input first if that range should be rejected.

Multiplication remains after the recursive call, so the function is not tail recursive. Use small inputs here to examine its structure. The next summation example discusses larger inputs.

## Choose a base case and the next input

{/* example: examples/learn/recursion.ssrg */}
```seseragi title="recursion.ssrg"
fn sumUpTo limit: Int -> Int = {
  fn loop n: Int -> total: Int
    -> Int =
    if n <= 0 then
      total
    else
      loop (n - 1) (total + n)

  loop limit 0
}

pub effect fn main =
  100000
  |> sumUpTo
  |> show
  |> println
```

```text title="Output"
5000050000
```

`loop n total` finishes when `n <= 0`. Otherwise, it decreases `n`, adds the current `n` to `total`, and calls itself. Both branches return an `Int`.

This definition returns 0 for a negative limit. Acceptable inputs and out-of-range behavior are design decisions for the function. Recursion itself does not guarantee positive inputs or termination.

## Keep implementation parameters local

`loop` is declared inside the `sumUpTo` block. Callers use `sumUpTo` without supplying an intermediate accumulator.

A local function can refer to its own name and lexical bindings declared before it. It cannot implicitly capture later local values or functions. Annotate parameters and the return type so the recursive function has a stable result type.

## Recognize tail recursion

This `loop` returns the recursive call's result directly. No addition or other work remains after the call. It is a direct self call in tail position.

Seseragi executes direct self tail calls in ordinary pure functions without growing the host call stack in proportion to the input size. This example has been checked with 100000 iterations.

The same guarantee does not cover calls such as `n + sumUpTo (n - 1)`, which perform work afterward, mutual recursion, partial application, or calls through callbacks. Do not apply the pure function's synchronous-loop guarantee directly to `effect fn` either. See [Performance](/en/docs/reference/performance) for its precise scope.

## Group mutual recursion with rec

Functions that call each other belong to the same `rec` group inside a function block. A bare `rec { ... }` is not permitted at module scope. Place this ordinary function declaration at module scope:

{/* example: examples/learn/focused/recursion-mutual.ssrg#declaration */}
```seseragi title="Function declaration"
fn parity n: Int -> String = {
  rec {
    fn even n: Int -> Bool =
      if n == 0 then True
      else odd (n - 1)

    fn odd n: Int -> Bool =
      if n == 0 then False
      else even (n - 1)
  }
  if even n then "even" else "odd"
}
```

`parity 6` produces `even`; `parity 7` produces `odd`. The inner even and odd functions can refer to each other within the group.

This definition assumes nonnegative input. Negative input never approaches zero, so it does not terminate. Mutual recursion also lacks the stack guarantee of direct self tail calls; this example is not a replacement for a large-input implementation.

### Walk recursive data

Recursion also works when a data type contains more values of the same type. This declaration represents either one leaf or a branch containing two trees. Place it at module scope:

{/* example: examples/learn/focused/recursion-tree.ssrg#data */}
```seseragi title="Type declaration"
type Tree =
  | Leaf
  | Branch (Tree, Tree)
```

Count leaves by returning 1 for a leaf and adding both subtree results for a branch:

{/* example: examples/learn/focused/recursion-tree.ssrg#declaration */}
```seseragi title="Function declaration"
fn countLeaves tree: Tree -> Int =
  match tree {
    Leaf -> 1
    Branch (left, right) -> {
      let leftCount =
        countLeaves left
      let rightCount =
        countLeaves right
      leftCount + rightCount
    }
  }
```

Use it inside `main`:

{/* example: examples/learn/focused/recursion-tree.ssrg#input */}
```seseragi title="Expression in main"
let pair = Branch (Leaf, Leaf)
Branch (pair, Leaf)
|> countLeaves
|> show
|> println
```

The output is 3. Each Branch visits both children, and reaching Leaf ends that call. Adding the two results remains afterward, so this function is also not tail recursive.

## Choose between recursion and collection operations

A range and `sum` can also express a sum. When a standard traversal describes the goal, use it to make termination and ordering easier to read.

Recursion is useful for recursively shaped data such as trees or for calculations that choose their own next input. [Arrays and lists](/en/docs/learn/arrays-and-lists) explains the cost of repeatedly splitting an Array into head and tail.

## Check the boundaries

Replace 100000 in `main` with 0, 1, and 5. The results are 0, 1, and 15. Removing the base case only keeps decreasing the input without returning a result. When reading recursion, check how each call approaches termination.
