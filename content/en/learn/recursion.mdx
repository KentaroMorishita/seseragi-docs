Recursion is a way of writing a function that calls itself, making the problem a little smaller each time. It can express repetition that is awkward to write with Array functions such as `map` and `reduce`.

This chapter checks the basics with a factorial, then moves on to summing a large range, functions that call each other, and tree-shaped data.

## Check termination with a small example

The factorial of 5 is `5 * 4 * 3 * 2 * 1`. Written recursively:

{/* example: examples/learn/focused/recursion-factorial.ssrg#declaration */}
```seseragi title="Function declaration"
fn factorial n: Int -> Int =
  if n <= 1 then
    1
  else
    n * factorial (n - 1)
```

{/* example: examples/learn/focused/recursion-factorial.ssrg#inputs */}
```seseragi title="Bindings in main"
let zero = factorial 0
let five = factorial 5
```

`zero` is 1 and `five` is 120. When `n <= 1`, it returns 1 and stops; otherwise it calls itself with the smaller `n - 1`. Recursion always needs these two things: a condition for stopping, and an input that gets smaller. Note that this version also returns 1 for negative numbers.

This `factorial` still has a multiplication to do after calling itself. Recursion like this can run out of stack for large inputs. The next example shows a version that is safe for large inputs.

## Choose a base case and the next input

{/* example: examples/learn/recursion.ssrg */}
```seseragi title="recursion.ssrg"
fn sumUpTo limit: Int -> Int = {
  fn loop n: Int -> total: Int
    -> Int =
    if n <= 0 then
      total
    else
      loop (n - 1) (total + n)

  loop limit 0
}

pub effect fn main =
  100000
  |> sumUpTo
  |> show
  |> println
```

```text title="Output"
5000050000
```

When `n` is 0 or less, `loop n total` returns the running total `total` and stops. Otherwise it decreases `n` by one, adds `n` to `total`, and calls itself again.

For a negative number, this `sumUpTo` returns 0. How to treat out-of-range input is up to the person writing the function.

## Functions inside functions

`loop` is a local function declared inside `sumUpTo`. Only `sumUpTo` is visible from outside, so callers do not have to pass the running `total`.

Inside a local function, you can use the function itself and values bound with `let` before it, but not values declared after it. Write the parameter and result types of a recursive function.

## Tail recursion

`loop` returns the result of calling itself directly, with no addition or other work left afterward. Recursion where calling itself is the very last step is called tail recursion.

Seseragi runs tail recursion as a loop. The stack does not grow no matter how many times it repeats, so this example works fine with 100000.

Recursion with work left after the call, such as `n + sumUpTo (n - 1)`, functions that call each other (next section), and calls through a function passed as an argument are not turned into loops. Neither is `effect fn`. See [Performance](/en/docs/reference/performance) for details.

## Group functions that call each other with rec

When local functions call each other, group them with `rec { ... }`. `rec` can be used only inside a function, not at the top level of a file.

{/* example: examples/learn/focused/recursion-mutual.ssrg#declaration */}
```seseragi title="Function declaration"
fn parity n: Int -> String = {
  rec {
    fn even n: Int -> Bool =
      if n == 0 then True
      else odd (n - 1)

    fn odd n: Int -> Bool =
      if n == 0 then False
      else even (n - 1)
  }
  if even n then "even" else "odd"
}
```

`parity 6` is `even` and `parity 7` is `odd`. `even` and `odd` call each other inside the same `rec`.

This example assumes numbers of 0 or more. A negative number never approaches 0, so it never finishes. Functions that call each other are not turned into loops either, so they are not suited to large numbers.

### Walk recursive data

Recursion also fits data that contains values of its own type. `Tree` below is either a leaf, or a branch holding two `Tree`s:

{/* example: examples/learn/focused/recursion-tree.ssrg#data */}
```seseragi title="Type declaration"
type Tree =
  | Leaf
  | Branch (Tree, Tree)
```

To count the leaves, return 1 for a leaf, and for a branch add up the leaves on each side:

{/* example: examples/learn/focused/recursion-tree.ssrg#declaration */}
```seseragi title="Function declaration"
fn countLeaves tree: Tree -> Int =
  match tree {
    Leaf -> 1
    Branch (left, right) -> {
      let leftCount =
        countLeaves left
      let rightCount =
        countLeaves right
      leftCount + rightCount
    }
  }
```

{/* example: examples/learn/focused/recursion-tree.ssrg#input */}
```seseragi title="Expression in main"
let pair = Branch (Leaf, Leaf)
Branch (pair, Leaf)
|> countLeaves
|> show
|> println
```

This prints 3. A branch visits both sides, and reaching a leaf ends that path. The shape of the code follows the shape of the data.

## Recursion or standard functions?

To compute a sum, a range and `sum` also work: `1..=100000 |> sum`. When a standard function can do the job, it shows what the code does more clearly and cannot loop forever.

Recursion shines for nested data such as trees, and for work that decides for itself what to process next.

## Check the boundaries

Replace 100000 in `main` with 0, 1, and 5: the results are 0, 1, and 15. Remove the stopping condition `if n <= 0` and it never finishes. When reading recursion, check that each call moves the input closer to the stopping condition.
