---
title: "Signals"
description: "Read and update changing state through Effects and explicitly compose derived values."
---

Ordinary values are immutable. For state that changes over time, create a `MutableSignal<A>` and read or update it through Effects. Derived values form read-only `Signal<A>` nodes.

## Set a new value

Start with updates and reads, without a derived value. Import `std/signal` as signals at module scope. Put these expressions in the do block of main:

{/* example: examples/learn/focused/signal-set.ssrg#set */}
```seseragi title="Expressions in main do"
count <- signals.make 1
before <- *count
count := 5
after <- *count
```

`before` is 1; `after` is 5. `count := 5` changes the stored state. The earlier snapshot `before` remains 1 after the update. The next example introduces a value calculated from that state.

## Create a source and a derived value

{/* example: examples/learn/signals.ssrg */}
```seseragi title="signals.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  count <- signals.make 1
  let doubled =
    count
    |> signals.map (\n -> n * 2)
  first <- *doubled
  println `before: ${first}`
  signals.update (\n -> n + 1) count
  second <- *doubled
  println `after: ${second}`
}
```

```text title="Output"
before: 2
after: 4
```

`signals.make 1` is a computation that creates a mutable integer Signal. `count <- ...` binds its success value.

`signals.map (\n -> n * 2) count` creates a derived Signal that doubles `count`. The mapping function is pure. Do not put output or asynchronous work inside it.

## Reading is an Effect too

`*doubled` is a `Task<Int>` that reads the current value. It is not a pure integer dereference, so use `first <- *doubled`. The captured `first` is an ordinary immutable integer.

A later Signal update does not change `first`. Read again when you need the updated value. A Signal is neither reassignment of an ordinary `let` binding nor a continuously changing integer value held in that binding.

## Update from the current value

`signals.update (\n -> n + 1) count` transforms the current value and stores the result atomically.

To supply a replacement value directly, write `count := 2`. This operator accepts only MutableSignal targets, not derived Signals such as `doubled` or ordinary bindings. When an update depends on the current value, use `update` instead of separate read and set operations.

## Commit several updates in a transaction

This example updates width and height together and computes their area:

{/* example: examples/learn/signal-transaction.ssrg */}
```seseragi title="signal-transaction.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  width <- signals.make 3
  height <- signals.make 4
  let area =
    signals.combine (*) width height
  signals.transaction [
    signals.planSet 5 width,
    signals.planSet 6 height,
  ]
  current <- *area
  current
  |> show
  |> println
}
```

```text title="Output"
30
```

`combine` supplies both Signal values to `(*)`, the multiplication operator referenced as a curried function value. Its dependencies are explicit arguments, not automatically tracked reads within the function.

`planSet` constructs an update plan, and `transaction` publishes all plans in one commit. Derived values and subscribers do not observe a combination in which only the width has changed. A transaction groups Signal updates; it does not make arbitrary I/O atomic.

## Choose a snapshot or a subscription

One read captures the published value at that time. When reading two Signals separately, an update may occur between reads. For a consistent combination, create a derived Signal with `combine` or a similar operation and read that Signal once. The captured value does not provide a lock against later updates.

Use `subscribe` explicitly to receive subsequent updates. A successful subscription also notifies its observer once with the current value. Release the returned Subscription with `unsubscribe` when it is no longer needed. Constructing a derived Signal or reading it once does not start a subscription.

Setting the same value still notifies by default. Use `distinct` to suppress equal consecutive values. See the [Signal reference](/en/docs/reference/signals) for lifetime and failure rules, and [State and actions](/en/docs/guides/state-and-actions) for connecting state to a view.

### Check subscription startup and cleanup

Record notified integers as a List in another Signal. Place these declarations at module scope. History is an alias for the longer type:

{/* example: examples/learn/focused/signal-subscription.ssrg#callback */}
```seseragi title="Notification recorder"
alias History =
  signals.MutableSignal<List<Int>>

effect fn remember history: History
  -> n: Int -> Unit = {
  let prepend = \seen -> n : seen
  signals.update prepend history
}
```

This observer only updates a Signal and has failure type Never. Main performs Console output. The checked program explicitly declares main's Console environment and failure. This fragment is the beginning of its declaration; place the later code in this do block:

{/* example: examples/learn/focused/signal-subscription.ssrg#entry */}
```seseragi title="Start of main declaration"
pub effect fn main -> Unit
with Console
fails ConsoleError = do {
```

First, prepare the observed state and an empty List for the history:

{/* example: examples/learn/focused/signal-subscription.ssrg#setup */}
```seseragi title="Expressions in main do"
count <- signals.make 0
let empty: List<Int> = `[]
history <- signals.make empty
```

Start subscribing, then change the state once:

{/* example: examples/learn/focused/signal-subscription.ssrg#subscription */}
```seseragi title="Expressions in main do"
let observer = remember history
subscription <-
  count
  |> signals.subscribe observer
count := 1
```

The subscription first reports 0 and then the updated 1. Prepending to the history puts the newest notification first.

{/* example: examples/learn/focused/signal-subscription.ssrg#cleanup */}
```seseragi title="Expressions in main do"
signals.unsubscribe subscription
count := 2
events <- *history
```

Displaying events with show produces this List:

```text title="Recorded values"
`[1, 0]
```

The update to 2 after cleanup is not recorded. This separates a read from the lifetime of an ongoing subscription.

### Reduce notifications for equal values

Use remember above to compare an ordinary subscription with one through distinct. Inside main's do block, create count with 0 and two mutable history Signals, all and unique, from empty Lists. Then use these expressions:

{/* example: examples/learn/focused/signal-distinct.ssrg#views */}
```seseragi title="Expressions in main do"
let distinct = signals.distinct count
let allObserver = remember all
let uniqueObserver = remember unique
normalSub <-
  count
  |> signals.subscribe allObserver
uniqueSub <-
  distinct
  |> signals.subscribe uniqueObserver
```

Give both subscriptions the same updates:

{/* example: examples/learn/focused/signal-distinct.ssrg#updates */}
```seseragi title="Expressions in main do"
count := 1
count := 1
```

| Subscribed Signal | Recorded values |
| --- | --- |
| count | `` `[1, 1, 0] `` |
| distinct | `` `[1, 0] `` |

The ordinary subscription also reports the repeated update to 1; distinct suppresses a value equal to its predecessor. This example unsubscribes both Subscriptions at the end. Distinct changes notification behavior without modifying the source's state.

## Change the update and transformation

Change the first example's update to `\n -> n + 3`; the final output becomes `after: 8`. Change the derived calculation to triple the value; the original increment then changes the result from 3 to 6.

Print `first` again at the end. It remains 2 after the update. Check the difference between the captured snapshot and the derived Signal. Continue to [Type classes](/en/docs/learn/type-classes) to understand operations such as `map` across different types.
