title: "Signals"
description: "Read and update changing state through Effects and explicitly compose derived values."

Values in Seseragi never change once created. Yet you also need state that changes over time, such as how many times a button was pressed. That is what Signals are for.

A `MutableSignal<A>` is a container for state you can change, read and written with Effects. Values computed from state become read-only `Signal<A>`s, and they follow the original state automatically when it changes.

## Set a new value

First, an example that only changes state and reads it back. Import `std/signal` as `signals`:

{/* example: examples/learn/focused/signal-set.ssrg#set */}
```seseragi title="Expressions in main do"
count <- signals.make 1
before <- *count
count := 5
after <- *count
```

`signals.make 1` creates a Signal holding 1. `*count` reads the current value, and `count := 5` changes it. `before` is 1 and `after` is 5. `before`, read earlier, stays 1 after the change.

## Compute a value from state

{/* example: examples/learn/signals.ssrg */}
```seseragi title="signals.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  count <- signals.make 1
  let doubled =
    count
    |> signals.map (\n -> n * 2)
  first <- *doubled
  println `before: ${first}`
  signals.update (\n -> n + 1) count
  second <- *doubled
  println `after: ${second}`
}
```

```text title="Output"
before: 2
after: 4
```

`signals.map (\n -> n * 2) count` creates a Signal representing "twice `count`". When `count` goes from 1 to 2, `doubled` goes from 2 to 4. It is like a spreadsheet formula that refers to another cell: change that cell and the result changes too.

The function passed to `signals.map` should only compute a value. Do not put Effects such as output inside it.

## Reading is an Effect too

`*doubled` is an Effect (`Task<Int>`) that reads the current value. The result depends on when you read it, so it is an Effect rather than an integer. That is why you receive it with `<-`, as in `first <- *doubled`. `first` is then an ordinary integer.

If the Signal changes later, the `first` you already received does not. Read again to get the new value.

## Update based on the current value

`signals.update (\n -> n + 1) count` updates the value to the current value plus 1. The read and the write happen together, so no other update can slip in between.

To set a value directly, write `count := 2`. `:=` works only on a `MutableSignal`, not on a computed Signal such as `doubled`. When the new value depends on the current one, use `update` rather than reading and then using `:=`.

## Group several updates

This example changes width and height together and computes the area:

{/* example: examples/learn/signal-transaction.ssrg */}
```seseragi title="signal-transaction.ssrg"
import * as signals from "std/signal"

pub effect fn main = do {
  width <- signals.make 3
  height <- signals.make 4
  let area =
    signals.combine (*) width height
  signals.transaction [
    signals.planSet 5 width,
    signals.planSet 6 height,
  ]
  current <- *area
  current
  |> show
  |> println
}
```

```text title="Output"
30
```

`signals.combine (*) width height` creates a Signal of the two values multiplied. `(*)` uses multiplication as a function of two arguments. The Signals it depends on are given as arguments; Signals read inside the function are not tracked automatically.

`planSet` creates a plan to set a value, and `transaction` applies all the plans at once. `area` and others never see the in-between state where only the width has changed. `transaction` groups Signal updates only, though; it does not include other work such as writing files.

## Read once, or keep receiving changes

Reading with `*` takes the value at that moment, once. If you read two Signals separately, an update may happen in between. To use two values from the same moment, combine them into one Signal with `combine` or similar, and read it once.

To keep receiving changes, subscribe with `subscribe`. A new subscription first receives the current value, then every update. When you no longer need it, pass the `Subscription` returned by `subscribe` to `unsubscribe`. Creating a computed Signal or reading it once does not start a subscription.

Updating with the same value still sends a notification. To be notified only when the value changes, use `distinct`. The detailed rules for subscriptions are in the [Signal reference](/en/docs/reference/signals), and connecting state to a screen is covered in the [State and actions](/en/docs/guides/state-and-actions) guide.

### Try subscribing and unsubscribing

Record the notified values in a List stored in another Signal. `History` is an alias for the longer type:

{/* example: examples/learn/focused/signal-subscription.ssrg#callback */}
```seseragi title="Notification recorder"
alias History =
  signals.MutableSignal<List<Int>>

effect fn remember history: History
  -> n: Int -> Unit = {
  let prepend = \seen -> n : seen
  signals.update prepend history
}
```

This function just adds the notified value to the front of the List. `main` starts as follows, and the code below goes inside this `do`:

{/* example: examples/learn/focused/signal-subscription.ssrg#entry */}
```seseragi title="Start of main declaration"
pub effect fn main -> Unit
with Console
fails ConsoleError = do {
```

First, prepare the state to watch and an empty List for the record:

{/* example: examples/learn/focused/signal-subscription.ssrg#setup */}
```seseragi title="Expressions in main do"
count <- signals.make 0
let empty: List<Int> = `[]
history <- signals.make empty
```

Start the subscription, then change the state once:

{/* example: examples/learn/focused/signal-subscription.ssrg#subscription */}
```seseragi title="Expressions in main do"
let observer = remember history
subscription <-
  count
  |> signals.subscribe observer
count := 1
```

The subscription reports 0 when it starts, then the updated 1. Values are added to the front of the List, so the newest comes first.

{/* example: examples/learn/focused/signal-subscription.ssrg#cleanup */}
```seseragi title="Expressions in main do"
signals.unsubscribe subscription
count := 2
events <- *history
```

Displaying `events` gives:

```text title="Recorded values"
`[1, 0]
```

The 2 set after unsubscribing is not recorded.

### Skip notifications for the same value

Using `remember` from above, compare an ordinary subscription with one through `distinct`. Create `count` with 0 and two records, `all` and `unique`, holding empty Lists, then write:

{/* example: examples/learn/focused/signal-distinct.ssrg#views */}
```seseragi title="Expressions in main do"
let distinct = signals.distinct count
let allObserver = remember all
let uniqueObserver = remember unique
normalSub <-
  count
  |> signals.subscribe allObserver
uniqueSub <-
  distinct
  |> signals.subscribe uniqueObserver
```

Update with the same value twice:

{/* example: examples/learn/focused/signal-distinct.ssrg#updates */}
```seseragi title="Expressions in main do"
count := 1
count := 1
```

| Subscribed Signal | Recorded values |
| --- | --- |
| count | `` `[1, 1, 0] `` |
| distinct | `` `[1, 0] `` |

The ordinary subscription receives both updates to 1. Through `distinct`, a value equal to the previous one is skipped. `distinct` does not change `count` itself, only how notifications are sent. (This example also unsubscribes both at the end.)

## Change the update and transformation

In the second example, change the update to `\n -> n + 3`: the last line becomes `after: 8`. Change `doubled` to triple the value: it prints `before: 3` and `after: 6`.

Print `first` again at the end: it is still 2 after the update. This shows the difference between a value read once and a Signal that follows the state.
