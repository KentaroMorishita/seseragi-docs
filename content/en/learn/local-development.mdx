---
title: Local development
description: Install the CLI, run a source file, and start developing and building a Web app.
---

To use Seseragi on your machine, you need two things: the CLI and Bun. If you only want to try it, the [Playground](https://seseragi.vercel.app/) runs in your browser with nothing to install.

## Install the CLI and Bun

[Download the CLI](https://github.com/KentaroMorishita/seseragi/releases) archive for your operating system and CPU. Extract it and place `seseragi` in a directory on your PATH. The archive also includes the LSP.

Install Bun using its [official instructions](https://bun.sh/docs/installation). You do not need Rust when using the prebuilt CLI.

Run both commands in your terminal. If each prints a version, you are ready:

```sh
seseragi --version
bun --version
```

## Run a source file

Save the code from [Your first program](/en/docs/learn/first-program#display-one-line) as `hello.ssrg`. Run it from the directory containing the file:

```sh
seseragi run hello.ssrg
```

It prints one line:

```text
Hello, Seseragi!
```

## Edit in VS Code

The same download page has a VSIX file for the VS Code extension. Download the one for your operating system and CPU, run “Extensions: Install from VSIX...” from the VS Code command palette, and select the file.

The VSIX includes the LSP, so there is nothing else to install.

## Create a Web app

Create a new Web app project. Run this where no `hello-web` directory exists yet:

```sh
seseragi new web hello-web
cd hello-web
```

This generates `seseragi.toml`, `seseragi.lock`, `src/app.ssrg`, and `src/main.ssrg`. The app's state and view live in `app.ssrg`; `main.ssrg` displays them on the browser page.

## Develop in the browser

Start the development server from the project directory:

```sh
seseragi dev --open
```

Your browser opens `http://127.0.0.1:3000/`. Every time you save a source file, the app is rebuilt and the browser reloads.

## Build for publishing

Stop the development server with `Ctrl-C`, then build from the same directory:

```sh
seseragi build .
```

The `dist/` directory now contains HTML, JavaScript, CSS, and other static files. To publish the app, serve its contents from any static host.

## After changing dependencies

`seseragi.lock` pins the packages and settings your project uses. Update it after changing dependencies or `seseragi.toml`, or the code a dependency package exports:

```sh
seseragi lock update
```

If the lockfile is missing or out of date, `run`, `dev`, and `build` stop with `SES-K0102`. The lockfile is never updated automatically, so unintended changes cannot slip in. When you see the error, check what changed before updating.
