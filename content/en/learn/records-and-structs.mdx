This chapter shows how to group several values into one. At the end, you write a function that takes a point and returns a new point shifted to the right, without changing the original.

The code in this chapter uses [Pipelines](/en/docs/learn/pipelines) for `|>` and `show`. The `do { ... }` in `main` runs the steps inside it from top to bottom; [Effects](/en/docs/learn/effects) covers it in detail.

## A record's type is its shape

`{ x: 1, y: 2 }` is a record with named fields. It works almost exactly like a TypeScript object literal, and its type is `{ x: Int, y: Int }`. Read a field with `point.x`.

A record's type is decided by its shape: which fields it has. This function accepts any record that has a `name`:

{/* example: examples/learn/focused/record-fields.ssrg#declaration */}
```seseragi title="Function declaration"
fn nameOf value: { name: String }
  -> String = value.name
```

`{ name: "Aki", score: 42 }` has `name: String`, so you can pass it even with the extra `score`. This is the same structural typing as TypeScript. A record without `name`, or with a `name` of another type, is rejected.

{/* example: examples/learn/focused/record-fields.ssrg#use */}
```seseragi title="Expression in main"
{ name: "Aki", score: 42 }
|> nameOf
|> println
```

This prints `Aki`. The function's type tells you which fields it uses.

## A struct is identified by its name

`struct` declares a named type. Unlike a record, a struct with a different name is a different type, even if the shape is the same.

First, declare `Point`:

{/* example: examples/learn/focused/struct-fields.ssrg#declaration */}
```seseragi title="Struct declaration"
struct Point {
  x: Int,
  y: Int,
}
```

Create a value with `Point { ... }` and read a field with `.x`:

{/* example: examples/learn/focused/struct-fields.ssrg#access */}
```seseragi title="Expression in main"
let point = Point { x: 3, y: 4 }
point.x
|> show
|> println
```

This prints 3.

Now declare `Size`, with exactly the same fields as `Point`:

{/* example: examples/learn/focused/struct-nominal-error.ssrg#size */}
```seseragi title="Another struct"
struct Size {
  x: Int,
  y: Int,
}
```

This function takes a `Point`:

{/* example: examples/learn/focused/struct-nominal-error.ssrg#declaration */}
```seseragi title="Function declaration"
fn readX point: Point -> Int =
  point.x
```

Passing a `Size` to it is a compile error:

{/* example: examples/learn/focused/struct-nominal-error.ssrg#invalid */}
```seseragi title="Bindings with a type error"
let size = Size { x: 3, y: 4 }
let wrong = readX size
```

`readX size` passes a `Size` where a `Point` is required, so it fails with `SES-T0101`. Types with different names cannot be mixed up, even when their fields match. This helps when values have the same shape but different meanings, such as a position and a size.

### Change part of a record with spread

Records support the same `...` spread syntax as TypeScript, so you can copy a record with some fields changed:

{/* example: examples/learn/focused/record-spread.ssrg#update */}
```seseragi title="Bindings in main"
let base = { name: "Aki", score: 30 }
let next = { ...base, score: 42 }
```

`next.score` is 42 and `next.name` is `"Aki"`, taken from `base`. `...base` copies the fields, and the `score` written after it overrides one. `base.score` is still 30.

## Produce an updated value

{/* example: examples/learn/records-and-structs.ssrg */}
```seseragi title="records-and-structs.ssrg"
struct Point {
  x: Int,
  y: Int,
}

fn moveX amount: Int
  -> point: Point -> Point =
  Point {
    ...point,
    x: point.x + amount,
  }

pub effect fn main = do {
  let start = Point { x: 1, y: 2 }
  let moved = moveX 3 start
  println `${start.x}, ${start.y}`
  println `${moved.x}, ${moved.y}`
}
```

```text title="Output"
1, 2
4, 2
```

`moveX 3 start` returns a new `Point` with 3 added to `start.x`. Structs support spread too: `Point { ...point, x: ... }` takes the original fields and replaces only `x`. `start` is still `1, 2`.

Creating a struct requires every field. With spread, a struct takes one value of the same type, placed first. A record can stack several records from left to right. [Data types](/en/docs/reference/data-types) lists the detailed differences.

## Destructure a value

Patterns take values out of tuples, records, and structs, much like TypeScript's destructuring. For example, inside `moveX` you could write:

```seseragi
let Point { x, y } = point
let offset = { x: amount, y: 0 }
let { x: dx, y: dy } = offset
```

`x: dx` takes the value of field `x` and names it `dx` (the same as TypeScript's `const { x: dx } = offset`). A struct pattern includes the type name, as in `Point { x, y }`; a record pattern does not.

Try it. First, create a record:

{/* example: examples/learn/focused/record-decomposition.ssrg#point */}
```seseragi title="Binding in main"
let point = { x: 3, y: 4 }
```

Take the fields out under different names:

{/* example: examples/learn/focused/record-decomposition.ssrg#rename */}
```seseragi title="Binding in main"
let { x: dx, y: dy } = point
```

`dx` is 3 and `dy` is 4.

## Records or structs?

When a function uses only a few fields, a record type says "this is all I need". When the type's name should tell meanings apart, such as a position, an amount, or an ID, use a struct or a [newtype](/en/docs/reference/data-types).

Structs can have methods, but they do not need to be objects that change themselves. An ordinary function that takes a `Point` and returns a new `Point`, like `moveX`, is enough.
