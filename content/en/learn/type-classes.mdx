The same `map` works on both Array and Maybe because each type has its own implementation of `map`. A type class is what groups "types that support this operation". It is close to a TypeScript `interface`, but a type class attaches implementations to types rather than to values.

This chapter uses a standard type class first, then defines your own type class for displaying values.

## Use a standard operation as a constraint

The `==` you have been using is an operation of the `Eq` type class. To use `==` in a generic function, add the condition "`A` implements `Eq`" with `where`:

{/* example: examples/learn/focused/type-class-eq.ssrg#declaration */}
```seseragi title="Function declaration"
fn same<A> left: A -> right: A
  -> Bool where Eq<A> =
  left == right
```

{/* example: examples/learn/focused/type-class-eq.ssrg#calls */}
```seseragi title="Expression in main do"
println $ show $ same 42 42
println $ show $ same "Aki" "Aki"
println $ show $ same [1, 2] [2, 1]
```

The results are `True`, `True`, and `False`. The body of `same` stays the same, but it uses the `Eq` implementation for `Int`, `String`, and Array in turn. Array comparison also compares the order of elements, so the last one is `False`.

## Declare a type class with trait

Now define your own type class. First, declare its operations with `trait`:

{/* example: examples/learn/focused/type-class-instances.ssrg#trait */}
```seseragi title="Trait declaration"
trait Render<A> {
  fn render value: A -> String
}
```

Next, write the target type and its implementation:

{/* example: examples/learn/focused/type-class-instances.ssrg#badge */}
```seseragi title="Type and instance"
struct Badge {
  label: String,
}

instance Render<Badge> {
  fn render value: Badge -> String =
    value.label
}
```

`trait Render<A>` is a promise: "has an operation `render` that takes an `A` and returns a `String`". A `trait` contains only types, no bodies.

`instance Render<Badge>` writes the body of `render` for `Badge`. With that, `Badge` keeps the `Render` promise.

## State a requirement with where

`framed<A>` below requires "`A` implements `Render`" with `where Render<A>`. Because of that condition, its body can call `render value`.

{/* example: examples/learn/focused/type-class-instances.ssrg#framed */}
```seseragi title="Function declaration"
fn framed<A> value: A -> String
where Render<A> =
  `<${render value}>`
```

Pass a `Badge` to `framed`:

{/* example: examples/learn/focused/type-class-instances.ssrg#badge-use */}
```seseragi title="Expression in main"
Badge { label: "ADMIN" }
|> framed
|> println
```

This prints `<ADMIN>`.

`Badge` has a `Render` instance, so it can be passed to `framed`. Passing a type without an instance is a compile error. Which implementation to use is decided at compile time; values are never inspected at run time to find one.

## Use one operation with different types

The standard `map` is an operation of the `Functor` type class. It transforms each element of an Array, the content of a `Just`, and the content of a `Right`. Each implements the same promise: "keep the outer shape and transform only the content".

Likewise, `Show` turns values into strings and `Eq` checks equality. Each type class has a fixed meaning; sharing a name does not mean anything goes.

## Create instances automatically

Add `deriving` to create `Eq` and `Show` instances automatically:

{/* example: examples/learn/deriving.ssrg */}
```seseragi title="deriving.ssrg"
type Phase deriving Eq, Show =
  | Ready
  | Done

pub effect fn main = do {
  println $ show $ Ready == Ready
  println (show Done)
}
```

```text title="Output"
True
Done
```

For a type with payloads or fields, the types inside must implement the same type class. For example, a type with a field lacking `Show` cannot derive `Show`. Type classes you define yourself, such as `Render`, cannot be derived.

### Derive operations for a type with fields

A struct with fields can derive `Eq` and `Show` too:

{/* example: examples/learn/focused/type-class-derived-fields.ssrg#declaration */}
```seseragi title="Struct declaration"
struct Point deriving Eq, Show {
  x: Int,
  y: Int,
}
```

Create two values that differ only in `y`:

{/* example: examples/learn/focused/type-class-derived-fields.ssrg#values */}
```seseragi title="Bindings in main do"
let left = Point { x: 1, y: 2 }
let right = Point { x: 1, y: 3 }
```

Compare and display them:

{/* example: examples/learn/focused/type-class-derived-fields.ssrg#comparison */}
```seseragi title="Expression in main do"
println $ show $ left == right
```

{/* example: examples/learn/focused/type-class-derived-fields.ssrg#display */}
```seseragi title="Expression in main do"
println $ show left
```

```text title="Output"
False
Point { x: 1, y: 2 }
```

The derived `Eq` compares fields one by one, and `Show` turns the type name and fields into a string. The `Int` fields have `Eq` and `Show`, so `Point` can derive them too.

## Rules for instances

A type can have only one instance of a given type class. An instance can be written only in the module that declares the `trait` or the module that declares the target type. Thanks to this rule, adding one import can never silently switch to another implementation.

Methods in `impl Badge` and `instance Render<Badge>` are different things. A method is an operation of that type alone; an instance implements a type class's promise. Type classes are not class inheritance.

The compiler checks types only. It does not check the properties a type class expects, such as "`a == a` is always `True`". When you write your own instance, check those with tests. See the [type class reference](/en/docs/reference/type-classes) for details.

### Define a second instance

Implement `Render` for another type:

{/* example: examples/learn/focused/type-class-instances.ssrg#tag */}
```seseragi title="Type and instance"
struct Tag {
  text: String,
}

instance Render<Tag> {
  fn render value: Tag -> String =
    `#${value.text}`
}
```

Pass it to the same `framed`:

{/* example: examples/learn/focused/type-class-instances.ssrg#tag-use */}
```seseragi title="Expression in main"
Tag { text: "help" }
|> framed
|> println
```

This prints `<#help>`. `Tag`'s `render` adds `#` in front, and `framed` wraps it in `< >`. Without rewriting `framed`, adding an instance is enough to support a new type.

## Try it

Put the `Badge` and `Tag` examples in one file and pass both to `framed`. Then delete `instance Render<Tag>` and check that the line passing a `Tag` to `framed` becomes an error.
