In Seseragi, types describe the shape of your data, functions transform it, and Effects describe output and changes to state. This course builds those ideas step by step, with small programs you run as you read.

If you have used functions, arrays, objects, and conditionals, you are ready. You do not need to know algebraic data types or type classes. For a quick comparison with TypeScript first, read [Coming from TypeScript](/en/docs/guides/typescript-to-seseragi).

## Run your first program

[Your first program](/en/docs/learn/first-program) prints one line of text and then changes it. [Local development](/en/docs/learn/local-development) sets up the CLI and editor so you can run the same program on your machine.

Each example comes with a file name and its output. Short excerpts are labeled with where they belong, such as "Function declaration" or "Expression inside main".

Run each example as it is first. Each chapter ends with exercises that change one value or type. Predict the result before you run it; comparing the two shows how types and evaluation work.

## 1. Transform values with functions

| Chapter | What you learn |
| --- | --- |
| [Values and expressions](/en/docs/learn/values-and-expressions) | Immutable values, types, blocks, and conditionals |
| [Functions](/en/docs/learn/functions) | Declaring and calling functions, partial application, lambdas |
| [Pipelines](/en/docs/learn/pipelines) | Chaining functions in the order they run with `|>` |
| [The application operator](/en/docs/learn/application-operator) | Removing nested parentheses with `$` |

Try naming a value, choosing a value with a condition, and calling a function one at a time, then combine functions. You also meet the difference between an `fn` that only returns a value and an `effect fn` that performs output.

## 2. Describe data and states

| Chapter | What you learn |
| --- | --- |
| [Records and structs](/en/docs/learn/records-and-structs) | Group values and produce updated values without changing the originals |
| [Algebraic data types](/en/docs/learn/algebraic-data-types) | Describe possible states as cases |
| [Pattern matching](/en/docs/learn/pattern-matching) | Select cases and extract their data |
| [Arrays and lists](/en/docs/learn/arrays-and-lists) | Transform, filter, and summarize collections |
| [Maybe and Either](/en/docs/learn/maybe-and-either) | Distinguish an absent value from a failure with a reason |

Once the shape of your data is fixed, so are the inputs a function accepts and the cases it must handle. Instead of giving `null` several meanings or adding Boolean flags, you learn to describe the state itself as a type.

## 3. Reuse behavior and use recursion

| Chapter | What you learn |
| --- | --- |
| [Generics](/en/docs/learn/generics) | Functions and data types that work with different types |
| [Recursion](/en/docs/learn/recursion) | Base cases, local functions, and tail recursion |

Generics let the same code work when the data type changes. Recursion solves a problem by calling the same function on a smaller input.

## 4. Compose interactions with the outside world

| Chapter | What you learn |
| --- | --- |
| [Effects](/en/docs/learn/effects) | Delayed computation, `do`, environments, and typed failures |
| [Signals](/en/docs/learn/signals) | Reading and updating state, derived values, and transactions |

After that, follow the [CLI applications](/en/docs/guides/cli-app) or [Web applications](/en/docs/guides/web-app) guide to build an app with input, output, and a user interface.

## Look up a specific rule

Learn explains ideas in order. To look up syntax and detailed rules, use the [Reference](/en/docs/reference); to find a standard function, the [standard library](/en/docs/reference/library); for commands, the [CLI reference](/en/docs/reference/cli).

Every example on these pages has been run with the CLI. The language and tools are still under development, so results may change in newer versions.
