
## Choosing operations

- DOM operations require the browser Dom capability. Rendering Html on a process target is separate from manipulating a real DOM.
- DomContent pairs initial Html with an explicit binding plan. Leaf updates preserve Element identity/focus; a region owns its children.
- Actions dispatch sequentially through a bounded FIFO. Overflow is failure, not silent dropping or conversion to parallel handlers.
- Mount listeners, subscriptions, and dispatch work share a scope. Failure, cancellation, and unmount release them; preserving DOM during cleanup does not preserve listeners.
- Keys identify direct siblings within one region. They are not global IDs or implicit component-state identities.

### `DomOptions`

<small className="api-kind">Struct</small>

```text
struct DomOptions {
  eventCapacity: Int,
  hydration: HydrationMode,
  cleanup: CleanupMode
}
```

- `eventCapacity`: Capacity of the queue for Actions from DOM events.
- `hydration`: Policy for existing DOM during the initial mount.
- `cleanup`: Policy for rendered DOM when the mount is released.

### `ElementRect`

<small className="api-kind">Struct</small>

```text
struct ElementRect {
  x: Float,
  y: Float,
  width: Float,
  height: Float,
  top: Float,
  right: Float,
  bottom: Float,
  left: Float
}
```

- `x`: The measured rectangle's x coordinate.
- `y`: The measured rectangle's y coordinate.
- `width`: The measured rectangle's width.
- `height`: The measured rectangle's height.
- `top`: The measured rectangle's top edge.
- `right`: The measured rectangle's right edge.
- `bottom`: The measured rectangle's bottom edge.
- `left`: The measured rectangle's left edge.
