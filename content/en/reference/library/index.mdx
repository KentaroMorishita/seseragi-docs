This reference covers 1,452 public names across 63 standard library interfaces, including Prelude. Choose a module below, then look up its types and functions.

## Read the types

Function arguments are curried. Types are listed in argument order, followed by the result. Most collection operations take their subject last, so you can use a [vertical pipeline](/en/docs/learn/pipelines). A `where` clause lists the required [type classes](/en/docs/reference/type-classes). These signatures are type notation, not executable declarations.

`Effect<R, E, A>` describes requirements, typed failure, and success. An imported module does not execute an Effect or supply its provider. See [Effect](/en/docs/reference/effects) and [runtime providers](/en/docs/reference/runtime-providers). Opaque types hide their representation; do not assume every error type has a `Show` instance.

## Execution environments

`process` means a CLI/server process; `browser` means a Web app or Playground browser execution. A portable interface can still require a capability supported by the chosen provider. Check requirements and failures in each signature, not only the module's target list.
