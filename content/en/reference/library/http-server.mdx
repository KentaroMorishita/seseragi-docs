
## Choosing operations

- The current request body is a Bytes snapshot. Decode text/JSON explicitly rather than manipulating a host Request object.
- Server-boundary handlers have Never failure. Map application errors to responses with recoverHandler or recovery instead of relying on implicit 500 responses.
- Servers and requests have parent/child resource scopes. Close, client disconnect, and root cancellation end request work or stream bodies and perform cleanup.
- streamResponse chunks must be nonempty and at most 64 KiB. Send according to write demand, keeping defects/cancellation separate from typed startup failures.
