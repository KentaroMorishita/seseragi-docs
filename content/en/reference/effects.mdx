Absence, recoverable failure, and external operations are represented in values and types. Seseragi has no `null`, `throw`, or `try/catch` syntax for ordinary control flow.

## Maybe, Either, and Effect

| Type | Meaning | Evaluation or execution |
| --- | --- | --- |
| `Maybe<A>` | `Nothing` or `Just A` | An evaluated value |
| `Either<E, A>` | `Left E` or `Right A` | An evaluated synchronous result |
| `Effect<R, E, A>` | Requires `R`, fails with `E` or succeeds with `A` | A deferred computation |
| `Task<A>` | `Effect<{}, Never, A>` | Deferred, no environment or typed failure |

Use Maybe when absence is normal, Either for a synchronous failure with a reason, and Effect for operations that must execute. Task is a transparent Effect alias, not a separate Promise type.

`maybe ?? fallback` returns the payload of Just and evaluates the fallback only for Nothing. It associates right, and the right operand has the result type `A`. It does not apply to Either or foreign nullable values.

## Construction and execution

Effects are cold. Constructing one does not execute it; running the same Effect twice performs its computation twice. `map` changes success values; `flatMap` and `do` sequence computations.

{/* example: examples/reference/effects.ssrg */}

```seseragi title="effects.ssrg"
import * as effects from "std/effect"

type InputError deriving Show =
  | BelowZero

fn nonNegative value: Int
  -> Effect<{}, InputError, Int> =
  if value < 0 then
    effects.fail BelowZero
  else
    effects.succeed value

pub effect fn main = do {
  let answer =
    nonNegative (-2)
    |> effects.recover (\_ ->
      effects.succeed 0)
  value <- answer
  value
  |> show
  |> println
}
```

`nonNegative (-2)` constructs a computation failing with BelowZero. `recover` replaces that typed failure with success 0; `value <- answer` binds the execution result. The program prints 0.

A general Effect run operation is not exposed to ordinary code. Hosts execute Effects at explicit boundaries such as public main, tests, or callback adapters. A do block sequences operations. Parallelism must be requested with an operation such as `effects.parallel`; the compiler does not automatically parallelize sequential effects.

### Executing the same Effect twice

{/* example: examples/reference/effect-execution.ssrg#announce */}

```seseragi title="Declaration: an output computation"
effect fn announce text: String =
  println text
```

After declaring announce, place the next fragment inside the do block of main. A block returning a plain value and a do block sequencing Effects have different roles.

{/* example: examples/reference/effect-execution.ssrg#cold */}

```seseragi title="Main do block: construction and two runs"
let job = announce "ran"
println "constructed"
job
job
```

The outputs are constructed, ran, and ran. The first let constructs the computation; the two later job expressions each execute it.

### Mapping success and binding the result

These fragments belong inside the same do block of main, where `effects` aliases `std/effect`. Mapping creates a `Task<Int>`; it does not extract its result as a plain value.

{/* example: examples/reference/effect-execution.ssrg#map-task */}

```seseragi title="Main do block: composing a Task"
let calculation =
  effects.succeed 21
  |> map (\n: Int -> n * 2)
println "mapped"
```

{/* example: examples/reference/effect-execution.ssrg#execution */}

```seseragi title="Main do block: receiving the result"
value <- calculation
value
|> show
|> println
```

After `mapped` is printed, `calculation` executes and yields 42 for output. `let` and `<-` have different roles here.

## Two effect fn forms

The compact form writes `=` immediately after the parameters. It infers `R`, `E`, and `A` from the body and stores a normalized Effect type in the public interface.

```seseragi title="Compact form"
effect fn greet name: String =
  println $ `Hello, ${name}`
```

The contract form starts with the success type and fixes the environment and error in the source.

```seseragi title="Contract form"
effect fn greet name: String -> Unit
with Console
fails ConsoleError =
  println $ `Hello, ${name}`
```

In a contract form, omitted `with` means `{}` and omitted `fails` means Never; neither is filled in from the body. There is no intermediate form adding only with/fails to a compact declaration. Both forms require an Effect body; ordinary values are not implicitly lifted.

### Inferred and explicit contracts

These declaration fragments use effects as the std/effect alias. Both return an Effect with empty requirements, Never failure, and Int success.

{/* example: examples/reference/effect-contracts.ssrg#compact */}

```seseragi title="Declaration: compact form"
effect fn compact value: Int =
  effects.succeed value
```

{/* example: examples/reference/effect-contracts.ssrg#contract */}

```seseragi title="Declaration: contract form"
effect fn contract value: Int
  -> Int =
  effects.succeed value
```

{/* example: examples/reference/effect-contracts.ssrg#run-contracts */}

```seseragi title="Main do block: using the computations"
first <- compact 4
second <- contract 5
println `${first}: ${second}`
```

The output is 4: 5. Omitting with/fails in contract form specifies an empty environment and Never, respectively.

### No implicit lifting of plain values

This is intentionally invalid. Even compact form requires an Effect body; answer returning a plain Int produces SES-T0101.

{/* example: examples/reference/invalid/pure-effect.ssrg#invalid */}

```seseragi title="Intentional Effect type error"
effect fn answer = 42

pub effect fn main =
  println "ready"
```

## Combining environments and failures

`R` is a record of required service fields. Composition takes their union, requiring identical types for shared names. Optional requirements are forbidden. `with Console` expands to the canonical requirement `{ console: Console }`. Supply environments explicitly with provide.

An Effect with fewer requirements can widen to a record containing all of its fields with identical types. Generic signatures may use a merge such as `R & { clock: Clock }` only in the first type argument of Effect or Stream. This is not a general intersection type.

Failures do not form automatic unions. Map distinct errors to an application ADT with mapError, or handle them with recover. Never alone may widen to a required error type, allowing Signal Tasks inside a fallible do block. Success types must remain consistent across the composition.

## Typed failure, defects, and cancellation

| Outcome | Treatment |
| --- | --- |
| Typed failure | A designed, recoverable error in `E`; handled by recover |
| Defect | Overflow, zero division, boundary-contract violations; not catchable by ordinary code |
| Cancellation | Interruption from host or parent; not converted to a typed error |

recover catches neither defects nor cancellation. A [TypeScript adapter](/en/docs/reference/typescript-interop) turns external throws/rejections into typed failures. Expected input errors belong in Either or an Effect error type, not in defects.

## Resources and entry points

Use `bracket acquire use release` or acquireRelease to register resources with a scope. Finalizers run once, in reverse order, on success, failure, or cancellation. The handoff from successful acquisition to finalizer registration is atomic against cancellation. A finalizer cannot leave a typed failure unhandled.

main is public, takes one unnamed Unit parameter, and returns an Effect succeeding with Unit. Requirements must be a record with a fully determined field set, and the failure type must be concrete. A non-Never error needs a Show instance. Unsupported services are rejected before execution rather than becoming missing services at runtime.

## Iteration with for

Use `for` inside an Effect to process elements of an Array, List, or Range sequentially. Each iteration runs in order and discards its result before moving to the next element.

{/* example: examples/reference/effect-for.ssrg#for-loop */}

```seseragi title="effect-for.ssrg"
pub effect fn main =
  for n <- 1..=3 {
    println $ show n
  }
```

This prints `1`, `2`, and `3` in order. The pattern on the left of `<-` must be irrefutable.

## Reading and providing environments

`effects.service` reads a value from the current environment record. `effects.provide` supplies the entire environment, while `effects.provideSome` transforms the outer environment to add or replace specific fields while forwarding the rest.

{/* example: examples/reference/effect-environment.ssrg#service-read */}

```seseragi title="Declaration: read from environment with service"
fn announce label: String
  -> Effect<{ settings: Settings, console: Console }, ConsoleError, Unit> = do {
  cfg <- effects.service (\env -> env.settings)
  println `${cfg.prefix}: ${label}`
}
```

{/* example: examples/reference/effect-environment.ssrg#provide-env */}

```seseragi title="Declaration and main: supply one field with provideSome"
fn withPrefix<E, A> prefix: String
  -> op: Effect<{ settings: Settings, console: Console }, E, A>
  -> Effect<{ console: Console }, E, A> =
  effects.provideSome (\env -> {
    settings: Settings { prefix: prefix },
    console: env.console,
  }) op

pub effect fn main =
  announce "ready"
  |> withPrefix "app"
```

`withPrefix` supplies `settings` while forwarding `console` from the caller's environment. The output is `app: ready`.

## Composing concurrency and schedules

Use `effects.fork` to start a child Fiber and `effects.join` to wait for it. Coordinate values across Fibers with `std/queue`, bound concurrency with `std/semaphore`, and retry or repeat Effects with a `Schedule` from `std/effect`.

The following functions exchange two strings between Fibers through a Queue:

{/* example: examples/reference/effect-concurrency/src/main.ssrg#fiber-queue */}

```seseragi title="Declarations: Fiber and Queue"
effect fn drain q: queues.Queue<String>
  -> Unit with Console fails WorkerError = do {
  first <-
    queues.take q
    |> effects.mapError QueueFailure
  second <-
    queues.take q
    |> effects.mapError QueueFailure
  println `${first}, ${second}`
  |> effects.mapError ConsoleFailure
}

effect fn sendTwice -> Unit with Console fails WorkerError = do {
  q <- queues.unbounded ()
  worker <- effects.fork (drain q)
  queues.offer "one" q
  |> effects.mapError QueueFailure
  queues.offer "two" q
  |> effects.mapError QueueFailure
  effects.join worker
}
```

Next, `Semaphore` guards each attempt while `effects.recurs` and `effects.retry` handle retries. Because `effects.retry` tracks timing, it adds `Clock` to the requirements:

{/* example: examples/reference/effect-concurrency/src/main.ssrg#semaphore-schedule */}

```seseragi title="Declarations: Semaphore and Schedule"
effect fn tryOnce sem: semaphores.Semaphore -> attempts: refs.Ref<Int>
  -> Int fails String =
  semaphores.withPermit sem $ do {
    n <- refs.modify (\c: Int -> (c + 1, c + 1)) attempts
    if n < 2 then effects.fail "busy" else effects.succeed n
  }

effect fn retryWithPermit -> Unit with Console, Clock fails WorkerError = do {
  sem <-
    semaphores.make 1
    |> effects.mapError SemaphoreFailure
  attempts <- refs.make 0
  policy <-
    effects.recurs<String> 2
    |> effects.fromEither
    |> effects.mapError ScheduleFailure
  done <-
    effects.retry policy (tryOnce sem attempts)
    |> effects.mapError (\_ -> QueueFailure queues.QueueClosed)
  println `attempts: ${done}`
  |> effects.mapError ConsoleFailure
}
```

Running `sendTwice` followed by `retryWithPermit` prints `one, two` and `attempts: 2`. See [std/effect](/en/docs/reference/library/effect), [std/queue](/en/docs/reference/library/queue), and [std/semaphore](/en/docs/reference/library/semaphore) for full signatures.
