---
title: Build components
description: Reuse a pure function that turns props into HTML in a browser view and SSR.
---

Pull a delivery-status card out into a function that takes a title and a description and returns HTML. A Seseragi component is just an ordinary `fn`, with no special machinery. Because building HTML is separate from displaying it in the browser, the same function works in the browser and for producing an HTML string.

Props use [records](/en/docs/learn/records-and-structs), and the Action type uses [generics](/en/docs/learn/generics). The `main` that shows the screen also uses [Effects](/en/docs/learn/effects) and imports from [Modules](/en/docs/learn/modules).

## Define props

The card needs two strings, `title` and `detail`. They become a record type, `CardProps`.

Pass props only the values needed to build the view. A component does not read or write state itself; if it needs state, the parent that owns the state passes in the current value.

## Write the complete card

Save the following as `components.ssrg`.

{/* example: examples/guides/components.ssrg */}
```seseragi title="components.ssrg"
import * as html from "std/web/html"

alias CardProps = {
  title: String,
  detail: String
}

fn card<Action> props: CardProps
  -> html.Html<Action> =
  html.section {
    class: "card",
    children: [
      html.h2<Action, String> {
        children: props.title
      },
      html.p<Action, String> {
        children: props.detail
      }
    ]
  }

pub effect fn main =
  card {
    title: "Delivery",
    detail: "Sent to Kyoto"
  }
  |> html.renderToString
  |> println
```

The `Action` in `card<Action>` is the type of events this HTML sends. The card sends none, so making it a type parameter lets it fit into a view of any Action type. `html.h2<Action, String>` spells out the Action type and the child type.

A string can be a child as is. Convert numbers with `show`. To mix strings and HTML in a children array, wrap the strings with `html.text`.

## Render HTML

```sh
seseragi run components.ssrg
```

It prints one line of HTML with an `h2` and a `p` inside a `section`. With line breaks added for readability:

```html
<section class="card">
  <h2>Delivery</h2>
  <p>Sent to Kyoto</p>
</section>
```

`renderToString` only builds an HTML string; `println` is what displays it.

## Compare different props

Try an even smaller badge that displays a single piece of text. Write the following two blocks in order in `component-props.ssrg`.

{/* example: examples/guides/component-props.ssrg#badge */}
```seseragi title="component-props.ssrg"
import * as html from "std/web/html"

alias BadgeProps = { label: String }

fn badge props: BadgeProps
  -> html.Html<Never> =
  html.span {
    class: "badge",
    children: props.label
  }
```

The badge sends no events, so its Action type is `Never`. The same `label` always gives the same HTML.

{/* example: examples/guides/component-props.ssrg#labels */}
```seseragi title="component-props.ssrg"
pub effect fn main = do {
  badge { label: "Ready" }
  |> html.renderToString
  |> println
  badge { label: "Waiting" }
  |> html.renderToString
  |> println
  badge { label: "<script>" }
  |> html.renderToString
  |> println
}
```

```sh
seseragi run component-props.ssrg
```

The first two lines are HTML showing `Ready` and `Waiting` in a `span`. The third passes `"<script>"`, which is displayed as plain text, not a tag. With line breaks for readability:

```html
<span class="badge">
  &lt;script&gt;
</span>
```

This example also confirms that prop strings are never interpreted as HTML.

## Call it from a Web view

You can place `card { title: "Delivery", detail: "Sent to Kyoto" }` as a child in the `view` from [Build a Web application](/en/docs/guides/web-app).

For a component that sends events, such as a button, take the Action to send on click as a prop too. The component never changes the parent's state directly; it only sends the Action the parent gave it, much like passing a callback prop in React.

## Preserve safe rendering

The `title` and `detail` strings are escaped automatically. Passing `"<script>"` just displays those characters; it never runs as a script.

URLs for links and images take a validated `WebUrl` type. Validate strings with `parseWebUrl`, and handle failure through the type as well. The detailed rules for props and rendering are in the [Web UI reference](/en/docs/reference/web-ui).

## Separate stateful parts

Passing the current value into components suits showing the same state in several places. When each part needs its own state, use the approach in [Stateful features](/en/docs/guides/stateful-features), which places two counters side by side, each working independently.
