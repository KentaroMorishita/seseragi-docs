description: Read a quantity from standard input, validate it, and print a total.

Read a one-line quantity and print its total at a unit price of 480. Accept integers from 1 through 1000. Keep parsing and validation in a pure function, and standard input and output in `main`.

This task uses function application and `match`, plus [Maybe and Either](/en/docs/learn/maybe-and-either) and [Effects](/en/docs/learn/effects). Review application syntax in [Functions and pipelines](/en/docs/learn/functions-and-pipelines).

## Prepare the toolchain

Install the CLI and Bun through [Local development](/en/docs/learn/local-development). This example runs as one file without additional packages.

It uses the standard input and Console capabilities supplied by the `process` target. It is not a browser program to run under the `web` target.

## Define the input contract

`quantity` parses a string and checks its range, returning `Either<AppError, Int>`. Malformed numbers, 0, 1001, and missing input become `InvalidQuantity`.

`Nothing` from `readLine` means end of input. It differs from `Just ""`, which means an empty line was read. Neither is a valid quantity for this application.

## Save the complete program

Save it as `quantity.ssrg`.

{/* example: examples/guides/cli-app.ssrg */}
```seseragi title="quantity.ssrg"
import * as ints from "std/int"

type AppError deriving Show =
  | InputFailure StdinError
  | InvalidQuantity
  | OutputFailure ConsoleError

alias Quantity = Either<AppError, Int>

fn quantity text: String -> Quantity =
  match ints.parse text {
    Right n ->
      if n >= 1 && n <= 1000 then
        Right n
      else
        Left InvalidQuantity
    Left _ -> Left InvalidQuantity
  }

pub effect fn main = do {
  line <-
    readLine ()
    |> mapError InputFailure
  let parsed: Quantity = match line {
      Just text -> quantity text
      Nothing -> Left InvalidQuantity
  }
  count <- fromEither parsed
  let total = 480 * count
  `Total: ${total}`
  |> println
  |> mapError OutputFailure
}
```

`fromEither` moves the validation result into an Effect. `mapError` converts `StdinError` and `ConsoleError` into `AppError`. The compiler does not automatically combine distinct failure types into a new type.

## Pass input and run

On macOS or Linux, pipe a quantity into standard input:

```sh
printf '3\n' |
  seseragi run quantity.ssrg
```

```text
Total: 1440
```

If you run `seseragi run quantity.ssrg` directly, enter a quantity and press Enter. The program reads one line; additional lines are not included in the calculation.

## Check invalid input

```sh
printf '0\n' |
  seseragi run quantity.ssrg
printf 'many\n' |
  seseragi run quantity.ssrg
```

Both produce an unhandled typed failure `InvalidQuantity` and exit with code 1. They do not print a total. Compile or target configuration failures use exit code 2.

To display a user-facing message, use `attempt` and `match` as shown in [Handle failures](/en/docs/guides/error-handling).

## Move into a package

Use a package with `seseragi.toml` when you want reusable modules or tests. Set `target = "process"` in `[run]` for this entry point.

[Testing](/en/docs/guides/testing) fixes the boundary cases you want to preserve. [Packages and deployment](/en/docs/guides/packages-and-deployment) separates an executable entry from a public API. The [CLI Reference](/en/docs/reference/cli) describes command options.
