title: Build a CLI application
description: Read a quantity from standard input, validate it, and print a total.

Build a CLI that reads one line with a quantity from standard input and prints the total at a unit price of 480. It accepts integers from 1 through 1000. Converting and validating the text happen in ordinary functions; standard input and output happen only in `main`.

It uses what you learned in [Algebraic data types](/en/docs/learn/algebraic-data-types), [Pattern matching](/en/docs/learn/pattern-matching), [Maybe and Either](/en/docs/learn/maybe-and-either), and [Effects](/en/docs/learn/effects). `deriving Show` on a type is covered in [Type classes](/en/docs/learn/type-classes).

## Prepare the toolchain

Install the Seseragi CLI and Bun by following [Local development](/en/docs/learn/local-development). The program is a single file and needs no extra packages.

Because it uses standard input and the console, it runs from the CLI (the `process` target), not in a browser.

## Decide what input to accept

The `quantity` function converts a string to an integer, checks the range, and returns `Either<AppError, Int>`. Text that is not an integer, 0, 1001, and so on all become the failure `InvalidQuantity`.

`readLine` returns `Nothing` when input has ended and `Just ""` when it reads an empty line; the two are distinct. Neither is a valid quantity here, so both are treated as failures.

## Save the complete program

Save the following as `quantity.ssrg`.

{/* example: examples/guides/cli-app.ssrg */}
```seseragi title="quantity.ssrg"
import * as ints from "std/int"

type AppError deriving Show =
  | InputFailure StdinError
  | InvalidQuantity
  | OutputFailure ConsoleError

alias Quantity = Either<AppError, Int>

fn quantity text: String -> Quantity =
  match ints.parse text {
    Right n ->
      if n >= 1 && n <= 1000 then
        Right n
      else
        Left InvalidQuantity
    Left _ -> Left InvalidQuantity
  }

pub effect fn main = do {
  line <-
    readLine ()
    |> mapError InputFailure
  let parsed: Quantity = match line {
      Just text -> quantity text
      Nothing -> Left InvalidQuantity
  }
  count <- fromEither parsed
  let total = 480 * count
  `Total: ${total}`
  |> println
  |> mapError OutputFailure
}
```

`fromEither` turns the validation result, an `Either`, into an Effect. For `Left`, the Effect fails there.

The standard input failure `StdinError` and the output failure `ConsoleError` are brought together into the application's `AppError` with `mapError`. Different failure types are never merged automatically, so you merge them yourself like this.

## Pass input and run

On macOS or Linux, pass a quantity to standard input like this:

```sh
printf '3\n' |
  seseragi run quantity.ssrg
```

```text
Total: 1440
```

If you run just `seseragi run quantity.ssrg`, type a quantity and press Enter. `readLine` reads one line, so further lines are ignored.

## Check invalid input

```sh
printf '0\n' |
  seseragi run quantity.ssrg
printf 'many\n' |
  seseragi run quantity.ssrg
```

Both fail with `InvalidQuantity`, and because nothing handles that failure, the CLI exits with code 1 without printing a total. (When a program cannot run at all because of a compile error or a configuration problem, the exit code is 2.)

To show a message for the user on failure, use `attempt` and `match`, introduced in [Handle failures](/en/docs/guides/error-handling).

## Distinguish blank input from parsing failure

The rest is a separate program that only tries out tidying input. Write the following three blocks in order in `cli-normalization.ssrg`. It uses fixed strings instead of standard input.

### Trim before parsing

`trim` from `std/text` removes surrounding whitespace. If nothing is left, the result is `EmptyLine`; if it cannot be read as an integer, `NotANumber`. Keeping the reasons separate lets you respond to each differently.

{/* example: examples/guides/cli-normalization.ssrg#parser */}
```seseragi title="cli-normalization.ssrg"
import * as ints from "std/int"
import * as text from "std/text"

type InputError =
  | EmptyLine
  | NotANumber

alias Parsed =
  Either<InputError, Int>

fn parse input: String -> Parsed = {
  let cleaned = text.trim input
  if cleaned == "" then
    Left EmptyLine
  else
    match ints.parse cleaned {
      Right n -> Right n
      Left _ -> Left NotANumber
    }
}
```

### Give each reason its own message

`message` only turns a result into text to display. It neither reads input nor prints anything.

{/* example: examples/guides/cli-normalization.ssrg#message */}
```seseragi title="cli-normalization.ssrg"
fn message result: Parsed -> String =
  match result {
    Right n -> `Quantity: ${n}`
    Left EmptyLine ->
      "Enter quantity"
    Left NotANumber ->
      "Enter a whole number"
  }
```

### Compare four inputs

{/* example: examples/guides/cli-normalization.ssrg#inputs */}
```seseragi title="cli-normalization.ssrg"
pub effect fn main = do {
  parse " 3 "
  |> message
  |> println
  parse ""
  |> message
  |> println
  parse "many"
  |> message
  |> println
  parse "0"
  |> message
  |> println
}
```

```sh
seseragi run cli-normalization.ssrg
```

```text
Quantity: 3
Enter quantity
Enter a whole number
Quantity: 0
```

`" 3 "` becomes 3, and the empty string and `"many"` get different messages. 0 can be read as an integer, so this `parse` accepts it. To limit the range to 1 through 1000, add a check like the earlier `quantity`.

## Move into a package

When you want to split functions into files or write tests, add a `seseragi.toml` to make a package. For a CLI application, set `target = "process"` under `[run]`.

[Testing](/en/docs/guides/testing) automates checks of boundary values, and [Packages and deployment](/en/docs/guides/packages-and-deployment) separates the application entry point from the functions you publish. Command options are in the [CLI reference](/en/docs/reference/cli).
