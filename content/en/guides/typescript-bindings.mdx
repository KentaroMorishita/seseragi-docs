---
title: TypeScript bindings
description: Choose pure or task contracts and handle TypeScript calls and exceptions at a typed boundary.
---

Call TypeScript functions you wrote yourself from Seseragi. Two functions, one that only transforms a string and one that returns a Promise that can fail, are connected in the way that suits each. No external libraries are used, so it works without a network.

This task uses imports from [Modules](/en/docs/learn/modules) and execution/failure from [Effects](/en/docs/learn/effects). Results are handled with [Maybe and Either](/en/docs/learn/maybe-and-either) and [Pattern matching](/en/docs/learn/pattern-matching). The `foreign` boundary declaration is introduced here.

## Prepare the files

Create the following files. The TypeScript side's `package.json` and lockfile are separate from Seseragi's `seseragi.toml` and `seseragi.lock`:

```text
bindings/
  seseragi.toml
  host/
    package.json
    bun.lock
    format.ts
  src/
    format.ssrg
    main.ssrg
```

```toml title="seseragi.toml"
[package]
name = "docs/typescript-bindings"
version = "0.1.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"

[foreign.typescript]
resolver = "node"
manifest = "host/package.json"
lockfile = "host/bun.lock"
```

```json title="host/package.json"
{
  "name": "docs-host",
  "version": "0.1.0",
  "type": "module"
}
```

With no host dependencies, save this as `host/bun.lock`. If Bun deletes an empty lock during a dependency-free install, the declared input still needs to exist.

```json title="host/bun.lock"
{
  "lockfileVersion": 1,
  "workspaces": {
    "": {
      "name": "docs-host",
      "version": "0.1.0"
    }
  },
  "packages": {}
}
```

## Write the host functions

{/* example: examples/guides/typescript-bindings/host/format.ts */}

```typescript title="host/format.ts"
export function bracket(
  value: string,
) {
  return `[${value}]`;
}

export async function loadLabel() {
  throw new Error(
    "Temporarily unavailable",
  );
}
```

`bracket` only transforms a string and returns it right away. `loadLabel` deliberately rejects its Promise, to try out failure handling.

## Declare the foreign calling contracts

{/* example: examples/guides/typescript-bindings/src/format.ssrg */}
```seseragi title="src/format.ssrg"
pub foreign "typescript"
from "../host/format.ts" {
  pure fn bracket value: String
    -> String
  task fn loadLabel -> String
}
```

`pure` is a promise made by the person writing the binding: "returns immediately, always gives the same result for the same input, never throws, and neither reads nor changes the outside world". The compiler cannot check that promise, so do not add it just because the work is cheap.

A function marked `task` appears in Seseragi as an Effect whose success type is `String` and failure type is `Js.Error` (`Effect<{}, Js.Error, String>`). If the function throws or its Promise is rejected, that becomes a `Js.Error` failure.

Also, if a TypeScript module has even one `pure` function, the module is treated as having no side effects when loaded. For a library that does something, or can fail, just by being loaded, do not declare `pure` functions.

## Use the bindings from Seseragi

{/* example: examples/guides/typescript-bindings/src/main.ssrg */}
```seseragi title="src/main.ssrg"
import * as effects from "std/effect"
import { bracket, loadLabel }
  from "./format"

pub effect fn main = do {
  "ready"
  |> bracket
  |> println
  result <-
    loadLabel ()
    |> effects.attempt
  let message = match result {
    Right value -> value
    Left _ -> "Please try again"
  }
  println message
}
```

`bracket` sits in a pipeline like any other function. `loadLabel` returns an Effect, so `attempt` receives its failure as a value for `match`. Exceptions from TypeScript become typed failures instead of something to `try/catch`.

## Run and inspect the boundary

Run the following in `bindings/`:

```sh
seseragi lock update
seseragi run .
```

```text
[ready]
Please try again
```

Calling `loadLabel` alone does not run the TypeScript function yet. It runs inside the `do` of `main`, where `attempt` catches the deliberate rejection.

## Wrap a binding in application types

When a TypeScript function returns `null` or `undefined`, receive it in the binding with a type such as `Js.NullOr` or `Js.UndefinedOr`, then convert it to `Maybe` inside the functions your app uses. Never treat an object that might change as an immutable record.

For a large library, `seseragi dts convert` drafts bindings from `.d.ts` files. A `.d.ts` file cannot tell whether a function is pure or throws, though. Check the list of items that could not be converted, and instead of using the generated file directly, write a wrapper that imports it.

The conversion rules, `null` handling, opaque types, and error kinds are in the [TypeScript interop reference](/en/docs/reference/typescript-interop). Publishing a wrapper as a package is covered in [Packages and deployment](/en/docs/guides/packages-and-deployment).
