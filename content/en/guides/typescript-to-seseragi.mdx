This guide puts the TypeScript you write every day next to Seseragi, covering functions, data, side effects, and Web UI. Most examples give the same result, but some behave differently, such as how numbers work and when side effects run. We look at those differences too.

Examples containing `main` can be saved under the file name in their heading and run with `seseragi run filename.ssrg`. See [Local development](/en/docs/learn/local-development) to set up the CLI.

Every TypeScript example has been type-checked with `strict` and run in Node.js to confirm its output.

## Pass a number to a function

Compare function calls using a function that doubles an integer.

{/* example: examples/guides/migration-typescript/call.ts#example */}

```typescript title="call.ts"
function double(value: number) {
  return value * 2;
}
console.log(double(21));
```

In Seseragi, `fn` defines a function. `n: Int` is the parameter and the final `Int` is the result type. Calls use no parentheses: write the argument after the function name, separated by a space, as in `double 21`.

`printValue` displays a value as it is. `main` is the program's entry point and is declared with `pub effect fn` because it produces output.

{/* example: examples/guides/migration.ssrg */}

```seseragi title="migration.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = {
  let answer = double 21
  printValue answer
}
```

Output

```text
42
```

Both print 42. Seseragi's `let` corresponds to TypeScript's `const`: it cannot be reassigned later.

`printValue` does not append a newline. Later examples use `println`, which accepts a string, to display multiple results on separate lines. Use `show` to convert numbers and other values to strings.

## Distinguish Int and Float from number

In TypeScript, both calculations below have type `number`. The [TypeScript Handbook's basic types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html) explains that integers and fractions do not have separate types.

{/* example: examples/guides/migration-typescript/numeric.ts#example */}

```typescript title="numeric.ts"
const whole: number = 5 / 2;
const fraction: number = 5.0 / 2.0;
console.log(`${whole}, ${fraction}`);
```

Output

```text
2.5, 2.5
```

In Seseragi, integers are `Int` and decimals are `Float`: two different types. Integer division drops the fractional part (it rounds toward zero, so `-5 / 2` is `-2`).

{/* example: examples/guides/migration-numeric.ssrg */}

```seseragi title="migration-numeric.ssrg"
pub effect fn main = {
  let whole: Int = 5 / 2
  let fraction: Float = 5.0 / 2.0
  println `${whole}, ${fraction}`
}
```

Output

```text
2, 2.5
```

`5` is inferred as `Int` and `5.0` as `Float`, so the types in this example can be omitted. `Int` and `Float` are never converted automatically; use a function to convert.

Also, `Float` values cannot be compared directly with `==` or `>`. To compare them, pick a suitable function such as `ieeeEq` or `totalCompare` from the [Float functions](/en/docs/reference/library/float).

Do not simply replace every TypeScript `number` with `Int`. When types are imported from `.d.ts` files, `number` becomes `Float` first. Use `Int` only when you know the value is an integer within the safe range. See [TypeScript bindings](/en/docs/guides/typescript-bindings) and [Types](/en/docs/reference/types).

## Group an argument expression with parentheses

Compare two results to see what the parentheses group.

{/* example: examples/guides/migration-typescript/grouping.ts#example */}

```typescript title="grouping.ts"
function double(value: number) {
  return value * 2;
}
const outside = double(20) + 1;
const grouped = double(20 + 1);
console.log(
  `${outside}, ${grouped}`,
);
```

In Seseragi too, the result depends on where function application ends and addition begins.

{/* example: examples/guides/migration-grouping.ssrg */}

```seseragi title="migration-grouping.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = {
  let outside = double 20 + 1
  let grouped = double (20 + 1)
  println `${outside}, ${grouped}`
}
```

Output

```text
41, 42
```

`double 20 + 1` doubles 20 and then adds 1. `double (20 + 1)` doubles the sum of 20 and 1.

Seseragi's parentheses group an expression passed as an argument; they do not mark a function call. Functions are called with spaces, and parentheses appear only where an expression needs grouping.

## Receive arguments one at a time

A TypeScript function with two parameters often looks like this:

{/* example: examples/guides/migration-typescript/arguments.ts#example */}

```typescript title="arguments.ts"
function add(x: number, y: number) {
  return x + y;
}
console.log(add(20, 22));
```

In Seseragi, separate the parameters with `->`. Call the function as `add 20 22`.

{/* example: examples/guides/migration-arguments.ssrg */}

```seseragi title="migration-arguments.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

pub effect fn main =
  printValue (add 20 22)
```

Output

```text
42
```

`Int -> Int -> Int` means "takes an `Int` and returns a function that takes an `Int` and returns an `Int`". So passing just one argument, as in `add 20`, gives a function waiting for the rest.

To write the same shape in TypeScript, return a function from another function.

{/* example: examples/guides/migration-typescript/partial.ts#example */}

```typescript title="partial.ts"
const add = (x: number) =>
  (y: number) => x + y;

const addTwenty = add(20);
console.log(addTwenty(22));
```

In Seseragi, you can pass only some arguments without any extra work (partial application).

{/* example: examples/guides/migration-partial.ssrg */}

```seseragi title="migration-partial.ssrg"
fn add x: Int -> y: Int -> Int =
  x + y

pub effect fn main = {
  let addTwenty = add 20
  let answer = addTwenty 22
  printValue answer
}
```

Output

```text
42
```

`addTwenty` has type `Int -> Int`. Note that writing `add (20, 22)` out of TypeScript habit passes one tuple, `(20, 22)`, rather than two arguments, and fails to type-check.

Practice application order and function types in [Functions and pipelines](/en/docs/learn/functions-and-pipelines).

## Pass an unnamed function

Compare a TypeScript arrow function with a Seseragi lambda expression.

{/* example: examples/guides/migration-typescript/lambda.ts#example */}

```typescript title="lambda.ts"
console.log(
  [1, 2, 3].map((n) => n * 2),
);
```

In Seseragi, `\n: Int -> n * 2` creates a function at that point. Write the parameter after the leading `\`.

{/* example: examples/guides/migration-lambda.ssrg */}

```seseragi title="migration-lambda.ssrg"
pub effect fn main =
  [1, 2, 3]
  |> map (\n: Int -> n * 2)
  |> show
  |> println
```

Both double every element. Node.js adds spaces around elements when displaying an array, but the resulting elements are the same. Seseragi's output is:

Output

```text
[2, 4, 6]
```

A lambda is useful for a short operation used once. Define a named function when an operation is reused or its name conveys meaning, as `double` does in the next example.

## Turn method chains into pipelines

First, compare a single transformation.

{/* example: examples/guides/migration-typescript/pipeline.ts#example */}

```typescript title="pipeline.ts"
function double(value: number) {
  return value * 2;
}
console.log([1, 2, 3].map(double));
```

Seseragi's `|>` passes the value on the left to the function on the right. `map double` is a function waiting for an array: the same partial application as in the preceding section.

{/* example: examples/guides/migration-pipeline.ssrg */}

```seseragi title="migration-pipeline.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main =
  [1, 2, 3]
  |> map double
  |> printValue
```

Output

```text
[2, 4, 6]
```

Next, keep numbers greater than 1 and then double them.

{/* example: examples/guides/migration-typescript/steps.ts#example */}

```typescript title="steps.ts"
function double(value: number) {
  return value * 2;
}
console.log(
  [1, 2, 3]
    .filter((n) => n > 1)
    .map(double),
);
```

In Seseragi, arrange the input and each stage vertically. `map` is available from the prelude, while this `filter` is imported from `std/array`.

{/* example: examples/guides/migration-steps.ssrg */}

```seseragi title="migration-steps.ssrg"
import * as arrays from "std/array"

fn double n: Int -> Int = n * 2
fn keep n: Int -> Bool = n > 1

pub effect fn main =
  [1, 2, 3]
  |> arrays.filter keep
  |> map double
  |> show
  |> println
```

Output

```text
[4, 6]
```

The first stage selects elements; the next transforms those remaining. Neither changes the original array. See [Arrays and Lists](/en/docs/learn/arrays-and-lists) for choosing individual operations.

## Use a conditional result as a value

This TypeScript example returns a string according to a condition.

{/* example: examples/guides/migration-typescript/condition.ts#example */}

```typescript title="condition.ts"
function result(score: number) {
  return score >= 70
    ? "pass"
    : "retry";
}
console.log(result(82));
console.log(result(65));
```

Seseragi's `if` is an expression. The value from either `then` or `else` becomes the function's result.

{/* example: examples/guides/migration-condition.ssrg */}

```seseragi title="migration-condition.ssrg"
fn result score: Int -> String =
  if score >= 70 then
    "pass"
  else
    "retry"

pub effect fn main = do {
  println (result 82)
  println (result 65)
}
```

Output

```text
pass
retry
```

Both branches must have the same type; here both are `String`. It is close to TypeScript's `? :` operator, so there is no need to declare a variable and assign it in each branch.

This example's `main` uses `do { ... }` to run several outputs in order. A plain `{ ... }` without `do` returns its last expression and does not run the Effects inside it in order. [Values and expressions](/en/docs/learn/values-and-expressions) and [Effects](/en/docs/learn/effects) explain the difference.

## Read a record field

Grouping named values and reading them with a dot looks similar.

{/* example: examples/guides/migration-typescript/record.ts#example */}

```typescript title="record.ts"
const point = { x: 3, y: 4 };
console.log(point.x);
```

{/* example: examples/guides/migration-record.ssrg */}

```seseragi title="migration-record.ssrg"
pub effect fn main = {
  let point = { x: 3, y: 4 }
  printValue point.x
}
```

Output

```text
3
```

In Seseragi, `{ x: 3, y: 4 }` is a record. Its type is decided by the field names and types, by shape, just like a TypeScript object type.

## Create a new record for an update

TypeScript's `const` only prevents reassigning the variable; the object's contents can still be changed. To keep the original, make a copy with spread syntax.

{/* example: examples/guides/migration-typescript/immutable.ts#example */}

```typescript title="immutable.ts"
const base = { count: 1 };
const next = {
  ...base,
  count: base.count + 1,
};
console.log(
  `${base.count}, ${next.count}`,
);
```

A Seseragi record cannot be changed in the first place. The same spread syntax creates a new record with some fields changed.

{/* example: examples/guides/migration-immutable.ssrg */}

```seseragi title="migration-immutable.ssrg"
pub effect fn main = {
  let base = { count: 1 }
  let next = {
    ...base,
    count: base.count + 1
  }
  let report =
    `${base.count}, ${next.count}`
  println report
}
```

Output

```text
1, 2
```

`next.count` is 2 and `base.count` stays 1. It is the same idea as making a copy when [updating object state in React](https://react.dev/learn/updating-objects-in-state), except that in Seseragi it is the only way.

## Distinguish type aliases from structs

This TypeScript example names the shape of an object.

{/* example: examples/guides/migration-typescript/alias.ts#example */}

```typescript title="alias.ts"
type Point = {
  x: number;
  y: number;
};

function horizontal(point: Point) {
  return point.x;
}
const point: Point = { x: 3, y: 4 };
console.log(horizontal(point));
```

To name a record type in Seseragi, use `alias`.

{/* example: examples/guides/migration-alias.ssrg#declaration */}

```seseragi title="Type and function declarations"
alias Point = { x: Int, y: Int }

fn horizontal point: Point -> Int =
  point.x
```

Inside `main` in the same file, pass a record with that shape.

{/* example: examples/guides/migration-alias.ssrg#use */}

```seseragi title="Excerpt inside main"
let point: Point = { x: 3, y: 4 }
printValue (horizontal point)
```

Output

```text
3
```

`alias` only adds a name, so `alias Point` accepts any record with the same fields, just like TypeScript's `type`.

Seseragi's `struct Point { ... }`, on the other hand, creates a type identified by its name. A struct with a different name is a different type, even with exactly the same fields. When porting a TypeScript object type, choose a record to work by shape, or a struct to tell meanings apart. [Records and structs](/en/docs/learn/records-and-structs) has concrete examples.

## Handle union cases with match

Next, compare data representing a parcel's delivery state. In TypeScript, a union type with a tag property such as `kind` represents the cases.

{/* example: examples/guides/migration-typescript/data.ts#declaration */}

```typescript title="data.ts"
type Delivery =
  | { kind: "preparing" }
  | { kind: "sent"; city: string };
```

Create a value:

{/* example: examples/guides/migration-typescript/data.ts#construct */}

```typescript title="data.ts"
const delivery: Delivery = {
  kind: "sent",
  city: "Kyoto",
};
```

Checking the case with `switch` makes that case's data available.

{/* example: examples/guides/migration-typescript/data.ts#label */}

```typescript title="data.ts"
function label(value: Delivery) {
  switch (value.kind) {
    case "preparing":
      return "Preparing";
    case "sent":
      return value.city;
  }
}
```

In Seseragi, the cases are `Preparing` and `Sent String`. `Sent "Kyoto"` creates a `Sent` value carrying a city name. There is no tag property to maintain yourself.

`match` tells the cases apart, and `Sent city` takes out the city name.

{/* example: examples/guides/migration-data.ssrg */}

```seseragi title="migration-data.ssrg"
type Delivery =
  | Preparing
  | Sent String

fn label d: Delivery -> String =
  match d {
    Preparing -> "Preparing"
    Sent city -> city
  }

pub effect fn main = {
  let delivery = Sent "Kyoto"
  println (label delivery)
}
```

Output

```text
Kyoto
```

The TypeScript `label(delivery)` also returns `Kyoto`. The difference is in missed cases: a Seseragi `match` that does not handle every case is a compile error.

Learn case definitions in [Algebraic data types](/en/docs/learn/algebraic-data-types) and value extraction in [Pattern matching](/en/docs/learn/pattern-matching).

## Represent an absent value with Maybe

In TypeScript, a value that may be missing is typed as `string | undefined` or similar. This function returns `Guest` only when there is no name.

{/* example: examples/guides/migration-typescript/maybe.ts#name */}

```typescript title="maybe.ts"
function name(
  value: string | undefined,
): string {
  return value ?? "Guest";
}
```

Seseragi uses `Maybe<String>`: either `Just`, with a value, or `Nothing`, without one.

{/* example: examples/guides/migration-maybe.ssrg#name */}

```seseragi title="Function receiving a Maybe"
fn name value: Maybe<String>
  -> String =
  value ?? "Guest"
```

In both, `??` uses the right side only when there is no value. An empty string counts as a value, so it is returned as is.

Compare three inputs. Square brackets are added only when printing, so the empty string stays visible.

{/* example: examples/guides/migration-typescript/maybe.ts#inputs */}

```typescript title="maybe.ts"
console.log(`[${name("Ada")}]`);
console.log(`[${name(undefined)}]`);
console.log(`[${name("")}]`);
```

In Seseragi:

{/* example: examples/guides/migration-maybe.ssrg#inputs */}

```seseragi title="Excerpt inside main"
let present = name (Just "Ada")
let absent = name Nothing
let empty = name (Just "")
println ("[" + present + "]")
println ("[" + absent + "]")
println ("[" + empty + "]")
```

Output

```text
[Ada]
[Guest]
[]
```

`Just ""` and `Nothing` are different. To reject empty strings as well, validate them separately from handling a missing value.

## Transform only the value inside a Maybe

Compare a function that doubles a value only when there is one.

{/* example: examples/guides/migration-typescript/maybe-map.ts#example */}

```typescript title="maybe-map.ts"
const double = (n: number) => n * 2;
function doublePresent(
  value: number | undefined,
) {
  return value === undefined
    ? undefined
    : double(value);
}
console.log(doublePresent(21));
console.log(
  doublePresent(undefined),
);
```

The output is 42 for 21, and `undefined` for absence. Seseragi's `map` serves the same purpose.

{/* example: examples/guides/migration-maybe-map.ssrg */}

```seseragi title="migration-maybe-map.ssrg"
fn double n: Int -> Int = n * 2

pub effect fn main = do {
  Just 21
  |> map double
  |> show
  |> println
  let absent: Maybe<Int> =
    Nothing
    |> map double
  absent
  |> show
  |> println
}
```

Output

```text
Just 42
Nothing
```

`map double` transforms only the content of a `Just` and returns `Nothing` unchanged. There is no need to check for a value with `if` as in TypeScript. (`Nothing` alone does not reveal the content type, so the type `Maybe<Int>` is written.)

This `map` is the same function as the array `map`, because both "transform the contents of a container". [Type classes](/en/docs/learn/type-classes) explains how, and [Maybe and Either](/en/docs/learn/maybe-and-either) covers missing values in detail.

## Represent a failure reason with Either

This example returns a failure reason for an empty name and a success value otherwise. In TypeScript, a union type can represent success and failure.

{/* example: examples/guides/migration-typescript/either.ts#validate */}

```typescript title="either.ts"
type NameResult =
  | { ok: true; value: string }
  | { ok: false; error: string };

function validate(
  text: string,
): NameResult {
  if (text === "") {
    return {
      ok: false,
      error: "Enter a name",
    };
  }
  return { ok: true, value: text };
}
```

Seseragi uses `Either<String, String>`. The first type is the failure reason and the second is the success value; both are strings here.

{/* example: examples/guides/migration-either.ssrg#validate */}

```seseragi title="Validation function"
fn validate text: String
  -> Either<String, String> =
  if text == "" then
    Left "Enter a name"
  else
    Right text
```

Add a function that turns the result into text to display.

{/* example: examples/guides/migration-typescript/either.ts#report */}

```typescript title="either.ts"
function report(value: NameResult) {
  return value.ok
    ? `Hello, ${value.value}`
    : value.error;
}
```

{/* example: examples/guides/migration-either.ssrg#report */}

```seseragi title="Formatting a result"
fn report r: Either<String, String>
  -> String =
  match r {
    Right name -> `Hello, ${name}`
    Left error -> error
  }
```

Validating `"Ada"` succeeds and `""` fails. A failure is an ordinary value, not an exception, so `match` handles each case.

{/* example: examples/guides/migration-either.ssrg#cases */}

```seseragi title="Excerpt inside main"
validate "Ada"
|> report
|> println
validate ""
|> report
|> println
```

Output

```text
Hello, Ada
Enter a name
```

TypeScript produces the same two strings with `report(validate("Ada"))` and `report(validate(""))`.

An `Either` is a value holding a result that has already been computed. It does not start asynchronous work or throw exceptions; such work is expressed with an Effect, covered next. [Handle failures](/en/docs/guides/error-handling) combines validation with `Either` and handling Effect failures.

## Compare when Promise and Effect execute

A TypeScript `async` function and a Seseragi `effect fn` both give a name to work with side effects. They differ in when that work runs.

This TypeScript function prints a message as soon as it is called.

{/* example: examples/guides/migration-typescript/effect.ts#announce */}

```typescript title="effect.ts"
async function announce(s: string) {
  console.log(s);
}
```

Call the function and `await` the same Promise twice. (To try it in a single file, combine it with the declaration above and add `export {};` at the end.)

{/* example: examples/guides/migration-typescript/effect.ts#execute */}

```typescript title="effect.ts"
const job = announce("ran");
console.log("constructed");
await job;
await job;
```

Output

```text
ran
constructed
```

The body runs the moment `announce("ran")` is called, so `ran` prints before `constructed`. Awaiting the same Promise twice does not run the body again.

In Seseragi, calling an `effect fn` only creates "work that prints when run"; nothing happens yet.

{/* example: examples/guides/migration-effect.ssrg#announce */}

```seseragi title="Function constructing an Effect"
effect fn announce text: String =
  println text
```

In the `do` block of `main`, `let job` creates the work, and each `job` line after it runs the work.

{/* example: examples/guides/migration-effect.ssrg#execute */}

```seseragi title="Excerpt inside main"
let job = announce "ran"
println "constructed"
job
job
```

Output

```text
constructed
ran
ran
```

This time `constructed` prints first. And running the same Effect twice prints twice.

To use a result several times, run the work once with `<-` and keep the result. This example prints a message and then returns 42.

{/* example: examples/guides/migration-effect-result.ssrg */}

```seseragi title="migration-effect-result.ssrg"
import * as effects from "std/effect"

effect fn produce n: Int = do {
  println "ran"
  effects.succeed n
}

pub effect fn main = do {
  let job = produce 42
  answer <- job
  println `${answer}, ${answer}`
}
```

Output

```text
ran
42, 42
```

`answer <- job` runs the work once and receives the resulting integer as `answer`. The two uses of `answer` after it just reuse that integer, so `ran` prints only once. Writing `let answer = job` instead of `<-` would only name the work, without running it.

The type `Effect<R, E, A>` carries three things: what the work needs (`R`), its failure type (`E`), and its success type (`A`). Unlike `Promise<A>`, which tells you only the success type, it tells you what the work uses and how it can fail.

| What you need to represent | What to use in Seseragi |
| --- | --- |
| A value computed from arguments | A regular `fn` |
| A value that may be absent | `Maybe<A>` |
| An obtained result that is success or failure | `Either<E, A>` |
| A computation with effects to construct and execute later | `Effect<R, E, A>` |

[Effects](/en/docs/learn/effects) covers building Effects and `do`, and the [Effect reference](/en/docs/reference/effects) has the detailed rules for the types.

## Compare React props and rendering functions

Start with a component that has no state or events. In React, [props](https://react.dev/learn/passing-props-to-a-component) pass values from a parent to a component.

{/* example: examples/guides/migration-typescript/react.tsx#badge */}

```tsx title="React component"
type BadgeProps = { label: string };

function Badge(props: BadgeProps) {
  return <span>{props.label}</span>;
}
```

In Seseragi, it is an ordinary function that takes props and returns HTML. Functions from the `html` module take the place of JSX.

{/* example: examples/guides/migration-props.ssrg#badge */}

```seseragi title="Function returning HTML"
import * as html from "std/web/html"

alias BadgeProps = { label: String }

fn badge props: BadgeProps
  -> html.Html<Never> =
  html.span { children: props.label }
```

The `A` in `Html<A>` is the type of events (Actions) the view can emit. This component emits none, so it is `Html<Never>`. Turning `badge { label: "Ready" }` into an HTML string gives:

Output

```text
<span>Ready</span>
```

Reading props looks similar, but Seseragi's `badge` itself is a pure function constructing an HTML value. Mounting it in the DOM is a separate operation. [Components](/en/docs/guides/components) covers multiple props and escaping.

Note that in the current version, an `Html<Never>` component cannot be placed directly in an `Html<Action>` view. A component used in a view needs the same Action type as the view. To reuse a component across views, make its Action type a [generic](/en/docs/learn/generics) type parameter and return `Html<A>`.

## Compare state updates as pure functions

A React [reducer](https://react.dev/learn/extracting-state-logic-into-a-reducer) is a function that returns the next state from the current state and an Action. Compare just this function before building a view.

{/* example: examples/guides/migration-typescript/update.ts#update */}

```typescript title="update.ts"
type Action =
  | { type: "increment" }
  | { type: "reset" };

function reducer(
  count: number,
  action: Action,
): number {
  switch (action.type) {
    case "increment":
      return count + 1;
    case "reset":
      return 0;
  }
}
```

In Seseragi, too, write `update` to compute the next state. Actions are an ADT, so the compiler points out any case the `match` misses. The arguments come in the order Action, current state, the reverse of a React reducer.

{/* example: examples/guides/migration-update.ssrg#update */}

```seseragi title="State update declarations"
type Action =
  | Increment
  | Reset

fn update action: Action
  -> count: Int -> Int =
  match action {
    Increment -> count + 1
    Reset -> 0
  }
```

In TypeScript, check it like this:

{/* example: examples/guides/migration-typescript/update.ts#cases */}

```typescript title="update.ts"
console.log(reducer(
  0, { type: "increment" },
));
console.log(reducer(
  9, { type: "reset" },
));
```

In Seseragi:

{/* example: examples/guides/migration-update.ssrg#cases */}

```seseragi title="Excerpt inside main"
update Increment 0
|> show
|> println
update Reset 9
|> show
|> println
```

Output

```text
1
0
```

`Increment` adds 1 to the current value, and `Reset` returns 0 whatever the value. You can run and test the update rules before connecting them to a view.

## Connect events and state to the UI

In React, `useReducer` connects the reducer to the view.

{/* example: examples/guides/migration-typescript/react.tsx#events */}

```tsx title="React events and state"
function Counter() {
  const [count, dispatch] =
    useReducer(reducer, 0);
  const increment = () => {
    dispatch({ type: "increment" });
  };
  return (
    <button onClick={increment}>
      {count}
    </button>
  );
}
```

In React, the click handler calls `dispatch`. In Seseragi, `onClick` takes the Action value itself.

{/* example: examples/guides/migration-web/src/main.ssrg#view */}

```seseragi title="View in a Web package"
fn view count: Int
  -> html.Html<Action> =
  html.button {
    buttonType: "button",
    onClick: Increment,
    children: `Count: ${count}`
  }
```

`view` only builds `Html<Action>` from the count. `onClick: Increment` means "send `Increment` when clicked". State changes are never written in `view`; they all belong to `update`.

Finally, mount it in `main`. Import `dom` from `std/web/dom`.

{/* example: examples/guides/migration-web/src/main.ssrg#mount */}

```seseragi title="Web package entry"
pub effect fn main =
  dom.app {
    target: "#app",
    initial: 0,
    update,
    view
  }
```

`dom.app` mounts the view on the `#app` element and starts from state 0. It passes each Action sent by a click to `update` to get the next state, then passes that to `view` to update the screen. The button starts at `Count: 0` and shows `Count: 1` after one click.

This example is a Web app that runs in the browser, so it is built as a Web package rather than run with `seseragi run`. See [Build a Web application](/en/docs/guides/web-app) for the steps.

`dom.app` takes care of managing state and updating the screen. [Stateful features](/en/docs/guides/stateful-features) shows how to give each part its own state, and [Forms](/en/docs/guides/forms) shows how input becomes Actions.
