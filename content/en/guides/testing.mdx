title: Write tests
description: Verify a public API with std/test and preserve meaningful boundary cases.
---

Test a shipping rule: a subtotal of at least 3000 has no fee; a smaller subtotal has a fee of 400. Fix cases immediately below, at, and above the boundary to detect changes to the condition.

The code uses [Functions and pipelines](/en/docs/learn/functions-and-pipelines), [Modules](/en/docs/learn/modules), and [Effects](/en/docs/learn/effects). This guide sets up the test files and runner commands below.

## Create a package for tests

Create this structure in `shipping/`. You need the CLI and Bun. Put normal functions in `src/` and tests in `tests/`.

```text
shipping/
  seseragi.toml
  src/
    shipping.ssrg
  tests/
    shipping.ssrg
```

```toml title="seseragi.toml"
[package]
name = "docs/shipping"
version = "0.1.0"
language = ">=0.1.0 <0.2.0"

[exports]
"." = "shipping"

[test]
target = "node"
jobs = 1
```

`"." = "shipping"` in `[exports]` defines the public entry. `target = "node"` in `[test]` selects the current test runner target; it is separate from an application's `run.target`.

## Write the public function

{/* example: examples/guides/testing/src/shipping.ssrg */}
```seseragi title="src/shipping.ssrg"
pub fn fee subtotal: Int -> Int =
  if subtotal >= 3000 then 0 else 400
```

Both `pub` on the function and the export map for its module are needed. The test imports `fee` through the package's public entry.

## Create a test tree

{/* example: examples/guides/testing/tests/shipping.ssrg */}
```seseragi title="tests/shipping.ssrg"
import * as test from "std/test"
import { fee } from "docs/shipping"

pub let tests: test.Test =
  test.suite "fee" [
    test.test "below threshold"
      (test.equal 400 (fee 2999)),
    test.test "at threshold"
      (test.equal 0 (fee 3000)),
    test.test "above threshold"
      (test.equal 0 (fee 3001))
  ]
```

`test.equal` takes the expected value first, followed by the actual value. The runner discovers `pub let tests: test.Test`. This binding publishes a test definition as required by the runner's contract.

`test.suite` and `test.test` construct ordinary values. Their body Effects run only when the runner executes those cases.

## Run the tests

Execute these commands in `shipping/`:

```sh
seseragi lock update
seseragi test
```

```text
PASS shipping::fee::below threshold
PASS shipping::fee::at threshold
PASS shipping::fee::above threshold
3 passed; 0 failed; 0 skipped
```

After changing the condition to `subtotal > 3000` and saving it, run `seseragi lock update` again, then `seseragi test`. The `at threshold` case fails, with 2 passed and 1 failed. Restore `>=`, update the lock, and rerun the tests.

Normal source changes alter content covered by the lock. Testing before updating it stops with `SES-K0102`. A test failure exits with code 1; stale locks and configuration, compile, or discovery problems exit with 2.

## Run a subset

```sh
seseragi test --filter threshold
seseragi test --exact \
  shipping::fee::at\ threshold
```

`--filter` matches a case-sensitive substring of the full name, not a regular expression. `--exact` selects a full case name. An empty selection exits with code 2 rather than succeeding.

`--jobs` selects concurrency. Each case uses an independent environment and resource scope, while reporting remains in definition order.

## Test success and typed failure separately

Use a separate package to divide name input into four cases. It follows the same rule as the [isolated form validation](/en/docs/guides/forms): trim surrounding whitespace and reject an empty name.

### Prepare the names package

```sh
mkdir -p names/src names/tests
cd names
```

Save this as `seseragi.toml`.

{/* example: examples/guides/testing-validation/seseragi.toml */}
```toml title="seseragi.toml"
[package]
name = "docs/names"
version = "0.1.0"
language = ">=0.1.0 <0.2.0"

[exports]
"." = "names"

[test]
target = "node"
jobs = 1
```

Put the pure validator in `src/names.ssrg`.

{/* example: examples/guides/testing-validation/src/names.ssrg#validator */}
```seseragi title="src/names.ssrg"
import * as text from "std/text"

alias Name = Either<String, String>

pub fn name input: String -> Name = {
  let cleaned = text.trim input
  if cleaned == "" then
    Left "missing name"
  else
    Right cleaned
}
```

### Specify expected values and failure reasons

Save these two blocks in order as `tests/names.ssrg`. `accepted` fixes the expected value's type as `Either<String, String>`; `missing` checks the accepted failure reason.

{/* example: examples/guides/testing-validation/tests/names.ssrg#helpers */}
```seseragi title="tests/names.ssrg"
import * as test from "std/test"
import * as effects from "std/effect"
import { name } from "docs/names"

alias Name = Either<String, String>

fn accepted value: String -> Name =
  Right value

fn missing error: String -> Bool =
  error == "missing name"
```

Use `test.equal` for accepted input. For empty input, `test.expectFailure` checks both that a typed failure occurs and that its reason matches.

{/* example: examples/guides/testing-validation/tests/names.ssrg#cases */}
```seseragi title="tests/names.ssrg"
pub let tests: test.Test =
  test.suite "name" [
    test.test "valid" $
      test.equal (accepted "Ada") $
        name "Ada",
    test.test "trimmed" $
      test.equal (accepted "Ada") $
        name " Ada ",
    test.test "blank" $
      name ""
      |> effects.fromEither
      |> test.expectFailure missing,
    test.test "spaces" $
      name "   "
      |> effects.fromEither
      |> test.expectFailure missing
  ]
```

```sh
seseragi lock update
seseragi test
```

```text
PASS names::name::valid
PASS names::name::trimmed
PASS names::name::blank
PASS names::name::spaces
4 passed; 0 failed; 0 skipped
```

`blank` and `spaces` pass by verifying that validation fails. `effects.fromEither` moves the validator's `Either` into an Effect.

### Read failing tests

Change only the expected value in `valid` to `accepted "Eve"`, update the lock, and run `seseragi test --filter valid`. The report distinguishes the expected `Right "Eve"` from the actual `Right "Ada"`. Restore the expected value before trying each of these changes separately.

| Change | Problem reported by `blank` |
| --- | --- |
| Return `Right "default"` for empty input | `expected a typed failure` |
| Make `missing` require another reason | `typed failure did not match` |

After each lock update, run `seseragi test --filter blank`. The first case succeeds when a failure was expected; the second fails with a different reason. Both test runs exit with code 1. Restore each change, update the lock, and check that all four cases pass again.

`expectFailure` verifies typed failures. It does not turn defects or cancellation into successful checks for an expected input error.

## Choose what to verify

These tests verify the fee rule, not browser input or interaction. Check input, focus, and event behavior in a browser as well. Pure update functions can be tested directly with the same `test.equal`.

[State and Actions](/en/docs/guides/state-and-actions) demonstrates an update function separated from its UI. See [CLI Reference](/en/docs/reference/cli) for timeout, filtering, and exit-code options.
