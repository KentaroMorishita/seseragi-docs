---
title: Packages and deployment
description: Separate public APIs from entry points and distribute process or Web artifacts.
---

Extract shipping calculations into a small library and use it from another application. `seseragi.toml` defines public modules and dependency entry points. Then distinguish distribution of process applications from static Web applications.

`import` and `pub` use the syntax from [Modules](/en/docs/learn/modules). See [Use Seseragi locally](/en/docs/learn/local-development) for CLI and Bun setup.

## Create two packages

Create this structure. `shipping/` is a library and `app/` is executable:

```text
shop/
  shipping/
    seseragi.toml
    src/
      shipping.ssrg
  app/
    seseragi.toml
    src/
      main.ssrg
```

No shared manifest is needed in the parent directory. Each `seseragi.toml` establishes its own package root.

## Define the library entry

```toml title="shipping/seseragi.toml"
[package]
name = "docs/shipping"
version = "0.1.0"
language = ">=0.1.0 <0.2.0"

[exports]
"." = "shipping"
```

{/* example: examples/guides/packages/shipping/src/shipping.ssrg */}
```seseragi title="shipping/src/shipping.ssrg"
pub fn fee subtotal: Int -> Int =
  if subtotal >= 3000 then 0 else 400
```

`pub` exposes the function, and `[exports]` defines module entry points available outside the package. An external package cannot import an internal module by path if the export map does not expose it.

## Use a path dependency

```toml title="app/seseragi.toml"
[package]
name = "docs/shop"
version = "0.1.0"
language = ">=0.1.0 <0.2.0"

[run]
entry = "main"
target = "process"

[dependencies.shipping]
package = "docs/shipping"
path = "../shipping"
```

{/* example: examples/guides/packages/app/src/main.ssrg */}
```seseragi title="app/src/main.ssrg"
import { fee } from "shipping"

pub effect fn main =
  fee 2999
  |> show
  |> println
```

`shipping` is the import name in source. The manifest specifies the real package name `docs/shipping` and the relative path `../shipping`. Imports do not address another package's `src/` directly.

## Lock and run

Execute these commands in `shop/`:

```sh
seseragi lock update app
seseragi run app
```

```text
400
```

`app/seseragi.lock` fixes exact dependency identities and content, toolchain data, and required Provider selections. After changing a manifest or dependency source, review the intended changes and explicitly update the lock.

Normal `run` and `build` commands do not update it automatically. A stale lock stops with `SES-K0102`. Version the manifest and lock together.

## Run a process artifact

```sh
cd app
seseragi build . --profile release
bun dist/entry.js
```

The built program also prints 400. The release artifact bundles generated JavaScript and its runtime into `entry.js`. This process application runs through Bun. `seseragi build` does not produce a standalone native executable for an OS.

A process application using services such as an HTTP server is also a different deployment target from a static Web site. Consult [Runtime Providers](/en/docs/reference/runtime-providers) for required services.

## Serve a Web artifact

Build the `counter/` project from [Build a Web application](/en/docs/guides/web-app):

```sh
seseragi lock update
seseragi build . --profile release
```

Its `dist/` contains `index.html` and browser JavaScript and CSS. Serve that directory through static hosting. Visitors do not need the Seseragi CLI or compiler repository.

With Vercel CLI installed and authenticated, publish the built directory:

```sh
vercel deploy dist --prod
```

Choose a static-site project configured to serve the uploaded files without an additional build. `--prod` publishes to production domains. See the [official Vercel CLI documentation](https://vercel.com/docs/cli/deploy) for the command and deployment configuration.

## Add HTML and public files

Configure `index` and `public` in `[web]` for a custom title or favicon. Put exactly one `<!-- seseragi:head -->` in the HTML `head` and one `<!-- seseragi:entry -->` in its `body`. Include the DOM target `<div id="app"></div>`.

Update the lock before a normal build when these inputs change. Edit the source inputs rather than generated `dist/` files. [Project configuration](/en/docs/reference/project-configuration) describes paths and document contracts.

## Check the publication boundary

Path dependencies support local development. They cannot remain in a manifest published to a registry. The current CLI has no package `publish` command; this guide covers local package separation and distribution of application artifacts.

Use [Testing](/en/docs/guides/testing) to verify imports through a changed public entry. To expose generated bindings, publish a handwritten adapter as described in [TypeScript bindings](/en/docs/guides/typescript-bindings).
