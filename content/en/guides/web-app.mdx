title: Build a Web application
description: Build an interactive counter using a pure update function and HTML.

Build a counter that goes up with “Add one” and back to 0 with “Reset”. The state is an `Int`, button presses are an `Action` type, and the screen is HTML built from the state. `dom.app` takes care of displaying it in the browser.

The Action type uses what you learned in [Algebraic data types](/en/docs/learn/algebraic-data-types) and [Pattern matching](/en/docs/learn/pattern-matching).

## Create a project

```sh
seseragi new web counter
cd counter
```

Replace `src/main.ssrg` with the code below. The generated `src/app.ssrg` is not used in this guide.

Leave `seseragi.toml` as it is. To set up the CLI and Bun, see [Local development](/en/docs/learn/local-development).

## Write the complete counter

{/* example: examples/guides/web-app/src/main.ssrg */}
```seseragi title="src/main.ssrg"
import * as dom from "std/web/dom"
import * as html from "std/web/html"

type Action =
  | Increment
  | Reset

alias View = html.Html<Action>

fn update action: Action -> n: Int
  -> Int =
  match action {
    Increment -> n + 1
    Reset -> 0
  }

fn view count: Int -> View =
  html.main {
    style: html.style {
      margin: "32px auto",
      maxWidth: "32rem",
      padding: "24px"
    },
    children: [
      html.h1 { children: "Counter" },
      html.p {
        children: `Count: ${count}`
      },
      html.button {
        buttonType: "button",
        onClick: Increment,
        children: "Add one"
      },
      html.button {
        buttonType: "button",
        onClick: Reset,
        children: "Reset"
      }
    ]
  }

pub effect fn main =
  dom.app {
    target: "#app",
    initial: 0,
    update,
    view
  }
```

`Increment` and `Reset` describe what the user did. `update` only returns the next count from the current count and an Action; it never touches the screen. `view` likewise only builds the screen (`Html<Action>`) from the current count.

`onClick: Increment` names the Action to send when clicked, not code to run on click.

## Operate the development server

Update the lockfile, then start the development server:

```sh
seseragi lock update
seseragi dev --open
```

Open `http://127.0.0.1:3000/` and you see “Count: 0”. Click “Add one” twice for “Count: 2”, and “Reset” to go back to “Count: 0”.

Saving a source file reloads the page, so the counter goes back to 0.

## Understand state and DOM ownership

`dom.app` creates a Signal holding the initial value and builds the screen with `view`. Each time an event happens, it computes the next state with `update` and applies only what changed to the screen. There is nothing magic about it: it is an ordinary standard-library function that bundles creating the Signal, finding where to display, and wiring up events.

Events are processed in the order they happen. The detailed rules are in the [Web UI reference](/en/docs/reference/web-ui).

## Style and build

`style` takes a style built with `html.style`. This example uses `maxWidth`, `margin`, and `padding` to limit the width, center the content, and add space inside. For CSS class names, use `class`.

Stop the development server with `Ctrl-C`, update the lockfile, and build:

```sh
seseragi lock update
seseragi build .
```

`dist/` now contains `index.html`, JavaScript, CSS, and so on. Serve them from an HTTP server or static hosting instead of opening the HTML file directly.

## Add another capability

[State and Actions](/en/docs/guides/state-and-actions) checks `update` without a screen, and [Forms](/en/docs/guides/forms) handles text input. To place several counters side by side, use the approach in [Stateful features](/en/docs/guides/stateful-features).
