Build a form that shows a greeting when you type a name and press “Greet”. Submitting it empty shows “Enter your name”. Store the text being typed and the submitted result in separate [Signals](/en/docs/learn/signals).

Connect the screen as in [Build a Web application](/en/docs/guides/web-app). [Effects](/en/docs/learn/effects) explains `Task<Unit>` and `do`; [Records and structs](/en/docs/learn/records-and-structs) explains the records used for HTML props.

## Prepare a project

```sh
seseragi new web greeting-form
cd greeting-form
```

In a project created with `seseragi new web`, replace `src/main.ssrg` with the code below. The generated `app.ssrg` is not used.

## Write the complete form

{/* example: examples/guides/forms/src/main.ssrg */}
```seseragi title="src/main.ssrg"
import * as dom from "std/web/dom"
import * as html from "std/web/html"
import * as signals from "std/signal"
import { MutableSignal }
  from "std/signal"

alias Field = MutableSignal<String>

alias View = html.Html<Task<Unit>>

fn greeting name: String -> String =
  if name == "" then
    "Enter your name"
  else
    `Hello, ${name}`

fn edited draft: Field
  -> reply: Field
  -> event: html.InputEvent
  -> Task<Unit> =
  signals.transaction [
    signals.planSet event.value draft,
    signals.planSet "" reply
  ]

fn submitted draft: Field
  -> reply: Field
  -> Task<Unit> = do {
  name <- signals.read draft
  signals.set (greeting name) reply
}

fn view draft: Field
  -> reply: Field
  -> current: String
  -> result: String -> View =
  html.main {
    style: html.style {
      margin: "32px auto",
      maxWidth: "32rem",
      padding: "24px"
    },
    children: [
      html.h1 {
        children: "Greeting"
      },
      html.form {
        onSubmit:
          submitted draft reply,
        children: [
          html.label {
            htmlFor: "name",
            children: "Your name"
          },
          html.input {
            id: "name",
            name: "name",
            value: current,
            onInput:
              edited draft reply
          },
          html.button {
            buttonType: "submit",
            children: "Greet"
          }
        ]
      },
      html.p {
        role: "status",
        children: result
      }
    ]
  }

fn perform action: Task<Unit>
  -> Task<Unit> = action

fn queryError error: dom.DomError
  -> String = show error

alias DomFailure =
  dom.DomRuntimeError<Never>

fn runtimeError error: DomFailure
  -> String = show error

pub effect fn main = do {
  draft <- signals.make ""
  reply <- signals.make ""
  let render = view draft reply
  let content =
    signals.combine render draft reply
  target <-
    dom.query "#app"
    |> mapError queryError
  let opts = dom.defaultOptions ()
  dom.run opts target perform content
  |> mapError runtimeError
}
```

`Field` is an alias for `MutableSignal<String>`. `draft` stores the text being typed, and `reply` stores the submitted result. `signals.combine` passes both values to `view`, so the field and result paragraph follow changes to either Signal.

## Update Signals from input

The `value` of `html.InputEvent` holds the typed text. `edited draft reply` is a function that takes event data and builds an update Task. `onInput` calls that function, and `dom.run` executes the Task.

`signals.planSet` plans to save the input and clear the previous result; `signals.transaction` applies both together. See [Signal updates](/en/docs/learn/signals#group-several-updates) for updating two Signals at once.

`value: current` displays the current text in the field. Matching `htmlFor: "name"` on the label with `id: "name"` on the field makes clicking the label select the field.

## Submit and validate

```sh
seseragi lock update
seseragi dev --open
```

Type `Ada` and press “Greet” to see “Hello, Ada”. Submitting it empty shows “Enter your name”. A form with `onSubmit` automatically stops the page reload and sends the `submitted draft reply` Task (no `preventDefault` needed). Pressing Enter in the field submits too.

This example accepts input made only of spaces as a name. To strip spaces, tidy the input before validating, as in the next section.

## Check name validation in isolation

Here, try the rule “strip surrounding spaces, and reject the name if nothing is left” without a screen. Write the following three blocks in order in `form-validation.ssrg`. It is a separate program from the Web form above.

### Return an accepted name or a failure

Using [Either](/en/docs/learn/maybe-and-either), an accepted name goes in `Right` and a hint on how to fix the input goes in `Left`.

{/* example: examples/guides/form-validation.ssrg#validation */}
```seseragi title="form-validation.ssrg"
import * as text from "std/text"

alias Name = Either<String, String>

fn name input: String -> Name = {
  let cleaned = text.trim input
  if cleaned == "" then
    Left "Enter your name"
  else
    Right cleaned
}
```

### Turn the result into a greeting

{/* example: examples/guides/form-validation.ssrg#greeting */}
```seseragi title="form-validation.ssrg"
fn greeting result: Name -> String =
  match result {
    Right value -> `Hello, ${value}`
    Left message -> message
  }
```

`greeting` uses [pattern matching](/en/docs/learn/pattern-matching) to return a greeting with the name on success, and the hint as is on failure.

### Compare valid, empty, and whitespace-only input

{/* example: examples/guides/form-validation.ssrg#inputs */}
```seseragi title="form-validation.ssrg"
pub effect fn main = do {
  name " Ada "
  |> greeting
  |> println
  name ""
  |> greeting
  |> println
  name "   "
  |> greeting
  |> println
}
```

```sh
seseragi run form-validation.ssrg
```

```text
Hello, Ada
Enter your name
Enter your name
```

`" Ada "` has its spaces removed and becomes `Ada`; `""` and `"   "` are both rejected. To use this check in the Web form, replace the original `greeting` with this `Name` alias and the two functions. In `submitted`, pass the text read from the Signal through `name` and `greeting`, then save it to `reply`.

## Return validation to the interface

`submitted` reads the input at submission time with `signals.read`, turns it into text with `greeting`, and saves it to `reply` with `signals.set`. Empty input saves a hint rather than failing the computation. A paragraph with `role: "status"` displays the result.

If you add something like saving to a server, keep validation failures separate from saving failures. The user fixes the input for one and retries for the other, so the hints differ. [Handle failures](/en/docs/guides/error-handling) covers how to handle failures.

## Divide the interface into parts

Repeated parts, such as a label paired with a field, can become functions that take props and return HTML ([Components](/en/docs/guides/components)). To place two forms with separate state side by side, use the approach in [Stateful features](/en/docs/guides/stateful-features). The detailed rules for input and keyboard events are in the [Web UI reference](/en/docs/reference/web-ui).
