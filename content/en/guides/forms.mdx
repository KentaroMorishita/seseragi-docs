title: Build a form

Build a form that shows a greeting when you type a name and press “Greet”. Submitting it empty shows “Enter your name”. The text being typed and the validation result are grouped into one `Model`, updated by `update`.

State, Actions, and `view` divide the work the same way as in [Build a Web application](/en/docs/guides/web-app).

## Prepare a project

```sh
seseragi new web greeting-form
cd greeting-form
```

In a project created with `seseragi new web`, replace `src/main.ssrg` with the code below. The generated `app.ssrg` is not used.

## Write the complete form

{/* example: examples/guides/forms/src/main.ssrg */}
```seseragi title="src/main.ssrg"
import * as dom from "std/web/dom"
import * as html from "std/web/html"

struct Model {
  draft: String,
  message: String
}

type Action =
  | Edited String
  | Submitted

alias View = html.Html<Action>

fn update action: Action
  -> model: Model -> Model =
  match action {
    Edited draft -> Model {
      ...model,
      draft,
      message: ""
    }
    Submitted ->
      if model.draft == "" then
        Model {
          ...model,
          message: "Enter your name"
        }
      else
        Model {
          ...model,
          message:
            `Hello, ${model.draft}`
        }
  }

fn edited event: html.InputEvent
  -> Action =
  Edited event.value

fn view model: Model -> View =
  html.main {
    style: html.style {
      margin: "32px auto",
      maxWidth: "32rem",
      padding: "24px"
    },
    children: [
      html.h1 {
        children: "Greeting"
      },
      html.form {
        onSubmit: Submitted,
        children: [
          html.label {
            htmlFor: "name",
            children: "Your name"
          },
          html.input {
            id: "name",
            name: "name",
            value: model.draft,
            onInput: edited
          },
          html.button {
            buttonType: "submit",
            children: "Greet"
          }
        ]
      },
      html.p {
        role: "status",
        children: model.message
      }
    ]
  }

pub effect fn main =
  dom.app {
    target: "#app",
    initial: Model {
      draft: "",
      message: ""
    },
    update,
    view
  }
```

`draft` is the text being typed, and `message` is the result to show after submitting. `Edited` clears the previous message when the input changes, and `Submitted` validates the current input.

## Turn an input event into an Action

The `value` of `html.InputEvent` holds the typed text. `edited` turns that text into an `Edited` Action. The browser's `Event` object itself never goes into the state.

`value: model.draft` shows the current value in the field, and `onInput: edited` sends an Action on every keystroke: the same shape as a controlled component in React. Matching `htmlFor: "name"` on the label with `id: "name"` on the field makes clicking the label select the field.

## Submit and validate

```sh
seseragi lock update
seseragi dev --open
```

Type `Ada` and press “Greet” to see “Hello, Ada”. Submitting it empty shows “Enter your name”. A form with `onSubmit` automatically stops the page reload and sends the Action (no `preventDefault` needed). Pressing Enter in the field submits too.

This example accepts input made only of spaces as a name. To strip spaces, tidy the input before validating, as in the next section.

## Check name validation in isolation

Here, try the rule “strip surrounding spaces, and reject the name if nothing is left” without a screen. Write the following three blocks in order in `form-validation.ssrg`. It is a separate program from the Web form above.

### Return an accepted name or a failure

Using [Either](/en/docs/learn/maybe-and-either), an accepted name goes in `Right` and a hint on how to fix the input goes in `Left`.

{/* example: examples/guides/form-validation.ssrg#validation */}
```seseragi title="form-validation.ssrg"
import * as text from "std/text"

alias Name = Either<String, String>

fn name input: String -> Name = {
  let cleaned = text.trim input
  if cleaned == "" then
    Left "Enter your name"
  else
    Right cleaned
}
```

### Turn the result into a greeting

{/* example: examples/guides/form-validation.ssrg#greeting */}
```seseragi title="form-validation.ssrg"
fn greeting result: Name -> String =
  match result {
    Right value -> `Hello, ${value}`
    Left message -> message
  }
```

`greeting` returns a greeting with the name on success, and the hint as is on failure.

### Compare valid, empty, and whitespace-only input

{/* example: examples/guides/form-validation.ssrg#inputs */}
```seseragi title="form-validation.ssrg"
pub effect fn main = do {
  name " Ada "
  |> greeting
  |> println
  name ""
  |> greeting
  |> println
  name "   "
  |> greeting
  |> println
}
```

```sh
seseragi run form-validation.ssrg
```

```text
Hello, Ada
Enter your name
Enter your name
```

`" Ada "` has its spaces removed and becomes `Ada`; `""` and `"   "` are both rejected. To use this check in the Web form, call `name model.draft` in `Submitted` and build `message` from the result.

## Return validation to the interface

A failed validation does not stop the app. `Submitted` puts the problem in `message` and returns it as the next state, and a paragraph with `role: "status"` displays it.

If you add something like saving to a server, keep validation failures separate from saving failures. The user fixes the input for one and retries for the other, so the hints differ. [Handle failures](/en/docs/guides/error-handling) covers how to handle failures.

## Divide the interface into parts

Repeated parts, such as a label paired with a field, can become functions that take props and return HTML ([Components](/en/docs/guides/components)). To place two forms with separate state side by side, use the approach in [Stateful features](/en/docs/guides/stateful-features). The detailed rules for input and keyboard events are in the [Web UI reference](/en/docs/reference/web-ui).
